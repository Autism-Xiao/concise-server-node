# 行政区划：列表一屏展示，超出一律表内滚动

日期：2026-11-07
涉及仓库：`concise-admin`（纯前端，后端零改动）

## 一、原来的问题

区划页是「树形懒加载 + 搜索平铺」，表格本身没有高度约束：

- 点「展开省级」后是 380 行，搜「东」命中 1,299 条（渲染前 200 条）——整页高度被撑到 2 万多像素
- 页面只有 `main` 这一条滚动条，表头（名称/区划代码/层级…）一滚就没了，看到第 30 行已经不知道哪列是哪列
- 顶部按钮、搜索框也跟着滚走，想换个关键字得先滚回顶部

## 二、改成了什么

**一屏布局 + 表内滚动 + 吸顶表头**：页面高度锁在可视区内，卡片吃掉剩余高度，数据多了只在表格区域里滚。

```
页面 h-full (flex-col)
├─ 标题 + 导入/刷新/新增   shrink-0
└─ Card flex-1 min-h-0
   └─ CardContent flex-1 min-h-0 (flex-col)
      ├─ 搜索行 + 层级筛选 + 展开/收起   shrink-0
      └─ Table（容器 flex-1 min-h-0 overflow-y-auto）
         └─ thead sticky top-0 z-10 bg-card
```

### 改动的文件

| 文件 | 类型 | 说明 |
| --- | --- | --- |
| `src/components/ui/table.tsx` | 修改 | `Table` 新增可选 `containerClassName`，透传到外层滚动容器（默认不变，其他页面零影响） |
| `src/features/system/region/index.tsx` | 修改 | 根节点 `space-y-6` → `flex h-full min-h-0 flex-col gap-6`；卡片/内容区改 `flex min-h-0 flex-1`；表格容器 `min-h-0 flex-1 overflow-y-auto rounded-md border`；`TableHeader` 加 `sticky top-0 z-10 bg-card`；加载骨架/错误态同样撑满一屏 |

## 三、关键点（为什么必须加在这层）

1. **竖向滚动必须落在 `Table` 自己那层容器上**。`Table` 的外层 div 已经有 `overflow-x-auto`，而 `overflow-x: auto` 会把 `overflow-y` 一起算成 `auto` —— 它本身就是一个滚动容器。如果再在外面套一层 `overflow-y-auto`，`sticky` 表头会粘在内层那个「高度=表格总高」的容器上，等于永远粘不住。
   → 所以给 `Table` 加 `containerClassName`，把 `flex-1 min-h-0 overflow-y-auto` 直接加在这一层。
2. **`min-h-0` 不能省**：flex 子项的默认 `min-height: auto` 会让内容撑开高度，`flex-1` 失效、又退回整页滚动。
3. **`h-full` 能生效依赖 `main[data-scroll=main]` 有确定高度**（`SidebarInset h-svh` → `main flex-1`），且多标签页容器用的是 `display: contents`，不会切断百分比高度链。
4. **吸顶表头要自带背景**（`bg-card`），否则下面的行会从表头缝隙里透出来。

## 四、验证（headless Chrome + CDP，视口 1484×805）

| 场景 | 结果 |
| --- | --- |
| 初始 34 行 | 表格区 `clientHeight=443`，`scrollHeight=2064`，页面 `scrollHeight=clientHeight=697`（页面不再滚） |
| 展开省级（380 行） | 表格区 `scrollHeight=22587`，页面仍 `697/697`，`pageScrollable=false` |
| 表内滚到底 | `thead.top=307`、容器 `top=306`，表头**仍在容器顶部可见**（吸顶生效） |
| 搜索「东」（命中 1,299，渲染 200） | 表格区 `scrollHeight=11945`，页面不滚，`命中 1,299 条，仅显示前 200 条` 提示正常 |

截图核对：顶部、滚到底、搜索三种状态均无错位/横向溢出/文字截断；tsc / eslint / 单测 7/7 全绿。

## 五、注意与后续

- 搜索结果仍有 **200 条渲染上限**（`SEARCH_LIMIT`）：关键字太宽时后端会回全量（例如「东」1,299 条），前端只画前 200 并提示细化关键字。现在有表内滚动，上限可以放心调大（1000 以内性能没问题），目前保持原样。
- 其他「长列表但不分页」的页面（如业务字典、菜单树）如果也想一屏滚动，直接复用 `<Table containerClassName="min-h-0 flex-1 overflow-y-auto rounded-md border">` + `TableHeader className="bg-card sticky top-0 z-10"` 这两行即可，不要再自己包一层 `overflow-y-auto`。
- 只有 3、5 行数据时，表格区仍占满卡片剩余高度，下方留白属于预期（列表区固定占位，切页/切关键字时不会跳高度）。
