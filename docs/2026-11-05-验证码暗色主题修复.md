# 验证码暗色主题不可读修复

- 日期：2026-11-05
- 仓库：`concise-server-node` + `concise-admin`（双端各一处小改）
- 现象：暗黑模式下登录页验证码几乎看不清

## 一、原因

后端 `captcha.service.ts` 生成 SVG 时只统一了配色（字符 `#3d4a57` 深灰、干扰线 `#c3ccd6` 浅灰），**SVG 背景是透明的**。前端 `CaptchaBox` 容器用的是 `bg-muted/30`（跟随主题），暗色下是深色底 —— 深灰字符压在深色底上，对比度趋近于 0。

## 二、改法：验证码当「图片」处理，固定白底

验证码的主流做法（jeecg、GitHub 等）都是浅色/白色底图，不跟随主题。分两层改：

| 文件 | 改动 |
| --- | --- |
| `concise-server-node/src/modules/auth/services/captcha.service.ts` | SVG 后处理时在 `<svg>` 开标签后注入 `<rect width="100%" height="100%" fill="#ffffff"/>` 垫底。**白底由后端给，任何端嵌（登录页/未来的移动端/邮件）都自带可读底色** |
| `concise-admin/src/features/auth/components/captcha.tsx` | 容器 `bg-muted/30 hover:bg-muted/60` → `bg-white hover:bg-white/85`。后端注入的白底 rect 会铺满容器，这层是兜底（防旧版后端或其他来源的透明 SVG） |

为什么不用 svg-captcha 自带的 `background` 参数：传了 background 会强制 `color: true`（字符随机彩色），而本项目后处理会把全部 fill 统一替换为深灰，背景 rect 的 fill 也会被一起替换掉，等于白传。直接注入 rect 更可控。

## 三、验证

- `GET /api/v1/auth/captcha` 实测：SVG 含 `<rect width="100%" height="100%" fill="#ffffff"/>` 且位于最前，字符 fill 仍为 `#3d4a57`，干扰线 `#c3ccd6`
- 两仓库 `tsc --noEmit`、eslint 通过；后端已重新构建 `dist`

## 四、注意

1. **后端进程需要重启**才会生效（`nest start` 只在启动时加载 dist，之前踩过这个坑）。
2. 验证码本质是「图片」，所以选择固定白底而不是 `dark:invert` 之类的 CSS 反色 hack —— 反色对灰阶有效，但以后若给字符加彩色，invert 会把颜色全部打乱。
3. 若以后想改成跟随主题的双色验证码，需要前端在请求时带主题参数并由后端出对应配色，目前没有必要。
