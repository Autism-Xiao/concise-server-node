# 2026-11-04 登录日志信息增强（browser/os/location 服务端采集）

## 背景

登录日志此前只有原始 `userAgent` 串和 IP，前端（concise-admin）还在自己解析 UA、`fetchPublicIp` 拿公网 IP 再 POST 自造日志——但后端根本没有这个 POST 接口，数据可伪造且与后端 `AuthService` 自动记录重复。本轮把采集全部收归服务端：**前端登录接口出入参完全不变**，日志的浏览器/操作系统/IP 归属地由后端在写入时从 `ip + User-Agent` 两个原料解析派生。

### 1. `src/utils/request-info.util.ts`（新增）

```ts
import { IP2Region } from 'ip2region/node'
import { UAParser } from 'ua-parser-js'

/**
 * 请求信息解析：从 ip + User-Agent 两个「原料」派生出日志展示字段
 * - browser：Chrome 156 / Edge 140 / Firefox 132 / Safari 18 …
 * - os：Windows 10 / macOS 15 / Android 14 …
 * - location：本机 / 内网IP / 广东省 深圳市 电信（ip2region 离线库，不依赖外网）
 *
 * 解析失败一律返回「未知」，日志增强永远不能影响登录主流程。
 */

/** ip2region 单例：应用生命周期内复用（同步构造只读 IPv4 库，约 11MB，首次调用时加载） */
let ipQuery: IP2Region | null = null
let ipQueryFailed = false

function getIpQuery(): IP2Region | null {
  if (ipQuery || ipQueryFailed) {
    return ipQuery
  }
  try {
    ipQuery = new IP2Region({ families: [4] })
  } catch (error) {
    // 库文件缺失/损坏时降级为「未知」，只记录一次
    ipQueryFailed = true
    console.error('[request-info] ip2region 初始化失败，归属地降级为未知:', error)
  }
  return ipQuery
}

/** 判断是否本机/内网地址（IPv4 + IPv6 常见形态） */
function isLocalOrPrivateIp(ip: string): 'local' | 'private' | null {
  const value = ip.trim()
  if (!value) return null
  if (value === '127.0.0.1' || value === '::1' || value === 'localhost' || value === '::ffff:127.0.0.1') {
    return 'local'
  }
  if (/^(10\.|192\.168\.|169\.254\.|fe80:|fc00:|fd)/i.test(value)) {
    return 'private'
  }
  // 172.16.0.0 ~ 172.31.255.255
  const m = /^172\.(\d+)\./.exec(value)
  if (m) {
    const second = Number(m[1])
    if (second >= 16 && second <= 31) return 'private'
  }
  return null
}

/** 浏览器：UAParser 主版本，如 "Chrome 156" */
export function parseBrowser(userAgent?: string | null): string {
  if (!userAgent) return '未知浏览器'
  try {
    const { browser } = UAParser(userAgent)
    if (!browser.name) return '未知浏览器'
    const major = (browser.version ?? '').split('.')[0]
    return major ? `${browser.name} ${major}` : browser.name
  } catch {
    return '未知浏览器'
  }
}

/** 操作系统：主版本，如 "Windows 10" / "macOS 15" */
export function parseOs(userAgent?: string | null): string {
  if (!userAgent) return '未知系统'
  try {
    const { os } = UAParser(userAgent)
    if (!os.name) return '未知系统'
    const major = (os.version ?? '').split('.')[0]
    return major ? `${os.name} ${major}` : os.name
  } catch {
    return '未知系统'
  }
}

/** IP 归属地：本机/内网直接判定，公网走 ip2region 离线库 */
export function describeIp(ip?: string | null): string {
  if (!ip) return '未知'
  const kind = isLocalOrPrivateIp(ip)
  if (kind === 'local') return '本机'
  if (kind === 'private') return '内网IP'
  const query = getIpQuery()
  if (!query) return '未知'
  try {
    // trust proxy 场景 X-Forwarded-For 可能带端口或 ::ffff: 前缀，先清洗
    const clean = ip.replace(/^::ffff:/, '').split(/[%:]/)[0].trim()
    const result = query.lookup(clean)
    if (!result) return '未知'
    const parts = [result.country?.name, result.subdivisions?.[0]?.name, result.city?.name, result.isp].filter(Boolean)
    return parts.length ? parts.join(' ') : '未知'
  } catch {
    return '未知'
  }
}

/** 一次解析出日志三件套 */
export function parseRequestInfo(ip?: string | null, userAgent?: string | null): { browser: string; os: string; location: string } {
  return { browser: parseBrowser(userAgent), os: parseOs(userAgent), location: describeIp(ip) }
}
```

### 4. `src/modules/system/log/log.service.ts`（recordLogin 修改点）

```ts
import { parseRequestInfo } from '../../../utils/request-info.util'

  /** 记录一次登录尝试（成功或失败）；浏览器/系统/归属地在写入时统一解析，调用方只给 ip + userAgent 原料 */
  async recordLogin(input: LoginLogInput): Promise<void> {
    try {
      // trust proxy 开启后 IPv4 可能以 ::ffff: 前缀（IPv4-mapped IPv6）落库，统一清洗成纯 IPv4
      const ip = input.ip.replace(/^::ffff:/, '')
      const { browser, os, location } = parseRequestInfo(ip, input.userAgent)
      await this.loginLogRepository.save(this.loginLogRepository.create({ ...input, ip, browser, os, location }))
    } catch (error) {
      console.error('[LogService] 登录日志写入失败:', error)
    }
  }
```

### 7. `concise-admin/src/lib/http.ts`（新增 getApiResult）

```ts
/** 后端统一响应外壳：{ code, message, result, success, timestamp } */
export interface ApiEnvelope<T> {
  code: number
  message: string
  result: T | null
  success?: boolean
  timestamp?: number
}

/**
 * 请求真实后端并解包 result：
 * - /backend-api 由 vite 代理转发到后端 /api
 * - 成功判定：success 优先，缺省时 code === 0（业务失败 HTTP 也是 200）
 * - 携带 token 时自动附加 Authorization 头
 */
export async function getApiResult<T>(url: string, init?: RequestInit): Promise<T> {
  const token = localStorage.getItem('concise-token') ?? ''
  const res = await fetch(url, {
    headers: { Accept: 'application/json', ...(token ? { Authorization: `Bearer ${token}` } : {}), ...init }
  })
  const json = (await res.json()) as ApiEnvelope<T>
  const ok = json.success ?? json.code === 0
  if (!ok || json.result === null) {
    throw new Error(json.message || `请求失败: ${res.status}`)
  }
  return json.result
}
```

```ts
interface BackendLoginLog {
  id: number
  /** 尝试登录的账号（不存在也记录） */
  username: string
  status: number
  message: string
  ip: string
  location?: string
  browser?: string
  os?: string
  userAgent?: string

/**
 * 拉取登录日志（真实后端 GET /api/logs/login）。
 * 后端是分页接口，这里取前 200 条倒序（列表页场景够用）；
 * 字段映射：username→user、0/1→失败/成功、createdAt→time。
 */
export async function fetchLoginLogs(): Promise<LoginLog[]> {
  const page = await getApiResult<{ items: BackendLoginLog[] }>('/backend-api/logs/login?page=1&pageSize=200')
  return (page.items ?? []).map(row => ({
    id: row.id,
    user: row.username,
    ip: row.ip,
    location: row.location || '未知',
    browser: row.browser || '未知',
    os: row.os || '未知',
    time: formatDateTime(row.createdAt),
    status: row.status === 1 ? '成功' : '失败',
    message: row.message
  }))
}
```

## 遇到的坑

1. **项目实际是 pnpm 管理**：node_modules 是符号链接指向 `.pnpm` 目录，`npm install` 会触发 arborist 的 `Cannot read properties of null (reading 'matches')` 崩溃且可能破坏依赖结构；装包必须用 `pnpm add`。
2. **ip2region v4 的构造是同步读文件**：默认双栈约 48MB 内存，只查 IPv4 用 `{ families: [4] }` 降到 11MB；做懒加载单例（首次调用才构造）避免拖慢应用启动，构造失败降级「未知」且只记一次。
3. **trust proxy 开启后 IPv4 会带 `::ffff:` 前缀**（IPv4-mapped IPv6）：Express 把 `req.ip` 表示成 `::ffff:127.0.0.1`，入库前统一 `replace(/^::ffff:/, '')` 清洗，否则列表里 IP 列很难看、ip2region 也查不到。
4. **DTO 校验在验证码校验之前**：造失败用例时 `captchaCode: 'wrong'`（5 位）根本到不了验证码逻辑，返回 1001「验证码为 4 位字符」；要测 412 必须传 4 位错码。
5. **前端 `getApiResult` 的成功判定要兼容两种形态**：`json.success ?? json.code === 0`——success 缺省的旧接口按 code 判断，避免一处封装堵死两种后端。

## 怎么扩展 / 使用

- **新日志字段**（如设备型号、登录耗时）：`login_log` 加列 → `recordLogin` 里解析并写入 → 前端 adapter 加映射，登录接口本身永远不用动。
- **IP 库升级**：`ip2region` 包内置 xdb 快照随包更新；要实时最新可传自定义 xdb 路径 `new IP2Region({ dbPath })`。
- **其他页面接真实后端**：照 `fetchLoginLogs` 模式——`getApiResult('/backend-api/xxx')` + adapter 映射字段，mock 请求保持不动直到页面整体切换。
- **操作日志页切真实数据**：等 dept/dict/file/level 等页面走后端接口后，`fetchOperationLogs` 换成 `getApiResult('/backend-api/logs/oper')` 并删 `withOperationLog`/`reportOperation`（后端 OperLogInterceptor 已自动记录真实写操作）。
