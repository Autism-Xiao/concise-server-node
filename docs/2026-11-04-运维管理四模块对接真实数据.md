日期：2026-11-04

## 一、先说数据库：只有定时任务有 jeecg 表

JeecgBoot 的「运维管理」四个页面里，**只有定时任务有表**（`sys_quartz_job`），另外三个本来就不建表：

| 页面 | JeecgBoot 的做法 | 本项目实现 | 表 |
|---|---|---|---|
| 定时任务 | `sys_quartz_job` + Quartz | `sys_quartz_job` + cron 包动态调度 | ✅ 与 jeecg 一致 |
| 在线用户 | Redis 里的 token 记录 | Redis 会话（`online:session:*`） | ❌ 无表（jeecg 也无） |
| 服务监控 | 系统 API 实时采集 | Node `os` / `fs.statfs` 实时采集 | ❌ 无表（jeecg 也无） |
| 缓存监控 | Redis INFO | Redis INFO + SCAN 前缀统计 | ❌ 无表（jeecg 也无） |

所以「sql 按 jeecg 搞」落在定时任务这一张表上，字段名/类型与 jeecg 官方 DDL 完全一致（未做任何重命名）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | varchar(32) PK | 32 位字符串主键 |
| `create_by` / `create_time` / `update_by` / `update_time` | varchar(32) / datetime | 审计四件套 |
| `del_flag` | int(1) | 删除标记，0 正常 / 1 已删除（**jeecg 是 int 型，不是 char**） |
| `job_class_name` | varchar(255) | 任务类名 |
| `cron_expression` | varchar(255) | cron 表达式 |
| `parameter` | varchar(255) | 参数 |
| `description` | varchar(255) | 描述 |
| `status` | int(1) | 0 正常（运行中）/ -1 停止 |

> 语义差异（代码里已注释）：jeecg 的 `job_class_name` 是 Java Quartz Job 实现类的全限定名，靠反射实例化；Node 没有反射式类加载，**改为「执行器标识」**，由 `JobHandlerRegistry` 注册的函数消费。

## 四、关键设计

### 1. 在线用户怎么来的（无表但真实）

JWT 是无状态的，没有会话表就没有「在线」概念。实现方式：

- `JwtStrategy` 开启 `passReqToCallback`，从 `Authorization` 头取原始 token
- 校验通过后 `SETEX online:session:<sha256(token)前32位> <剩余有效期> <JSON>`
  JSON 含：`sessionId/userId/username/dept/ip/location/browser/os/loginTime/lastActive/expiresAt`
- IP 归属地、浏览器、系统复用 `src/utils/request-info.util.ts`（与登录日志同一套解析）
- 强制下线：`SETEX online:revoked:<tokenHash>` 黑名单 + 删除会话；策略每次校验先查黑名单，命中直接 401

优点：不依赖登录接口改动，令牌不落库（只存哈希），水平扩容时多实例共享同一份 Redis 会话。

### 2. 定时任务执行器

```ts
// 任意业务模块注入 JobHandlerRegistry 即可扩展
registry.register('myJob', async ({ parameter, job }) => {
  // 干活
  return '执行结果摘要'
}, '我的任务说明')
```

调度：`cron` 包（v4）动态 `CronJob.from({ cronTime, onTick, start, timeZone: 'Asia/Shanghai' })`，
应用启动时 `onModuleInit` 全量加载 `status=0 && del_flag=0` 的任务，CRUD 后增量重挂。

运行记录（上次执行/结果/耗时/下次执行）只存内存，**进程重启后上次执行信息会清空**，`nextRun` 由当前 cron 实时计算。

### 3. 服务/缓存监控

- CPU 使用率：两次 `os.cpus()` times 差值，采样 200ms（瞬时值）
- 磁盘：Windows 遍历 C~H 盘符 + `fs.statfs`，类 Unix 取 `/`
- 缓存统计：`INFO` 取版本/内存/命中率，`DBSIZE` 取总数，`SCAN` 按 `xxx:` 前缀分组；TTL 每前缀抽样 20 个 key（pipeline）取最大值，避免全量 TTL 查询
- 清理：`SCAN MATCH prefix*` + `DEL` 分批删；不传前缀只清 `online:session:`、`online:revoked:`、`captcha:`，**不会 flushdb**

## 五、遇到的坑

1. **`id` 必须手动生成**：`JobService` 没继承 `BaseService`，`repository.save()` 不会补 32 位主键，报 `Field 'id' doesn't have a default value` —— 创建时显式 `randomId32()`。
2. **cron v4 的时间方法叫 `toJSDate()`**：`nextDate()` 返回的是 `DateTime`，不是 luxon 的 `toDate()`，写错直接编译不过。
3. **本机 Redis 是 3.0.504**：不支持多字段 `HSET`（4.0+）与 `MEMORY USAGE`（4.0+）。会话改用 `SETEX` + JSON 字符串，TTL 用 pipeline `TTL`，`SCAN`/`DBSIZE`/`INFO` 都在 3.0 可用。
4. **`passReqToCallback` 会改 `validate` 签名**：第一个参数变成 request，写成 `validate(request, payload)`，否则拿不到原始 token。
5. **新表 collation 必须 `utf8mb4_unicode_ci`**：与库内既有表一致，否则与其他表 JOIN 报 `ER_CANT_AGGREGATE_2COLLATIONS`（上次岗位表踩过，这次迁移直接写对）。
6. **oxlint `unicorn/no-useless-spread`**：`for (const id of [...map.keys()])` 被判多余，Map 迭代时删除当前 key 是安全的，改成直接迭代 `map.keys()`。
