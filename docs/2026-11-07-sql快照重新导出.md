## 导出参数逐条说明

```bash
MYSQL_PWD="$DB_PWD" mysqldump -h127.0.0.1 -P3306 -uroot \
  --default-character-set=utf8mb4 \   # 中文/emoji 不乱码
  --single-transaction --quick \      # InnoDB 一致性快照，导出期间不锁表
  --no-tablespaces \                  # 普通账号无 PROCESS 权限时也能导
  --set-gtid-purged=OFF \             # 避免在非 GTID 环境还原失败
  --routines --events --triggers \    # 存储过程/事件/触发器一并带上
  --hex-blob \                        # 二进制字段转十六进制
  concise_server > sql/concise_server_full_2026-11-07.sql
```

> 密码从 `.env` 的 `DB_PASSWORD` 读取放进 `MYSQL_PWD`，不写在命令行里（否则会进 shell 历史和进程列表）。

## 需要注意

1. **旧文件可恢复**：两个旧 sql 都在 git 历史里（`git show HEAD~1:sql/xxx.sql`），本地另存了一份到系统临时目录 `sql-backup-20261107/`（重启后会清）。
2. **区划数据没丢**：`sys_region` 的 44,983 条在新快照里；单独重建走 `scripts/import-region-2024.cjs`。因此不再单独维护 `sys_region_data_2024.sql`。
3. **快照含敏感数据**：`sys_user.password`（Argon2id 哈希）、租户、操作日志。仓库如果要公开，先把 `sql/` 移出或改私有存储。
4. **恢复后 token 失效**：`.env` 的 `JWT_SECRET` 与快照生成时不一致的话，旧 token 全部无效，重新登录即可。
5. **快照不含 `CREATE DATABASE`**：恢复前必须先手工建库（README 里给了命令）。

## 以后怎么更新

结构或数据有较大变更后（新增表、批量导入、迁移脚本执行完），按 `sql/README.md` 里的「重新导出快照」命令重跑一次，然后照本例做「导入临时库 → 逐表比行数 → 删临时库」的验证，再提交。
