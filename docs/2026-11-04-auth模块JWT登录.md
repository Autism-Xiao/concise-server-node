## 接口一览

| 方法 | 路径 | 认证 | 说明 |
|---|---|---|---|
| POST | `/api/auth/login` | 无 | 登录，返回 `{accessToken, refreshToken, expiresIn, userInfo}` |
| POST | `/api/auth/refresh` | 无 | 用 refreshToken 换新令牌对 |
| GET | `/api/auth/profile` | Bearer token | 当前登录用户信息（无 token/假 token 返回 401） |

## 实测结论（6 项全过）

1. 创建用户 → 密码以 `$2b$10$...` bcrypt 形态入库（数据库已确认）
2. 登录成功 → 拿到双令牌
3. 密码错误 → 401「用户名或密码错误」
4. profile 无 token → 401
5. profile 带合法 token → 返回用户信息（不含密码）
6. 刷新令牌 → 新 accessToken 正常签发

## 遇到的坑（已解决）

1. auth 的 service 在 `services/` 子目录，相对路径要多退一层（`../../user/...`）
2. jsonwebtoken v9 的 `expiresIn` 类型是 `StringValue`（模板字符串字面量类型），普通 `string` 不能直接赋——需 `import type { StringValue } from 'ms'` 断言；`ms` 类型需显式装 `@types/ms`
3. passport-jwt 的 `secretOrKey` 不接受 `string | undefined`，需 `as string` 断言

## 安全设计说明

- 密码只在创建/更新时哈希，任何查询响应都不返回密码字段
- 每次请求 token 验签后仍查库核对用户状态——禁用账号即时生效，无需等 token 过期
- 错误提示统一为「用户名或密码错误」，不暴露账号是否存在
