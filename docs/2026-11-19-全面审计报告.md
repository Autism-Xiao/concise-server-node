- **P1**：2FA 的 TOTP/备份码失败不计入账号级登录锁定（只对 `LOGIN_FAILED` 计数），已掌握密码者可在线爆破 2FA。

## 五、综合风险清单（去重合并，统一分级）

### 🔴 严重（阻断，立即处理）

**S1 — 真实密钥与数据库口令被提交进 git 仓库**
- 证据：`git ls-files .env` 返回 `.env`；`.gitignore` 中 `# .env` 为注释态（第 67 行附近仅 `.env.docker` 生效）；`git log -- .env` 显示已在提交 `28df4e2` 中。文件内含 64 位 JWT 双密钥、DB 口令（6 位纯数字）、DB 名等明文。
- 攻击场景：任何有仓库读权限者（含历史克隆/CI 缓存/fork）可取出双密钥，线下签发任意用户（含超管）令牌，完全接管系统。所有 RBAC/租户隔离在伪造超管令牌前失效。
- 修复：①立即轮换 JWT 双密钥与 DB 口令（旧 token 全失效需重登）；②`git rm --cached .env` 并恢复 `.gitignore` 的 `.env` 规则；③用 BFG/git-filter-repo 清洗历史并强推（需团队协同）；④生产密钥改环境变量/密钥管理服务注入。

### 🟠 高危（尽快处理）

**H1 — 数据库 6 位纯数字弱口令，且 `.env.example` 用同款弱口令作范例**
- 证据：`.env` DB_PASSWORD 长度 6、纯数字；`.env.example` 同型占位。
- 场景：MySQL 端口若对内网/公网可达，秒级爆破 + root 直取全库。
- 修复：≥16 位随机强口令；最小权限专用账号、禁 root 远程；example 改空值或明显占位符。

**H2 — 2FA 失败不计入账号级锁定，可在线爆破（代码审计 P1）**
- 证据：`auth.service.ts:455-459` 仅 `LOGIN_FAILED` 计数，TOTP/备份码错误抛 `TOTP_INVALID(2106)` 走 `return null`；登录接口 IP 限流 120/60 可换 IP 绕过（`auth.v1.controller.ts:72`）。
- 场景：已知密码的攻击者对每个 30s 窗口约可试 3 个 TOTP，且备份码空间可枚举。2FA 最后一道防线缺账号级熔断。
- 修复：将 `TOTP_INVALID` 纳入 `recordLoginFailure` 白名单累计，达阈值写 `ACCOUNT_LOCKED`。

### 🟡 中危（迭代处理）

- **M1 账号锁定只按用户名、可被定向 DoS**：`auth.service.ts:456-475` 以 `loginFailKeyOf(username)` 为键，无 IP 维度；知账号即可用 5 次错误密码锁他人 24h。建议账号+IP 双维度 + 异常锁定告警。
- **M2 TOTP ±1 步窗口内可重放**：`totp.util.ts verifyTotpCode(window=1)` 无一次性消费记录。建议记录最近成功 counter 拒绝复用。
- **M3 前端权限守卫 fail-open**：`concise-admin/src/routes/_authenticated.tsx:134-139` 权限为 null 一律放行，加载失败时普通用户可见管理页结构（后端仍拦数据，故中危）。建议改错误/重试态。
- **M4 OIDC 回调地址未配置时由 Host 头推导**：`sso.v1.controller.ts:119-123` 用 `req.get('host')`；建议生产强制 `OIDC_REDIRECT_URI`。
- **M5 Redis 未设密码**：`.env` `REDIS_PASSWORD=` 为空；当前仅 127.0.0.1 尚可控，但容器/多机部署会裸奔（ticket/黑名单/限流计数可被读写）。建议 `requirepass` + 绑定地址。
- **M6 applySort 原型链命中致 500**：`sort.ts:29` `allow[query.sortBy]`，传 `__proto__/constructor` 命中原型链拼非法列名 → 列表 500，可稳定 DoS（列名带引号，非注入）。建议 `hasOwnProperty` 判定或 `Object.create(null)`。
- **M7 备份码消费非原子**：`totp.service.ts:146-152` 查→判→改三步，并发双登录可同时通过。建议条件 UPDATE + `affected===1` 判定。
- **M8 refreshToken 未校验账号状态**：`auth.service.ts:386` / `user.service.ts:920-929` 仅过滤软删不查 status，冻结用户仍可换发令牌。建议 refresh 前校验 `status===1`。
- **M9 冒烟脚本与代码脱节**：`smoke-captcha` 容差断言未同步（17/18）、`smoke-tenant-isolation` 弱口令被策略拦（中断），长期红灯掩盖真实回归。建议同步脚本断言与口令。

### 🟢 低危 / 技术债（择机处理）

- **L1** `main.ts:189-194` ValidationPipe 开 whitelist 未开 `forbidNonWhitelisted`，未知字段静默丢弃。
- **L2** `tsconfig.json:15` `sourceMap:true`，生产产物带 `.js.map` 泄露源码结构。
- **L3** 全局 helmet CSP 关闭（上传/预览接口另有 CSP，JSON API 影响有限）。
- **L4** SSO 一次性 code 存进程内存 Map，多实例 exchange 会错配（可用性）。
- **L5** 登录限流按 IP，代理池可绕（由账号锁定兜底）。
- **L6** 生成器分页 DTO 仅 `@IsInt()` 无 `@Min/@Max`，`pageSize=999999` 可拉全表；模板应 `extends PagerDto`。
- **L7** 分页字段两套命名（`current/size` 见 `tenant-user.dto.ts`、`reminder` 控制器 vs 其余 `page/pageSize`），语义不统一。
- **L8** 错误码注释与前端消费不符（8104/8105 注释称前端弹框，实际按 `quota.reason` 分支）；`roles.decorator.ts:3` 注释「角色 name」实为 `roleCode`。
- **L9** dashboard 裸 SQL 参数按占位符出现顺序 push（`dashboard.service.ts:350-367`），新增 WHERE 易错位致统计错误或租户过滤失效。
- **L10** **oxlint 3 error / 41 warning**：3 个 error 为 `no-floating-promises`（未 void/await 的 Promise）在 `reminder.scheduler.ts`、`webhook.service.ts`、`file.cleaner.ts`；41 warning 多为 `restrict-template-expressions` 与 DTO 展开丢原型，非功能缺陷但建议清理。

## 七、纵深防御建议

1. **密钥治理优先于一切加固**：建立轮换 SOP + CI 密钥扫描（gitleaks/trufflehog pre-commit hook）。
2. **收敛 fail-open 语义**：梳理所有「Redis 不可用→放行」路径（锁屏、验证码关闭），确保有等价第二道闸门（账号锁定始终生效）。
3. **权限声明 CI 兜底**：`PermsGuard` 对未声明 `@Perms()` 的接口默认放行；加静态检查，除健康/认证/公开类外写接口必须声明 `@Perms`/`@ApiScope`。
4. **可观测性**：对锁定触发、refreshToken 重放、平台级权限拒绝、Webhook SSRF 拦截加安全告警聚合。
5. **会话加固**：评估 accessToken 短 TTL + 服务端 session 版本（当前 2h 内靠黑名单即时吊销，方向已正确）。
