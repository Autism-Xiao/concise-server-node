# 2026-11-07 菜单图标选择器

## 需求

菜单编辑/新增弹窗中，「图标」输入框旁增加图标选择入口：点开弹层选择图标后，图标实时预览在选择框上，文本框继续保存 lucide 组件名（如 `LayoutDashboard`），二者联动。

## 交互说明

- 触发按钮：当前 icon 名称在图标库内 → 显示该图标；为空或名称无效 → 显示 `SmilePlus` 占位（muted 色）
- 弹层：顶部搜索框（按名称模糊过滤），网格点选即写回输入框并关闭；底部显示数量 + 「清除图标」
- 手动在输入框输入有效名称，预览同样实时更新；手动输入库里没有的名称不报错，只是预览显示占位
- 后端无需改动：存储的仍是 lucide 组件名字符串，历史数据完全兼容

## 扩展方式

- 加图标：往 `icon-picker.tsx` 的 import 和 `ICON_MAP` 各加一行（PascalCase 名称必须与 lucide-react 导出一致，否则运行时不渲染）
- 想要全部图标：把 `ICON_MAP` 换成 `import { icons } from 'lucide-react'`，代价是主包体积明显增大（未采用）

## 遇到的坑

1. **TS2774**：本 TS 版本对「函数类型（组件）或其与 undefined 的联合」做真值判断直接报错，即使 `const a: LucideIcon | undefined = ICON_MAP[value]` 也不行。改为 `const hasIcon = value in ICON_MAP` 判存在性，组件变量不带 undefined 注解，条件全部用 `hasIcon`。
2. **Popover 的 align/sideOffset 属于 Positioner 而非 Popup**：封装 PopoverContent 时要把这两个 prop 显式声明并传给 Positioner，否则 TS 报错。
3. 图标名先经脚本比对 `node_modules/lucide-react/dist/esm/icons/*.mjs` 全量校验（214/215 通过，剔除不存在的 `shapes-plus`），避免手写名称拼错运行时不渲染。
