# 会话过期：先弹「重新登录」确认框，不再闪跳

日期：2026-11-17 · 类型：体验修复 · 仓库：concise-admin

## 问题

登录超时（任意请求收到 401）时，`lib/http.ts` 的 `handleUnauthorized()` 直接
`window.location.assign('/login')` 整页跳转。用户看到的是「页面闪一下就回到登录页」：
不知道发生了什么，正在填的表单/筛选条件瞬间消失，也没有任何解释。

## 改法

401 处理只负责「登出 + 广播事件」，跳转决定权交给用户：

```
401 → logout() → notifySessionExpired()（去重广播）
                    ↓
     SessionExpiredDialog（挂在 __root，全站唯一）
                    ↓ 用户点「重新登录」
     resetSessionExpiredFlag() + location.assign('/login')
```

弹框不可关闭（受控 Dialog 且忽略 onOpenChange：Esc / 点遮罩 / 右上角 X 全部无效），
只有「重新登录」一个出口——此时 token 已清空，留在原页面的任何请求都会失败，
「留在本页」没有意义。

| `concise-admin/src/lib/session-expired.ts` | 新增 | 会话过期事件单例：notify / on / reset 三件套，`notified` 标记去重 |
| `concise-admin/src/components/session-expired-dialog.tsx` | 新增 | 全局「登录已过期」弹框，i18n 文案，点击重新登录后整页跳 `/login` |

| `concise-admin/src/config/i18n.ts` | 修改 | 新增 `session.expired.title/desc/action` 中英三键 |

## 每项的作用与设计取舍

- **去重标记 `notified`**：登出后并发的一批在途请求（顶栏消息轮询等）会同时收到 401，
  没有去重会连弹 N 个框。`resetSessionExpiredFlag()` 只在「重新登录」被点击后复位，
  下一轮会话过期才能再弹。
- **保留整页跳转而不是 SPA 路由**：登出已清空 localStorage 凭证、页签缓存、设置快照，
  `location.assign('/login')` 顺带清掉内存里的全部组件状态（keep-alive 页签、轮询定时器），
  回到最干净的登录页。SPA navigate 会留下大量悬挂状态，收益只有「不刷新」这一个。
- **弹框不提供「留在本页」**：token 已清、后端会话已作废，留下来页面是死的；
  与其给一个假选项，不如一个明确的「重新登录」。

## 踩的坑

1. **这个项目的 Dialog 是 Base UI（`@base-ui/react`）不是 Radix**：没有
   `onEscapeKeyDown` / `onPointerDownOutside` 回调，也没有 `dismissible` 属性
   （先按 Radix 习惯写全部 TS2322）。受控组件下 `onOpenChange={() => undefined}`
   本身就是「Esc/点遮罩关不掉」的正确实现，不需要任何拦截回调。
2. **`npx tsc --noEmit` 过了但 `npm run build` 报错**：build 走 `tsc -b`（项目引用），
   检查口径与前者不同——以后以 `tsc -b` 为准，别被单跑 tsc 的假绿骗了。
3. 401 有两个触发点（HTTP 状态码 + body `code===401`），两处都走 `handleUnauthorized`，
   改一处即全覆盖；`tests/http-unauthorized.test.cjs`（后端）锁定的约定没有动。

## 如何扩展

- 管理员强制下线（WS `force-offline`，`lib/realtime.ts`）目前仍是 toast + 直接跳转，
  语义不同（有人主动踢你），如需统一体验可复用 `notifySessionExpired` 加 reason 参数。
- 若将来接「自动续签」（前端用 refreshToken 静默刷新），401 的处理入口不变，
  只需要在 `handleUnauthorized` 之前插入续签重试逻辑。
