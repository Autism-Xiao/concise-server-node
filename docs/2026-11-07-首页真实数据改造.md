# 首页（仪表盘）接真实数据：一个聚合接口 + 按权限逐块裁剪

> 日期：2026-11-07
> 后端提交：`feat(dashboard): 首页概览聚合接口，按权限逐块裁剪`（见 git log）
> 前端提交：`feat(dashboard): 首页接真实数据，按权限裁剪 + 首页常驻`

## 一、为什么要改

改造前首页是**纯 mock**：`fetchDashboard()` 直接取 `/mock/dashboard.json`（10.8 KB 静态 JSON），内容是 SaaS 模板数据 —— 总收入 ¥12,500 / 新客户 / 活跃账户 / 增长率、移动端 vs 桌面端访客、文档表（大纲/历史业绩/核心人员/重点文档）。

这套语义在系统里**一个实体都对不上**：库里真实存在的是 `sys_user` / `sys_role` / `sys_dept` / `sys_permission` / `sys_log` / `sys_file` / `task` / `sys_announcement` / `sys_quartz_job`。所以不是「数据源没接」，是整套 UI 放不进真实数据。

顺带发现两个既有问题：

1. **首页对大多数人不可达**：`/dashboard` 不在 `lib/permissions.ts` 的 `ALWAYS_ALLOWED` 里，而 `menu_35`（仪表盘）在库里只授权给了 viewver 角色。`editor` / `auditor` / 无角色账号进首页会 403，只能靠 `resolveHomePath()` 的兜底被甩到「注册表里第一个有权限的业务页」—— 每个账号落地页都不一样。
2. **数据范围（data_scope）漏了「全部」这一档**：`applyDataScope` 里没有 `scope === ALL` 的分支，导致 data_scope=1（全部）的账号仍被自己的部门收窄；没挂部门的账号直接 `1 = 0`，看不到任何人。表现是「有 `system:user:list` 的审计员打开用户列表是空的」。

## 三、每个东西是干什么的

### 三道闸门（「不同用户看不同数据」的实现）

| 层级 | 控制什么 | 依据 | 结果 |
|---|---|---|---|
| ① 块级 | 这块要不要出现 | 按钮权限（`system:user:list` 等） | 返回 `null`，前端不渲染 |
| ② 行级 | 同一个数字算多大范围 | `sys_role.data_scope` | 用户总数 24 → 本部门 3 |
| ③ 归属级 | 是不是我的数据 | `owner_id` / `assignee_id` | 我的存储、我的待办 |

### 权限门槛与降级规则

| 区块 | 全站口径（需权限） | 降级口径（仅登录） |
|---|---|---|
| 用户总数 | `system:user:list`，按 dataScope 收窄 | 无（没权限就隐藏） |
| 今日登录 | `system:log:login` | 自己的登录记录 |
| 登录趋势 | `system:log:login` | 自己的登录记录 |
| 最近操作 | `system:log:oper` | 自己的操作记录 |
| 在线人数 | `system:online:list` | 隐藏 |
| 角色总数 | `system:role:list` | 隐藏 |
| 系统状态 | `system:monitor:server` | 隐藏 |
| 我的存储 / 待办 / 公告 | — | 始终可见（按 owner/assignee 过滤） |

降级块在响应里带 `scope: 'self'`，前端据此在标题上标「仅我的」—— 否则用户会怀疑「为什么我和同事看到的数字不一样」。

## 四、遇到的坑

1. **`null` 不是 `0`**：没权限的块必须返回 `null`。返回 0 前端无法区分「真的没有数据」和「你没权限看」，只能靠猜，猜错就是一个误导性的「用户总数 0」。
2. **`task.assignee_id` 是 `int`，`sys_user.id` 是 `varchar(32)`**（JeecgBoot 主键）。两者永远匹配不上，实测那条 `assignee_id=1` 的历史任务对任何账号都不显示。所以 `myTasks` 对「ID 不是纯数字」的账号仍统计 `assignee_id = 0`（未指派），否则有任务权限的账号会以为系统里一条任务都没有。**彻底修需要把该列迁成 varchar**，属独立改动，本轮没做。
3. **`data_scope` 漏了 `ALL` 档**（本次修）：`applyDataScope` 只处理了 4/3/2 三档，`1`（全部）会掉进「本部门」逻辑，没部门的账号变 `1 = 0`。修完 `auditor` 能看到 24 个用户，且首页数字与用户列表 `total` 完全一致（冒烟里加了这条同口径断言）。
4. **趋势图不能只画有数据的天**：库里登录日志只有 4 天，`GROUP BY` 只返回 4 行；如果直接喂给图表，折线会把不相邻的两天连起来，看起来像「连续下降」。所以按日期补零到固定 7 天。
5. **`DATE_FORMAT(create_time,'%Y-%m-%d')` 要用本地时区口径**：JS 侧生成日期键也必须用 `getFullYear/getMonth/getDate`（不能用 `toISOString().slice(0,10)`，那是 UTC，凌晨 8 点前会错一天）。
6. **`getServerInfo()` 内部有 200ms CPU 采样**：必须和其它查询一起放进 `Promise.all`，串行会把 200ms 叠加到首屏。
7. **`npm run restart` 可能根本没重启**：`nest build` 会清 `dist`（700+ 文件），被 safe-delete 钩子拦成 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`，而 `&&` 短路后 `serve.mjs` 压根没跑 —— 表面上「重启成功」，实际还是旧进程。判断方法：`curl /api/v1/dashboard/overview` 回 404 说明路由没注册（回 401 才是已注册但没带 token）。
8. **`node scripts/serve.mjs | head -20` 会杀掉服务**：`head` 读满 20 行关管道，子进程跟着退出，任务却显示 `completed exit 0`。启用服务的命令不要接管道。
9. **`sys_announcement` 的标题列叫 `titile`**（JeecgBoot 历史拼写），不是 `title`；直接写 `select title` 会报 Unknown column。

## 五、怎么扩展

### 加一个新的首页块（三步）

1. `dashboard.types.ts`：加 `XxxBlock` 类型，在 `DashboardOverview` 里加 `xxx: XxxBlock | null`（带 `@ApiPropertyOptional`）。
2. `dashboard.service.ts`：
   - 在 `PERM` 里加权限标识常量；
   - 写一个 `private async xxxBlock(actor)`；
   - 在 `overview()` 的 `Promise.all` 里加一行 `can(PERM.xxx) ? this.xxxBlock(actor) : Promise.resolve(null)`。
3. 前端：`api.ts` 加类型，`components/` 加组件，`index.tsx` 里 `{data.xxx && <XxxCard ... />}`。

**不需要**改 `@Perms`、不需要给角色单独授权、也不需要写 `if (role === 'xxx')` —— 权限判定只看权限集合。

### 跑冒烟

```powershell
# 1. 起一个关掉验证码的测试实例（不与 3459 抢端口）
$env:PORT="3461"; $env:CAPTCHA_ENABLED="false"; node dist/main.js

# 2. 另开一个终端跑断言（脚本会临时建 auditor / 无角色账号并在结束时删除）
node scripts/smoke-dashboard.mjs
```

覆盖点：未登录 401、admin 全量、viewer 降级、auditor 有日志无角色/在线/监控、无角色只剩「我的」、趋势 7 天连续、首页数字与用户列表 `total` 同口径、操作日志不返回 `params`/`errorMsg`。

### 已知可继续优化

- 待办块要真正有数据，需要把 `task.assignee_id` 迁成 `varchar(32)`（连带任务模块的 DTO、筛选、指派下拉）。
- 登录趋势可加「按小时」视图（`sys_log` 有 `create_time` 索引，改 `DATE_FORMAT` 粒度即可）。
- 「我的最近操作」在详情页可点进 `/system/log/operation` 并带 `id` 过滤。
- 存储块可加「回收站占用」提示（`is_deleted = 1` 的字节数），配合二期的 `FILE_RECYCLE_DAYS` 引导清理。
