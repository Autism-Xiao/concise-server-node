# 按钮级权限落地 + 角色授权闭环

> 日期：2026-11-04 ｜ 仓库：concise-server-node（后端）+ concise-admin（前端）

## 这是什么

RBAC 收尾两件事：
1. **按钮级权限落地**：各页面写操作按钮按 `hasPermission(perm)` 控制显隐（超管 `['*']` 全显示）
2. **角色授权闭环**：角色权限页对接真实后端——列表/创建/编辑/删除走 `/api/roles`，授权走新增的 v1 接口，弹窗勾选后端菜单树（含按钮），保存后用户重新登录即生效

## 接口（按约定挂 v1）

```
GET /api/v1/roles/:id/menu-ids   → { menuIds: ['menu_1', ...] }      # 授权回显
PUT /api/v1/roles/:id/menus      body { menuIds } → { menuIds }      # 全量覆盖，复用 assignMenus
```

均为 `@Roles('admin')`（类级）。

## 授权数据流（闭环）

```text
角色权限页「分配权限」→ 勾选菜单树（GET /api/menus/tree 数据源）
  → PUT /api/v1/roles/:id/menus 全量覆盖 sys_role_permission
  → 用户重新登录 → GET /api/v1/auth/permissions
      ├ menus 树 → 侧边栏/路由守卫
      └ permissions 按钮编码 → hasPermission() 控制页面按钮
```

## 遇到的坑

1. **v1 控制器相对路径多写一层**：`role.v1.controller.ts` 与 role.controller 同目录，import 该用 `./dto`、`./role.service`，写成 `../` 导致 tsc 报 Cannot find module
2. **admin 角色在 sys_role_permission 里只绑了 menu_1/menu_2**——不影响（超管走 `['*']` 分支不查关联表），但说明库里 admin 的授权记录不是全量，别用 admin 验证授权过滤
3. 重写 index.tsx 时一次 Edit 误删了 useDataTable 段，靠 tsc 当场发现修复

## 怎么扩展 / 使用

```tsx
// 任意页面包按钮
import { hasPermission } from '@/lib/auth'
{hasPermission('system:notice:add') && <Button>新增公告</Button>}
```

权限编码即 `sys_permission.perms`（menuType=2 的按钮记录），在角色管理页勾选即可下发。**相关用户重新登录后生效**（前端 localStorage 缓存）。

## 实测结果
