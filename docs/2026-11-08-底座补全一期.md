## 遇到的坑

1. **可空字符串列必须显式 `type:'varchar'`**（项目已知坑再犯）：`senderId` 漏写导致 TypeORM 推断成 Object，启动即炸。
2. **`import type` 导入 DTO 会擦掉 design:paramtypes**：控制器参数类型变成 Object，全局 ValidationPipe 直接跳过校验转换，`dto.userIds` 为 undefined → 500。DTO 必须**值导入**。
3. **`dataSource.query` 的 `IN (?)` 不展开数组**（与 QueryBuilder 不同），要手拼占位符。
4. **Nest POST 默认 201**：冒烟断言按 200 写会假挂。
5. MySQL 迁移 `UPDATE ... WHERE <> 0` 不处理 NULL，改 NOT NULL 前要连 NULL 一起归零（WARN_DATA_TRUNCATED）。

## 怎么扩展

- 系统事件要发消息：注入 `MessageService` 调 `notify(title, content, userIds, msgType)`，或发用户名数组（service 内部解析）。
- WebSocket 推送接入后，`notify` 可在落库后同时 emit（下一期接线）。
- 多实例部署：确认 `REDIS_ENABLED=true` 即可，定时任务 cron 已有分布式锁；日历提醒的抢权式 UPDATE 本身多实例安全。
