# 2026-11-04 按钮级权限 + 日志 + 部门模块

本轮在 RBAC 体系之上补齐三块能力：按钮级权限、登录/操作日志、部门管理。提交后接口总数达 20+。

## 一、按钮级权限 @Perms()

### 新增文件

| 文件 | 说明 |
|---|---|
| `src/common/decorators/perms.decorator.ts` | `@Perms('system:user:add')` 声明接口所需权限标识 |
| `src/common/guards/perms.guard.ts` | 全局守卫：实时查库（user_roles → role_menus → menu.permission）匹配权限集合，任一命中放行；`admin` 角色直接放行；未声明 `@Perms()` 的接口不受限 |

### 说明

- 权限标识存在 `menu.permission` 字段（按钮类型菜单 type=2），数据结构上一轮已就绪
- 守卫顺序：`JwtAuthGuard`（认证）→ `RolesGuard`（@Roles 模块级）→ `PermsGuard`（@Perms 按钮级）
- 权限每次请求实时查库，改权限立即生效，不信任令牌负载
- 日志接口权限从 `@Roles('admin')` 改为 `@Perms('system:log:login'/'system:log:oper')`——审计员角色无需 admin 角色也能查日志

## 实测结论（12 项全过）

- ✅ admin（bypass）可访问所有 @Perms 接口
- ✅ auditor 角色（有 system:log:* 权限、非 admin）查登录/操作日志 200 —— PermsGuard 正向
- ✅ 无角色 guest 查日志 403、auditor 创建用户 403（RolesGuard 类级拦截）—— 负向
- ✅ 操作日志自动记录：模块、`POST /api/depts`、参数 JSON（密码脱敏）、耗时 14ms
- ✅ 登录日志记录成功与失败（错误密码 → status=0 "用户名或密码错误"）
- ✅ 部门树 `总公司 → 研发部/测试部` 正确组装
- ✅ build / eslint / 单测 / e2e 全绿

## 使用约定（以后照抄）

- 模块级权限：Controller 类上加 `@Roles('admin')`
- 按钮级权限：方法上加 `@Perms('模块:资源:动作')`，并在菜单管理里录入对应 type=2 按钮
- 写操作自动产生操作日志，想自定义模块名加 `@OperLog('模块名')`

## 测试数据现状

用户：admin / guest / auditor1（角色 auditor，仅日志查看权限）；部门：总公司→研发部、测试部；角色：admin/viewer/editor/auditor；按钮权限：system:log:login、system:log:oper。
