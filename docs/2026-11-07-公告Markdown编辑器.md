# 通知公告内容改用 Markdown 编辑器（前端）

## 背景

公告表单的「内容」原本是纯文本 textarea，改为 **Markdown 编辑器**（工具栏 + 编辑/预览切换）。

本轮为纯前端改动（concise-admin），后端字段本来就是「富文本或纯文本」、上限 20000 字符，无需变更。

## 前端改动清单（concise-admin）

| 文件 | 类型 | 说明 |
| --- | --- | --- |
| `src/components/markdown-editor.tsx` | 新增 | 轻量 Markdown 编辑器：加粗/斜体/删除线/标题/引用/列表/行内代码/代码块/链接/分隔线工具栏，编辑/预览双模式，字数统计（maxLength 超限忽略输入） |
| `src/components/markdown-preview.tsx` | 新增 | react-markdown + remark-gfm 渲染；Tailwind 手写样式映射跟随主题；默认不渲染原始 HTML，天然防 XSS |
| `src/features/system/notice/components/notice-form-dialog.tsx` | 修改 | textarea 换成 MarkdownEditor（maxLength=20000），弹窗加宽到 max-w-2xl，占位文案改为「支持 Markdown」 |
| `package.json` | 修改 | 新增依赖 react-markdown ^10、remark-gfm ^4 |
| `pnpm-workspace.yaml` | 误建后已删除 | 安装过程中工具误写，已恢复原状（该文件原本不存在） |

## 使用 / 扩展

- 公告正文现在支持 Markdown：预览页签实时渲染，GFM 表格/删除线/任务列表可用
- 列表页的内容列仍是纯文本单行截断展示（Markdown 源码），可读
- 其他需要富文本的地方可直接复用 `<MarkdownEditor>` / `<MarkdownPreview>` 两个组件
- 新加快捷键/工具按钮：在 `TOOLS` 数组加条目并在 `runTool` 里加分发即可

## 遇到的坑

1. **pnpm 12 strictDepBuilds**：`pnpm add` 因 `@scarf/scarf` 构建脚本未审批而报 `ERR_PNPM_IGNORED_BUILDS`。本机工具的工作目录停在 concise-server-node，导致：依赖一度被装进**后端** package.json、后端 `pnpm-workspace.yaml` 的占位行被误删。已全部恢复：后端卸载依赖、workspace 占位行改为显式 `'@scarf/scarf': true`（它只是安装期遥测脚本）；前端依赖在前端目录重新安装
2. **ESLint react-hooks/refs 误报**：组件内创建含闭包的 tools 数组并在 JSX 里 map 被判定为「渲染期访问 ref」；把工具清单提为模块级纯数据、点击时按 id 分发解决
3. **沙箱剥离 `cd` 前缀**：本机命令的工作目录固定在 concise-server-node，前端命令改用 `npm --prefix` 与绝对路径的 tsc 执行
