# 开放平台：应用凭证 + OAuth2 + Webhook

## 这是什么

第三方系统对接底座的两条通道：

1. **拉（API）**：管理员创建应用、发 `client_id + client_secret`，对方拿它走 OAuth2
   `client_credentials` 换短期访问令牌（2h），调 `/v1/open/**` 开放接口；
2. **推（Webhook）**：对方提供一个 https 回调地址订阅平台事件，事件发生时平台 POST JSON 过去，
   带 HMAC-SHA256 签名，失败自动重试 3 次。

## 安全模型（本模块最值得看的部分）

- **Secret 明文只出现一次**：创建/重置的响应里给一次，之后库里只有 sha256。
  列表展示的是前 8 位明文前缀（`sk_f5725…`），只用来识别"哪把钥匙"。
- **sha256 而不是 argon2**：换 token 是高频机器调用，慢哈希会把每次请求拖慢几百毫秒；
  机器密钥本身是 192 位随机数，没有弱口令爆破面，sha256 + 常量时间比较足够。
- **停用/删应用即时生效，不留 2 小时窗口**：应用令牌签发时 scope 写进了 JWT payload，
  但 `JwtStrategy.validate` 对 app 令牌**每次实时查库**校验状态并取最新 scope（单主键点查，代价可忽略）。
  代价是没了 token 层缓存，换来的是"停用即断"，比"对方拿旧令牌再刷两小时"重要得多。
- **凭据错误不区分账号/密钥**：token 端点失败统一一句「client_id 或 client_secret 错误」，防 client_id 枚举。
- **Webhook URL 强制 https**、签名密钥 256 位随机（服务端要拿它算签名，所以必须可读，存明文但只在管理端可见）。

## 协议要点（对接方视角）

```text
POST /api/v1/open/token
{ "client_id": "app_xxx", "client_secret": "sk_xxx", "grant_type": "client_credentials" }
→ 200 { "access_token": "…", "token_type": "Bearer", "expires_in": 7200, "scope": "user:read" }
```

- token 端点是**裸响应**（没有 `{code, result}` 包装）——对接方拿现成 OAuth2 客户端库调的，别让人家改解析。
- Webhook 请求头：`X-Concise-Event`（事件名）、`X-Concise-Delivery`（幂等键，重试用同一个）、
  `X-Concise-Signature: sha256=<HMAC-SHA256(secret, rawBody)>`；2xx 视为成功，否则按 1s/5s/15s 重试，共 4 次尝试。

## 踩的坑

- **控制器前缀漏了 `v1`**：本仓库全局 prefix 是 `/api`，控制器要写 `@Controller('v1/apps')`。
  写成 `'apps'` 的话路由变成 `/api/apps`，第一次实测直接 `Cannot POST`。
- **`toPagination()` 不能用于库侧分页**：它按传入数组长度算 total。分页在 SQL 里做的要用
  `new Pagination(rows, total, page, size)` 直接构造（和字段级审计同一个坑）。
- **TypeORM `select` 必须对象形式**：`select: ['secretPrefix']` 会 TS2559，`select: { secretPrefix: true }` 才对。
- **统一响应包装是全站默认**：OAuth2 端点想裸返回必须加拦截器跳过开关（@RawResponse + Reflector），
  不能只在控制器里返回不同结构。
- **sys_user 没有 mobile 列**：开放接口字段白名单写 `row.mobile` 直接 TS2339，别照抄别处的用户字段清单。
- **停用即时生效 vs 令牌缓存**：最初方案把 scope 放 JWT 里就算完，实测发现"停用后旧令牌还能刷 2 小时"。
  改成 validate 实时查库后，这条测试通过（停用 → 同一令牌立即 401）。

## 如何扩展

- **新增开放接口**：在 `open.v1.controller.ts` 加方法 + `@ApiScope('xxx')` + 手写字段白名单；需要新 scope 就
  在 `openapi.constants.ts` 的 `APP_SCOPES` 加一条（前端 `SCOPE_OPTIONS` 同步加展示名）。
- **新增 webhook 事件**：`WEBHOOK_EVENTS` 加事件名 → 在业务写路径调 `webhookService.dispatch('xxx', data)`
  → 前端 `EVENT_OPTIONS` 同步。dispatch 是 fire-and-forget，不 await、不抛错。
- **密钥轮换策略**：当前 `resetSecret` 是"旧版本全撤 + 发新版本"。要做"新旧并存 7 天"的话，
  `sys_app_secret` 的版本结构已经就绪（按 status 控制哪把有效）。
- 应用令牌**不会**出现在操作日志的"操作人"里（operate_user_id 为空）——需要区分时看
  `sys_log.user` 是否为应用名（username 字段是 appName）。
