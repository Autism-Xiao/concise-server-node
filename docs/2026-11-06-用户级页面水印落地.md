## 二、接口与规则速查

```
GET  /api/v1/users/me/watermark      当前用户生效配置（lines 已解析好占位符）
PUT  /api/v1/users/me/watermark      自助修改，仅 enabled/content/density，传 null 恢复继承
PUT  /api/v1/users/:id/watermark     管理员管控单人（enforced 1=强制开 2=强制关），需 system:user:update
GET  /api/v1/system/watermark        全局策略，需 system:watermark:edit
PUT  /api/v1/system/watermark        改全局策略，enabled 与 mode 自动联动
```

生效优先级：`mode=off` → 用户 `enforced=2` → `enforced=1` → `mode=forced` → `用户.enabled ?? 全局.enabled`。
前三档与 forced 用户都改不了，前端拿到 `editable=false` 直接置灰并展示 `reason`。

## 三、遇到的坑

1. **路由顺序**：`PUT /v1/users/me/watermark` 与 `PUT /v1/users/:id/watermark` 段数相同，`me` 必须先声明，否则 "me" 会被当 id 查库。已放在同一个 Controller 里用声明顺序保证。
2. **用户侧样式参数必须拒收**：DTO 只声明三个字段，`opacity/rotate/fontSize` 传了也会被 `ValidationPipe({ whitelist })` 丢弃——否则用户把 opacity 调成 0 等于关水印。冒烟里有专门用例。
3. **排序规则不一致**：新表默认 `utf8mb4_0900_ai_ci`，`sys_user` 是 `utf8mb4_unicode_ci`，JOIN 直接报 `Illegal mix of collations`。迁移已改显式 `COLLATE=utf8mb4_unicode_ci`，本机库已 ALTER 修正。
4. **`??` 会吞 0**：`custom?.enabled ?? setting.enabled` 恰好是想要的语义（0 不跳过），但单测里专门锁了这个行为，防止将来有人改成 `||`。
5. **软删用户的孤儿行**：删除用户若不清 `sys_user_watermark` 会越积越多（冒烟旧实例跑的时候正好踩到）。已在 `UserService.delete` 事务里补清理，并手工清掉一条历史孤儿行。
6. **`req.user` 没有 username 字段别乱传**：JWT 自签测试 token 时 payload 只有 id/username，与真实登录一致，所以冒烟可以直接 mint guest token 测强制场景，不必真登录。
7. **前端 lint 空转 disable**：`react-refresh/only-export-components` 对该文件不生效，disable 注释本身成了 warning，删掉即可。

## 四、怎么用 / 怎么扩展

- **管理员**：`系统设置 → 水印策略` 改全局默认（开关/模式/文案/不透明度/角度/字号）；`用户管理 → 行内水滴图标` 给单人开关，可选"强制开/强制关"让用户自己改不动。
- **普通用户**：右上角设置抽屉里开关水印、改内容与密度；被管理员锁定时置灰并显示原因。
- **新增占位符**：在 `watermark-template.util.ts` 的 `values` 里加一项，并在 `PLACEHOLDER` 正则里登记即可，前后端无需其他改动。
- **给某个角色统一配置**（如"所有 auditor 强制开"）：加一张角色级表或直接在角色保存逻辑里批量 upsert `sys_user_watermark`，`resolveWatermarkState` 不用动。
- **运维注意**：普通管理员要用这两个入口，需在菜单管理里给对应角色配置 `/settings/watermark` 菜单与 `system:watermark:edit`、`system:user:update` 权限点；超管开箱即用。
