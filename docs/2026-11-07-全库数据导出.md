# 全库数据导出（sql/concise_server_full_2026-11-07.sql）

## 背景

用户要求把当前数据库的真实数据导出归档到 `sql/` 目录，作为可复现的备份快照。

## 改动清单

| 文件 | 类型 | 说明 |
| --- | --- | --- |
| `sql/concise_server_full_2026-11-07.sql` | 数据 | mysqldump 全库导出（24 张表结构 + 数据 + 触发器/存储过程，约 8MB），`--single-transaction` 保证一致性快照 |
| `sql/README.md` | 文档 | 登记新文件与全库恢复步骤，补充敏感数据提示 |

## 导出时数据规模（精确 COUNT）

| 表 | 行数 | 表 | 行数 |
| --- | --- | --- | --- |
| sys_region | 44983 | sys_role | 4 |
| sys_log | 4241 | sys_quartz_job | 3 |
| sys_user | 175 | sys_dict / sys_level / sys_position | 3~5 |
| sys_permission | 110 | base_schedule_* | 日程 2 条 |

其余（公告、任务等）为空表，共 24 张表全部包含。

## 使用方式（恢复）

```bash
export MYSQL_PWD=你的密码
"C:/Program Files/MySQL/MySQL Server 8.4/bin/mysql.exe" -uroot --default-character-set=utf8mb4 -e "DROP DATABASE IF EXISTS concise_server; CREATE DATABASE concise_server DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
"C:/Program Files/MySQL/MySQL Server 8.4/bin/mysql.exe" -uroot --default-character-set=utf8mb4 concise_server < sql/concise_server_full_2026-11-07.sql
```

## 遇到的坑

- `information_schema.tables.table_rows` 对 InnoDB 是估算值（显示 region=35/users=0），实际 44983/175——统计必须用 `COUNT(*)`
- 快照含 `sys_user` 密码哈希（Argon2id，不可逆但属敏感数据），仓库公开前需评估；恢复后 JWT_SECRET 变了会导致旧 token 全部失效，重新登录即可

## 扩展说明

以后需要新的快照，同样用 mysqldump 导出到 `sql/`，文件名带日期（`concise_server_full_YYYY-MM-DD.sql`），并在 `sql/README.md` 登记。旧快照过多时可归档删除，保留最新即可。
