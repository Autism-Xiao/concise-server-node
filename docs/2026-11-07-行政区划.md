# 2026-11-07 行政区划功能

## 需求

依据用户提供的 34 个省级行政区划 JSON（含区划代码/邮编/层级/经纬度/拼音），设计并落地一套完整的行政区划功能：后端真实模块 + 数据库预置 + 批量导入 + 前端管理页接真数据（原来是 mock 读写 public/mock/regions.json）。

## 总体设计

- **关联键用区划代码**：`area_code` 全局唯一、`parent_code` 级联（顶级 '0'），不依赖自增 id；层级 `level` 0省/1市/2区县/3街道（街道预留），`level_text` 由后端按 level 推导，不接受前端传入
- **预置数据**：迁移里直接插入用户提供的 34 个省级行政区划（含港澳台的电话区号/特殊邮编、山西与陕西同为 ShanXi 的拼音）
- **市/县级数据**：通过 `POST /v1/regions/import` 批量导入（按 areaCode upsert），兼容第三方区划库原始 JSON（多余字段如 id/levelText/pid 自动忽略，id 不会被外部值覆盖主键）
- **权限**：tree / children / code 登录即可（级联选择器到处用）；列表/增删改/导入需 `system:region:list/add/update/delete/import`（在菜单管理里给角色勾选）

## 遇到的坑

1. **迁移 SQL 占位符数量不匹配**：第一版用 `INSERT ... SELECT ... WHERE NOT EXISTS` 复用 areaCode 参数，实际占位符比参数多一个直接 ER_PARSE_ERROR；改为迁移内先查存在集合再拼 VALUES（值都是迁移内置常量，无注入面）
2. **bigint 主键序列化**：TypeORM bigint 主键返回字符串，前端 `Region.id` 要用 `number | string`
3. **编辑回填竞态**：级联选择器如果在 effect 里「拉数据 + 清空下级」一起做，祖先链异步回填会被清掉；拆开——effect 只拉数据，清空放 onChange 处理器
4. **第三方数据的 id 会污染主键**：导入 upsert 时 `{...prev, ...item}` 会把外部 id 盖进来，务必先解构剔除

## 使用与扩展

- **导入市/县级数据**：页面「导入区划」粘贴 JSON 数组即可，或脚本 `POST /v1/regions/import`；建议分省分批（单次 ≤5000）
- **给角色开权限**：菜单管理里新增「行政区划」菜单 + 按钮（system:region:list/add/update/delete/import），角色授权勾选
- **级联选择器复用**：其他模块选属地可直接用 `GET /v1/regions/children/:parentCode` 懒加载
