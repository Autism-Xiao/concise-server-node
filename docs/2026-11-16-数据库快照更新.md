# 数据库快照：导出 11-16 并发现本机库落后于远端

> 2026-11-16 · 数据快照 · 结论与最初预期相反，务必读完再操作

## 背景与真实结论

用户要求「把数据库更新一下，按昨天的日期」后，本机 `sql/` 只有 11-07 / 11-10 两份，于是先按当天日期导出了一份 `concise_server_full_2026-11-16.sql`。

**push 时才发现真相反过来了**：远端 `d82a689` 里已经有 `concise_server_full_2026-11-15.sql`，而且那份数据比本机全得多：

| 项 | 11-15 快照（远端，正确基线） | 11-16 快照（本机导出） |
| --- | --- | --- |
| 表数 | 33 | 31 |
| 总行数 | 46,918 | 46,012 |
| `migrations` | 55 | 52 |
| `sys_permission` | 166 | 149 |
| `sys_role_permission` | 569 | 521 |
| `sys_log` | 935 | 134 |

缺的是代码生成器产出的 `customer`、`biz_order` 两张表，以及一批权限/角色授权/日志数据。**本机这套 MySQL 没有跟上远端代码的迁移进度**，所以 11-16 快照不是「最新」，而是「旧库的新副本」。

## 定位调整

| 文件 | 类型 | 说明 |
| --- | --- | --- |
| `sql/concise_server_full_2026-11-16.sql` | 新增 | **降级为本机旧库现场备份**（回滚点），不再标为最新快照 |
| `sql/README.md` | 修改 | 在 11-15 行下方补 11-16 行并标注「勿用于恢复，仅作覆盖前回滚点」；冲突处取远端版本（远端 11-15 才是正确基线） |

本地库要真正“更新”，正确顺序是：**先补 schema（`pnpm run migration:run`，或直接用 11-15 快照整库恢复），再重新导出**。直接拿 11-16 恢复会把远端的 `customer` / `biz_order` 和数据一起抹掉。

## 导出与验证（对本地库本身是准确的）

1. `node scripts/dump-sql.mjs` → 6.6 MB / `grep -c '^CREATE TABLE'` = 31，与本地源库表数一致
2. 建临时库 `concise_verify_tmp` → 全量导入 → **exit 0**（1.9 秒）
3. 逐表 `COUNT(*)` 比对本地源库与临时库：**31 张全一致，总行数 46,012，0 差异**
4. 确认快照内 `sys_user` 有 `totp_secret` / `totp_enabled`（2FA 列在，因为本机库跑过 `AddUserTotp`）
5. 验证完 `DROP DATABASE concise_verify_tmp`

即：**快照忠实反映了本机库**，问题在于本机库本身是旧的。

## 踩的坑

- **bash 双引号里的反引号会被当命令替换**：`"SELECT COUNT(*) FROM db.\`$t\`"` 中反引号先被 shell 执行，表名变成空串，31 张表全报 `ERROR 1103 Incorrect table name ''`，但循环照跑完、变量累加成 0 —— 得到假的「总行数 35」。表名是安全标识符时不要加反引号，或整条 SQL 用单引号包裹。
- **`information_schema.tables.table_rows` 是 InnoDB 估算值**：`migrations` 估 47、真实 52，拿它校验会误判，必须 `COUNT(*)`。
- **先 `git fetch` 再判断“最新”**：只看本地 `sql/` 目录就下结论，会漏掉远端已有的更新快照。这次的返工全因本地落后 28 个提交。
- **文档清单要对 `ls` 核**：`sql/README.md` 里 `backup-pre-restore.sql` 那行对应的文件其实已不在目录。

## 如何扩展

- 补 schema 后重新导出：`pnpm run migration:run` → `node scripts/dump-sql.mjs`
- 指定文件名日期：`node scripts/dump-sql.mjs --date=2026-11-20`
- 整库恢复前先导一份现场：`node scripts/dump-sql.mjs --date=2026-11-16-pre-restore`（`DROP DATABASE` 没有撤销键）
