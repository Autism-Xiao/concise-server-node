# 平台管理员开关 + 鉴权用户缓存可失效

> 承接《多租户隔离落地》。上一轮把 `sys_user.is_platform_admin` 立成了平台 / 租户的唯一分界，
> 但没有提供任何修改入口 —— 只能手工 `UPDATE sys_user`。本轮补上接口与界面，
> 并顺带修掉一个只有实测才会暴露的问题：**取消平台管理员 30 秒内仍然有效**。

## 二、后端：为什么必须是独立端点

通用更新接口 `PUT /users/:id` 走 `UpdateUserDto extends PartialType(CreateUserDto)`，一旦把
`isPlatformAdmin` 加进 DTO，任何持有 `system:user:update` 的**租户管理员**都能把自己提成平台管理员 ——
上一轮刚建立的两层结构会立刻失效。所以：

1. **不入通用 DTO**：字段根本不在白名单里，`ValidationPipe` 的 `whitelist` 会直接剥掉；
2. **再显式删一次**：`stripUnwritableFields()` 里 `delete data.isPlatformAdmin`，防的是以后有人
   把它加进 DTO 或走 service 直传，等于给这个字段加了条「永远不可写」的注释级保险；
3. **只走 `PUT /users/:id/platform-admin`**，且权限点 `system:user:platform` 的 `scope='platform'` ——
   `PermsGuard` 对 platform 作用域的权限点要求 `is_platform_admin=1`，租户管理员即便勾上这个按钮也调不动。

三道门：

| 门 | 位置 | 拦住什么 |
| --- | --- | --- |
| ① 权限点 scope=platform | `PermsGuard` | 租户管理员给自己授权也无效 |
| ② `actor.isPlatformAdmin` 复查 | `UserService.setPlatformAdmin` | 别的 service 内部调用绕过守卫 |
| ③ 不能取消自己 / 最后一个 | `UserService.setPlatformAdmin` | 平台层被锁死、无法自助恢复 |

幂等：重复授予 / 重复取消直接返回，不写库（`@OperLog` 仍会留一条「操作」记录，便于审计）。

## 三、鉴权缓存：为什么抽出来

`JwtStrategy` 原本有一个私有的 30s `Map` 缓存用户态（`users + user_roles + roles` 三表 join 是热路径）。
冒烟时发现：**取消平台管理员后，该账号 30 秒内仍然能进平台视角** —— 因为缓存里还是 `isPlatformAdmin=1`。

降权不即时是安全问题（升权晚 30 秒无所谓，降权不行），所以：

- 缓存挪到 `AuthUserCacheService`（`@Global` 单例），`JwtStrategy` 读、业务写路径负责失效；
- 值类型用 `unknown`，避免 `shared/` 反向依赖 `modules/`；取用时由调用方断言；
- 命中判定用「`!== undefined`」而不是真值判断，这样「查过但用户不存在」的 `null` 也能被缓存。

失效点（这是唯一入口，新增写路径请照此办理）：

| 写操作 | 为什么必须失效 |
| --- | --- |
| `setPlatformAdmin` | `isPlatformAdmin` 就在缓存里，降权必须立刻生效 |
| `setStatus` | `validate` 读 `user.status`，冻结后不能让旧缓存继续放行 |
| `assignRoles` | `RolesGuard` 直接读缓存的 `roles` |
| `delete`（软删） | 否则被删账号在 30s 内仍能通过鉴权 |

> 角色本身被停用 / 删除时（`RoleService`）目前仍是 30s 延迟，与既有的 `PermissionCacheService` 同语义，
> 本轮没有扩大改动范围；需要即时生效时调 `invalidateAll()`。

## 四、前端

- **徽标**：账号列用户名后面跟一个「平台」小徽标（`isPlatformAdmin === 1`）。没有单开一列 ——
  平台管理员通常只有一两个，加列会把本来就不宽的用户表再挤 80px。
- **操作项**：只在 `hasPermission('system:user:platform')` 且 `user.username !== getUsername()` 时出现。
  自己那一行不显示，因为后端一定会拒（避免用户点了才看到 400）。
- 授予后提示「最多 30 秒生效」—— 前端拿到的权限集合来自登录时的 `getPermissions()`，需要重新登录才刷新；
  后端缓存虽然即时失效了，但前端本地权限列表不会自动重拉。

## 六、坑

1. **冒烟脚本复制 admin 整行造临时账号**：`SELECT *` + 展开会把新加的 `is_platform_admin` 一起带过来，
   导致「临时账号一出生就是平台超管」，4 项越权断言全部失真。以后加账号级标志位，记得同步改这个脚本。
2. **`pageSize` 上限是 100**：冒烟里传 200 会被 `@Max(100)` 拒成 400，返回体没有分页结构，
   表现为「列表查不到该用户」，很容易误判成后端 select 漏字段。
3. **缓存 key 是 userId 不是 token**：重新登录拿新 token 也读同一份缓存，所以「取消后重登」无法自证生效 ——
   必须靠写路径主动失效，或者等 30s。
4. **`@Global()` 模块的 provider 才是共享单例**：如果 `AuthCacheModule` 不加 `@Global` 且 auth / user
   两个模块各自 `providers: [AuthUserCacheService]`，会拿到两个 Map，失效永远打不中。

## 七、怎么用

**接口**

```http
PUT /api/v1/users/:id/platform-admin
Authorization: Bearer <platform-admin-token>
Content-Type: application/json

{ "isPlatformAdmin": true }
```

**界面**：用户管理 → 目标用户「更多操作」→「设为平台管理员 / 取消平台管理员」。
账号列出现「平台」徽标即表示生效（本人重新登录后前端权限集合才会刷新）。

**没有接口时的兜底**（保持可用）：

```sql
UPDATE sys_user SET is_platform_admin = 1 WHERE username = 'xxx';
```

改完需要重启或等 30s（进程内缓存不含手工改库）。
