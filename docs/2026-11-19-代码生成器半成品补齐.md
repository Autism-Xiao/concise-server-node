## 每项作用（P0 硬伤）

1. **下划线字段名的驼峰映射**：entity 属性是 `tsProp(name)`（`customer_name` → `customerName`），但 `searchConds`/`queryConds`/`uniqueFields` 模板原来拼的是原始蛇形 `field.name`。TypeORM QB 的 `alias.xxx` 按**实体属性名**解析，蛇形会 `EntityPropertyNotFoundError`；`assertAllUnique` 里 `record[field]` 取蛇形键也取不到 DTO 的驼峰属性 → 查重静默失效。全部改用 `tsProp(field.name)`。
2. **`uniqueLabels` 缺逗号**：`join('\n')` 生成的对象字面量在多唯一字段时是 `a: 'x'\n b: 'y'` → 语法错误。改 `join(',\n')`。（单唯一字段时不暴露，靠极端组合测出来。）
3. **迁移 `down()`**：原来 `LIKE 'menu_${module}%'` 前缀删除会误删 `menu_xxx_other`；且 `DROP TABLE` 会把已有业务数据一起删。改为按 4 个精确 id 删除菜单授权与菜单，故意不删表（要删需人工确认）。
4. **force 语义统一**：DTO 注释原写「已有文件不覆盖」，但 `service.generate` 实际 `push('--overwrite')`、前端确认框也写「备份后覆盖」。统一为「备份后覆盖」。
5. **预览与生成不一致**：预览走 `--out` 暂存，`writeIfAbsent` 原本跳过真实仓库存在性检查，导致预览说全部新建、实际生成却 skip。现在暂存时记录每个文件在真实仓库的状态（`new`/`skip`/`overwrite`）回传，页面标注 + warning 提示。

## 每项作用（P1 规约对齐）

- 后端 `ListDto extends PagerDto`（page/pageSize/sortBy/sortOrder 由基类提供，不再手抄）；service import `applySort`，生成 `XxxSORTABLE` 白名单（前端列 id → QB 属性名，排除 text 列，补 id 兜底防翻页重复），`listByQuery` 调用 `applySort`。
- 前端 `api.ts` 的 fetch 参数改 `XxxListParams`（含 sortBy/sortOrder 与 query 字段），返回 `PageResult<Xxx>`。
- 前端 `index.tsx` 改 `useServerTable`（服务端分页/筛选/排序、300ms 防抖、请求序号防竞态、删空末页回退）；`fetchPage` 用 `useCallback`；写操作后 `reload()` 保留查询条件；`!booted` 才出骨架屏、之后表格保持挂载由 `DataTable loading` 盖遮罩（防搜索闪烁）；工具栏 `RefreshButton className="ms-auto"` 靠右 + `DataTableViewOptions` 成组；bool 列用 `StatusBadge` 静态圆点；标题统计用 `total`。

## 踩的坑

1. `StatusBadge` import 必须**条件生成**（`feHasType('bool')`），否则无 bool 字段的模块会留下未使用 import —— 与历史「MaxLength import 分支漏」同类。
2. `departWhere` 那种「const 箭头函数先定义再用」的 TDZ 问题这里也存在：`sortableBlock`/`uniqueLabelMap` 都放在所用变量之后生成模板字符串，验证过执行顺序无误。
3. 验证产物要用**极端字段组合**：单唯一字段不触发 `uniqueLabels` 缺逗号、无下划线字段不触发 QB 命名问题。本次用 full（双唯一 + 下划线 + 枚举 + bool + decimal + datetime + text）+ min（无唯一/无布尔/无搜索）两套 spec。
4. 清理临时验证目录时 safe-delete 钩子拦截了 `rm`/PowerShell `Remove-Item`/Node `fs.rmSync`，最终用 `mv` 移出工作区——以后验证产物要写进临时目录时用 `--out`，别写进真实 `src/` 后再删。
5. `--out` 暂存模式下迁移若与仓库已有内容相同会被去重跳过，所以预览文件数可能比产物清单少 1（正常，非 bug）。

## 如何扩展

- 加字段类型：同时改 `CODEGEN_FIELD_TYPES`（dto）、`MENU_ICONS`/`CODEGEN_TYPE_OPTIONS`（页面）、`TYPE_MAP`（脚本），三处必须一致。
- 加列表筛选 UI：目前 query 字段只在后端过滤、前端表单未提供筛选控件（fetchPage 用 `Record<string, never>`）。要补可在生成的 index 里加 filters state 并传给 `useServerTable`，同时 `fetchPage` 把 filters 展开进请求。
- 模板任何改动都要用 full + min 两套 spec 生成后，把产物临时放进两个仓库用真实 tsconfig 编译一遍，再移出清理。
