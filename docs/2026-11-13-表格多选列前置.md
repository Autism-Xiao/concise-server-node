# 表格多选列提到序号前面

| 项 | 内容 |
|---|---|
| 日期 | 2026-11-13 |
| 仓库 | concise-admin（文档按惯例登记在本仓库） |
| 触发 | 用户要求「表格：多选在序号的前面」 |

## 背景

上一轮加序号列时，`DataTable` 的渲染顺序是「序号 → 各列」，而多选列（id=select）定义在各列的第一个，于是显示成「序号 → 勾选框 → 数据列」，勾选框被序号顶到了第二列。用户要求勾选框排最左。

## 改了哪些文件

| 文件 | 类型 | 说明 |
|---|---|---|
| `concise-admin/src/components/data-table/data-table.tsx` | 修改 | 渲染顺序改为「多选 → 序号 → 数据列 → 操作列」 |

仅 1 个文件——多选列前置逻辑收在 `DataTable` 内部，用户/角色/公告 3 个带勾选列的页面零改动自动生效。部门、文件管理两个自绘表格本来就是「勾选框 → 序号」，无需调整。

## 实现要点

- 表头与单元格各做一次「拆分渲染」：从 `headerGroup.headers` / `row.getVisibleCells()` 里把 `id === 'select'` 的找出来先渲染，其余照常遍历但跳过 select，序号插在两者之间。
- 没有多选列的页面（大多数）自然走原路径，`showSerial` 开关也不受影响。
- 操作列 sticky 判断用的是「最后一个可见列的 id」，select 提到最左不影响它。

## 验证

- 无头 Chrome 实测三页表头文字顺序：用户管理 `多选|序号|账号|…|操作`、角色权限 `多选|序号|角色名称|…`、通知公告 `多选|序号|标题|…`，截图确认无错位；
- `tsc --noEmit`、ESLint、`pnpm build` 通过。

## 怎么扩展

- 新列表页想带多选：在 columns 里定义 `id: 'select'` 的列即可，位置无所谓——`DataTable` 固定把它排到最左、序号紧随其后。
