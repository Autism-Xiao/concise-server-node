## 发现并修复的真 bug：refreshToken 续期必然失败

**现象**：`POST /v1/auth/refresh`（不带 accessToken 的正确用法）恒报 `1002 用户不存在`。

**根因链**：`TenantMiddleware` 挂在 `forRoutes('*')`，无 Bearer 令牌的请求拿到 `tenantId: 0` 的空上下文 → `refreshToken()` 里 `userService.findOneDetail(id)` 末尾的 `assertUserVisible(id)` 对 tenantId=0 执行 `applyTenantToUsers` → `1 = 0` 恒假 → NotFoundException。

**影响**：前端在 accessToken 过期（2h）后调 refresh 续期必然失败，用户被踢回登录页——双令牌机制实际失效。

**修复**：抽 `findOneDetailForAuth()`（保留软删过滤与 roles/depts/posts 关联加载，去掉管理端语义的租户可见性断言），refresh 专用。令牌已验签，id 可信，无需再按租户收窄。手动验证 + 冒烟 221/221 通过。

## 代码安全性分析

**干净项（扫描证据）**：
- 无硬编码密钥/密码（src 全扫）
- SQL 全参数化：运行时插值只有 `?` 占位符拼接（`map(() => '?')`）与内部构造的 tenantFilter 子句，无用户输入直拼；migrations 里的字符串是静态 DDL
- 无 eval / Function / shell 注入面；无模板串路径拼接
- helmet 8 已启用；JWT_SECRET/REFRESH 启动期强校验（≥16 位、必填）
- auth 端点独立限流：验证码 30/min、登录 120/min、refresh 20/min
- @Public 暴露面小：captcha×2、refresh、sso×3、health（callback/authorize 由 HMAC state 保护）
- 存储 provider 有 resolve 防穿越；上传文件头 magic bytes 校验（冒烟持续回归）
- 前端唯一 `dangerouslySetInnerHTML` 是自身路由 DOM 快照（React 已转义，注释说明），无外部输入

**待办/限制**：
1. **pnpm audit 没跑成**：npmmirror 不支持 audit 端点、官方源网络不通——需在有外网的机器补一次依赖漏洞审计
2. CORS 未配置：同源部署无碍；若前后端分域需显式 enableCors 白名单
3. token 存 localStorage（XSS 面放大器）：中后台常见取舍，httpOnly cookie 方案改动大，暂维持
4. 冒烟脚本建议：`smoke-captcha` 需要单独开验证码实例跑（本次未覆盖）
