## 一、系统参数配置中心（sys_config）

**为什么先做它**：密码策略要能改而不重启，就得先有「运行时可调的标量」容器。字典管枚举、个人设置管界面偏好，两者都替代不了它。

| `src/modules/system/config/system-config.service.ts` | 新增 | 三级取值：进程缓存(30s) → 数据库 → **代码默认值**；类型校验；`getPasswordPolicy()` 快捷方法 |
| `src/modules/system/config/config.v1.controller.ts` | 新增 | `GET /v1/configs`、`/groups`、`PUT /v1/configs`、`PUT /v1/configs/batch`、`POST /reload` |

| `src/app.module.ts` | 修改 | 注册 SystemConfigModule |

**设计要点**

- **代码默认值兜底**：`DEFAULTS` 常量里每个键都有值，配置表为空系统也能跑。新增参数必须先加常量再加迁移。
- **类型由表声明**：`value_type=number` 时传 `abc` 直接 1001，避免把 `minLength` 写成字符串导致比较失效。
- **批量更新走事务**：整批校验通过才写，不会出现「改了一半」。
- 进程缓存 30s：多实例部署时别的实例改完最多 30s 生效（参数类配置对此不敏感）。

| 文件 | 类型 | 说明 |
| --- | --- | --- |
| `src/modules/auth/entities/user-backup-code.entity.ts` | 新增 | `sys_user_backup_code`：只存 sha256，`used_at` 标记一次性 |
| `src/migrations/1794410000000-CreateBackupCode.ts` | 迁移 | 建表 |
| `src/modules/auth/services/totp.service.ts` | 修改 | activate 时签发 10 条；`regenerateBackupCodes()` 需 TOTP；`consumeBackupCode()` 严格一次性；deactivate 时清空；status 返回剩余条数 |
| `src/modules/auth/controllers/auth.v1.controller.ts` | 修改 | 新增 `POST /v1/auth/2fa/backup-codes`（限流 10 次/5 分钟） |
| `src/modules/auth/dto/login.dto.ts` | 修改 | `totpCode` 放宽为「6 位动态码 或 8 位备份码」 |
| `src/modules/auth/services/auth.service.ts` | 修改 | 登录门禁：TOTP 不过再试备份码 |

**为什么用 sha256 而不是 Argon2**：备份码是 8 位高熵随机串（32^8 ≈ 1.1e12），登录时 10 条比对若走慢哈希要 500ms+；sha256 足够抗暴力且不拖慢登录。

**为什么必须做**：没有备份码时，认证器丢失 = 账号被永久锁死，只能让运维改数据库。

## 四、SSO 补 2FA 门禁（两阶段）

| 文件 | 类型 | 说明 |
| --- | --- | --- |
| `src/modules/auth/services/auth.service.ts` | 修改 | 新增 `assertSsoTotp()`：动态码或备份码，与密码登录同口径（2105/2106） |
| `src/modules/auth/services/sso.service.ts` | 修改 | 新增 `peekSsoCode()`（只查不消费） |
| `src/modules/auth/controllers/sso.v1.controller.ts` | 修改 | exchange 改为「peek → 验 2FA → 消费 code → 签发」 |
| `src/modules/auth/dto/sso.dto.ts` | 修改 | exchange 入参支持 totpCode |

**关键坑**：一次性 code 是「用后即焚」。若沿用原来的「先 consumeSsoCode 再验码」，第一次不带码的请求会返回 2105 **同时把 code 烧掉**，用户带着验证码重试必然失败（SSO 凭证无效）。必须拆成 peek / consume 两阶段。

## 验证（都是接口级实测）

| 场景 | 结果 |
| --- | --- |
| 参数列表 / 分组 | `GET /v1/configs` 返回 5 条内置参数，groups 返回 `["security"]` |
| 参数改值 | minLength 8→10 成功，读回 10（缓存失效生效），再改回 8 |
| 类型校验 | number 传 `abc` → 1001「密码最小长度 必须是数字」 |
| 不存在的键 | → 1001「参数 not.exists 不存在」 |
| 弱口令建用户 | `12345678` → 1001「需包含大写/小写/数字/符号中的至少三类」 |
| 强口令建用户 | 成功，`passwordExpireAt` 自动算成 today+90 天 |
| 常见弱口令重置 | `Password1` → 1001「密码过于常见」 |
| 含用户名 | `Tmp_pw_test9` → 1001「密码不能包含用户名」 |
| 重复字符 | `aaaaaaaaA1` → 1001「不能是重复字符或连续序列」 |
| 2FA 错码激活 | 2106 |
| 2FA 激活 | 返回 10 条备份码，status 剩余 10 |
| 重新生成 | 10 条且与旧码全不同 |
| **备份码登录** | 成功拿到 token；同码第二次 → 2106；不带码 → 2105 |
| 关闭 2FA | 备份码表清空为 0 条 |

## 踩的坑

- **`aaaaaaaaA1` 一开始没拦住**：原判据是「所有字符相同」（`new Set().size === 1`），`aaaaaaaaA1` 有 3 种字符就绕过了。改成「单字符占比过半」。
- **登录 DTO 的 `@Matches(/^\d{6}$/)` 卡死备份码**：备份码形如 `A3F9-K2MP`，校验层就 1001 了，压根到不了服务端。正则要放宽成 `^(\d{6}|[A-Za-z0-9]{4}-?[A-Za-z0-9]{4})$`。
- **`sys_role` 没有 `del_flag` 列**：迁移里给 admin 补授权时照抄了其他表的写法，直接 `ER_BAD_FIELD_ERROR`。
- **TypeORM `select` 只能用对象形式**：`select: ['configGroup']` 报 TS2559，要写 `select: { configGroup: true }`。

## 如何扩展

- 加参数：`DEFAULTS` 加默认值 → 迁移里 `INSERT IGNORE` 一行 → 业务里 `getNumber/getBoolean` 读
- 加策略项：`PasswordPolicy` 接口加字段 + `getPasswordPolicy()` 返回 + `assertPasswordStrength` 消费
- 租户差异化参数：给 `sys_config` 加 `tenant_id`，`get()` 里做「精确租户 → 回落 0（平台默认）」两级查找
