# Node 层性能优化（2026-11-08）

## 本轮范围

压测基线（见同日《压测基线与负载脚本》）定位出热路径三大开销后，落地三项 Node 层优化。

## 改动清单

| 文件 | 类型 | 说明 |
| --- | --- | --- |
| `src/main.ts` | 修改 | 启用 `compression`（阈值 1KB）：JSON 大响应体积砍 60~94% |
| `src/modules/auth/strategies/jwt.strategy.ts` | 修改 | validate() 的 `findOneWithRoles`（三表 join）加 30s 内存缓存——该查询原本**每个鉴权请求**都执行，是热路径最大单笔开销；超 2000 条自动清理过期项 |
| `src/config/database.config.ts` | 修改 | `connectionLimit` 10 → 20（支持 `DB_POOL_SIZE` 覆盖）+ `enableKeepAlive`（避免空闲后首请求重建连接的长尾） |
| `package.json` | 依赖 | + compression / @types/compression |

## 一致性边界（必须知道的取舍）

- JWT 用户态缓存 30s：冻结/删除/改角色最多延迟 30s 生效。安全兜底不受影响——强制下线/登出走 **Redis 黑名单，即时生效**；需要立即改权限时走既有的权限缓存清理。
- 连接池 20：多副本部署注意 MySQL `max_connections` 总量 = 实例数 × 20 + 余量（默认 151 够 7 实例）。

## 效果（本机实测，±20% 噪声，重方法轻数字）

- **压缩（确定性收益）**：menus/tree 响应 48.5KB → 3.1KB（-94%）；对列表/树/导出类接口普遍 60~90%。
- JWT 缓存 + 池扩容：users 列表并发 100 下 RPS 80 → 111（+39%），低并发 avg 137ms → 116ms。DB 侧剩余成本是每请求多条查询的 MySQL 本身，Node 侧已无免费午餐。
