# 锁屏启动闪屏修复（关页面重开短暂显示工作区）

- 日期：2026-11-21
- 类型：修复
- 涉及仓库：前端 `concise-admin`（代码）+ 后端仓库（本文档）

## 现象

开启锁屏后，关闭标签页/浏览器再进入系统，会短暂闪现工作区内容（侧边栏、页面数据），随后才切到锁屏遮罩。

## 根因

前端 `src/context/lock-provider.tsx`：

- 锁屏状态源在服务端 Redis（`GET /v1/auth/lock-state`），本地 `sessionStorage` 只是会话级瞬时镜像。
- 首帧用 `useState(isLocked)` 读本地镜像。**关标签页/浏览器重开会清空 sessionStorage** → 首帧 `locked=false` → 立即渲染工作区 `children`。
- 服务端状态是 `useEffect` 里异步拉取的，等 `/auth/lock-state` 返回 `locked=true` 才 `setLocked(true)` 切锁屏。
- 这中间的时间差就是"工作区先闪一下再锁屏"。之前只处理了"启动期在途响应别覆盖用户刚点的锁"（`interactedRef`），没处理首帧渲染的闪现。

## 修复

`concise-admin/src/context/lock-provider.tsx`：

1. 新增 `checking` 状态（初值 `true`），表示"服务端锁屏状态是否已确认"。
2. 启动对齐 effect 加 `.finally(() => !cancelled && setChecking(false))`——成功/失败/失败降级都结束 `checking`，**绝不卡在遮罩里**（失败时 fail-open 保留本地现状，与服务端"查不到当没锁"一致）。
3. 渲染层加 `pendingVerify = checking && !locked`：
   - 仅当「本地未锁 + 服务端未确认」这段窗口，盖一层与 `LockScreen` 同款的全屏遮罩（`fixed inset-0 z-[100] bg-background/80 backdrop-blur-md` + 转圈）。
   - 遮罩盖住 `children` 而非卸载（避免工作区组件重新挂载/重新拉数据）。
   - **本地已锁（`locked=true`）的路径不加遮罩**——直接渲染 `LockScreen`，不必等接口，否则"转圈→锁屏"又是一次新闪屏。

修复后时序：首帧无论本地是否锁定，工作区都不会暴露；服务端确认后要么落到锁屏（本地锁着/服务端说锁）、要么落到工作区（都没锁），中间无内容闪现。

## 验证

- 前端 `npx tsc --noEmit` ✅ · `npx eslint src/context/lock-provider.tsx` ✅ · `npx prettier --check` ✅
- `npx vite build --outDir` 临时目录 ✅（仅既有 chunk 体积警告）
- 逻辑边界：`interactedRef` 防覆盖逻辑保持不变；fail-open 语义不变；锁屏 POST 失败仍只影响持久化。

## 踩的坑

1. 遮罩只在 `checking && !locked` 时加——若无条件加，本地已锁的用户会经历"转圈→锁屏"的二次闪屏，反而更糟。
2. `.finally` 必须判断 `cancelled`，否则 effect 清理后仍 setState（React 卸载态更新告警）。
3. 用 `aria-hidden` 标记纯视觉遮罩，避免读屏软件念空遮罩；`Loader2` 用 `animate-spin`。
4. 前端无 docs 目录，变更文档仍写后端仓库 `docs/`（与锁屏状态服务端化、字典颜色等历次前端改动一致），前端代码单独提交推送。

## 如何扩展

- 若将来锁屏状态改为首屏同步读取（如服务端渲染注入），可移除 `checking`/`pendingVerify` 这套客户端遮罩。
- 遮罩视觉与 `LockScreen` 外层保持一致，若调整锁屏样式需同步这里的 class。
