## 每个东西是干什么的

### 1. 验证码接 Redis（支持多实例）
- `REDIS_ENABLED=true`：验证码存 Redis，多实例部署时任一实例签发、任一实例校验均可；过期由 Redis EX 自动回收。
- `REDIS_ENABLED=false` 或 Redis 连接失败：自动降级为进程内存 Map（原行为，仅单实例有效），应用不会被 Redis 故障拖垮。
- 一次性校验：Redis 模式在 MULTI 事务里 GET+DEL，并发重放只有首个请求能命中。

### 2. 日志导出
- `GET /api/logs/login/export`、`GET /api/logs/oper/export`，过滤条件与分页列表完全一致（username/status/module/startTime/endTime）。
- 权限点 `system:log:export`（PermsGuard 实时查库）。
- 返回 CSV：UTF-8 BOM 保证 Excel 直开不乱码；参数 JSON 等含逗号/引号/换行的字段自动转义；上限 5 万行。

### 3. 菜单按钮权限录入
迁移已执行成功，当前 menu 表落库结果：
- 系统管理（目录）→ 用户管理 / 部门管理 / 字典管理 / 日志管理 / 公告管理 / 任务管理
- 按钮：system:user:add|update|delete、system:dept:*、system:dict:*、system:log:login|oper|delete|**export**、system:notice:list|add|update|publish|delete、system:task:add|update|delete
- 历史孤儿按钮「日志查询」「操作日志查看」（原 parentId=0）已挂回「日志管理」。

## 遇到的坑

1. **menu 表列名是 snake_case**：TypeORM 1.x 默认命名策略把 createdAt 映射为 `created_at`，迁移初版用 camelCase 报 `Unknown column 'createdAt'`，已改为 `created_at/updated_at`。
2. **路由顺序抢占**：`GET logs/login/export` 声明在 `GET logs/login/:id` 之后时，"export" 会先命中 `:id` 被 ParseIntPipe 打回 400。必须把导出端点声明在参数路由之前。
3. **本地 `.env` 丢失**：仓库只有 `.env.example`，migration:run 因 DB 密码为空被拒。按记忆中的约定重建了 `.env`（root/123456，PORT=3459，重新生成 JWT 密钥——注意：若前端/其他环境依赖旧 JWT 签发的令牌，需重新登录）。
4. **后台进程杀不干净**：Windows 下 taskkill 掉包装进程后 node 子进程仍占着 3459，用 `netstat -ano | grep LISTENING` 找真实 PID 再杀。

## 怎么扩展/使用

- **开启 Redis**：`.env` 里 `REDIS_ENABLED=true`（Redis 默认 127.0.0.1:6379），重启即可，无需改代码。
- **新加按钮权限**：在对应 Controller 加 `@Perms('模块:资源:动作')`，再往菜单管理（或迁移 SEED_MENUS 数组）里补一条 type=2 的按钮记录，角色管理里勾选即可生效。
- **导出扩展**：其他列表需要导出时，复制 log.controller 的 export 端点写法（`@Res({ passthrough: true })` + StreamableFile，TransformInterceptor 对文件流自动放行）。
- **Swagger**：导出端点已加 @ApiOperation，`/api/docs` 可见。
