# 四项遗留治理：旧路由下线 / 列表结构统一 / 权限缓存 / 密码迁移

> 日期：2026-11-06
> 前情：上一轮`docs/2026-11-06-安全与数据一致性修复.md`里明确"有意识放弃"的四项，这次全部补上。
> 结论：四项都可以修，而且不必做成 breaking —— 关键是用**渐进式**手段（开关、透明升级、写侧失效）而不是一把梭。

## 一、为什么当初放弃，现在怎么解决

| 项 | 当初放弃的原因 | 这次的解法 |
| --- | --- | --- |
| 旧 40 条路由下线 | 怕有外部客户端在用，硬删不可回滚 | 条件注册 + `LEGACY_ROUTES_ENABLED` 开关，默认关闭；关掉时是 404 不是删文件 |
| 列表结构两套 | 改成统一结构要动前端 4 页 4 个 api，属于 breaking | 后端统一包装 + 前端每个 api 只加一行 `.then(p => p.records)`，页面组件零改动 |
| 密码迁 argon2id | 存量密码是 jeecg 算法，批量刷库有风险 | **登录时透明升级**：老格式校验通过后当场改写为 argon2id，不需要停机迁移 |
| 权限集合缓存 | 缓存要有失效机制，否则改权限不生效 | 按角色缓存 + 写侧主动失效（授权/删除/菜单变更立刻 del），Redis 挂了自动回源 |

## 三、逐项说明

### 1. 旧路由下线（开关式）

**问题**：`/api/auth/**`、`/api/users/**` 等和 `/api/v1/**` 并存，同一能力两条路径。攻击面翻倍（少挂一个守卫就是绕过通道），Swagger 重复，改策略要改两遍。

**做法**：不删文件，改成"条件注册"。Nest 只有在 `controllers` 数组里才注册路由，所以：

```ts
controllers: [UserV1Controller, ...(LEGACY_ROUTES_ENABLED ? [UserController] : [])]
```

关闭时请求直接 404（`Cannot GET /api/users`），**不是 403** —— 403 会泄露"接口存在但你没权限"。

**关掉旧路由时才发现 v1 不完整**：`refresh` / `profile` 原本只在旧控制器里，冒烟立刻报 404。已在 `AuthV1Controller` 补齐。这是本次最值钱的一条经验：**下线旧路由前，先确认新路由是能力全集**。

### 2. 列表结构统一

**约定**（写进 Swagger 顶部）：

- 列表查询接口 → `{ records, total, current, size, pages }`
- 数据源接口（`depts/tree`、`menus/tree`、`roles/options`、`dicts/code/:code`）→ 数组

字典量级数据（角色/部门/职级/岗位/字典/菜单）不做服务端分页，但仍用分页结构包一层，`size = total`、`pages = 1`，语义是"一次全量返回"。这样前端只有一套读法。

`toPagination` 支持真分页：传 `pageSize` 就内存切片（越界返回空数组，不报错），不传就全量。将来某个接口数据涨起来，改一行就能真分页，**结构不用再变**。

### 3. 权限缓存

**为什么能缓存**：`PermsGuard` 是全局守卫，每个带 `@Perms()` 的请求都要跑 `sys_permission ⋈ sys_role_permission` 的两表 join。管理后台一屏几十个请求，这是纯浪费。

**key 设计**：按**角色**缓存（`perm:role:<roleId>`），不按用户。用户挂多角色时合并结果即可，用户换角色不需要清缓存（`JwtStrategy` 每次请求都查库带 `roles`，本来就是实时的）。

**失效点**（这是缓存能不能用的关键）：

| 操作 | 失效动作 |
| --- | --- |
| 角色授权 `assignMenus` | `invalidateRole(roleId)` |
| 角色删除 `deleteRole` | `invalidateRole(roleId)` |
| 菜单新增/修改/删除 | `invalidateAll()`（SCAN 删，菜单是权限点的定义源） |
| Redis 不可用 | 自动回源查库，只打一条 warn 日志 |

实测：收回授权后**下一次请求立刻 403**，恢复后立刻 200 —— 没有"等 5 分钟才生效"的问题。

**为什么 TTL 还要留 5 分钟**：兜底。比如有人直接改数据库、或者某条失效路径漏了，最坏 5 分钟自愈。

### 4. 密码迁移 argon2id

**老算法的问题**：`PBEWithMD5AndDES` 单轮 MD5 + 8 字节 DES 密钥 + 8 位 ASCII 盐，抗 GPU 爆破能力接近于零。

**新算法**：`@node-rs/argon2`（Rust napi 预编译，Windows/Linux 都有现成二进制，不需要本地编译链）。参数取 OWASP 2024 推荐档位 `m=19456, t=2, p=1`，实测单次 **18ms**，输出 97 字符 PHC 串，`varchar(255)` 余量充足。

**透明迁移流程**：

```
登录请求
  → verifyPassword()
      密码以 $argon2id$ 开头? → argon2 verify
      否则                    → 老算法复算比对（salt 非空才走这条）
  → 校验通过且是旧格式 → upgradePasswordHash()：当场改写为 argon2id，salt 置 null
```

用户无感，不需要停机刷库，也不需要"下次改密码时生效"。只写 `password` / `salt` 两列，**不动 `update_time`** —— 用户并没有"修改"账号。

**为什么不用 scrypt 兜底**：`@node-rs/argon2` 装得上就用真的 argon2id（行业标准、参数可移植到 Java/Go）；如果哪天装不上，`password.util.ts` 里只有三个函数需要替换，`UserService` 不用改。

## 四、踩到的坑（下次直接看这里）

1. **`salt?: string | null` 会让 TypeORM 推断成 `Object`，启动直接拒绝建连**
   `DataTypeNotSupportedError: Data type "Object" in "UserEntity.salt" is not supported by "mysql"`
   → 必须显式写 `@Column({ type: 'varchar', length: 45, nullable: true, ... })`。

2. **`@node-rs/argon2` 的 `Algorithm` 是 const enum，开 `isolatedModules` 后不能当值用**
   `TS2748: Cannot access ambient const enums when 'isolatedModules' is enabled`
   → 不传 `algorithm`，该库默认就是 Argon2id；再靠 `$argon2id$` 前缀校验兜住"默认值变了"的风险。

3. **关掉旧路由才发现 v1 缺 `refresh` / `profile`**
   → 冒烟从 147 项里报了 6 个 FAIL，其中 4 个是这条。教训：**下线重复路由 = 一次能力盘点**，要按功能清单核，不是按文件核。

4. **`pnpm add @node-rs/argon2` 会报 `ERR_PNPM_IGNORED_BUILDS`（@scarf/scarf 的安装脚本被拦）**
   与 argon2 无关（它是预编译二进制，不需要 build script），不影响运行。

5. **本地 `curl 127.0.0.1` 返回 502 `upstream connect failed`**
   → 环境里配了 HTTP 代理，本地回环也被代理。调试本地实例加 `--noproxy '*'`。

6. **测试脚本里登录请求 400 "用户名不能为空"**
   → 自定义 `fetch` 封装把 headers 整个替换掉了，丢了 `Content-Type`。写接口脚本时 headers 要 merge，不能覆盖。

## 六、上线注意

1. **`LEGACY_ROUTES_ENABLED` 默认 false**。如果还有老客户端/脚本在调无版本前缀的接口，先置 `true` 观察访问日志，确认无调用后再回 false。
2. **`@node-rs/argon2` 是平台相关依赖**。部署机 `pnpm install` 必须重新装（不要跨平台拷贝 `node_modules`），Linux 会装 `@node-rs/argon2-linux-x64-gnu`。
3. **前端必须跟着发**。列表接口结构变了，旧前端读 `result.map` 会拿到 `undefined`。发布顺序：先后端（兼容窗口内旧前端会 500/空白）→ 立刻发前端；或者前后端同批发布。
4. **`sys_user.password` 保持 `varchar(255)`**，不要缩。argon2 是 97 字符，历史 jeecg 最长 208 字符（账号名很长时 DES 密文变长）。
5. **不需要跑新迁移**。本次没有 DDL 变更（`salt` 本来就可空），`password` 列长度够用。

## 七、还剩什么（这次真没做的）

| 项 | 为什么不做 |
| --- | --- |
| 物理删除旧控制器文件 | 开关关掉后已经不可达，留着当迁移期参照；确认外部无依赖后删 5 个文件即可 |
| 存量密码离线批量重算 | 需要明文密码才能算哈希，做不到。只能靠登录透明升级，长期未登录账号会一直是旧算法 —— 可选做法：下线前给长期未登录账号强制重置密码 |
| 权限缓存按用户维度预热 | 当前按角色缓存 + 合并，已够用；用户维度会放大失效范围 |
| 列表接口真分页 | 角色/部门/职级/岗位/字典/菜单都是字典量级（最多几十上百条）。`toPagination` 已支持传 `pageSize`，需要时改一行 |
