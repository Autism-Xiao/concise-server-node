# 弹框全局固定头尾 + 消息接收人分段选择器

日期：2026-11-14 ｜ 仓库：concise-admin（纯前端）

## 需求

1. 弹框全局封装成公共组件，保留租户管理那种「固定头尾 + 内容区滚动」的体验（此前只有租户表单手写了这套布局，其余 30+ 个弹框仍是整个弹框一起滚，小屏时标题和底部按钮会被滚走）。
2. 消息中心发送弹框：「选择个别」换个更顺口的词；全站用户/指定用户两种模式互斥，切换时清空已选（全站=全部，切回来不能残留上一批名单）；两个幽灵按钮太丑，换更合适的组件形态。

## 实现

### 1. DialogContent 全局默认固定头尾（`src/components/ui/dialog.tsx`）

- 新增 `splitDialogSlots()`：把 children 自动分拣为 header（DialogHeader）/ footer（DialogFooter）/ body（其余；DialogBody 仅展开其内容交给统一滚动区），纯文本子节点归入 body 不丢弃，Fragment 递归展开。
- DialogContent 新增 `layout` prop：**默认 `'fixed'`**（头尾钉住、底部带 `border-t` 分隔、内容区 `flex-1 min-h-0 overflow-y-auto` 并带 `data-scroll="dialog"` 细滚动条——即租户那种滚动条）；`layout="free"` 保留原来的整个弹框滚动，供自绘满幅布局豁免（命令面板、登录验证码弹框已标注）。
- 租户表单弹框改为零手写布局（删掉 `flex flex-col overflow-hidden` + DialogBody + footer 手动 border-t），成为默认行为的自然受益者。
- 清理 5 个曾手动加 `overflow-y-auto` 的弹框（menu/dept/region 表单与导入、recycle-bin），避免覆盖公共层的 `overflow-hidden` 破坏固定布局。
- **14 个「Footer 写在 `<form>` 里」的弹框统一迁移**（job/dept/dict/dict-item/name/level/menu/notice/post/region/role/task/tenant-admin/batch-roles/batch-watermark/calendar）：Footer 移出 form 成为 DialogContent 直接子元素，form 加 `id`，提交按钮加 `form="xxx-form"` 属性（HTML 原生的表单外提交）。用一次性 codemod 完成，结构与 tenant 样板一致。

### 2. Segmented 分段选择器（`src/components/ui/segmented.tsx`，新增）

Tabs 风格的分段控件：`bg-muted` 凹槽 + 选中项浮起白底块（`bg-background shadow-sm`），替代「两个幽灵按钮」的廉价感。role=radiogroup/radio，支持整体 disabled。

### 3. 消息发送弹框（`src/features/system/message/index.tsx`）

- 接收范围改为 Segmented：「全站用户 | 指定用户」（原「选择个别」改为更通用的「指定用户」，备选词：指定成员/手动挑选/自定义选择）。
- 互斥清空：`switchRecvMode` 切换即清空 `receiverIds`/`usersCache`；切到全站自动拉满（`fetchAllUserBriefs`），失败或无权限自动回退到指定用户模式；切回指定用户自动聚焦搜索框。
- 全站模式下选人控件替换为一张信息卡（Users 图标 + 「将发送给全站 N 名用户」+ 「仅覆盖发送时已存在的账号」提示）；获取中显示 loading 文案。
- 标题/正文去掉 Label 只留 placeholder，弹框更清爽；发送按钮在拉取名单期间禁用。

## 验证

- tsc / eslint / prettier 全绿；`npm test` 9/9 通过（dialog-fixed-layout 测试已重写为断言新架构：默认 fixed、自动分拣、free 豁免、租户表单零手写）。
- 无头 Chrome 截图实测：消息弹框两种模式（指定用户选人面板 / 全站信息卡 + toast「已选择全站 4 名用户」）、租户弹框（样板）、菜单弹框（长表单 88vh：标题钉顶、取消/保存钉底带分隔线、内容区滚动）。

## 踩坑

- **最大坑**：13 个弹框的 `<DialogFooter>` 写在 `<form>` 内部——按元素类型分拣会把 footer 划进滚动区，长表单（菜单管理）底栏直接消失。静态缩进判断不可靠，最后用 TypeScript 编译器 API 解析 JSX 找出全部嵌套用例，codemod 批量迁移。
- 提交按钮移出 form 后必须补 `form="id"`，否则点保存不再触发 onSubmit（HTML 原生 form 属性正好解决）。
- 使用方传的 `className="overflow-y-auto"` 会经 tailwind-merge 覆盖公共层的 `overflow-hidden`，整弹框滚动回归——必须清理这类旧类。
- `splitDialogSlots` 最初丢掉纯文本 children，会静默吞内容，已补「非元素真值归入 body」。

## 如何扩展

- 新弹框直接 `DialogHeader → 内容 → DialogFooter` 平铺即可，头尾自动钉住；表单类推荐 `form id="x-form"` + 提交按钮 `form="x-form"` 的解耦写法（Footer 必须是 DialogContent 的直接子元素，写进 form 里会被划进滚动区）。
- 需要自绘满幅内容（命令面板类）时传 `layout="free"`，并自行用 `DialogBody` 接管滚动。
- 互斥的少量选项切换用 `Segmented`；多于 3 个选项或需要说明文字时改用 Select。
