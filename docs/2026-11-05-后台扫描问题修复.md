## 每个东西是干什么的

- **updateTime 两处修复**：与上次「角色 create 不写 createTime」同根——`BaseService.update` 不自动补时间戳，各服务需手写。这两处是漏网之鱼。
- **@Perms 补齐**：`@Roles('admin')` 是角色级、`@Perms` 是按钮级；缺 `@Perms` 意味着将来放宽角色限制时这些写操作会绕过按钮权限。用户新增/修改/删除本来就有 `system:user:*` 按钮（menu_7/8/9），绑定角色/部门复用 `system:user:update`（分配角色/部门本质上是一次用户更新）。
- **菜单按钮种子**：菜单管理此前是唯一没有任何按钮权限的模块，现补齐三个。
- **日志导出 xlsx**：`toCsv` 换 `buildXlsx`，自动获得表头加粗、冻结首行、自动筛选、预设列宽。前端文件名从 `Content-Disposition` 解析，无需其他改动。
- **测试套件**：`@nestjs/*` 12.x 是 ESM-only，Jest 30 需要 Node 24.9+ 才能原生 `require(esm)`，本机 Node 22.22.2 跑不了任何 import nest 包的测试。改配置转换整个 nest 依赖树代价高，故删掉脚手架 spec、给纯逻辑工具补真实单测，让 `npx jest` 真正变绿。

## 遇到的坑

1. **`user.v1.controller` 绑定角色/部门最初找不到方法名**：service 里叫 `assignDepts` 不是 `setDepts`。
2. **jest 失败的根因有迷惑性**：报错指向 `app.controller.spec.ts`，实际是 `@nestjs/common` 本体 ESM；改写 spec 去掉 `@nestjs/testing` 后依然挂，因为 `app.controller.ts` 自己也 import 了 `@nestjs/common`。Node 22 之下无解，只能绕开 nest 包做单测。
3. **验证 `assignDepts`**：guest 用户不存在（库里的测试用户是 ceshi/crudtest 等），改用 admin 幂等重绑当前部门来触发 update 语句。
4. **不要顺手升级 Node**：Jest 的 require(esm) 要求 Node 24.9+，本机只有 22.22.2；如果以后升级 Node 到 24.9+，可以恢复 `@nestjs/testing` 风格的集成测试。

## 怎么扩展 / 使用

- **新增菜单按钮权限**：在 `scripts/seed-menus.cjs` 的 `BUTTONS` 数组加一行（id 顺延），执行 `node scripts/seed-menus.cjs`，再在角色管理里给对应角色勾选。
