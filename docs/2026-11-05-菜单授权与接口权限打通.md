# 菜单授权与接口权限打通（修「勾了菜单却看不到数据」）

- 日期：2026-11-05
- 涉及仓库：`concise-server-node`（后端）、`concise-admin`（前端）

## 一、现象

给「访客」角色勾选了菜单后，用访客账号登录：

- 侧边栏出现了**没被授权**的菜单（例如角色管理）
- 点进去页面能打开，但列表**没有任何数据**

## 二、根因：三个独立缺陷叠在一起

### 1. 控制器类级 `@Roles('admin')` 把非管理员全部挡死

11 个 v1 控制器（user / role / menu / dept / dict / dict-item / level / post / job / online / monitor）+ 旧 tasks 控制器，类上都写着 `@Roles('admin')`。

角色守卫的执行顺序是 `JwtAuthGuard → RolesGuard → PermsGuard`，`RolesGuard` 先返回 false，**方法上的 `@Perms()` 根本没机会执行**。所以无论怎么勾菜单、勾按钮，非 admin 一律 403。

### 2. 权限汇总只收集按钮节点，忽略了菜单节点

`auth.service.getPermissions()` 原来这样收集权限码：

```ts
// 改前：只认 menuType === 2（按钮）
allMenus.filter(menu => menu.menuType === 2 && allowedIds.has(menu.id) && menu.perms)
```

而「角色权限」「用户管理」这类**菜单节点**本身就带 `perms`（如 `system:role:list`），用于控制"能不能进页面 / 能不能查列表"。被过滤掉后，前端 `hasPermission('system:role:list')` 永远是 false。

### 3. 前端「菜单树为空」被当成「接口异常」，回退到静态全量菜单

`concise-admin/src/lib/permissions.ts` 改前：

```ts
if (tree?.length) { ... }        // 空数组 → 走 mock 兜底
...
const role = roles.find(r => r.code === code)
if (!role) return null           // null = 完全不过滤 = 放行全部菜单
```

访客角色（`viewer`）在 `public/mock/roles.json` 里不存在 → 返回 `null` → 路由守卫与侧边栏都**不做任何过滤** → 侧边栏渲染静态全量菜单（含角色管理）→ 点进去接口 403 → 页面空白。

`useMenuTree()` 同理：`return tree?.length ? tree : null`，把空数组变成了 null。

## 三、修复后的权限模型

| 层级 | 数据 | 作用 | 校验点 |
| --- | --- | --- | --- |
| 菜单节点 `menu_type = 0/1` | `sys_permission.perms`（如 `system:role:list`） | 侧边栏是否出现该入口 + 能否调用该模块的**查询**接口 | `@Perms('system:role:list')` |
| 按钮节点 `menu_type = 2` | `sys_permission.perms`（如 `system:role:add`） | 页面内按钮是否显示 + 能否调用**写**接口 | `@Perms('system:role:add')` |
| 登录可用元数据 | 无 | 跨模块下拉、树形结构、字典项 | 不加 `@Perms`，仅需登录 |

**不再使用 `@Roles('admin')` 做接口门禁。** 超级管理员的放行只保留一处判定：`hasSuperRole()`（`admin` / `superadmin`）+ 后端下发 `permissions: ['*']`。

## 六、使用这一版需要做的两件事

1. **重新登录**。前端 `permissions` / `menus` 是登录时的快照，改完角色授权不会推给在线会话。
2. **角色授权里要同时勾「菜单节点」和「按钮节点」**。只勾按钮不勾菜单 → 按钮权限有了，但侧边栏看不到入口；只勾菜单不勾按钮 → 能进页面看数据，不能增删改（这是设计意图）。

## 七、踩过的坑

1. `RolesGuard` 在 `PermsGuard` 之前执行，类级 `@Roles` 会短路掉所有方法级 `@Perms`——排障时先看类上有没有 `@Roles`。
2. 前端 `getMenuTree()` 返回 `[]` 和 `null` 语义完全不同：`[]` 是"登录了但一个菜单都没授权"，`null` 是"没有数据"。原代码用 `tree?.length` 把两者合并，直接导致越权显示。
3. `getRoleCode()` 的默认值是 `'superadmin'`，一旦 localStorage 被清而组件仍挂载，就会走超管放行分支。现在放行只认后端 `'*'`。
4. 跨模块下拉（用户表单 → 角色列表、用户表单 → 部门树）会被各自模块的权限码卡住。凡是"下拉/树/字典"这类元数据，统一不加 `@Perms`，或单开一个 `/options` 接口。
5. 全局 `ValidationPipe` 的 `whitelist` 不会影响 `@Query()` 里显式声明的字段，但 `GET /roles/options` 这种无参接口不要同时被 `@Get(':id')` 抢匹配——静态路由必须声明在动态路由之前。

## 八、新增一个模块时要改哪几处

1. `sys_permission` 里建菜单节点（`menu_type=1`，填 `perms: 'system:xxx:list'`）与按钮节点（`menu_type=2`，`system:xxx:add/update/delete`），并写进 `scripts/seed-menus.cjs`。
2. 控制器**不要**加类级 `@Roles`；查询接口加 `@Perms('system:xxx:list')`，写接口加对应按钮码。
3. 需要给别的模块做下拉的，单独开 `/options` 或无 `@Perms` 的 tree 接口，别复用全量列表。
4. 前端页面按钮用 `hasPermission('system:xxx:add')` 控制显隐，和后端保持同一套码。
