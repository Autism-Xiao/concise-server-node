# 刷新按钮与列显示成组靠右（位置修正）

## 背景

上一轮把刷新按钮放到 `DataTableViewOptions`（列显示）左侧后，截图反馈**位置还是错的**：刷新按钮仍在搜索框旁，蓝色箭头指向最右侧「列显示」按钮的左边——用户要的是两者相邻、一起靠右。

## 根因

`DataTableViewOptions` 的触发按钮自带 `className="ms-auto h-8"`。在 `flex items-center gap-2` 工具栏里，`ms-auto`（`margin-inline-start: auto`）只作用于**它自己这一个元素**，把列显示按钮单独顶到最右；排在它**前面**的刷新按钮并不受影响，仍紧跟在搜索框/下拉后头。所以「放在列显示左边」只是 DOM 顺序相邻，视觉上并没有靠右——这正是反复调不准的原因。

## 修法

把靠右的间距从列显示按钮挪到刷新按钮上，让两个按钮作为一个整体靠右：

- `DataTableViewOptions` 触发按钮：`className="ms-auto h-8"` → `className="h-8"`。
- 14 个带列显示的表格页：紧邻列显示的 `RefreshButton` 补 `className="ms-auto"`。这样刷新按钮吸收左侧剩余空间，把自身连同紧跟其后的列显示按钮一起推到最右，刷新在左、列显示在右，正是箭头所指位置。

## 各项作用

- **成组靠右**：`ms-auto` 挂在组内第一个元素（刷新按钮）上，整组（刷新 + 列显示）一起靠右，二者左右相邻，符合截图箭头位置。
- **职责收敛**：靠右对齐由使用方工具栏决定，公共组件 `DataTableViewOptions` 不再硬编码对齐方式，避免组件悄悄改变布局。

## 踩的坑

- **`ms-auto` 只作用于自身**：它不会把前面的兄弟元素一起带走。想让「A + B」成组靠右，得把 `ms-auto` 加在 A 上，而不是 B 上。上次误加在列显示（B）上，导致刷新（A）掉队。
- **无列显示的页面不动**：缓存/供应商/部门/菜单/行政区划 5 页没有列显示按钮，刷新按钮保持原位置；字典左列表同理，不要一刀切全加 `ms-auto`。
- **构建被安全钩子拦**：`npm run build` 清空 `dist` 时触发 safe-delete 批量删除确认（190 个文件），非代码问题。改用 `npx vite build --outDir <全新目录>` 验证通过。

## 如何扩展

新表格页放刷新按钮时，若带列显示，按下面写法保证成组靠右：

```tsx
<RefreshButton onClick={() => void reload()} className="ms-auto" />
<DataTableViewOptions table={table} columnLabels={columnLabels} />
```

不带列显示时不要加 `className="ms-auto"`（否则会被单独推到最右）。

验证：`npx tsc -b --noEmit`、`npx eslint`（15 个改动文件）、`npx vite build --outDir <新目录>` 均通过。
