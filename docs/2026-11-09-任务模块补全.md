# 任务模块补全：v1 接口 + 菜单权限 + 前端页面 + 首页待办（2026-11-09）

收尾上一轮挂着的「`task.assignee_id` 是 int，`sys_user.id` 是 varchar，导致我的待办恒为 0」。

## 先说结论：类型早修好了，真正缺的是三层东西

排查时发现 `src/migrations/1794190000000-FixTaskAssigneeType.ts` 已经把列改成 `varchar(32)` 并跑过了（`SHOW COLUMNS FROM task` 确认 `assignee_id varchar(32) NOT NULL DEFAULT '0'`），`dashboard.service.ts` 也早就用字符串比较统计。**「恒为 0」的真实原因是整个任务模块是半成品**：

1. 后端只有 `@Controller('tasks')`（旧版无前缀路由，受 `LEGACY_ROUTES_ENABLED` 控制，默认**不注册**）→ 任务接口实际不可用
2. `sys_permission` 里没有任务菜单和按钮节点 → 角色权限页无从勾选，前端也没有入口
3. 前端没有任务页面，首页 `dashboard` 返回的 `myTasks` 块没人消费
4. 库里 4 条任务全是 `assignee_id = '0'`（未指派），就算接口通了也统计不出「我的」

所以这轮把三层补齐，而不是再动一次类型。

## 各部分在干什么

### 后端：三个新增能力

**1. 负责人存在性校验**

```
POST /v1/tasks { assigneeId: 'not-exist-user-id' }
→ 400 负责人不存在或已被删除
```

不校验会写出「指向不存在用户」的孤儿指派：任务页负责人显示空白，首页待办又统计不到，最难排查。校验走 `UserService.findExistingBriefs`（过滤软删）。

**2. 列表批量翻译负责人姓名**

`assignee_id` 存的是 32 位字符串主键，前端只拿 ID 没法显示人。列表返回后按去重 ID 批量 `lookupBrief`（单次上限 100，与 pageSize 上限一致），结果写进非表字段 `assigneeName`。用户已删 / ID 拼错时字段为空，前端显示「用户已删除」而不是假装「未指派」。

**3. `GET /v1/tasks/mine`**

登录即可访问（不挂 `@Perms`），供任务页「我负责的」和首页待办下钻使用。

### 迁移：菜单与按钮权限

| 节点 | perms | 授权角色 |
|---|---|---|
| 任务管理（`/system/task`，挂在协同办公下 sort 5） | `system:task:list` | admin、editor |
| 新增任务 | `system:task:add` | admin、editor |
| 修改任务 | `system:task:update` | admin、editor |
| 删除任务 | `system:task:delete` | admin |

viewer / auditor 未授，需要时在角色权限页自行勾选。授权用 `NOT EXISTS` 保证可重复执行，`down()` 先删授权行再删节点。

### 前端页面

- 顶部副标题按口径给数字：「共 5 个任务，待处理 2 个、进行中 2 个」/「我负责 0 个任务…」
- 筛选：关键字（前端过滤）、所属范围、状态、优先级
- 操作列按状态机渲染**只有合法目标**：待处理 → 开始/取消，进行中 → 完成/取消，已取消 → 重开，已完成无按钮
- 截止时间两行：绝对时间 + 相对提示（`已逾期 3 天` 标红 / `今天到期` / `还剩 5 天`）
- 无 `system:task:list` 权限的账号进页面默认落在「我负责的」，不会因为列表接口 403 就整页报错

### 选人控件加单选模式

`UserMultiSelect` 加 `single`：选中一人后自动收起面板、再点同一人即取消、底部文案变「已指派（点其他人可替换）/ 未指派」。任务负责人直接复用它的服务端搜索、`lookup` 回显、已删用户标红等逻辑，不另写一套。

## 踩到的坑

1. **`mine` 一开始用 `listByQuery({ assigneeId })`，查不到任何数据**。根因是 `applyTenantScope`：新建用户 `login_tenant_id` 为 NULL 且没有 `sys_user_tenant` 关联 → 上下文按 `tenant_id = 0` 过滤（只看平台共享数据），而任务落库 `tenant_id = 1`。而首页 `dashboard.myTasks` 走裸 SQL 不隔离 → 卡片显示 1 条、点进去 0 条，自相矛盾。**修法：`mine` 刻意不加租户作用域**，条件只有 `assignee_id = 当前登录用户 id`（主键不可伪造，只可能查到自己的活）。
2. **`getManyAndCount()` 只在无 join 的 QB 上安全**；这次列表没 join（负责人姓名是后置翻译），所以能直接用。
3. **`assigneeName` 不能加 `@Column`**，否则 TypeORM 会想建列；只加 `@ApiPropertyOptional` 作为接口文档字段。
4. **前端写操作必须显式带 `Content-Type: application/json`**，`getApiResult` 不会替你补（`notice/api.ts` 同理）。
5. 新菜单的 `component` 字段对齐现有习惯填 `system/task/index`（TanStack Router 文件式路由实际不读它，只是元数据）；`icon` 用 `ListTodo`，需确认在 `icon-picker` 的 `ICON_MAP` 里，否则侧边栏退化成圆点。

## 怎么扩展

- **加导出**：照 `notice` 的导出接口抄一个 `GET /v1/tasks/export`，菜单补 `system:task:export` 按钮节点。
- **加评论/附件**：task 表加子表，`GET /v1/tasks/:id` 里带出来即可，列表不要带（N+1）。
- **批量操作**：需要先建 `system:task:delete` 之外的批量权限节点，参考 `batch-watermark` 的 `{ ids, mode }` 契约。
- **任务提醒**：`due_date` 已有索引需求（当前无），要按截止时间扫「即将到期」建议加 `(status, due_date)` 索引。
- **首页待办口径**：`scope='all'` 时后端把未指派任务也算进「我的待办」（历史设计），卡片上已标「含未指派」。如果希望严格只算本人的，改 `dashboard.service.ts` 的 `myTasks()` 去掉 `OR assignee_id = '0'` 分支即可（注意首页与任务页数字需要一起对）。
