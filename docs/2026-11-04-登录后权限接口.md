# 登录后权限接口（GET /api/v1/auth/permissions）

> 日期：2026-11-04 ｜ 仓库：concise-server-node（后端）+ concise-admin（前端）

## 这是什么

登录链路的最后一块：登录成功后前端调用一次该接口，拿到 **角色 code、按钮权限编码、按角色过滤的菜单树**，替代之前的 mock 数据（`/mock/menus.json` + `/mock/roles.json`），侧边栏可见范围与按钮级控制从此以数据库 RBAC 为准。

## 接口设计

```
GET /api/v1/auth/permissions        （需 Bearer token）
→ result:
{
  "roles": ["admin"],                        // 角色 code 数组
  "permissions": ["system:user:add", ...],   // 按钮权限编码汇总；超管返回 ["*"]
  "menus": [ ...按角色过滤的菜单树... ]        // 不含按钮节点，保留祖先层级
}
```

实现规则：

1. **超管**（roleCode 为 `admin`/`superadmin`）：`permissions = ['*']`，menus 为全量有效菜单树
2. **非超管**：汇总 `sys_user_role → sys_role_permission` 关联的菜单 id；按钮权限取 `menuType=2 且配置了 perms` 的编码去重；菜单树只保留授权节点并**自动补齐祖先链**（子菜单可见则父目录可见）
3. 只返回 `status='1'` 且未删除的菜单
4. 服务端 `@Perms` 实时查库鉴权不变——就算前端漏判，接口层也拦得住；本接口只负责「告诉前端该显示什么」

## 约定：接口版本

**后续新增或修改的接口一律挂 `/api/v1` 下**（如本接口）。旧 `/api/auth/**` 保留兼容，等全部迁完统一下线。

## 遇到的坑

1. **前端角色取值 bug**：后端 `userInfo.roles` 是对象数组 `[{ roleCode, ... }]`，原代码 `user.roles?.[0]` 把整个对象存进 localStorage 当角色用，`getRoleCode()` 永远走 `'superadmin'` 默认值 → 角色判断实际失效。修复：`roles[0]?.roleCode`，且无角色时默认 `viewer`（最小权限）而非 `superadmin`
2. **字段名叫 `perms` 不叫 `permission`**：MenuEntity 的权限编码字段是 `perms`（对齐 JeecgBoot），第一版写 `permission` 编译报错
3. **测试环境没有存活的非超管用户**：tester/wangwu 都是 `del_flag=1`。验证非超管分支时用 UserService 临时建了 `permtest`(viewer) 用户，测完软删清理
4. **独立应用上下文取依赖**：`app.get(DataSource)` 取不到，要用 `getDataSourceToken('default')`；`app.get('DataSource')` 字符串注入名也不行

## 怎么扩展 / 使用

```ts
// 前端任意组件里做按钮级控制
import { hasPermission } from '@/lib/auth'
{hasPermission('system:user:add') && <Button>新增用户</Button>}

// 权限数据变化后（登录/切换角色）通知侧边栏重算
notifyPermissionsChanged()
```

后端给角色分配菜单/按钮后（角色管理页勾选），用户**重新登录**即可生效（权限在登录时拉取并缓存到 localStorage）。

## 实测结果

- `admin`：`roles: ["admin"]`，`permissions: ["*"]`，全量菜单树（含按钮节点）✅
- 临时 viewer 用户：`roles: ["viewer"]`，`permissions: []`（该角色未配按钮权限），菜单树只剩授权的 1 个顶级节点 ✅
- 未登录调用：`1003 未授权，请先登录` ✅
- `tsc` / `eslint` / `nest build` 前后端全过
