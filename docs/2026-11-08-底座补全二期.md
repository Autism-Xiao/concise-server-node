### 使用方法

1. `.env` 配置 `OIDC_ENABLED=true` + IdP 三件套（issuer/clientId/clientSecret），回调地址默认按请求域名推导为 `http://<host>/api/v1/auth/sso/callback`（反代环境建议显式配 `OIDC_REDIRECT_URI`）。
2. IdP 侧注册客户端，回调地址填上面的地址。
3. 登录页出现「单点登录（SSO）」按钮；首次登录若本地无账号且 `OIDC_AUTO_CREATE=true`，自动建档（密码随机只能 SSO 登录）并绑定 `OIDC_DEFAULT_ROLES` 角色编码。
4. Keycloak / Casdoor / Authing / 企业微信扫码网关等标准 OIDC 提供方均适用。

### 已知限制

- 一次性 code 与验证码同理存**进程内存**，多副本部署需换 Redis（state 签名本身无状态，无此限制）。
- 自动建档角色解析用 `roleCode`（sys_role.role_code），配置里写编码不是 id。

## 验证

- **OIDC 端到端**（mock IdP 冒烟，跑完即删）：discovery → authorize 302（state 签名）→ mock 授权 → callback 302 回前端带 sso_code → exchange 拿到 accessToken/refreshToken；**同一 code 重放被拒**（1001）；`ssoadmin` 自动建档成功（realname/email 落库、绑定 viewer 角色、create_by=sso），验证后测试数据已清理。
- `GET /v1/auth/sso/config` 未开启时返回 `{enabled:false}`，authorize 返回 400。
- 后端 nest build 全绿；前端 `tsc -b` 全绿。

## 遗留与建议（下期）

- 需要接真实 IdP 时优先用 Keycloak 试一把（标准授权码最稳）。
- 一次性 code 换 Redis 前不要上多副本。
- 代码生成器如需覆盖树表/主子表场景再扩展模板。
