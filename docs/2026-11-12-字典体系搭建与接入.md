# 字典体系搭建与接入（下拉选项收敛到数据库）

| 项 | 内容 |
|---|---|
| 日期 | 2026-11-12 |
| 仓库 | concise-server-node + concise-admin |
| 触发 | 用户问「项目能用到哪些字典，帮我新建和使用」→ 盘点发现库里只有 2 个字典且前端零消费 |

## 背景

字典管理页（系统管理 → 数据字典）能增删改查，后端也有 `GET /v1/dict-items/code/:code`（全员可用、只回启用项、按 sort_order 排序），但**没有任何业务页面在读字典**——用户性别、公告类型、优先级这些下拉全部写死在代码里，改个文案就得发版。

## 后端改动（concise-server-node）

**新增 `scripts/seed-dicts.cjs`（幂等种子脚本）**：

- 按 `dict_code` 补齐/更新字典，按 `(dict_id, item_value)` 补齐/更新字典项；可重复执行（二跑 0 新建）
- 全部 `tenant_id=0`（平台共享：所有租户可见共用一套）；顺带把既有 2 个字典的 tenant_id 从 1 归一到 0
- 8 个字典 / 20 项：

| 编码 | 名称 | 项 | 接入位置 |
|---|---|---|---|
| `sys_user_gender` | 用户性别 | 未知/男/女（0/1/2） | 用户表单、个人资料 |
| `sys_menu_status` | 菜单状态 | 启用/停用（1/0） | 菜单表单状态单选 |
| `sys_notice_category` | 公告类型 | 通知公告/系统消息（1/2） | 公告表单、列表、筛选 |
| `sys_notice_priority` | 公告优先级 | 高/中/低（H/M/L） | 公告表单、列表标签 |
| `sys_notice_target` | 通告对象 | 全体用户/指定用户（ALL/USER） | 公告表单 |
| `sys_task_priority` | 任务优先级 | 低/中/高（0/1/2） | 任务表单、列表、筛选 |
| `sys_org_category` | 机构类型 | 公司/部门/岗位/子公司（1~4） | 部门表单 |
| `sys_tenant_plan` | 租户套餐 | 试用版/标准版/企业版 | 租户表单 |

**故意不建字典的**：公告发布状态、任务状态、定时任务状态、日志成功/失败——这些是**状态机**，后端按值分支（发布/撤销/执行各有校验），字典里多出来的项后端不认识，就是死选项。字典只适合「纯展示」的枚举。

## 前端改动（concise-admin）

**新增 `src/lib/dict.ts`（唯一读字典入口）**：

- `useDict(code, fallback)` → 返回 `Record<存储值, 显示文案>`，与 `<Select items={...}>` 同形直接传
- 模块级缓存 + 并发去重：同编码全站只请求一次
- **必须传 fallback**：字典被删/接口挂掉/返回空时回落到代码内默认项，下拉不空、页面不崩
- `clearDictCache()`：字典管理页每次 loadItems 前调用，改完文案业务页下次进来自动生效

**接入 10 个文件**（统一模式：`const items = useDict(code, 原写死的表)`，渲染 `Object.entries(items).map(...)`）：

用户表单性别、个人资料性别、公告表单（类型/优先级/通告对象）、公告列表（类型列/优先级标签/类型筛选）、任务表单优先级、任务列表（标签/筛选）、部门表单机构类型、租户表单套餐、菜单表单状态单选。

顺带统一了一处文案不一致：个人资料页原写「保密」、用户表单写「未知」，现在都跟字典（未知）。

## 验证（端到端）

- 种子二跑幂等；`GET /backend-api/v1/dict-items/code/...` 代理链路 200，不存在编码回 1001（前端静默用兜底）
- **实战验证**：把库里「高」临时改成「紧急」→ 无头浏览器打开公告新增弹窗，优先级下拉显示「紧急/中/低」，3 个字典请求各 1 次 → 跑种子恢复
- `tsc -b`、ESLint、前端 7/7 测试通过

## 如何扩展

1. 加新字典：在 `seed-dicts.cjs` 的 `DICTS` 里加一段 → `node scripts/seed-dicts.cjs`
2. 页面接入：`useDict('编码', {原写死项})` + `Object.entries().map()` 渲染选项
3. 判断标准：值被后端分支的（状态机）不进字典；纯展示文案的进字典

## 坑

- 字典项排序：菜单状态原来是「停用 sort0 / 启用 sort1」，导致下拉停用排前面；种子里改成启用在前
- `listByCode` 全局按编码查（不按租户过滤），同一编码只能有一套 → 平台级字典定 `tenant_id=0` 即可，**不支持按租户覆盖**（以后要覆盖得改接口加租户优先级）
- `useDict` 的 fallback 对象若内联在组件里每次渲染都是新引用，但不进 deps 数组，无碍；真正影响渲染的是 `items` 本身的缓存引用
