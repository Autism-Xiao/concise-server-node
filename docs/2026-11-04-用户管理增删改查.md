# 用户管理增删改查（v1 接口 + 前端对接）

## 背景

数据库物理表 `sys_user`/`sys_user_role`/`sys_depart` **本来就是 JeecgBoot 设计**（32 位字符串主键、realname/salt/org_code/depart_ids、`sys_user_depart` 多对多、jeecg 兼容密码加密），实体层也已对齐——**无需删表重建**。本轮只做两件事：按 v1 约定开控制器 + 前端用户管理页对接。

## 改动

### 后端（concise-server-node）

| 文件 | 类型 | 说明 |
|---|---|---|
| `src/modules/user/user.v1.controller.ts` | 新增 | `/api/v1/users`：列表/详情/新增/更新/删除/绑角色/绑部门，复用现有 DTO 与 Service，类级 `@Roles('admin')` + 方法级 `@Perms(system:user:*)` + `@OperLog` |
| `src/modules/user/user.module.ts` | 修改 | 注册 UserV1Controller |
| `src/modules/user/user.service.ts` | 修改 | `listByQuery` 补带出角色（`find + relations + 嵌套 select` 只取 id/roleName/roleCode），前端角色列展示用 |

旧 `/api/users` 路由保留兼容，前端已切 v1。

### 前端（concise-admin）

| 文件 | 类型 | 说明 |
|---|---|---|
| `src/features/users/api.ts` | 重写 | 对接 `/backend-api/v1/users`：fetchUsers（分页/keyword/status）、createUser、updateUser、deleteUser、fetchBackendDepts（直连 `/backend-api/depts`，dept 管理页还是 mock 不复用）；`userStatusMap`（1 正常/2 冻结） |
| `src/features/users/index.tsx` | 重写 | 列表列改为 jeecg 字段（账号/姓名/邮箱/手机号/状态/角色/创建时间）；状态筛选对齐 1/2；增删改走真实接口 + `withOperationLog`；按钮权限沿用 `hasPermission` |
| `src/features/users/components/user-form-dialog.tsx` | 重写 | 账号创建后不可改（disabled）；密码新增必填/编辑留空不改；角色、部门多选（复选框列表，部门首个为主部门）；性别/状态对齐后端枚举 |

## 坑

- 编辑用户**不下发 username**（密码算法绑定账号，后端禁改）；密码留空时 payload 不带 password 字段，避免触发 6 位校验。
- 列表带角色的 select 嵌套：`select: { id: true, roles: { id: true, roleName: true, roleCode: true } }`，顶层必须带上 id 否则没法映射回用户。
- dept 管理页仍是 mock（数字 id），用户表单的部门数据**直连后端** `/api/v1` 之外的老路由 `/api/depts`，不要 import dept 模块的 mock fetchDepts。
- 详情/列表响应不含 password/salt（实体 `select: false`），已实测验证。

## 实测（全流程）

```text
列表   total:4，crudtest|admin 角色正确带出
新增   crudtest → 32位 id 生成、jeecg 算法加密入库
更新   改名+冻结+改手机号 → code:0
详情   响应不含 password/salt ✅
删除   软删除成功；再查 → 1002 用户不存在 ✅
```

## 使用

前端「用户管理」页即开即用；给非超管角色勾 `system:user:add/update/delete` 可控制按钮显隐，后端 `@Perms` 兜底。
