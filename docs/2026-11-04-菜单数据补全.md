# 菜单数据补全（sys_permission 按 frontend 路由灌数）

> 日期：2026-11-04 ｜ 仓库：concise-server-node

## 这是什么

`sys_permission` 表此前只有「系统管理」子树 + 按钮权限，且部分 url 与前端实际路由对不上（`/system/user` vs `/system/users`、`/tools/storage` vs `/system/file`）。本次按前端真实路由（`concise-admin/src/routes/_authenticated/**`）补全菜单树，使 `GET /api/v1/auth/permissions` 返回的 `menus` 能与前端侧边栏/路由守卫精确匹配。

| `docs/2026-11-04-菜单数据补全.md` | 新增 | 本文档 |

数据库变化：更新 8 条、新增 17 条（`menu_35` ~ `menu_51`），现共 25 条菜单（不含按钮 24 条按钮不变）。

## 关键修正

## 遇到的坑

1. **实体字段是 `url` 不是 `path`**：`MenuEntity` 对齐 JeecgBoot `sys_permission.url`，前端 `PermissionMenu` 与 `collectPaths` 也要用 `url`（前端侧已兼容 url/path 双字段）
2. **临时测试用户唯一键冲突**：上轮软删的 `permtest` 占着 `uniq_sys_user_username`，软删不释放唯一索引——重测前要硬删
3. 脚本 require 路径：`scripts/` 下引用编译产物要 `require('../dist/app.module')`

## 怎么扩展 / 使用

- 菜单有增删改：直接改 `scripts/seed-menus.cjs` 里的 `MENUS` 数组后重跑（幂等）
- **角色授权注意**：给角色勾菜单时要把父级目录一起勾上（接口会补祖先链，但子菜单本身必须授权才可见）；例如 viewer 只勾「系统管理」时，子菜单一个都看不到
- 前端刷新后重新登录即可拉到新菜单树
