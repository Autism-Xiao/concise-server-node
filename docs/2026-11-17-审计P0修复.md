## 每项修复对应的问题

1. **跨租户用户接管链**（P0）：`findOne` 不带租户条件，update/delete/resetPassword/setStatus/批量三处全部可按 id 跨租户写 → findOne 走 EXISTS 租户过滤后整条链关闭。
2. **写路径含共享行**（P0）：`tenantRawCondition` 的 `OR tenant_id=0` 让租户能改删平台数据 → 新增 `tenantWriteCondition`，读/写分离。
3. **/v1/open/ 人类令牌直通**（P0）：任意登录账号可拉全平台用户 → ApiScopeGuard 对非应用令牌 403；开放接口补应用租户过滤。
4. **app/webhook IDOR**（P0）：跨租户可重置别人应用密钥拿明文 → findOne 补归属租户。
5. **派发跨租户**（P0）：A 租户用户事件（含姓名）推给 B 租户回调 → dispatch 带 `opts.tenantId`，订阅按「同租户或平台」过滤。
6. **SSRF**（P0）：回调地址只查 https 前缀 + fetch 跟重定向 → IP 段黑名单（RFC1918/环回/169.254 元数据/CGNAT/ULA）+ DNS 解析校验 + `redirect:'manual'`。
7. **改密后 refresh 仍有效 7 天**（P0）：refresh 轮换只查令牌级黑名单 → 新增用户级吊销标记检查；自助改密改为全量下线（含当前设备，前端改完跳登录页）。
8. **前端 2h 硬踢**（P0）：access 过期直接弹框 → 401 先单飞静默续签并重放，refresh 也失效才弹框。
9. **webhook secret 拿不到 + reset 权限码错**（P0）：页面展示签名密钥 + 复制；按钮权限码 `system:app:update` → `system:app:reset`。
10. **2FA 重绑无需密码**（P0）：被盗会话可覆盖式绑自己的认证器 → setup/deactivate 需密码。
11. **自助改邮箱接管账号**（P0）：被盗 token 可改邮箱走 forgot 链路 → 改邮箱需密码。
12. **滑块验证码可撞**（P0）：容差 ±5 且 verify 无独立限流 → ±3 + verify 独立限流 30/min（两个控制器都加了）。

## 踩的坑

- **sys_user 没有 tenant_id 列**：用户租户归属在 `sys_user_tenant` 关联表，租户过滤必须走 `applyTenantToUsers` 的 EXISTS 子查询——一开始按 business 表的套路写 `where: { tenantId }` 直接编译报错。
- **MySQL UPDATE 相同值 affected=0 陷阱**：mysql2 默认带 `FOUND_ROWS` 标志（值没变也报 affected=1），所以 BaseService.update 的 404 检查不会误伤「提交表单没改任何值」的场景；但去掉该标志的部署会误报 404。
- **@RawResponse 接口的返回形状**：`/v1/open/token` 返回的是 OAuth 裸体 `{ access_token }` 不是统一包装 `{ code, result }`，写冒烟脚本时按统一包装解析导致假 401。
- **改密端点是 PUT 不是 POST**：`@Put('password')`，用 POST 打会 404 经错误过滤器变成别的业务码。
- **吊销标记按秒对齐**：`revokeUser` 存 `floor(now/1000)*1000`，判断是 `iat*1000 < at`（严格小于）——同一秒内「登录→改密→重放旧 refresh」会放行，这是防误杀同秒新令牌的刻意取舍；真实场景（登录和改密隔了不止一秒）实测 2101 拒绝生效。
- **Base UI Dialog 没有 `dismissible`/`onEscapeKeyDown`**（上轮已踩，这轮写 2FA 弹窗时再次确认）：受控 `onOpenChange` 忽略即防关。
- **node --test 沙箱缺 `AbortSignal`**：http.ts 的 refreshAccessToken 用了 `AbortSignal.timeout`，测试 vm 里没注入会 ReferenceError 被 catch 吞成 null，续签测试全部假失败——沙箱 globals 必须补 `AbortSignal`。
- **审批拦截**：本会话多次命令含密码相关关键词被安全审批卡住且审批超时；期间一个「还原密码」脚本显示被拦但**实际已执行**（依据是密码状态变化与登录验证），教训：敏感操作的结果必须用只读探针复核，不能信单次输出。

## 冒烟结果（3461 实例）

```
人类令牌调 /open/users        → 403 ✓
应用令牌换发 → 调 /open/users → 200 ✓（total=4）
停用应用后旧令牌              → 401 ✓（回归上轮修的漏洞）
云元数据/环回地址建订阅        → 拒绝 ✓（内网地址校验生效）
公网域名建订阅 → 删除          → 0 ✓
改密后旧 refreshToken 重放     → 2101 拒绝 ✓（间隔 >1s 的真实场景）
改密用新密码登录               → 0 ✓
```

冒烟产生的应用/订阅已删除，admin 密码已还原为原始值并复核登录成功；临时脚本已删。

## 如何扩展

- **新增开放接口**：`open.v1.controller` 加方法 + `@ApiScope('xxx')` + 字段白名单；scope 进 `openapi.constants.ts` 的 `APP_SCOPE_KEYS`；前端 `SCOPE_OPTIONS` 同步。
- **写路径租户过滤的统一姿势**：QueryBuilder 一律 `applyTenantScope` / `applyTenantToUsers`（读）或 `tenantWriteCondition`（写）；`FindOptionsWhere` 一律 `writeTenantWhere` 思路——不要手写 `OR tenant_id=0` 的写条件。
- **敏感自助操作加密码确认**：后端 service 里 `assertPassword(userId, password)` 模式（见 totp.service），DTO 加可选 password 字段，前端弹窗加一步输入。
- **前端新增会话相关测试**：`tests/http-unauthorized.test.cjs` 的 `loadHttp({ fetchFn })` 模式可复用；沙箱 globals 记得带 `AbortSignal`。
