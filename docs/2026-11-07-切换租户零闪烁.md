# 切换租户零闪烁（旧画面快照 + 骨架判据）

> 日期：2026-11-07　仓库：concise-admin（前端）　承接：[切换租户软刷新](./2026-11-07-切换租户软刷新.md)

## 一、问题：软切换之后还是"闪一下"

上一轮把 `window.location.reload()` 换成了「推进 epoch → 页面重挂 → 重拉数据」，整页白屏没了，但用户体感仍然是**闪一下**。

用 headless Chrome + CDP **逐帧采样**（rAF 每帧记录内容区文本长度、骨架数量、遮罩状态）拿到了确切时序：

| 时刻 | 内容区 | 骨架 | 用户看到的东西 |
| --- | --- | --- | --- |
| 949ms | 739 字 | 0 | 旧租户数据 |
| 1059ms | 0 字 | 20 | 遮罩出现（白色半透明 + 模糊） |
| 1073~1290ms | 50~0 字 | 20 | **骨架屏**←这就是"闪" |
| 1306ms | 707 字 | 0 | 新租户数据 |

页面标记 `window.__marker` 全程存活 → **确认没有整页刷新**，闪的唯一来源是：**重挂载让页面回到了 loading 初始状态**，旧 DOM 被卸载、骨架屏顶上，230ms 后数据回来。

同时发现第二个问题：`/v1/dashboard/overview` **发了两次**（dev 模式 React StrictMode 双跑 effect），第一个 219ms 返回并渲染完成，第二个拖到 440ms 才结束。原本"等在途请求归零"的判定因此白等 200ms，遮罩一直盖到 570ms。

## 二、方案：把旧画面冻结成一张快照

重挂载是省不掉的（页面数据都在组件内部 state，项目没有全局数据缓存层），所以换个思路——**不让用户看见重挂载的过程**：

```
点切换
  → POST /tenants/switch
  → 克隆当前内容区 DOM 成快照，盖在原位（fixed + 视口坐标，像素级对齐）
  → 写 localStorage → epoch + 1 → 页面在快照下面默默重挂、发请求
  → 新页面骨架消失（或请求归零）→ 快照 140ms 淡出
```

用户看到的是「旧数据 →（静止几百毫秒）→ 新数据」，中间既没有骨架也没有白屏。

### 为什么用 DOM 克隆而不是"保留旧组件树"

保留旧组件树需要每个页面自己响应 `epoch` 并做 stale-while-revalidate，要改 20+ 个页面；
而克隆出来的只是静态 DOM（无组件、无 effect、不会再发请求），一个地方就能兜住所有页面。

本项目图表是 recharts（SVG），`cloneNode` 能完整复制；如果以后引入 canvas 图表，需要在克隆后把 canvas 用 `toDataURL()` 换成 `<img>`。

## 四、揭幕时机怎么判（核心逻辑）

`isNewContentReady()` 分两条路，避免把"还在加载"的样子露出来：

- **页面有骨架屏**（列表/看板类）：只要骨架**出现过又消失**且已渲染出文字 → 立刻揭幕。
  不能等在途请求归零 —— dev 模式下 StrictMode 让 effect 跑两遍，第二个请求比第一个晚 200ms，白等一截。
- **页面没有骨架**（纯表单/静态页）：退回「在途请求归零 + 安静 400ms」。
  这条是保守路线：宁可多盖一会儿，也不能让空表格提前露出来（那看起来就像"数据全没了"）。
- 兜底：最短冻结 60ms（新页面头几帧还是空的）、最长 2500ms（有轮询请求的页面也一定会揭幕）。

## 五、实测结果（CDP 真实鼠标点击）

切到「长沙示范科技有限公司」：

```
快照窗口 1077~1455ms（378ms）
用户可见的空白帧数      = 0
骨架屏暴露帧数（无快照盖着）= 0
内容塌缩帧数            = 0
window.__marker 存活    = 是（未整页刷新）
```

切回「平台视角」：快照 377ms，空白 0、骨架暴露 0，顶栏正确回到「平台视角」。

## 六、坑

1. **在途计数必须成对**：`beginApiCall()` 放在 `try` 第一行、`endApiCall()` 放 `finally`，否则失败一次计数就永不归零，遮罩会一直盖着。测试里已加断言。
2. **克隆必须在 `setEpoch` 之前同步做**：React 提交新一轮渲染后 DOM 就是新页面了，抓到的会是骨架。顺序是 `setTenantId` → `captureMainSnapshot()` → `setEpoch()`。
3. **快照容器用 `fixed` + 视口坐标**：`main` 是滚动容器，`absolute` 会跟着滚走；`fixed` 相对视口，且 `SidebarInset` 没有 transform 所以不会被祖先劫持定位。
4. **快照要还原滚动位置**：内容容器 `marginTop: -scrollTop`，外层 `overflow-hidden`，否则滚动过的页面快照会错位。
5. **不要用 `display:none` 藏新内容**：会让图表按 0 尺寸初始化，交换后不重绘。这里新页面是正常布局的，只是被盖住。
6. **手写 vm 沙箱测试要同步加桩**：`http.ts` 多了 `@/lib/api-activity` 依赖，`http-unauthorized.test.cjs` 的 `require` 桩不加就 `Unexpected import`（和之前 `tab-page-renderer` 的坑同源）。
7. **dev 下的双请求是 StrictMode 行为**，生产构建不会有；但它暴露了「无条件等在途归零」的脆弱性，所以判据改成以 DOM 为准。

## 七、怎么调 / 怎么回退

- 觉得过渡太慢：调小 `SNAPSHOT_FADE_MS`（140ms）或 `SNAPSHOT_MIN_HOLD_MS`（60ms）。
- 觉得某类页面揭幕太早：把那类页面的骨架接上（`data-slot="skeleton"` 由 `components/ui/skeleton.tsx` 自带），会上自动走"骨架消失即揭幕"的快路线。
- 完整回退：`tenant-switcher.tsx` 里把 `applySwitch` 换回 `switchTenant + window.location.reload()`，`epoch` 恒为 0 时其余逻辑与改动前完全一致。
