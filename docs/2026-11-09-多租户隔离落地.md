## 二、每个东西是干什么的

### 2.1 身份分层：`sys_user.is_platform_admin`

之前 `isSuper` 由 `role_code in ('admin','superadmin')` 推导，而 `sys_role` 是**租户级**表 ——
只要平台把 admin 角色分给某个租户用户，或者租户自己建了同名编码（旧代码允许），这个用户就：
可以带任意 `X-Tenant-Id` 读别的租户（`resolveTenant` 超管分支只校验租户存在，不校验归属）；
不带请求头时 `tenantId = null`，所有 `BaseService` 查询完全不过滤（全库裸奔）。

现在身份是账号属性：

- `TenantAccessService.loadMembership` 读 `is_platform_admin`；
- `PermsGuard` / `RolesGuard` / `AuthService.getPermissions` / `DashboardService.ownedPerms` / `UserService.applyDataScope` 统一读 `req.user.isPlatformAdmin`；
- 非平台管理员在 `resolveTenant` 里**永远拿不到 `null`**（没有可用租户时返回 `0`）。

### 2.2 角色唯一键：`(tenant_id, role_code)`

旧索引 `uniq_sys_role_role_code` 是全局唯一，租户 B 建不了自己的 `operator` 编码，软删角色还占坑。
现在按租户唯一；内置保护改看 `is_builtin`（否则租户的 admin 编码会被误当成平台内置角色而删不掉/停不了）。

### 2.3 权限分层：`sys_permission.scope`

`platform` 的语义是「光有权限码不够，还必须是平台管理员」：

- `PermsGuard`：先判作用域，非平台管理员命中平台权限直接 403，文案是「`xxx` 是平台级权限，仅平台管理员可操作」；
- `AuthService.getPermissions`：平台级菜单不进租户用户的导航树；
- `MenuService.getTree`：角色授权页也不给租户管理员看平台菜单；
- `RoleService.assignMenus`：即使硬传 id 也拒绝授权平台节点。

被标为 platform 的：租户管理、菜单管理、运维（定时任务/在线用户/服务监控/缓存监控）、存储配置。

### 2.4 用户表的租户收窄

`sys_user` 本身没有 `tenant_id`（一人可属多租户，这是对的），但「用户管理」页必须只列本租户成员：

```sql
EXISTS (SELECT 1 FROM sys_user_tenant ut
         WHERE ut.user_id = user.id AND ut.tenant_id = :scopeTenantId AND ut.status = 0)
```

覆盖 `scopedQuery`（列表/导出/首页用户总数）、`listRecycled`、`lookupBrief`（选人控件）、
`findExistingBriefs`（批量操作目标校验）、`findOneDetail`（详情，跨租户按 404 处理）。

### 2.5 审计日志的 `tenant_id`（**语义与其它表相反**）

| 值 | 含义 |
| --- | --- |
| `> 0` | 该操作发生在哪个租户 |
| `0` | 平台视角下的操作，**只有平台管理员能看** |

其它表 `0` 表示「所有租户可见的共享数据」，日志不是：审计可见性 ≠ 数据共享。
所以 `LogService.applyLogTenantScope` 用**严格相等**，绝不 `OR tenant_id = 0`；租户视角永远看不到平台级记录。

### 2.6 水印策略按租户

`sys_watermark_setting` 主键变 `tenant_id`：读的时候「本租户 → `0` 平台默认 → 兜底常量」三级回落；
写的时候只写当前租户那一行（平台视角写 `0`）。用户列表批量带出的水印状态（`attachWatermark`）同口径。

### 2.7 建号即入租户

`UserService.create` 在事务里补一行 `sys_user_tenant`：

- 租户管理员建号 → 加入**本租户**；
- 平台视角建号 → 加入**默认租户 1**（与存量账号升级时的处理一致）。

不打这一行的后果：新账号 `filterTenantId()` 解析成 `0`，登录后用户列表/任务/公告全是空的（历史遗留问题，本次一并修掉）。

## 三、遇到的坑

1. **回填「平台管理员」的口径一开始太宽。**
   首版按「持有 admin/superadmin 角色 且 角色属于租户 1」回填 —— 而 admin 角色是**共享**的那一条，
   演示租户的用户也挂着它，于是一批租户用户被标成平台管理员，等于把要修的漏洞又复制了一遍。
   现在 179427 已改成窄口径（`username='admin'` 或持有 `superadmin` 角色），并加了 179431 纠正存量。
   **更多平台管理员请逐个授予，不要按角色批量刷。**

2. **`sys_role.tenant_id` 默认是 0，而 `BaseService.create` 之外的手写创建点不会打标。**
   `RoleService.createRole` 走的是自己的事务 + `repo.create`，漏了 tenantId → 租户建的角色变成「平台共享角色」，
   出现在所有租户列表里。同一类问题在 `FileService`（建文件夹/上传）也有，已一并修。
   **凡是手写 `repository.create(...)` 的地方，都要问一句「tenant_id 谁负责写」。**

3. **裸 SQL 的参数顺序必须与拼接顺序一致。**
   `dashboard.service.ts` 用 `?` 占位符 + 参数数组，`tenantClause(column, params)` 会 push 参数，
   所以必须按 SQL 里 `?` 出现的顺序调用它。`selfFilter` 先拼、`tenantFilter` 后拼，参数也就先后对应。

4. **`DeleteQueryBuilder` 与 `SelectQueryBuilder` 不能混用泛型。**
   抽公共方法时写 `ReturnType<Repository<T>['createQueryBuilder']>` 会被推断成 `SelectQueryBuilder`，
   `.delete()` 出来的 builder 传进去直接 TS2345。显式声明 `DeleteQueryBuilder<SysLogEntity>`。

5. **登录请求没有 token，中间件给的上下文是租户 0。**
   所以登录日志不能直接用 `TenantContext.currentTenantId()`，
   要按「用户上次选择的租户 → 第一个可用租户 → 默认租户」推导（`LogService.resolveLoginTenant`）。

6. **新账号默认会加入默认租户，写断言时要注意。**
   平台视角建号 → 自动进租户 1；再把它分到租户 A 后，它同时属于 1 和 A，
   「默认当前租户」不一定是 A（取 `login_tenant_id`，没有则取可用租户里 id 最小的）。
   冒烟脚本里已改成「current 必须是自己所属的某个租户」。

7. **既有的 `scripts/smoke-tenant.mjs` 有 4 项断言基于旧语义**（它把「持有 admin 角色」当成超管）。
   改造后该脚本失败 4 项，新脚本 `smoke-tenant-isolation.mjs` 已覆盖同等语义并全绿。
   ⚠️ 该文件含测试凭据，本轮工具无法读取，**待下轮按新模型更新那 4 项断言**：
   `mine 只返回自己所属租户` / `默认当前租户 = A` / `带未加入的租户头 → 403` / `普通用户切平台视角被拒`。

## 四、怎么扩展 / 使用

### 新增一张表要不要隔离（四问）

1. 是某个租户的业务资产？→ 加 `tenant_id INT NOT NULL DEFAULT 1`，继承 `BaseService` 即自动读写隔离；
2. 是所有租户共用的只读/平台配置？→ 不隔离（或 `tenant_id=0` 共享）；
3. 是「人」的全局身份？→ 不隔离，用 `sys_user_tenant` 表达归属；
4. 是个人偏好且与租户无关？→ 不隔离，跟人走。

### 新增接口

- 一律 `@Perms('system:xxx:yyy')`，不要用 `@Roles('admin')`（会短路按钮权限）；
- 平台级能力（影响全平台唯一资源）要把对应权限行的 `scope` 置 `platform`，
  否则租户管理员能自己授权给自己；
- 手写 QueryBuilder 时：`SELECT` 用 `applyTenantScope(qb, alias)`，
  `UPDATE/DELETE` 用 `tenantRawCondition()`，别自己拼 `tenant_id = ?`。

### 新增裸 SQL / 报表

- 走 `DashboardService.tenantClause(column, params, { shared })`；
  `shared: true` 表示沿用「0 是共享数据」，审计类用默认（严格相等）；
- 平台视角（`filterTenantId() === null`）自动不过滤，不用额外判断。

### 平台管理员从哪来

迁移只回填 `admin` 与 `superadmin` 持有者。后续要新增：

```sql
UPDATE sys_user SET is_platform_admin = 1 WHERE username = 'xxx';
```

（暂未提供接口；如需要，请在用户管理里加一个「平台管理员」开关，且**只有平台管理员能改**。）
