# 启动时自动清理端口占用（EADDRINUSE）

**日期**：2026-11-07
**仓库**：backend（concise-server-node）

## 现象

反复启动后端时稳定复现：

```
Error: listen EADDRINUSE: address already in use :::3459
    at ExpressAdapter.listen (.../express-adapter.js:243:32)
    at async bootstrap (E:\oneself\concise\concise-server-node\src\main.ts:146:3) {
  code: 'EADDRINUSE', errno: -4091, syscall: 'listen', address: '::', port: 3459
}
```

堆栈里只有 Node 内部帧，看不出是谁占着端口，也不知道该杀哪个 PID —— 每次都得手动
`netstat -ano | findstr :3459` → `taskkill /PID xxx /F`，非常啰嗦。

## 根因

`app.listen(port)` 失败时是异步 reject，而 `src/main.ts` 末尾原本是裸的 `void bootstrap()`，
没有任何 catch。于是：

1. 进程已经初始化完整个 Nest（建了连接池、Redis 连接、装了定时任务），才在最后一步 listen 失败；
2. 失败现场只剩一个原始堆栈，看不出「上一次的 `node dist/main.js` 没退」这个真正原因。

占端口的多半是上一轮自己在别的终端 / 后台任务里起的 `node dist/main.js`。
它不是 daemon，关终端不一定带走，于是下次启动必撞。

## 方案：`scripts/serve.mjs`

新增启动包装脚本，**启动前先把「自己家的旧实例」结束掉**，再拉起 `dist/main.js`。

```
node scripts/serve.mjs
  ├─ 读端口：process.env.PORT > .env 的 PORT > 3000
  ├─ 检查 dist/main.js 是否存在（没有就提示先 npm run build）
  ├─ net.createServer().listen(port) 探测端口
  │    ├─ 能绑 → 直接启动
  │    └─ EADDRINUSE → netstat 取 PID → 读命令行 → 判定是否本项目实例
  │           ├─ 是 → taskkill /T /F（Windows）/ SIGKILL（*nix）→ 轮询等端口释放（最多 8s）
  │           └─ 不是 → 打印占用者后退出 1，绝不误杀
  └─ spawn(node, [dist/main.js])，stdio 继承，转发退出码
```

判断端口是否被占**以能否 bind 为准**，不用解析 netstat 的状态词（中文系统本地化风险）；
netstat 只用于拿 PID 做诊断和清理。

### 命令行

| 命令 | 作用 |
| --- | --- |
| `npm run start:prod` | 启动（已指向 `scripts/serve.mjs`），撞端口自动清理旧实例 |
| `npm run restart` | `npm run build` 后再启动，改完代码重启用这条 |
| `node scripts/serve.mjs --port 3460` | 临时换端口（会把 `PORT` 注给子进程） |
| `node scripts/serve.mjs --dry-run` | 只打印「谁占着端口」，不做任何结束动作 |
| `node scripts/serve.mjs --force` | 连「不是本项目的占用者」也结束（慎用） |

### 安全线（`isOurInstance`）

只有同时满足下面三条才会被自动结束，避免把别人的服务杀掉：

1. 命令行里出现 node 可执行（`node.exe` 或行首/空白后的 `node`）；
2. 命令行命中 `dist/main.js`、`dist/main` 或 `nest start`；
3. 如果是绝对路径形式（`D:\...\dist\main.js`），该路径必须落在本仓库目录内。

不满足就原样打印占用者（pid / 进程名 / 完整命令行）后 `exit 1`，交给人判断。
实测：占位服务 `node -e "http.createServer().listen(3461)"` 被正确拒绝，且脚本退出后
该占位服务仍在监听（200）。

## `src/main.ts` 的兜底提示

把末尾的 `void bootstrap()` 换成带 catch 的调用，端口冲突时给三行人话，`exit 1`：

```
端口已被占用（EADDRINUSE: 3459），大概率是上一次的 node dist/main.js 还在跑。
  npm run start:prod    启动前自动结束旧实例（推荐）
  node scripts/serve.mjs --dry-run    只查看是谁占着，不做处理
```

其它异常仍然原样 `console.error` + `exit 1`（原来完全没有 catch，未处理的 rejection
在 Node 24 下会直接按致命错误打印，容易被误认为业务崩溃）。

## 验证

| 场景 | 预期 | 实测 |
| --- | --- | --- |
| 端口被旧 `node dist/main.js`（pid 26384）占着 | 自动结束并启动 | ✅ 打印 `结束 pid=26384（D:\programs\nodejs\node.exe dist/main.js）` → `端口已释放` → 启动成功，`/api/v1/auth/captcha` 200 |
| 连跑两次（第二次面对第一次起的实例） | 同样自动结束再起 | ✅ 结束 pid=22016 → 新实例 pid=26968，接口 200 |
| 端口被非本项目进程占用 | 拒绝、退出 1、对方存活 | ✅ 退出码 1，占位服务仍 200 |
| `--force --dry-run` | 判定被绕过但不动手 | ✅ 打印「结束 pid=23468」后 dry-run 退出 0 |
| 直接 `node dist/main.js` 撞端口 | 三行提示 + 退出 1 | ✅ 无原始堆栈，退出码 1 |

## 坑

1. **PowerShell 里的 `$PID`**：拼 `Get-CimInstance -Filter "ProcessId=$pid"` 时若用双引号，PowerShell 会把
   `$pid` 当内置变量（当前进程 ID）插值，查出来永远是自己。必须让 JS 侧先把数字拼进去，PowerShell 串用单引号：
   `-Filter 'ProcessId=26384'`。
2. **`lsof` 在无监听时退出码为 1**：`execFileSync` 会抛异常，必须 try/catch 当空数组处理，不能当失败。
3. **`endsWith(':3459')` 不会误吞 `:13459`**：`'0.0.0.0:13459'.endsWith(':3459') === false`（末 5 位是 `13459`），
   所以直接用它匹配端口是安全的。
4. **`taskkill` 要加 `/T`**：`npm run start:prod` 会多一层 npm → node 的父子链，只杀父 PID 会留下孤儿占端口。
5. **别用 `nest start --watch`**：本机 safe-delete 钩子会拦住它清 dist（675 文件超过阈值 50），进程反复重启失败。
   这条和端口问题是两个独立故障，别混在一起排查。

## 如何扩展

- **多端口并行**：脚本已经支持 `--port`，起第二个实例用 `node scripts/serve.mjs --port 3460`，互不干扰。
- **改成自动挑空闲端口**：把 `releasePort()` 换成从 `port` 往上找第一个 `canBind` 成功的端口，适合 CI 里并跑多实例。
- **清理规则扩展**：`isOurInstance` 只认 `dist/main` 与 `nest start`；若以后加了 `worker.js` 之类的常驻进程，
  在 `hitsEntry` 正则里一并列出即可。
- **Linux 生产**：生产不该靠这个脚本，交给 systemd/pm2 管进程；脚本定位是本地开发。
