# 验证码改造：SVG 字符验证码 → 滑块验证码（rc-slider-captcha）

- 日期：2026-11-05
- 仓库：`concise-server-node` + `concise-admin`（双端联动改造）
- 背景：字符验证码体验差且中文识别率低，换成主流的滑块拼图验证码

## 一、方案选型

| 候选 | 结论 |
| --- | --- |
| `rc-slider-captcha`（React 组件，6.5k 周下载、中文文档、内置 TS 类型） | **采用**。组件只管 UI 与拖拽，图像与校验由我们自己的后端实现 |
| `@slider-captcha/react` + `@slider-captcha/core` | 6 年未维护，server 端要在 session 里存答案，与本项目 Redis 多实例架构不合 |
| `@baanihali/captcha` 等 | 太新/下载量个位数，单维护人，风险高 |

组件契约：`request: () => Promise<{ bgUrl, puzzleUrl }>`（URL 或 dataURL 均可）；`onVerify(data: VerifyParam)` 返回 resolve = 成功 / reject = 失败（失败自动刷新）；`data.x` 是拼图横向位移，交给后端比对。

## 二、后端（concise-server-node）

**新依赖**：`jimp@0.22.12`（纯 JS 图像库、CJS 兼容；1.x 转 ESM 与本项目 CJS 构建冲突，锁 0.22）；移除 `svg-captcha`。

**`captcha.service.ts` 全部重写**：

| 方法 | 职责 |
| --- | --- |
| `create()` | 程序化生成 320x160 背景（竖向渐变 + 8 个随机半透明圆形纹理，无外部图片依赖），在随机 x（60~260）切出 60px 通高拼图条，背景同区域压暗描边形成缺口；答案 x 存 Redis `captcha:{id}`（EX 300s）；返回 `{ captchaId, bgUrl, puzzleUrl }`（PNG dataURL） |
| `verify(captchaId, x)` | challenge 先 MULTI GET+DEL（一次性，防并发重放），`|x - 答案| ≤ 5px` 通过 → 发一次性 ticket（`captcha-pass:{uuid}`，EX 120s）；不通过/过期分别抛 `CAPTCHA_INVALID` / `CAPTCHA_EXPIRED` |
| `assertTicket(ticket)` | 登录时消费 ticket（同样一次性）；原 `assertValid(captchaId, captchaCode)` 删除 |

**接口变化**（旧路由 `/auth/**` 与 v1 同步）：

| 接口 | 改动 |
| --- | --- |
| `GET /v1/auth/captcha` | 返回 `{ captchaId, bgUrl, puzzleUrl }`（原 `{ captchaId, svg }`） |
| `POST /v1/auth/captcha/verify` | **新增**，入参 `{ captchaId, x }`，返回 `{ ticket }` |
| `POST /v1/auth/login` | `captchaId + captchaCode` → `captchaTicket`（CAPTCHA_ENABLED=true 时必填） |

**配置清理**：`captcha.config.ts` 删 `debug`（滑块无明文 code，CAPTCHA_DEBUG 废弃，.env 里残留会被忽略）；`env.validation.ts` 同步删 `CAPTCHA_DEBUG`；`.env.example` 更新注释（顺带再次修掉 `REDIS_JS` → `REDIS_DB` 笔误）。

## 三、前端（concise-admin）

**新依赖**：`rc-slider-captcha@1.9.0`；删除 `features/auth/components/captcha.tsx`（CaptchaBox）。

| 文件 | 改动 |
| --- | --- |
| `features/auth/api.ts` | `CaptchaData{svg}` → `CaptchaChallenge{bgUrl,puzzleUrl}`；新增 `verifyCaptcha(captchaId, x)`；`LoginPayload` 改 `captchaTicket?` |
| `features/auth/login.tsx` | 验证码输入框 + SVG 图 → `<SliderCaptcha>`；captchaId/ticket 放 ref（`request`/`onVerify` 闭包取最新值）；提交前校验 `captchaTicket`；登录失败重置滑块（ticket 一次性）；tipText 走 i18n |
| `config/i18n.ts` | 删 `captchaPlaceholder/captchaRefresh/captchaLoadError`，`captchaRequired` 改「请先完成滑块验证」，新增 7 个 slider.* 文案（中英） |

关键点：**前端 bgSize 保持组件默认 320x160，与后端生成尺寸一致** —— 若显示尺寸 ≠ 生成尺寸，`data.x` 需要乘缩放比例，等尺寸就完全不用管。

## 四、安全模型

- 答案只存服务端 Redis，前端拿到的是切好的图，**无法从响应里直接读出答案**
- challenge 一次性：verify 无论成败都销毁，重放返回「已过期」
- ticket 一次性：登录无论成败都消费（先消费再验密码，防爆破复用）
- 进阶可做（未做）：用 `VerifyParam` 里的 `trail`/`duration` 做轨迹人机校验，组件文档明确支持

## 五、验证（真实运行 + 真实 Redis）

| 场景 | 结果 |
| --- | --- |
| `GET /v1/auth/captcha` | code 0，bgUrl/puzzleUrl 均为 data:image/png，图可见缺口条 + 描边 |
| 正确位置 verify | code 0，返回 ticket |
| 同一 challenge 重放 | code 413「验证码已过期」 |
| 错误位置（x=20） | code 412「滑块位置不正确」 |
| 带 ticket 登录 | ticket 被消费（后续凭证错误与否都不影响一次性） |
| 重放 ticket | code 413「验证已失效」 |
| 不带 ticket 登录 | code 417「请先完成滑块验证」 |

两仓库 tsc / eslint / jest(6 用例) / vite build 通过。

## 六、扩展

- **换真实照片背景**：`generateBackground()` 换成 `Jimp.read(某图)` 后做同样的切条即可，其余逻辑不动
- **调难度**：TOLERANCE（容差）、拼图宽度、x 取值范围都在文件顶部常量区
- **接第三方人机校验**（轨迹/时长）：在 `verify()` 里加，对前端透明
- **CAPTCHA_ENABLED=false**：登录不要求 ticket，但登录页仍展示滑块（与旧字符码行为一致）；要做成「后端开关控制前端显隐」需再暴露一个公开配置接口
