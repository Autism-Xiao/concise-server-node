# 行政区划管理改成树形懒加载

**日期**：2026-11-07
**仓库**：backend（concise-server-node）+ frontend（concise-admin）

## 问题

区划管理页原来用 `DataTable` 平铺渲染 `GET /v1/regions` 的全量记录，34 个省级和 343 个市级、3255 个区县混在一张表里，
父子关系只能靠「区划代码 / 上级代码」两列自己脑补。用户反馈：「行政区划应该树状图展示，现在直接平铺了」。

## 为什么不能直接上全量树

`GET /v1/regions/tree` 是现成的，但实测不能用在管理页：

| 指标 | 实测值 |
| --- | --- |
| 区划总量 | 44,983 行（省 34 / 市 343 / 区县 3255 / 街道 41,351） |
| 全量 JSON 体积 | 约 12.1 MB |
| 全量查询耗时 | 约 650 ms（还没算 `buildRegionTree` 的 O(n²) 递归组装） |

一次性塞给前端既卡接口又卡浏览器，因此采用**懒加载树**：展开哪层查哪层。

## 改动文件

### 后端

| 文件 | 类型 | 说明 |
| --- | --- | --- |
| `src/modules/system/region/region.service.ts` | 修改 | 新增 `stats()`：一条 `GROUP BY level` 查出总数与各层级数量；新增 `RegionStats` 接口类型 |
| `src/modules/system/region/region.v1.controller.ts` | 修改 | 新增 `GET /api/v1/regions/stats`（登录即可访问，不加 `@Perms`） |

`stats` 接口存在的意义：树形懒加载后前端手上只有当前展开的节点，拿不到「共多少条」。
为了显示一个总数去拉 12 MB 全量不合理，用 group by 一条 SQL 解决（响应约 80 字节）。

**路由顺序**：`@Get('stats')` 必须声明在 `@Get(':id')` 之前，否则 `/regions/stats` 会被 `:id` 吃掉当成 id 查详情。

### 前端

| 文件 | 类型 | 说明 |
| --- | --- | --- |
| `src/features/system/region/api.ts` | 修改 | 新增 `RegionStats` 类型与 `fetchRegionStats()` |
| `src/features/system/region/index.tsx` | 重写 | `DataTable` 平铺改成手写树表（与部门管理同风格）：懒加载展开、层级缩进、层级徽标、搜索平铺、静默刷新 |

移除了 `DataTable` / `DataTablePagination` / `DataTableViewOptions` 依赖：树形数据没有分页语义，列显隐也失去意义。

## 页面行为

- **初始**：只请求 `GET /regions/children/0`（34 个省级）+ `GET /regions/stats`，表格 34 行，每行前有展开箭头。
- **展开**：点箭头 → `GET /regions/children/:areaCode`，结果写入 `childMap[areaCode]` 缓存，收起再展开不重复请求。
- **展开省级**：一键并发拉 34 个省的子级并全展开（约 377 行），用来快速确认树形结构。
- **收起全部**：清空 `expanded`，缓存保留，再次展开是瞬时的。
- **搜索**：关键字/层级变化后防抖 300 ms 走 `GET /regions`，结果**平铺**展示并关闭展开箭头。
  搜索结果跨层级，强行套树会把命中的子孙藏起来；超过 200 条只渲染前 200 条并提示细化关键字。
- **刷新**：静默刷新（不闪骨架屏、不丢展开状态），重新拉根节点 + 所有已展开节点的子级。
- **保存 / 删除 / 导入后**：走同一个静默刷新，树不会被重置回收起状态。

## 数据事实（导入的真实区划库）

- 全部 44,983 个节点从 `parentCode='0'` 出发都可达，**无孤儿节点**（不会出现树里看不到、只能搜索才找得到的区划）。
- 单节点最多 52 个直接子级（重庆万州区），懒加载一屏内可接受。
- 有 77 条「跳级」数据：东莞、中山这类不设区的地级市，街道/镇直接挂在市级下面（`level` 1 → 3）。
  前端判断是否还有下级用的是 `level < 3`，跳级数据仍能正常展开；`level=3` 之后不会再加载（数据里也没有 level 4）。

## 坑

1. **`level < 3` 判断可展开**：不能假设父级 level 一定是子级 level - 1（上面 77 条跳级数据），
   所以只按「最大层级 3」封顶，不按父子层级差推断。
2. **`expandedRef` 而不是依赖 `expanded`**：`loadTree` 若把 `expanded` 放进依赖数组，每次展开节点都会重建
   callback → 触发 `useEffect(loadTree)` → 整棵树重载。用 ref 读最新值、依赖数组留空。
3. **`hasChildren` 需要「已加载但为空」的分支**：`children ? children.length > 0 : node.level < 3`，
   否则加载到空数组的节点会一直显示可展开箭头，点了只出现「暂无下级区划」。
4. **搜索结果不显示箭头**：`renderRows(nodes, depth, expandable)` 第三个参数控制；
   搜索结果是扁平数组，箭头点了也拉不到子级（子级不在结果集里）。
5. **`stats` 里的 COUNT 是字符串**：MySQL 驱动返回 `count` 为 string，必须 `Number()` 转换再做累加。

## 如何扩展

- **加到「街道」层**：`level` 已经封顶 3，要支持更细层级需同时改后端 `REGION_LEVELS` / `REGION_LEVEL_TEXTS` 和前端 `LEVEL_TEXTS`、`LEVEL_BADGE`。
- **树里直接新增下级**：`RegionFormDialog` 现在靠三级级联选上级，若要支持「在某节点下新增」，
  给它加一个 `parentCode` 入参预填级联即可（参考 dept 的 `createParentId`）。
- **区划树缓存到 Redis**：区划是低频变更的基础数据，可在 `listChildren` 外层加短 TTL 缓存；
  注意导入后要主动失效，否则前端刷新拿到旧层级。
