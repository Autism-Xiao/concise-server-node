# 角色管理归属分组展示 + 归属筛选

| 项 | 内容 |
|---|---|
| 日期 | 2026-11-13 |
| 仓库 | concise-admin（文档按惯例登记在本仓库） |
| 触发 | 用户问「角色管理 admin 登录和多租户怎么区分，全部混在一个列表里好吗，有没有更方便的方案」→ 给 4 个方案让用户选 → 选「分组展示 + 归属筛选」 |

## 背景

每个租户一套 admin/editor/viewer 模板（`sys_role` 唯一键 `(tenant_id, role_code)`，设计如此），平台管理员以平台视角登录会看到所有租户的角色混排（当前 10 个），唯一区分手段是角色名下一行灰色小字「租户：XXX」，信息太弱、像重复数据。

**先讲清一个事实**：租户隔离数据层早就有了——列表接口挂 `applyTenantScope`，普通租户用户从来只看到「本租户 + 平台共享」；admin 切到具体租户（顶栏切换器）也只剩该租户角色。乱只乱在「平台视角」的展示。

## 每个东西是干什么的

**DataTable 分组能力（可选，不影响其他页面）**：

- `groupOf(row)` → 组 id；组顺序按数据首次出现顺序（所以想让平台共享排最前，在数据层排序即可）；
- `groupLabel(groupId)` → 组头内容；组头行是灰色背景条 + 折叠箭头 + 项数，点击折叠/展开（组头显示「已折叠 N 项」）；
- 组头行 colSpan 全宽，不参与列对齐，也不加 sticky——横向滚动时整行滚走属正常；
- 序号保持全局连续（组头不占号）；折叠只影响显示，不影响勾选与分页。

**角色页**：

- 搜索栏旁新增「归属」下拉：全部归属 / 平台共享 / 各租户（选项从数据动态生成）；
- 分组排序：平台共享（tenantId=0）排最前，租户间按名称中文排序，组内保持创建时间顺序；
- pageSize 10 → 50：角色是全量小表，避免分组跨页重复出组头；
- 副标题跟随筛选状态：「共 10 个角色」/「筛选出 N 个角色（全部共 10 个）」；
- 角色名下的小字「租户：XXX」保留——分组被折叠或用户用「列显示」隐藏列时兜底。

## 遇到的坑

1. **组头行与 sticky 操作列的关系**：组头行是单一 colSpan 单元格，如果也给 sticky 类，组头会横跨到底——干脆不给 sticky，行为与预期一致。
2. **分页与分组的相互作用**：分组作用于「当前页行模型」，pageSize 太小会跨页重复组头；角色页 pageSize 放大到 50 规避。其他页面若要用分组也要注意这一点。
3. **前端 Role 类型一直没有 tenantId**：后端实体一直返回该字段，前端类型漏写——加类型前分组只能靠 tenantName 兜底，这次顺手补上。

## 验证

- 无头 Chrome 实测：分组组头（平台默认租户 4 项 / 深圳 3 项 / 长沙 3 项）、折叠后组头显示「已折叠 4 项」且序号连续、归属下拉选项动态生成、选深圳后只剩该组且副标题变「筛选出 3 个角色（全部共 10 个）」；
- `tsc --noEmit`、ESLint、`pnpm build` 通过。

## 怎么扩展

- 其他列表页想按某维度分组：数据按组排好序 → `groupOf={(row) => row.xxx}` + `groupLabel={(id) => ...}` 两个 prop 即可，无需动 DataTable；
- 组头文案/样式想调整：`groupLabel` 返回任意 ReactNode；折叠逻辑内聚在 DataTable，无需外部状态。
- 提醒：普通租户用户登录看到的角色列表本来就是「本租户 + 平台共享」，不会混排；本方案优化的是平台管理员的视角。
