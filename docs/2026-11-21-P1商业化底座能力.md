## 二、每项作用与关键决策

### 1. 租户级配额

- 参数：`tenant.quota.maxUsers`、`tenant.quota.maxStorageMb`，平台行给默认值 `0`（不限制），租户可覆盖，升级后存量行为不变。
- **用户数口径**：`sys_user_tenant.status=0` JOIN `sys_user.del_flag=0`；`login_tenant_id` 只是上次登录选择，不能当归属。
- **存储口径**：`sys_file` 中严格 `tenant_id=本租户`、`is_deleted=0`、`is_folder=0` 的 `size` 之和。个人配额用 `applyTenantScope`（含共享行 0），租户配额刻意不含共享行。
- 挂载点只有三个：`UserService.create`、`TenantService.assignUsers`（按实际新增数，已存在成员不重复占额）、`FileService.upload`。旧 `/v1/upload`（`tool_storage`）不参与，敏感文件必须走文件中心。
- 平台视角（`tenantId<=0`）不判配额，避免把平台共享数据算进某个租户。

### 2. 租户维度限流

- `@RateLimit({ by: 'tenant' })`：key 为 `rl:{route}:t{tenantId}`，**刻意不带 IP**，同租户所有成员/出口共用一个桶，这才是租户级配额语义。
- 匿名 / 平台视角（`null` / `0`）自动回退 IP 维度，否则全站匿名流量并进一个桶会形成新 DoS 面。
- 全局可用 `RATE_LIMIT_BY=tenant` 切换；`account` 维度仍不开放为全局默认——Guard 在 JWT 之前，拿不到登录用户（`auth.v1.controller.ts` 的旧注释依旧成立）。

### 3. 用量计量

- 选 MySQL 原子 upsert 而不是 Redis INCR：本地/CI 默认关闭 Redis，且用量要能当账单底稿。
- 内存攒批 30 秒 / 500 键刷一次，进程正常退出再刷；`GET /v1/metering/usage` 查询前主动 flush，管理端看到的是当前值。
- 指标：`api.calls`、`api.errors`（全局）、`file.upload.count`、`file.upload.bytes`（文件中心）。
- 强杀进程最多丢一个窗口，适合展示与超额告警；精确计费仍需对账业务表。

### 4. 字段级脱敏

- 新权限点 `data:sensitive:view`：租户模板 admin/editor 会拿到（后缀 `view` 不在危险名单），viewer 拿不到（只读白名单不含 `view`）。存量租户须跑一次 `POST /v1/tenants/provision-all`。
- 判定与 `PermsGuard` 同口径：角色权限集合 ∩ 租户套餐权限，平台管理员 bypass，应用令牌无角色一律脱敏；缓存异常 fail-closed。
- **返回「移除字段 + `maskedFields` 标记」而不是打码字符串**：前端编辑表单直接用列表行回填，打码值会被原样 PUT 回后端覆盖真实数据（手机号是字符串还能写进去，金额会 400）。
- 前端据此显示 `••••••`、禁用输入框，并在提交时再剔除一次，双保险。

## 三、踩的坑

1. **viewer 没有 `customer:update`**：最初用 viewer 验证"编辑不覆盖原值"得到 403，误以为脱敏坏了。改为在冒烟里临时造「有 list/update、无敏感权限」的角色。
2. **角色表没有 `del_flag`**：`sys_role` 软删字段不存在，脚本查询要改用 `status=1`。
3. **配置接口漏传 token**：`PUT /v1/configs` 返回「未授权」，脚本断言误报配额失效；所有管理端调用都要带 Bearer。
4. **CI 数据库口令不同**：本地 `123456`、CI 是 job 级 `DB_PASSWORD=root`，CI 步骤必须显式传 `SMOKE_DB_PASSWORD`。
5. **前端 `format:check` 有 88 个既有告警**，包含本轮改的 4 个 tsx（它们原本就不符合该规则）；`lint` / `build` 通过，未做全量格式化以免扩大改动面。
6. **提交风险**：上一轮 lint-staged 曾误带工作区里的 SQL 备份删除，本轮提交前逐项核对 `git status`，只 add 本轮文件。

## 四、如何扩展

- **加配额项**：迁移里插新 `tenant.quota.*` 平台行 + `DEFAULTS` + `QuotaService` 新方法 + 业务写入口调用；默认 0 保证灰度安全。
- **加指标**：任意服务注入 `MeteringService`，`record('xxx.yyy', delta)` 即可；展示自动出现在 usage 接口。
- **给其它实体脱敏**：controller 上加 `@Sensitive('字段名')`，前端按 `maskedFields` 显示；导出接口是 `StreamableFile`，拦截器管不到，需在 rows 映射里手写脱敏。
- **换限流维度**：接口级 `@RateLimit({ by })` 优先，全局 `RATE_LIMIT_BY` 兜底；新维度同时改 `RateLimitOptions['by']` 与 `buildRateLimitKey`。
