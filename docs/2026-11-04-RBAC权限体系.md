# 变更说明：RBAC 权限体系（roles / menus + 全局守卫）

> 日期：2026-11-04 ｜ 提交：`（本次）`

中后台核心权限模型打通：**用户 → 角色 → 菜单（权限）** 三级关联，接口层由两个全局守卫把关。

## 权限模型

```
user ──(user_roles)── role ──(role_menus)── menu
                        │                     ├── type 0 目录 / 1 菜单 / 2 按钮
                        │                     └── permission 权限标识（如 system:user:list）
接口鉴权：JwtAuthGuard（认证）→ RolesGuard（@Roles 角色匹配）
前端动态路由数据源：GET /api/menus/tree（按角色分配）
```

## 接口一览（新增 11 个，全部带 Swagger 文档）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET/POST | `/api/roles`、GET/PUT/DELETE `/api/roles/:id` | admin | 角色 CRUD（创建/更新可带 menuIds） |
| PUT | `/api/roles/:id/menus` | admin | 为角色绑定菜单（全量覆盖） |
| GET | `/api/menus/tree` | admin | 菜单树（前端动态路由数据源） |
| GET/POST | `/api/menus`、GET/PUT/DELETE `/api/menus/:id` | admin | 菜单 CRUD |
| PUT | `/api/users/:id/roles` | admin | 为用户绑定角色（全量覆盖） |

## 实测结论（8 项全过）

1. admin 访问 `@Roles('admin')` 接口 → 200
2. admin 创建无角色用户 guest → 200
3. **guest 访问 admin 接口 → 403 Forbidden**
4. guest 访问自己的 profile（无角色要求，登录即可）→ 200
5. admin 创建角色 editor → 200
6. 菜单树返回「系统管理 → 用户管理」正确层级
7. 角色绑菜单 → 返回带 menus 的角色
8. 无 token → 401

## 遇到的坑（已解决）

1. **UserModule 未引入 RoleModule**：UserService 注入 RoleEntity 仓库启动报错——跨模块用仓库需 imports 对方模块
2. **TypeORM `findOne` 同时用 `relations` + `select`** 会生成坏的 distinct 别名（`Unknown column 'distinctAlias.UserEntity_id'`）——改用 QueryBuilder 的 `addSelect` + `leftJoinAndSelect` 解决
3. 守卫注册后别忘了给 login/refresh/根路由标 `@Public()`，否则自己人打自己人

## 数据现状（测试数据）

- 角色：admin（绑 2 个菜单）、viewer、editor（绑 2 个菜单）
- 用户：admin（admin 角色）、guest（无角色，密码 guest123）
- 菜单：系统管理（目录）→ 用户管理（菜单，permission=system:user:list）
