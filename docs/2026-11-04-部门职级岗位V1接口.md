# 部门/职级/岗位管理 V1 接口

> 日期：2026-11-04
> 仓库：concise-server-node

## 背景

三个模块按既定套路补齐：
- **部门**：`sys_depart` 已存在（jeecg 设计），service 已有防环/软删/子级保护，本次只把 CRUD 迁到 `/api/v1/depts`
- **职级**：jeecg-boot 无原生职级表，按 jeecg 风格自建 `sys_level`（32 位字符串主键 + tenant_id + 审计四列）
- **岗位**：jeecg-boot 有原生 `sys_position`，对齐其结构（post_code/post_name/post_sort），补充 `dept_id`（所属部门）与 `status`

## 接口清单（V1）

### 部门 `/api/v1/depts`（admin，写操作带 system:dept:* 权限）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/depts/tree` | 部门树（children 递归） |
| GET | `/api/v1/depts?keyword=` | 全量扁平列表（排除已删除，keyword 模糊匹配名称） |
| GET | `/api/v1/depts/:id` | 详情 |
| POST | `/api/v1/depts` | 创建（orgCode 不传自动生成，如 A01/A01A01） |
| PUT | `/api/v1/depts/:id` | 更新（换父防环；orgCode 变更同步刷新用户 org_code） |
| DELETE | `/api/v1/depts/:id` | 软删除（有子部门或挂用户时拒绝） |

### 职级 `/api/v1/levels`（admin，写操作带 system:level:* 权限）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/levels?keyword=` | 列表（level_rank 降序=级别从高到低） |
| GET | `/api/v1/levels/:id` | 详情 |
| POST | `/api/v1/levels` | 创建（levelName 唯一） |
| PUT | `/api/v1/levels/:id` | 更新（改名校验唯一） |
| DELETE | `/api/v1/levels/:id` | 删除（硬删，暂无关联数据） |

Body：`{ "levelName": "P6", "levelRank": 6, "status": "1", "remark": "高级工程师" }`

### 岗位 `/api/v1/posts`（admin，写操作带 system:post:* 权限）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/posts?keyword=&deptId=` | 列表（post_sort 升序，带所属部门；支持部门过滤） |
| GET | `/api/v1/posts/:id` | 详情 |
| POST | `/api/v1/posts` | 创建（postCode 唯一；deptId 必须存在且未删除） |
| PUT | `/api/v1/posts/:id` | 更新（改编码/换部门同上校验） |
| DELETE | `/api/v1/posts/:id` | 删除（硬删，暂无关联数据） |

Body：`{ "postCode": "dev_engineer", "postName": "研发工程师", "deptId": "dept_1", "postSort": 1, "status": "1", "description": "..." }`

## 验证结果

服务层全用例实测通过：

- 职级：创建/重复名拦截/更新/列表过滤/删除 ✓
- 岗位：创建带部门/重复编码拦截/不存在部门拦截/更新/列表带部门名/删除 ✓
- 部门：树组装/创建自动 orgCode(AA03)/父级=自身拦截/软删 ✓

## 踩坑

- **collation 冲突（ER_CANT_AGGREGATE_2COLLATIONS）**：新表按惯性写成 `utf8mb4_general_ci`，库内既有表（sys_depart/sys_user）是 `utf8mb4_unicode_ci`，ManyToOne JOIN 直接报错——新表必须跟库内既有表对齐 collation，迁移已改为 unicode_ci 并 ALTER 修正存量表
- **node -e 跑不了 NestFactory**：`node -e` 下 `require('@nestjs/core')` 行为异常（createApplicationContext 缺失），验证脚本一律写成临时 .cjs 文件执行
- 上一轮中断残留的测试数据会干扰重跑，重测前先按名称清理
