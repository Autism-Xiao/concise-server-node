# 供应商菜单补录 + 生成器菜单自动化

## 背景

上一轮代码生成器只产出**代码**（entity/service/controller + 前端页面/路由/page-registry），但没产出**菜单数据**——侧边栏是动态菜单（读 `sys_permission`），没录入就看不到「供应商管理」入口。路由本身一直在：`/system/suppliers`。

## 改动清单

| 文件 | 类型 | 说明 |
| --- | --- | --- |
| `src/migrations/1794220000000-GenSupplierMenu.ts` | 新增 | 补录菜单：`menu_supplier`（供应商管理，协同办公下第 4 项，perms=supplier:list）+ 3 个按钮（add/update/delete）；down 级联清理 role_permission 关联 |
| `scripts/gen-module.cjs` | 修改 | 迁移模板自动带上菜单 INSERT（页面节点 + 3 按钮，id 前缀 `menu_<module>`）与 down 清理；页脚说明从「三件事」减为「两件事」（不再需要手动录菜单） |

## 遇到的坑

- 生成器第一版把菜单留给「菜单管理手动录入」，demo 页面因此成了「有路由无入口」；动态菜单架构下**新页面上线必须配菜单数据**，这条已固化进生成器。
- 菜单 id 前缀用 `menu_<module>`（如 menu_supplier），down 用 `LIKE 'menu_<module>%'` 级联删按钮，不用逐个列 id。

## 怎么扩展/使用

- 以后 `node scripts/gen-module.cjs ...` 生成新模块：跑完 `migration:run` + 退出重登即可见页面入口；想挪菜单位置，在菜单管理里改 parent 即可。
- `menu_collab`（协同办公）只是 demo 惯例挂载点，真实业务模块自行调整。

## 验证

- `migration:run` 成功；`sys_permission` 中 4 行（1 页面 + 3 按钮）确认落库，url=/system/suppliers、perms 与控制器 @Perms 一致。
- 超管默认全可见（withHomeMenu/超管分支不走 role_permission），无需额外授权；其他角色按需在角色授权里勾选。
