# 登录锁定提示 / 锁屏记住密码 / 水印权限收紧

日期：2026-11-07
涉及仓库：`concise-server-node`（后端）、`concise-admin`（前端）

## 一、需求原文与落地口径

| 用户诉求 | 落地做法 |
| --- | --- |
| 1. 锁屏的时候记录密码也存在（每次都要手动输入） | 登录页「记住密码」的凭证抽成公共模块，锁屏页按当前账号读出来**自动填充**，点一次「解锁」即可；同时补 `autocomplete="current-password"`，让浏览器密码管理器也能填 |
| 2. 输入错误没有提示，5 次后要锁定到 24 才能解冻 | 后端每次密码错误都返回「还可尝试 N 次」，第 5 次返回 429 + `ACCOUNT_LOCKED` + 「已锁定 1 天，到期自动解冻，或联系管理员提前解锁」；前端登录页/锁屏页常驻展示，锁定后禁用输入 |
| 3. 设置水印只有 admin 有 setting 可以自由开关，剩下的由 admin 对每个用户设定 | 服务端 `PUT /users/me/watermark` 只有超管可调，非超管 `editable=false` 且带原因；前端「水印策略」入口按权限显示、配置抽屉里普通用户只能看状态，逐人开关走「用户管理 → 水印」 |

### 1. 失败计数与提示

- 阈值仍是 `LOGIN_MAX_FAILS`（默认 5），锁定时长 `LOGIN_LOCK_HOURS`（默认 24 小时），都可用环境变量覆盖。
- 第 N 次（N<5）错误：HTTP 401 + `code=1007` +「用户名或密码错误，还可尝试 `5-N` 次（连续错误 5 次将锁定 1 天）」。
  登录场景保留「用户名或密码错误」的模糊措辞，不暴露账号是否存在；锁屏场景（账号已确定）直接说「密码不正确」。
- 第 5 次：HTTP 429 + `code=1009` +「密码错误次数过多，账号已锁定 1 天，到期自动解冻，或联系管理员提前解锁」。
- 锁定期内任何尝试（含密码正确）都被 `assertNotLocked()` 拦下并告知剩余时长。
- 管理员解锁：`DELETE /api/v1/users/:id/lock`（前端「用户管理 → 更多 → 解锁登录」），清零计数、幂等。

### 2. 水印权限

- `GET /users/me/watermark`：任何人都能读自己的生效配置；`editable` 现在**同时**要求「超管」+「当前策略允许」。
- `PUT /users/me/watermark`：非超管 403，文案「水印由管理员统一设置，如需调整请联系管理员」。
- `PUT /users/:id/watermark`：保持 `system:user:update`（管理员逐人设定 `enforced` 0/1/2）。
- `GET|PUT /system/watermark`：保持 `system:watermark:edit`（全局策略，可授予安全管理员角色）。

### 锁屏自动填充的取舍

- 只填充「登录时勾过记住密码」的账号，并且必须与当前登录用户名匹配（同机换人登录后不会填上一个人的密码）。
- 不自动解锁：仍然要用户点一次「解锁」。锁屏防的是「人离开座位被顺手操作」，点一下按钮的成本很低，但能挡住路过的人。
- 本地存储仍只是 base64（不是加密）—— 这是原「记住密码」就有的取舍：同源脚本本来就能读 localStorage，勾选时应当清楚「公共设备不要勾」。

## 四、踩坑记录

1. **锁屏不能用 401**：`getApiResult` 把 401 统一当「登录过期」强制登出，所以 `verify-password` 未锁定必须用 400，只有锁定才用 429。
2. **锁定文案的时长格式**：`formatLockDuration(86400)` 输出「1 天」而不是「24 小时」，断言要么同时接受两种写法，要么按 `1 天` 写。
3. **登录页 toast 不够**：错误信息一闪而过，用户根本看不清「还剩几次」，必须再加一条常驻错误条。
4. **`dist` 瞬时缺失**：`nest build` 的 `deleteOutDir` 会先清空再写入，紧接着启动进程会报 `Cannot find module dist/main.js`，等构建结束后再启动即可。
5. **3461 冒烟实例**：必须用后台任务方式启动（`PORT=3461 CAPTCHA_ENABLED=false node dist/main.js`），`(... &)` 子 shell 退出后进程会被回收。

## 五、怎么用 / 怎么扩展

- 调整锁定策略：改 `.env` 的 `LOGIN_MAX_FAILS` / `LOGIN_LOCK_HOURS` 后重启；前端文案会跟随后端下发，不需要同步改代码。
- 需要「只记住账号不记住密码」：登录页取消勾选即可（会立即 `clearRemember()`）；锁屏页则退回手动输入。
- 需要给某个用户开/关水印：用户管理 → 行内水滴按钮 → 选「强制开启 / 强制关闭 / 跟随全局」。
- 需要把「逐人设定」变成批量：现有 `PUT /users/:id/watermark` 可循环调用；后续可在用户列表加多选批量入口（复用 `BatchRolesDialog` 的交互）。
- 若以后要让非超管的「安全管理员」也能自管水印：把 `WatermarkService.resolve/updateMine` 里的 `hasSuperRole` 换成权限码判断（例如 `system:watermark:edit`）即可，判定出口只有这两处。
