# 通知公告导入（仅导入，不做导出）

日期：2026-11-05
需求：“通知公告导入就行”——公告模块只做导入，不提供导出。

## 一、接口清单

| 方法 | 路径 | 权限码 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/v1/notices/import-template` | `system:notice:import` | 下载导入模板（xlsx） |
| POST | `/api/v1/notices/import` | `system:notice:import` | multipart 上传，字段名 `file`，≤5MB / ≤1000 行 |

两个接口都在 `NoticeV1Controller` 里，位置在 `GET /:id` **之前**，避免 `import-template`、`import` 被 `:id` 路由吃掉。

> 之前一度实现了 `GET /v1/notices/export`，按“只要导入”的要求已删除，同时删掉了 `menu_77（公告导出）` 权限和 `sys_permission` 里的对应行。

## 二、导入规则

1. **匹配依据是标题**：标题（大小写不敏感、去首尾空格）已存在 → 更新该条；不存在 → 新增。
   - 文件里若带「编号」列（例如手工 CSV），仍优先按 id 精确命中，属于兼容能力，模板里不再提供这一列。
2. **更新只覆盖填了值的列**：类型/优先级/状态/通告对象/生效时间/指定用户/内容留空 = 不改动原值；「内容」留空不会把正文清空。
3. **状态语义**：
   - 填「已发布」且原来不是已发布 → 补 `send_time`、`sender`（当前导入操作人），清 `cancel_time`；
   - 填「未发布」→ 清 `send_time`、`cancel_time`，回到草稿；
   - 填「已撤销」→ 记 `cancel_time`；
   - 新增时留空按「未发布」处理，避免一个空格把公告发到线上。
4. **通告对象**：`全体用户` / `指定用户`；填「指定用户」时必须在「指定用户」列写登录账号或姓名（多个用 `/ , 、 ; |` 分隔），解析不到任何账号即整行失败。
5. **时间**：支持 `2026-01-01`、`2026-01-01 08:00`、`2026/01/01`、ISO 8601；填了但解析不出来 → 整行失败（不静默当空）；开始时间晚于结束时间也报错。
6. **同一份文件内标题不能重复**：重复行计入 `skipped` 并给出行号，不会互相覆盖。
7. **单行失败不影响其它行**，逐行统计返回。

## 三、返回结构

```json
{
  "code": 0,
  "result": {
    "total": 4,
    "created": 1,
    "updated": 0,
    "skipped": 1,
    "failed": 2,
    "errors": [
      { "row": 12, "title": "QA 时间非法", "message": "生效开始「2026-13-01」不是有效日期，请用 2026-01-01 或 2026-01-01 08:00 格式" },
      { "row": 13, "title": "QA 指定用户不存在", "message": "指定用户不存在：nobody999（请填登录账号或姓名）" },
      { "row": 14, "title": "QA 公告导入测试", "message": "文件内标题重复，本行已跳过（同一条公告只能出现一次）" }
    ]
  }
}
```

`row` 是 **Excel 左侧的真实行号**（模板标题在第 1 行、说明 2~8 行、表头第 10 行、数据从第 11 行开始），前端展示时直接说“第 12 行”即可对上。

## 五、模板设计

`buildImportTemplateXlsx`（`src/utils/xlsx.util.ts`）统一生成：

- **第一个工作表「公告导入」**：第 1 行大标题；2~8 行填写说明；第 10 行表头（必填列用 richText 加 `*`，hint 落成单元格批注）；之后是空数据行。
- **第二个工作表「填写示例」**：两条示例（全体用户已发布 / 指定用户未发布），只读第一个工作表，所以示例不会被误导入。

九列：标题* / 类型 / 优先级 / 状态 / 通告对象 / 指定用户 / 生效开始 / 生效结束 / 内容。

## 六、踩过的坑

1. **路由顺序**：`@Get('import-template')` 必须写在 `@Get(':id')` 之前，否则会被当作 id 查询，报“公告不存在”。
2. **表头定位**：模板表头是 richText（`标题` + 加粗黄色 ` *`），`cell.text` 读出来是「标题 *」。`readXlsxTable({ headerKeys })` 定位前会剔掉 `\s * ＊`，否则永远匹配不上。
3. **行号**：必须用 `eachRow` 的真实行号算偏移（`headerRowNumber + index + 1`），不能按数组下标，否则报错行号会比 Excel 少 9 行。
4. **清空字段要用 QueryBuilder**：`repository.update()` 会跳过 `undefined` 且不接受 `null`，“把发布时间清空”这类操作必须走 `.createQueryBuilder().update().set()`。
5. **`In` 导入**：删掉导出方法后 `In` 变成未使用，eslint 会拦（`no-unused-vars`），记得一起删。
6. **公告标题字段名是 `titile`**（jeecg 原始拼写），写原生 SQL 或 QueryBuilder 时别写成 `title`。

## 七、怎么扩展

- 加导入字段：在 `NoticeImportField`、`NOTICE_IMPORT_ALIASES`、`resolveImportColumns` 的映射里加一项，再在 `importNotices` 里读 `pick(cells, 'field')` 决定写入。
- 改模板列：只改 `downloadTemplate()` 里的 `columns` / `samples` / `notes`，导入侧按表头别名识别，列顺序可以随意调整。
- 想支持导出：把本次删掉的 `export` 方法按用户/角色导出的写法加回来，模板里再加「编号」列即可实现“导出→改→回导”闭环（服务层已保留按 id 命中的能力）。
