# 开通租户需要 VIP（自助开通团队）

- 日期：2026-11-17
- 类型：功能（商业化 SaaS 化）
- 关联：`2026-11-17-参数配置租户化.md`（额度参数复用 sys_config）、`2026-11-17-租户隔离收尾.md`

## 需求

- 普通账号：**进入系统可正常使用**（登录、业务、共享视图），不需要 VIP。
- 「开通租户」= 增值能力：**必须 VIP**，且受可开数量额度限制。
- VIP 由**平台管理员手动授予**；开通入口面向**所有登录用户自助**（成功即成为该租户管理员）。

## 关键设计

### 1. VIP 为什么落在用户上，而不是租户

开通租户时租户还不存在，所以不能用「租户套餐 = VIP」来表达资格。字段放在 `sys_user`：

| 列 | 说明 |
|---|---|
| `vip_level` | 0 普通 / 1 VIP |
| `vip_expire_at` | 到期时间；NULL = 永久；过期只影响**新开通** |

平台管理员（`is_platform_admin=1`）天然免检、不限额度（本来就能在租户管理里直接建）。

### 2. 额度口径：按「自己开通的团队」计数

`sys_tenant.owner_user_id`（迁移 1794860000000）记录开通人；`applyQuota` 只数 `owner_user_id = 本人 AND del_flag = 0`。

**踩过的坑**：第一版数的是 `sys_user_tenant` 行数，结果新账号建号时自动加入默认租户 1，额度一开始就是 1/1，直接开不了。被邀请加入别人的租户不应消耗自己的额度，平台代开的租户 owner 为 NULL 也不占。

额度值来自 `sys_config.tenant.vip.maxTenants`（默认 1，平台级 `allow_tenant=0`，租户不可自调）。

### 3. 读回退与缓存

- 资格查询直接读库（VIP 是可交易状态，不吃 30s 配置缓存；额度参数走 `SystemConfigService`，30s 缓存可接受）。
- 开通成功后 `permissionCache.invalidateAll()` + `tenantAccess.invalidate()`：新角色授权与用户归属缓存立即失效。

## 接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/v1/tenants/apply/quota` | 登录即可 | `{ isVip, vipExpireAt, ownedCount, maxTenants, canApply, reason }`；reason：`'' / NEED_VIP / QUOTA_EXCEEDED`；平台管理员 maxTenants=-1 |
| POST | `/v1/tenants/apply` | 登录即可 | 校验 VIP + 额度后事务建租户；限流 10 次/小时（IP） |
| PUT | `/v1/users/:id/vip` | `system:user:vip`（scope=platform） | `{ vipLevel: 0|1, vipExpireAt?: 'YYYY-MM-DD' }`；平台管理员专用 |

错误码：`8104 TENANT_APPLY_NEED_VIP`（403）、`8105 TENANT_APPLY_QUOTA`（400），前端据此切升级/超限文案。

### 开通事务（applyCreate）

```
建 sys_tenant（plan=standard、owner_user_id=本人）
→ provisionIn 初始化 admin/editor/viewer 角色与授权
→ sys_user_tenant 加入本人
→ sys_user_role 绑该租户 admin
→ sys_user.login_tenant_id = 新租户
```

任一步失败整体回滚，不会留下「建了租户却进不去」的空壳；并发编码冲突由联合唯一键兜底转 8101。

## 踩的坑

1. **额度不能数归属关系**：建号自动加入默认租户，`sys_user_tenant` 计数一上来就是 1，必须用 `owner_user_id` 口径。
2. **限流的 `by: 'account'` 无效**：RateLimitGuard 在 Jwt 之前执行拿不到 `req.user`，实际只按 IP 计数；已改 10 次/小时并注释说明。
3. **路由顺序**：`GET apply/quota` 必须放在 `GET :id` 之前，否则被 `ParseIntPipe` 吃掉变 400。
4. **VIP 权限点必须 scope=platform**：否则持有 `system:user:update` 的租户管理员能给本租户的人发 VIP；前端 `hasPermission('system:user:vip')` 只在平台视角可见。
5. 冒烟压测过 5 次/小时后被自身限流挡下，排障时清 `rl:POST /api/v1/tenants/apply:<ip>` 即可。

## 如何扩展

- **VIP 发放方式**：目前平台手动授予；后续可加激活码/订单支付，只改「谁写 vip_level/vip_expire_at」，开通链路不变。
- **多档会员**：`vip_level` 从 0/1 扩成枚举后，额度改读「按等级取参数」即可（`tenant.vip.maxTenants.<level>`）。
- **租户详情展示开通人**：`owner_user_id` 已在表里，租户管理列表加一列/筛选即可。
- **前端可选增强**：切换器入口显示「已开通 N/M」；VIP 即将到期提示。
