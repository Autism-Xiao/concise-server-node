### 2. 后端接口清单

统一约定：导出 `GET .../export`（透传列表筛选条件）、模板 `GET .../import-template`、导入 `POST .../import`（multipart，字段名 `file`）、批量删除 `POST .../batch-delete`（body `{ ids }`）。

| 模块 | 新增接口 | 权限点 |
| --- | --- | --- |
| 层级 | `GET /v1/levels/export`、`/import-template`、`POST /import`、`POST /batch-delete` | `system:level:export/import`（删复用 delete） |
| 岗位 | `GET /v1/posts/export`、`/import-template`、`POST /import`、`POST /batch-delete` | `system:post:export/import` |
| 字典 | `GET /v1/dicts/export`、`/import-template`、`POST /import`、`POST /batch-delete`、`POST /v1/dict-items/batch-delete` | `system:dict:export/import` |
| 部门 | `GET /v1/depts/export`（带完整路径）、`POST /batch-delete` | `system:dept:export` |

## 二、关键设计选择

1. **批量删除仍然逐条执行，不是一条 SQL 全删**
   目的：保住各模块自己的业务保护规则（部门有子部门不能删、角色下有人不能删、公告已发布不能删、admin 不能删）。`runBatchDelete` 把每条失败原因收集回来，前端一次请求就能告诉用户「哪几条为什么没删掉」。

2. **字典导入做双工作表，靠 `dictCode` 关联**
   `字典类型` 与 `字典项` 两张表可以只填一张；类型先落库，项再按 `dictCode` 找字典。导出的文件列与导入模板完全一致，**导出 → 改 → 再导回**能闭环。

3. **软删的字典命中时恢复而不是报错**
   `dict_code` 唯一索引不区分 `del_flag`，若按「已存在就跳过」处理，用户永远导不进同名编码。导入逻辑改为：命中已软删的字典 → `del_flag=0` 并更新。

4. **模板里不放示例数据行**
   模板只放空行 + 说明文字（示例写进 notes），避免用户直接导入把示例数据落库。

## 三、踩到的坑

| 坑 | 现象 | 处理 |
| --- | --- | --- |
| `manager.save` 不生成字符串主键 | 字典项导入 500，`id` 为 NULL 触发主键约束 | 显式 `id: randomId32()`；BaseService.create 才有自动补 id 的逻辑 |
| 双表导入时单表可能为空 | 只填字典项时被 `assertImportRows` 判定「没有数据行」 | 新增 `assertImportLimit`（只校验上限），全文件无数据时统一报「没有可导入的数据行」 |
| 同一模块多个 `@Get` 路由顺序 | `GET export` 若写在 `@Get(':id')` 之后会被当成 id | 所有 `export` / `import-template` 一律放在 `:id` 之前 |
| 前端 `tsc --noEmit -p tsconfig.json` 与 `tsc -b` 结果不同 | 单独 typecheck 通过，`npm run build` 报错 | 以 `npm run build`（`tsc -b`）为准，最终验收跑一次完整构建 |
| 批量删除 DTO 文案 | 在线用户场景下「请选择要删除的数据」读起来别扭 | 统一改为「请选择要操作的数据」 |

## 四、怎么扩展到下一个模块

四步，以「新增一个 XXX 管理」为例：

1. **后端 service**：加 `exportXxxs(query)`（`slice(0, 5000)`）、`importXxxs(rows, headerRow, operator)`、`batchDelete(ids)`。
   导入直接抄 `level.service.ts`：`resolveImportLayout` → 循环 `pickCell` → `failImportRow` → `createImportResult`。
2. **后端 controller**：`GET export` / `GET import-template` / `POST import` / `POST batch-delete`，全部放在 `@Get(':id')` 之前，各配 `@Perms` + `@OperLog`。
3. **菜单权限**：在 `scripts/seed-menus.cjs` 的 `BUTTONS` 追加两行（export / import），执行一次。
4. **前端**：api 加 `exportXxxs`（`downloadFromApi`）、`downloadXxxTemplate`、`importXxxs`（FormData）、`deleteXxxs`（`batchDeleteRequest`）；页面加三个按钮 + `<ExcelImportDialog>` + `ConfirmDeleteDialog`（批量）。

不需要新写的：表格勾选（`useDataTable` 的 `rowSelection`）、结果提示（`toastBatchResult`）、模板样式（`buildImportTemplateXlsx`）。

## 五、验收记录（PORT=3459，admin）

| 用例 | 结果 |
| --- | --- |
| 层级导出 / 模板 | 200，7.7KB / 10.3KB，中文文件名正常 |
| 层级导入 4 行（1 正常 + 1 重复 + 1 缺名称 + 1 等级非法） | `created:1, skipped:1, failed:2`，行号 3/4/5 与 Excel 对齐 |
| 层级批量删除（含不存在 id） | `deleted:1, failed:[]`（不存在的 id 静默忽略） |
| 岗位导入（1 正常 + 1 部门不存在） | `created:1, failed:1`，提示「所属部门「xxx」不存在，请先在部门管理中创建」 |
| 字典导入（2 类型 + 3 项） | `total:5`，项重复被跳过、孤儿项报「字典「xxx」不存在」 |
| 字典批量删除（有字典项） | `deleted:0`，失败原因「该字典下存在 1 个字典项，请先删除字典项」 |
| 公告批量删除（含已发布） | 失败原因「已发布的公告不能直接删除，请先撤销」 |
| 用户 / 角色 / 部门批量删除 | 分别返回「内置管理员账号不允许删除」「内置管理员角色不允许删除」「该部门下存在子部门，无法删除」 |
| 部门 / 菜单 / 定时任务导出 | 200，7.9KB / 11.8KB / 7.8KB |
| 在线批量下线（不存在会话 / 空数组） | `failed:[{reason:"在线会话不存在或已过期"}]` / 400「请选择要操作的数据」 |
| 无 token 访问导出 | 401 |
