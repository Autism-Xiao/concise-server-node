# 角色管理：状态开关列 + 列序调整（2026-11-07）

## 需求

对齐 jeecg 角色管理演示：① 角色列表加一列「状态」开关（表格内直接启停）；② 「角色名称」与「权限字符」两列换个位置（jeecg 里名称在编码前）。

## 后端（sys_role 加 status）

| 文件 | 说明 |
| --- | --- |
| `src/migrations/1794150000000-AddRoleStatus.ts` | `sys_role` 加 `status TINYINT NOT NULL DEFAULT 1`（1 正常 / 0 停用），hasColumn 幂等 |
| `entities/role.entity.ts` | `status` 列声明 |
| `dto/create-role.dto.ts` | `status?: number`（@IsIn [0,1]），update DTO 经 PartialType 继承 |
| `role.service.ts` | create 带默认 1；update 显式传入才改（沿用 dataScope 的「undefined 不动」约定）；**内置超管角色停用返回 400**；`listOptions` 过滤 `status=1`（停用角色不能再分配给新用户） |
| `jwt.strategy.ts` | validate 里 `user.roles` 过滤掉停用角色 → RolesGuard 的 @Roles 匹配立即失效 |
| `auth.service.ts` | `getPermissions` 用过滤后的角色集合（角色码 + 菜单聚合）→ 停用角色在线用户侧边栏/按钮权限立即消失 |

「停用」语义贯通三处：**下拉不可选 / @Roles 失效 / 权限计算剔除**。超管（admin）角色禁止停用，避免把管理员全锁门外。

## 坑

- `toggleStatus` 直接写在组件里会被 `useMemo(columns, [permLoading, togglingId, toggleStatus])` 的 exhaustive-deps 抓住（每次渲染都是新引用）。改 `useCallback` 后又报依赖变化，最终方案：**连点守卫用 `useRef`，`useCallback([])`**，依赖数组干净。
- 内置 admin 停用要 400 拦在前端 + 后端双保险，前端 Switch 置灰只是体验层。
- 3459 常驻实例开了验证码（CAPTCHA_ENABLED），脚本联调登录会被 417 挡，测试走 `PORT=3461 CAPTCHA_ENABLED=false` 实例。
- 乐观更新失败回滚要用**行对象捕获的旧值**，不能用 `role.status` 之外的状态源。
