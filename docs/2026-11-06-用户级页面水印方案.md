# 用户级页面水印方案（设计稿，未落代码）

> 状态：待评审。本文取代 `2026-11-06-后端水印方案.md`（那份是图片水印，需求理解有误）。  
> 目标：水印的**开关与内容由后端按用户下发**，前端只负责画；admin 能管全局默认，也能单独管某个人。

---

## 一、需求复述与一处歧义

要做的是登录后覆盖全屏的**安全水印**（canvas 斜向平铺底纹），不是给图片打码。要解决的问题：

1. 现在水印只由前端控制，用户自己就能关掉，等于没有管控力；
2. 配置存在前端设置里，**全站共用一份**，跟登录的是谁没关系；
3. 水印内容里的用户名取自 localStorage、IP 由前端调外部接口取，都可被篡改。

「默认开关在 admin」有三种理解，本方案按 **(b)** 实现，并保留切到 (a)/(c) 的开关：

| 解读                            | 含义                 | 本方案如何覆盖                                        |
| ----------------------------- | ------------------ | ---------------------------------------------- |
| (a) admin 账号默认开、其他人默认关        | 只给管理员打水印           | 全局 `enabled=0` + 给 admin 单独一条 `enabled=1` 记录即可 |
| (b) **全局默认值由 admin 配置，新用户继承** | 管理端可改默认开关/内容，用户可覆盖 | 默认实现                                           |
| (c) 开关权限只归 admin，用户不能自己关      | 强管控                | 全局 `mode='forced'`，用户侧 `editable=false`        |

## 二、现状漏洞（改之前先确认这些）

| 环节  | 现状                                                               | 问题                                      |
| --- | ---------------------------------------------------------------- | --------------------------------------- |
| 开关  | `settings.watermark`，存 `/api/settings`（dev 是项目根 `settings.json`） | 全局共享一份；清缓存 / 换设备 / 换人登录都不变，谈不上"按用户"     |
| 内容  | `settings.watermarkContent`，支持 `{username}` `{ip}`               | 与用户无关，谁改都改全站                            |
| 用户名 | `getUsername()` 读 `localStorage['concise-user']`                 | 前端可随手改，水印写"张三"实际是李四                     |
| IP  | `usePublicIp()` 调外部服务                                            | 依赖外网、可被代理伪造、慢且可能失败                      |
| 密度  | `compact/default/loose` 三档 → tile 尺寸                             | 样式参数由前端定，用户可自行调稀到几乎看不到                  |
| 渲染  | `components/watermark.tsx`，canvas 平铺 + MutationObserver 防删       | 渲染层没问题，可复用；缺 opacity/rotate/fontSize 入参 |

**能力边界要说清楚**：页面水印天然防不住"会开 F12 的人"（删 DOM、截图后 P 图都能去掉）。后端化能拿到的是三件事——**配置不可绕过**（清了 localStorage 重登照样有）、**内容不可伪造**（IP/时间由服务端给）、**改动可审计**（谁在什么时候关的，有日志）。这是管控与溯源，不是 DRM。

## 三、数据模型

### 3.1 全局策略 `sys_watermark_setting`（单行，id 恒为 1）

```sql
CREATE TABLE sys_watermark_setting (
  id          TINYINT      NOT NULL DEFAULT 1,
  enabled     TINYINT      NOT NULL DEFAULT 1  COMMENT '全局默认开关(1开 0关)，新用户继承',
  mode        VARCHAR(16)  NOT NULL DEFAULT 'optional' COMMENT 'optional可自选/forced强制开/off全关',
  content     VARCHAR(200) NOT NULL DEFAULT '{username}' COMMENT '默认内容模板，支持占位符',
  density     VARCHAR(16)  NOT NULL DEFAULT 'default' COMMENT 'compact/default/loose',
  opacity     TINYINT      NOT NULL DEFAULT 8  COMMENT '不透明度百分比 4~30',
  rotate      SMALLINT     NOT NULL DEFAULT -22 COMMENT '倾斜角度',
  font_size   TINYINT      NOT NULL DEFAULT 14 COMMENT '字号 px 10~24',
  updated_by  VARCHAR(32)  NULL,
  updated_at  DATETIME     NULL,
  PRIMARY KEY (id)
) COMMENT '页面水印全局策略';
```

### 3.2 用户覆盖 `sys_user_watermark`

```sql
CREATE TABLE sys_user_watermark (
  user_id     VARCHAR(32) NOT NULL COMMENT 'sys_user.id',
  enabled     TINYINT     NULL COMMENT '1开 0关 NULL继承全局',
  enforced    TINYINT     NOT NULL DEFAULT 0 COMMENT '0不强制 1强制开 2强制关(仅admin可设)',
  content     VARCHAR(200) NULL COMMENT 'NULL继承全局',
  density     VARCHAR(16)  NULL COMMENT 'NULL继承全局',
  updated_by  VARCHAR(32) NULL,
  updated_at  DATETIME    NULL,
  PRIMARY KEY (user_id)
) COMMENT '用户级页面水印配置';
```

**为什么用 NULL 而不是写死值**：改全局默认时，没主动设置过的用户自动跟随；否则每次改默认都要批量刷全表。

**为什么用户表加一列不行**：`enabled/content/density/enforced` 四个字段 + 后续可能的样式扩展，塞进 `sys_user` 会让这个核心实体越来越肥，且水印是"偏好"不是"身份"。

### 3.3 生效优先级（`resolve()` 的唯一真相）

```
mode = 'off'                → 关（editable=false，用户改不了）
user.enforced = 2           → 关（管理员点名关，用户改不了）
user.enforced = 1           → 开（管理员点名开，用户改不了）
mode = 'forced'             → 开（全站强制，用户改不了）
user.enabled ?? global.enabled → 最终结果（editable=true）
```

`editable` 只有一个来源：**上面五条里有没有命中"用户改不了"的分支**。前端拿到 `editable=false` 就把开关置灰并给出原因，而不是偷偷忽略用户的点击。

## 四、接口契约

响应统一 `{ code, data, message }`（项目既有约定），下面只写 `data`。

### 4.1 当前用户读取（登录即可，无需按钮权限）

```
GET /api/v1/users/me/watermark
```

```json
{
  "enabled": true,
  "lines": ["张三", "10.0.0.8", "2026-11-06 21:59"],
  "density": "default",
  "opacity": 8,
  "rotate": -22,
  "fontSize": 14,
  "mode": "optional",
  "enforced": 0,
  "editable": true,
  "reason": null,
  "custom": { "enabled": null, "content": null, "density": null }
}
```

- `lines` 是**后端解析完占位符的最终文本**，前端只负责画，不再做任何字符串替换。
- `custom` 回填用户自己的原始设置，用于设置面板显示"跟随全局 / 已自定义"。
- `reason`：`editable=false` 时的原因文案，如 `管理员已强制开启` / `全局已关闭水印`，前端直接展示。

### 4.2 当前用户修改

```
PUT /api/v1/users/me/watermark
{ "enabled": false, "content": "{username} {date}", "density": "loose" }
```

**只接受这三个字段**，`opacity/rotate/fontSize` 一律不接受——否则用户把不透明度设成 0，等于关掉了水印，管控形同虚设。`ValidationPipe` 的 `whitelist` 会自动丢弃越权字段。

命中不可编辑分支时返回业务错误（HTTP 200 + 业务 code），文案用 `reason`，而不是静默成功。

### 4.3 admin 管全局

```
GET  /api/v1/system/watermark      @Perms('system:watermark:edit')
PUT  /api/v1/system/watermark      @Perms('system:watermark:edit')
{ "enabled": true, "mode": "optional", "content": "{username} {date}", "density": "default",
  "opacity": 8, "rotate": -22, "fontSize": 14 }
```

`mode='forced'` 与 `enabled=0` 语义重叠，校验上加一条：`enabled=0` 时强制 `mode='off'`，避免出现「开着但全局关」的自相矛盾状态。

### 4.4 admin 管单个用户（这就是"根据用户单独开关"）

```
PUT /api/v1/users/:id/watermark   @Perms('system:user:update')
{ "enabled": true, "enforced": 1, "content": "研发部·张三", "density": "compact" }
```

- `enforced=1/2` 是强管控档，命中后用户自己改不动；
- 传 `null` 表示恢复继承；
- 复用现有 `system:user:update` 权限，不新增权限点，减少菜单配置工作量。

### 4.5 列表与详情的联动

`GET /v1/users` 每行多返回两个字段，避免前端逐行再查一次：

```json
{ "watermarkEnabled": 1, "watermarkEnforced": 0, "watermarkEffective": true }
```

实现上必须 `leftJoin` 水印表一次取回，**不能**在 map 里逐条 `findOne`（200 行用户就是 200 次 SQL）。

### 4.6 占位符

| 占位符                 | 值                      | 来源                         |
| ------------------- | ---------------------- | -------------------------- |
| `{username}`        | 登录账号                   | 服务端                        |
| `{nickname}`        | 真实姓名                   | 服务端                        |
| `{dept}`            | 主部门名称                  | 服务端（已有 dept 关联）            |
| `{ip}`              | 客户端 IP                 | `req.ip`（`TRUST_PROXY` 已配） |
| `{date}` / `{time}` | `2026-11-06` / `21:59` | 服务器时间                      |
| `{userId}`          | 用户 id                  | 服务端                        |

规则：

|   |   |
| - | - |

- 多行用 `\n` 或 `|` 分隔，解析后为 `lines: string[]`；
- 模板为空 → 兜底 `[username]`；模板全是占位符但解析为空 → 同样兜底；
- 内容长度上限 200 字符，防止超长文本把前端 canvas 拖死；
- 未知占位符原样保留（`{foo}` 就显示 `{foo}`），不做静默丢弃，便于用户发现写错。

## 七、安全与审计

1. **越权字段**：`PUT /users/me/watermark` 只认三个字段，样式参数（opacity/rotate/fontSize）只有全局设置能改，防止"用户把水印调透明"。
2. **IDOR**：`PUT /users/:id/watermark` 必须走 `@Perms('system:user:update')`，不能让用户改别人的。
3. **内容注入**：水印走 canvas `fillText`，不碰 innerHTML，当前无 XSS 面。若将来支持富文本水印，必须转义。
4. **审计**：三个写接口都加 `@OperLog('水印设置')`，记录"谁把谁的水印关了"。这条日志是事后追责的关键，别省。
5. **超长内容**：200 字符硬限制，服务端截断 + 返回提示。
6. **IP 伪造**：`TRUST_PROXY` 默认 `false`（上一轮已修），别为了拿"公网 IP"把它开成 `true`，否则水印上的 IP 就是攻击者手填的。

## 八、性能

- 读路径：1 次 `sys_watermark_setting`（单行，可进程内缓存 60s）+ 1 次用户行，合计 1~2ms。**一期不做 Redis 缓存**——配置要求"改完立刻生效"，加缓存就要写失效逻辑，而收益不到 1ms，不划算。
- 写路径：`upsert` + `invalidate`（如果后续加了缓存）。
- 列表：`leftJoin` 一次取回，杜绝 N+1。
- 前端：登录后一次请求，结果放 context；不在每个页面重复拉。

## 九、上线顺序与回滚

1. **后端先上**：只新增接口与表，旧前端继续用本地设置，**零影响**（不像上次列表结构变更那种破坏性改动）。
2. 前端随后上：一次性切到后端数据源。
3. 回滚：前端回退版本即可；后端可把全局 `mode='off'` 让所有人无水印（保留接口）。
4. 旧数据：`sys_user_watermark` 为空 = 全部继承全局，无需迁移用户偏好（原本也没按用户存过）。

## 十、坑位清单

1. **路由顺序**：`GET /v1/users/me/watermark` 必须在 `GET /v1/users/:id` **之前**声明，否则 `me` 会被当成 id 去查库，返回「用户不存在」。这是 Nest 按注册顺序匹配的经典坑。
2. **DTO 类型**：`enabled` 是 `1/0` 还是 `boolean`，全链路要统一。建议后端存 `tinyint`、接口用 `boolean`、DTO 加 `@IsBoolean()` + `@Transform`，别两套混用。  
   |  |  |  
   | --- | --- |
3. **可空列的类型推断**：`enabled?: number | null` 在 TypeORM 里会被推成 `Object` 导致 `DataTypeNotSupportedError`（上一轮 `salt` 字段踩过），显式写 `@Column({ type: 'tinyint', nullable: true })`。
4. **改全局默认后要提醒"仅影响未自定义用户"**：否则管理员会疑惑"我改了怎么有人没变"。前端在保存成功提示里写清楚。
5. **退出登录清状态**：watermark provider 的数据要随登出清空，否则换账号登录会先闪一下上一个人的水印（内容里含用户名，属信息泄露）。
6. **多标签页**：A 标签改了水印，B 标签不会自动更新。一期可接受（刷新即同步），要更顺可以走 `storage` 事件广播。
7. **首屏闪烁**：`_authenticated` 挂载后才拉到配置，会有一瞬间无水印。介意的话把结果塞进 login 响应（P1）。
8. **`{dept}` 依赖 dept 关联**：`getProfile` 的 user 不一定带 dept，`resolve()` 要么显式查一次部门名，要么降级为空。

## 十二、待确认

1. **「默认开关在 admin」按哪个解读**？我按 (b) 全局默认由 admin 配、用户可覆盖实现；(c) 强管控只需把 `mode` 设 `forced`。
2. **普通用户能否自己关水印**？能关 = `optional`；不能关 = `forced`。这直接决定产品形态。
3. **`{ip}` 要内网地址还是公网出口 IP**？前者后端直接给，后者需要 trust proxy 配合，且要接受"代理层没配好就不准"。


4. **水印内容是否允许用户自定义**？允许则用户可以把内容改成空白规避（已有 200 字符与空值兜底，但仍可写空格）。建议：用户只能改"模板里的展示字段"，或干脆内容也由 admin 统一。
