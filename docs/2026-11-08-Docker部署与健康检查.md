## 每个东西是干什么的

### 健康检查接口

之前上线风险分析里的 P1 缺口。负载均衡 / 容器探活现在有正式目标：

```bash
curl http://localhost:3000/api/v1/health
# {"status":"ok","db":true,"redis":"ok","uptime":10,"timestamp":"..."}
```

- DB 挂 → HTTP 503（`status:"ok"` 变 `"degraded"` 路径不存在——db:false 直接 503）
- Redis 挂 → 仍 200，但 `redis:"down"`，配合监控告警（与业务降级策略一致：Redis 只是加速层）

### Dockerfile（两阶段）

- **builder**：`corepack enable` 用 pnpm 装依赖（`HUSKY=0` 跳过 prepare 钩子——容器内无 git 仓库会炸）→ `nest build` → `pnpm prune --prod` 裁掉 devDependencies
- **runtime**：`node:22-alpine` + tzdata（timezone '+08:00' 需要）+ 非 root 用户 `app`，只拷 node_modules/dist/package.json/entrypoint

### docker-compose.yml

三个服务、两个数据卷（mysql-data / uploads）+ redis-data：

- app 的 `DB_HOST=mysql`、`REDIS_HOST=redis` 走容器网络；`DB_POOL_SIZE=20`
- `TRUST_PROXY=loopback,linklocal,uniquelocal`：Docker 内网网段视为可信代理
- mysql 带 `utf8mb4_unicode_ci`（与现有表一致，防 0900_ai_ci JOIN 报错）+ `max_connections=300`
- app healthcheck 打 `/api/v1/health`，mysql/redis 各自带探活
- `JWT_SECRET`/`JWT_REFRESH_SECRET` 用 `:?` 强制从 `.env.docker` 读取，缺失即拒绝启动

## 遇到的坑

1. **容器内没有 git**：husky 的 `prepare` 脚本直接失败 → `HUSKY=0 pnpm install`
2. **上传目录环境变量是 `FILE_STORAGE_DIR`** 不是想当然的 UPLOAD_DIR（见 `local-storage.provider.ts`）
3. **entrypoint 必须 LF**：Windows 上写 shell 脚本很容易变 CRLF，容器里 `#!/bin/sh\r` 找不到解释器；已确认本文件是 LF，编辑时别用会转换换行的编辑器
4. **迁移只能跑一份**：多副本时 `RUN_MIGRATIONS` 只给一个实例开 true，否则并发迁移冲突

## 怎么使用

```powershell
# 前置：装 Docker Desktop（本机尚未安装，首次构建需在有 Docker 的机器验证）
cp .env.docker.example .env.docker
# 编辑 .env.docker：填 JWT_SECRET / JWT_REFRESH_SECRET（生成命令见模板内注释）+ 数据库密码

docker compose up -d --build     # 构建 + 启动全栈
docker compose logs -f app       # 应用日志
curl http://localhost:3000/api/v1/health   # 探活
docker compose down              # 停止（-v 连数据卷一起删）
```

生产建议：MySQL 数据卷 + uploads 卷纳入宿主机备份；迁移改用 CI 流水线单独跑而不是容器启动时跑。

## 怎么扩展

- **多副本**：`docker compose up -d --scale app=3` 前先把 SSO 一次性 code 的内存 Map 换 Redis（约 20 行），并关掉除一个实例外的 RUN_MIGRATIONS
- **镜像发布**：`docker build -t registry.example.com/concise-server:v1 . && docker push ...`，compose 里把 `build: .` 换成 `image: ...`
- **前端**：concise-admin 产物是静态文件，可再加一个 nginx 服务挂 dist + `/api` 反代到 app（需要时再说）
