# 移除「任务 / 应用 / 聊天」三个演示菜单

## 背景

这三项是脚手架早期留下的演示页，不是业务功能：

- **任务**（`/tasks`）：看板样式，数据读 `public/mock/tasks.json`，跟后端的任务表没打通；
- **应用**（`/apps`）：`data/apps.ts` 里硬编码的几个第三方应用卡片，按钮点了没反应；
- **聊天**（`/chats`）：三条写死的假会话。

页面、路由、i18n、菜单入口一起清掉，顺带把数据库里的菜单节点和角色授权删干净 —— 只删前端会出现「侧边栏还在、点进去 404」。

## 菜单数据

删掉的 6 个节点（迁移里写死）：

| id | 名称 | 类型 |
| --- | --- | --- |
| `menu_27` | 任务（`/tasks`） | 菜单 |
| `menu_28` / `menu_29` / `menu_30` | 任务新增 / 修改 / 删除 | 按钮（`system:task:*`） |
| `menu_36` | 应用（`/apps`） | 菜单 |
| `menu_37` | 聊天（`/chats`） | 菜单 |

连带删掉 `sys_role_permission` 里指向它们的授权（否则角色权限树会渲染出孤儿节点）。`down` 只恢复菜单节点，**不恢复角色授权** —— 授权属于运行期数据，回滚后应在「角色权限」页重新勾选。

> 「定时任务」（`menu_48`，`/ops/job`）名字里也有「任务」，但那是运维模块，没动。

## 已登录用户为什么不用重新登录

菜单在登录时（`features/auth/login.tsx`）拉到 localStorage，之后不再主动刷新。所以已经在用的浏览器里，缓存树仍带着这三个节点。两道兜底让它立刻消失：

1. **侧边栏**：`toDynItem` 里新增一条校验 —— 普通 SPA 菜单的路径必须能在 `PAGE_REGISTRY` 里找到，找不到就不渲染。外链（`internalOrExternal=1`）和 iframe 内链（`isRoute=0`）不查表，分别走站外和 `/iframe` 承载页；
2. **标签页**：`tabs-provider` 恢复 localStorage 里的页签时本来就按 `isRegisteredPage` 过滤，残留的 `/tasks` 页签会自动掉。

这条校验是通用兜底：以后再下线页面，忘了删菜单也不会在侧边栏留死链接。

## 保留了什么

- **后端 `modules/task`（`/api/v1/tasks`、`base_task` 表）没删**。它和前端那个 mock 看板是两件事，首页概览的「我的待办」统计走的就是这套接口；
- 首页概览接口 `GET /v1/dashboard/overview` **仍返回 `myTasks` 字段**，只是前端不再消费（多出来的 JSON 字段会被忽略）。如果确认以后都不需要，再单独做接口裁剪；
- `help-center`、设置中心等页面与该三项无关，未受影响。

## 验证

```bash
# 后端：迁移已执行（31 个）
cd E:/project/oneself/concise-server-node; npm run restart

# 确认菜单已删（应为空）
SELECT id, name, url FROM sys_permission WHERE id IN ('menu_27','menu_28','menu_29','menu_30','menu_36','menu_37');
SELECT * FROM sys_role_permission WHERE permission_id LIKE 'menu_2%' AND permission_id IN ('menu_27','menu_28','menu_29','menu_30');

# 前端
cd E:/project/oneself/concise-admin; pnpm dev
```

本地结果：迁移执行成功（`DELETE 6 行`），复查查询为空；两端 `tsc` / `eslint` / `vite build` 全绿，dashboard chunk 从 372.44 kB 降到 370.57 kB。

页面自测：登录后侧边栏应只剩「仪表盘 / 系统管理 / 运维管理 / 帮助中心」，首页右侧不再有「我的待办」卡片，快捷入口第一项变成「文件管理」。

## 扩展说明

- 以后要恢复某个演示页：先 `migration:revert` 找回菜单节点并重新授权，再把页面文件从 git 历史取回（`git show <commit>:src/features/tasks/index.tsx`）；
- 下线新页面时的标准动作：删 `features/*` + `routes/*` + `page-registry` 登记 + `nav.ts` 兜底 + i18n 键，然后写一条删菜单节点的迁移（顺手删 `sys_role_permission`）。页面除了，侧栏会自动兜住，但菜单管理页里仍会显示这些节点，所以迁移不能省。
