# 头像上传后顶栏不显示（2026-11-11）

## 现象

个人资料页上传头像成功（落库 `sys_user.avatar = /upload/2026-11-11/图片/avater-*.png`，图片 URL 实测 `200 image/png` 可访问），但顶栏右上角的头像按钮始终只显示姓名首字的兜底圆块。

## 根因

**顶栏 `ProfileDropdown`、侧边栏 `NavUser`、锁屏 `LockScreen`、首页欢迎条 `WelcomeBar` 的头像组件从头到尾只渲染了 `AvatarFallback`，压根没有渲染 `AvatarImage`** —— 不是图片加载失败，是压根没请求过图片。此前只有个人资料页接了 `AvatarImage`。

| 文件 | 类型 | 说明 |

## 头像渲染逻辑（统一）

```
avatar 非空 → resolveAvatarUrl() 归一 → <AvatarImage> 显示图片
空 / 加载失败 → <AvatarFallback> 姓名（或真名）首字兜底
```

`resolveAvatarUrl()` 规则：空值 → `undefined`（不请求不存在的图）；`http(s)://` 或 `/` 开头 → 原样；其余补前导斜杠。相对路径 `/upload/...` 开发环境由 vite `/upload` 代理转发后端，生产由网关/Nginx 转发，前端不用拼 host。

## 遇到的坑

1. **中文目录「图片」**：后端 `getFileType` 返回中文类型名直接拼进落盘路径（`/upload/2026-11-11/图片/xx.png`）。实测浏览器自动编码后访问正常（200），这次没动它；若后续发现某些环境（老网关/CDN）对非 ASCII 路径处理不佳，应改后端 `FileType.IMAGE` 落盘为英文（`image`）。
2. **ProfileDropdown 原实现每次 render 直接读 `getName()`**：没有 state，`AUTH_CHANGED_EVENT` 广播了也不会重渲染 —— 只加 `AvatarImage` 不加 state 同步的话，改完头像顶栏仍不更新。
3. **欢迎条的头像兜底是自定义 div**（带渐变底色），直接换 shadcn `Avatar` 会丢样式 —— 兜底类名挪到 `AvatarFallback` 上保留原观感。

## 扩展/使用

- 其他页面要显示当前用户头像：`import { getAvatar, resolveAvatarUrl } from '@/lib/auth'`，渲染 `<AvatarImage src={resolveAvatarUrl(getAvatar())} />` + 首字兜底即可，不用再发请求。
- 用户管理列表显示他人头像：直接 `resolveAvatarUrl(row.avatar)`（数据来自接口，不走本地缓存）。
- 后端无需任何改动。
