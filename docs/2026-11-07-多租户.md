# 多租户：sys_tenant / sys_user_tenant + 请求级隔离 + 前端切换

> 目标：把「租户管理」从 mock 变成真表真接口，并让业务数据按租户自动隔离。
> 表结构参照 jeecg 的 `sys_tenant` + `sys_user_tenant`（用户与租户多对多），隔离范围限定在**核心业务表**（字典/公告/任务/文件/职级/岗位/部门/角色）。

## 二、每个东西是干什么的

### 表结构

- `sys_tenant`：租户主表。`code` 全局唯一（含软删记录也占索引）、`status` 0 正常/1 停用、`expire_at` 到期日（NULL=永久）、`del_flag` 软删。
- `sys_user_tenant`：用户与租户多对多，`(user_id, tenant_id)` 唯一。一个人可以属于多个租户，顶栏切换即可换视角。
- `sys_user.login_tenant_id`：上次选择的租户，作为「请求没带 `X-Tenant-Id` 时的默认值」。
- 业务表 `tenant_id`：**NOT NULL DEFAULT 1**。`0` 是特殊值，表示「平台共享数据」，所有租户都能看到。

### 隔离规则（唯一真相在 `tenant-scope.util.ts`）

| 上下文 tenantId | 生成的 SQL 条件 | 语义 |
| --- | --- | --- |
| `null` | 不加条件 | 超管平台视角，看全部 |
| `0` | `tenant_id = 0` | 不属于任何租户，只看共享数据 |
| `> 0` | `(tenant_id = :id OR tenant_id = 0)` | 本租户 + 共享数据 |

### 请求链路

```
请求 → TenantMiddleware（解 token，查归属，开 AsyncLocalStorage 作用域）
     → JwtAuthGuard → RolesGuard → PermsGuard → Controller/Service
     → applyTenantScope() 读上下文 → WHERE 自动带上租户条件
```

中间件里必须用 `TenantContext.run(store, next)` 包住 `next()`，在 Guard 里 `set` 是无效的——Guard 执行时下游的异步链路早已脱离作用域。

### 九个接口

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/v1/tenants` | `system:tenant:list` | 分页 + `userCount` |
| GET | `/v1/tenants/mine` | 登录即可 | 当前生效租户 + 可切换列表 + `isSuper` |
| POST | `/v1/tenants/switch` | 登录即可 | 校验归属后记住；`tenantId=0` 回平台视角（仅超管） |
| GET/POST/PUT/DELETE | `/v1/tenants/:id` | `list/add/edit/delete` | CRUD，删除为软删 |
| GET/PUT | `/v1/tenants/:id/users` | `system:tenant:user` | 成员列表 / 覆盖式分配 |

删除保护：`id=1` 默认租户不可删；租户下还有成员时拒绝（提示先移除）。

## 三、遇到的坑

1. **TypeORM 列类型推断失败**：`@Column({ length: 32 })` 在可空情况下被推断成 `Object`，启动直接 `DataTypeNotSupportedError`。可空字符串列必须写 `@Column({ type: 'varchar', length: 32 })`，日期同理 `type: 'datetime'`。
2. **在 Guard 里设上下文无效**：Guard 是同步返回布尔值，进入 Controller 后已经换了异步链路。必须用中间件 + `AsyncLocalStorage.run()` 包住 `next()`。
3. **BaseService 之外还有手写 QueryBuilder**：12 个 service 的 `createQueryBuilder` 不带租户条件，必须逐个补 `applyTenantScope()`。补的时候注意别用 `where()` 覆盖已有条件——用 `andWhere(new Brackets(...))`。
4. **`switch` 传 0**：`resolveTenant` 里 `requested > 0` 才生效，0 会走到「用默认租户」分支，把普通用户「切平台视角」的请求静默变成切回自己第一个租户。现在 `switch(0)` 单独判超管 + 置 `login_tenant_id = NULL`。
5. **超管只属于租户 1**：迁移把所有存量用户塞进租户 1，超管用 `mine` 只能看到 1 个租户，切换器形同摆设。改为超管直接列 `sys_tenant` 全表。
6. **新表 COLLATE 要显式指定**：`sys_user` 是 `utf8mb4_unicode_ci`，新表若用默认 `utf8mb4_0900_ai_ci`，JOIN 时会报排序规则冲突。
7. **冒烟脚本踩的四连坑**：手机号唯一索引（加时间戳后缀）、POST 返回 201 不是 200、临时账号无字典权限（改用 admin + `X-Tenant-Id` 验隔离）、字典接口返回 Pagination 不是裸数组。
8. **`Pagination` 是普通 class**：没有 `withTotal()` 这类链式方法，直接 `new Pagination(records, total, page, size)`。
9. **`npm run restart` 会假重启**：`nest build` 清 dist（700+ 文件）被 safe-delete 钩子拦，`&&` 短路后 `serve.mjs` 根本没跑。判断法：`curl /api/v1/<新路由>` 回 404 = 旧进程还在，回 401 才是新代码在跑。

## 四、怎么扩展 / 使用

### 让一张新表参与隔离

1. 迁移里加列：`ALTER TABLE xxx ADD COLUMN tenant_id INT NOT NULL DEFAULT 1` + 索引；
2. 实体加 `@Column({ name: 'tenant_id', type: 'int', default: 1 }) tenantId: number`；
3. 如果继承 `BaseService` → 什么都不用做，list/findOne/create/update/delete 自动带条件；
4. 如果手写 QueryBuilder → 引入 `applyTenantScope(qb, 'alias')`；
5. `UPDATE/DELETE` 无别名时用 `tenantRawCondition('tenant_id')` 拼条件。

### 前端切换租户

```ts
import { setTenantId } from '@/lib/auth'
import { switchTenant } from '@/features/system/tenant/api'

const applied = await switchTenant(3) // 0 = 平台视角（仅超管）
setTenantId(applied) // 之后所有请求自动带 X-Tenant-Id
window.location.reload() // 整页重载，避免上一个租户的列表/字典缓存残留
```

### 已知遗留 / 语义约定

- **平台视角下写入 = 平台共享数据**：超管切到「平台视角」后新建字典/公告/部门，`tenant_id` 会是 `0`（所有租户可见）。要建「某租户专属」的数据，先在切换器里切进那个租户再建。`BaseService.stampTenant()` 只在上下文有租户时才打标，实体列默认值兜底成 0，所以不会静默串租户。
- **归属缓存 30s**：改完角色/分配租户后如果立刻看不到变化，等半分钟或重启服务（`assignUsers` / `update` 已主动 `invalidate()`）。
- **`sys_user` / `sys_permission` / `sys_log` 不隔离**：账号和菜单权限是平台级数据，跨租户共用一套。真正的隔离靠「用户—租户归属」+ 业务表 `tenant_id`。
