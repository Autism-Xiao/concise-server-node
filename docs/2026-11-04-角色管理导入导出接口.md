# 角色管理：导入 / 导出接口

> 2026-11-04 · 后端 `concise-server-node` + 前端 `concise-admin`

给角色管理加了 CSV 导入导出：导出当前（可筛选）角色清单，导入时按「角色编码」判定新增或更新。
与日志导出保持同一套 HTTP/CSV 约定（`text/csv; charset=utf-8` + UTF-8 BOM + `Content-Disposition: attachment`），**不引入 xlsx 依赖**，Excel 可直接打开导出文件，也能另存为 CSV 再导回。

## 二、接口

三个接口都在 `/api/v1/roles` 下，需 Bearer Token + `@Roles('admin')`，并按按钮权限二次校验。

| 方法 | 路径 | 权限编码 | 说明 |
|---|---|---|---|
| GET | `/api/v1/roles/export?keyword=` | `system:role:export` | 导出 CSV，keyword 与列表一致（名称/编码模糊），不分页、不截断 |
| GET | `/api/v1/roles/import-template` | `system:role:import` | 下载导入模板（表头 + 2 行示例） |
| POST | `/api/v1/roles/import` | `system:role:import` | multipart 上传 CSV，字段名 `file`；写操作进操作日志 |

**导出列**：`角色名称, 角色编码, 描述, 已授权菜单数, 创建时间`

```csv
﻿角色名称,角色编码,描述,已授权菜单数,创建时间
访客,viewer,,3,2026-11-04 12:34:28
编辑者,editor,,2,2026-11-04 12:34:28
```

**导入列**：`角色名称, 角色编码, 描述`（导出文件直接回导也可行，多余列被忽略）

```csv
﻿角色名称,角色编码,描述
运营专员,operator,负责日常运营，仅可查看数据
财务审核,finance_auditor,
```

**导入返回**（HTTP 201，`result` 为报告）：

```json
{
  "total": 6,
  "created": 2,
  "updated": 1,
  "skipped": 1,
  "failed": 2,
  "errors": [
    { "row": 5, "roleCode": "io_operator", "message": "文件内角色编码重复，本行已跳过" },
    { "row": 6, "roleCode": "1bad_code", "message": "角色编码需字母开头，只能包含字母/数字/下划线/冒号/点/短横线，且不超过 100 个字符" },
    { "row": 7, "roleCode": "", "message": "角色编码不能为空" }
  ]
}
```

`row` 是**用户视角的表格行号**（含表头，从 1 开始），可直接对照 Excel 定位；无表头文件按数据行号从 1 开始。

## 三、导入规则

1. **按 `roleCode` 判定**：库里没有 → 新增；已有 → 更新名称与描述，**不动已授权菜单**（避免一次导入把权限洗掉，授权仍在「分配权限」里做）。
2. **空描述不清空原值**：更新时描述列留空，认为「没填」而非「清空」，保留原备注。新增时空描述落 `NULL`。
3. **角色名称为空** → 用 `roleCode` 兜底，避免出现无名角色。
4. **文件内编码重复**：保留第一行，后续行计入 `skipped` 并给出提示。
5. **单行失败不影响其他行**：非法编码、空编码等只让该行失败，最终汇总在 `errors`。
6. **文件校验**：仅 `.csv`（后缀不区分大小写），≤2MB（multer `limits.fileSize`），≤2000 行；超限直接 400 提示拆分。
7. **编码校验**：必须 UTF-8。用 `\uFFFD` 替换字符判定解码失败，提示「另存为 CSV UTF-8」，避免 GBK 文件灌进一堆乱码。

## 四、遇到的两个坑

**1. 路由顺序：`GET /roles/export` 会被 `GET /roles/:id` 吃掉**
`@Get(':id')` 在 Nest 里是先注册先匹配，把 `export` 当成 id。新增的三个路由必须声明在 `@Get(':id')` **之前**（本次放在 `list()` 之后、`findOne()` 之前），否则请求会 404「角色不存在」。

**2. 不能用 `@OperLog` 记录导出**
`OperLogInterceptor` 只对 `POST/PUT/PATCH/DELETE` 生效，GET 上的 `@OperLog` 是空转。所以导出不加该装饰器（避免误解），导入是 POST，会自动写 `sys_log`（实测 `角色管理 - POST /api/v1/roles/import`，operate_type=2）。

## 五、前端使用

角色页头部按钮顺序：`导出`（`system:role:export`）、`导入`（`system:role:import`）、`新增角色`。

- **导出**：把搜索框关键字一并带上，导出的是筛选后的结果；空列表时按钮禁用。
- **导入**：弹窗内先「下载模板」→ 填写 → 「选择文件」→「开始导入」；结果区显示 `共 N 行 / 新增 / 更新 / 跳过 / 失败`，失败明细最多显示 10 条（其余折叠成「另有 N 条」）。有任意新增或更新时自动刷新列表。
- 文件选择用隐藏 `<input type="file" accept=".csv,text/csv">`，选完只展示文件名与大小，点「开始导入」才真正上传（可重选）。

## 六、怎么扩展

| 需求 | 做法 |
|---|---|
| 再多导出一列（比如「用户数」） | `role.service.exportRoles` 里补 `relations.users` 计数，controller 的 `toCsv` 表头与 `map` 同步加一列；导入侧不需要改（多余列自动忽略） |
| 导入同时绑定菜单授权 | 模板加「菜单编码」列（逗号分隔），`importRoles` 里按 `sys_permission.perms` 反查 id 后调 `assignMenus`；注意此时「更新不清空授权」的规则需要改成「有该列才覆盖」 |
| 换成真正的 xlsx | 安装 `exceljs`，把 controller 里的 `toCsv`/`parseCsv` 换成 `workbook.xlsx.load/ writeBuffer`；接口签名与返回结构不变，前端只需把 `accept` 改成 `.xlsx` |

## 七、验证记录

服务层用例：带逗号/引号的描述往返正确、已存在角色只改名称保留描述、文件内重复跳过、非法编码失败、空编码失败、非 UTF-8 文件被拦、无表头文件按 `角色名称,角色编码,描述` 位置解析、导出按 keyword 过滤。

HTTP 联调（本地 3465，CAPTCHA 关闭）：

- `GET /api/v1/roles/export` → 200，`text/csv; charset=utf-8`，`attachment; filename="roles-<ts>.csv"`，首行带 BOM
- `GET /api/v1/roles/import-template` → 200，模板两行示例
- `POST /api/v1/roles/import` → 201 `{total:1,created:1}`；同文件再导一次 → `{created:0,updated:1}`（幂等）
- 上传 `roles.xlsx` → 400「仅支持 CSV 文件…」
- 导出的 CSV 中能查到刚导入的角色；操作日志有 `POST /api/v1/roles/import` 记录
