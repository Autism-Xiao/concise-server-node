# 前端首页跟随权限：只授权业务菜单时不再登录即 403

- 日期：2026-11-05
- 仓库：`concise-admin`（本轮为纯前端改动，后端未改）
- 背景：给角色只勾一个业务菜单（如「用户管理」）后，登录进系统直接落到 403，侧边栏有菜单但页面打不开，用户以为「菜单权限没生效」

## 一、根因：落地页写死 `/dashboard`，但后端菜单里没有「仪表盘」

后端的菜单树是业务菜单（系统管理 / 任务 / 运维监控…），**没有仪表盘节点**，所以只授权业务菜单的账号，其可见路径集合里不含 `/dashboard`。而前端有 5 处把落地页写死：

| 位置 | 改前 | 后果 |
| --- | --- | --- |
| `src/routes/index.tsx` | `/` → 重定向 `/dashboard` | 打开根路径直接进无权限页 |
| `src/routes/login.tsx` | 已登录访问 `/login` → `/dashboard` | 同上 |
| `src/features/auth/login.tsx` | 登录成功 `navigate('/dashboard')` | **登录即 403**（本次现象的直接原因） |
| `src/context/tabs-provider.tsx` | 固定「首页」标签 = `/dashboard`，`closeAll` 回 `/dashboard` | 标签栏挂一个打不开的页签；全关后回到 403 |
| `src/components/layout/app-sidebar.tsx` | Logo `<a href="/dashboard">` | 点 Logo 反而被甩到 403 |

权限守卫（`routes/_authenticated.tsx` 的 `PermissionGuard`）逻辑本身没错：路径不在可见集合里就 403。错的是「默认要去哪个页面」这件事被写死了。

## 二、改法：新增一层「首页解析」

新增 `src/lib/home-path.ts`：

```ts
resolveHomePath(permitted: Set<string> | null): string | null
```

规则（顺序即优先级）：

1. `permitted === null`（超管，不做过滤）→ `/dashboard`
2. 有 `/dashboard` 权限 → `/dashboard`
3. 按 `PAGE_REGISTRY` 的注册顺序，取**第一个有权限的业务页面**（`/tasks` → `/system/users` → …）
4. 一个都没有 → `null`，由调用方展示「未分配菜单」提示

「业务页面」= 在 `PAGE_REGISTRY` 里注册过，且不属于 `/errors`、`/settings`、`/help-center` 这些常驻页面。这条过滤很关键：
- 菜单里只勾了目录节点（如「系统管理」，`url=/system`）但没勾任何子菜单时，`/system` 不是已注册页面，**不能当落地页**，否则进去就是 404
- 错误页/设置页是所有账号都能进的常驻页面，不能作为「首页」

另有 `resolveHomePathFromStorage()`：直接读 localStorage 里的登录快照同步解析，供路由 `beforeLoad` 与标签页初始化使用（这两处不在 React 渲染期，拿不到 hook）。

## 三、逐个改动点

| 文件 | 类型 | 改了什么 |
| --- | --- | --- |
| `src/lib/home-path.ts` | 新增 | `resolveHomePath` / `resolveHomePathFromStorage`，首页解析的唯一出口 |
| `src/lib/permissions.ts` | 修改 | `loadPermittedPaths()`（async）改为同步 `computePermittedPaths()`：解析本来就是同步的，改成同步才能被路由 `beforeLoad` 和 `TabsProvider` 初始化复用 |
| `src/routes/index.tsx` | 修改 | `/` 重定向到 `resolveHomePathFromStorage()` |
| `src/routes/login.tsx` | 修改 | 已登录访问 `/login` 时同样按权限跳 |
| `src/features/auth/login.tsx` | 修改 | 登录成功先写菜单快照，再按 `resolveHomePath(computePermittedPaths())` 跳转 |
| `src/routes/_authenticated.tsx` | 修改 | `PermissionGuard` 三段兜底：① 一个业务页面都没有 → 渲染 `<NoMenuAccess/>`；② 落在 `/dashboard` 但无权限 → 转到自己的首页；③ 其它无权限路径 → 照旧 403 |
| `src/features/errors/no-menu-access.tsx` | 新增 | 「尚未分配功能权限」页：说明原因 + 刷新 + 退出登录，不再用 403 冒充 |
| `src/features/errors/error-page.tsx` | 修改 | 「回到首页」改走 `/`（由首页解析决定落地页），不再写死 `/dashboard` |
| `src/context/tabs-provider.tsx` | 修改 | ① 固定标签 = `resolveHomePath()` 的结果，解析不到就不固定；② 恢复历史标签时按当前权限过滤（换账号不会带回上个会话的无权页签）；③ `closeAll` 回动态首页；④ 错误页不占标签位 |
| `src/components/layout/app-sidebar.tsx` | 修改 | Logo 从 `<a href="/dashboard">` 改为 `<Link to={homePath}>` |

## 四、行为对照

| 场景 | 改前 | 改后 |
| --- | --- | --- |
| 只授权「用户管理」 | 登录 → `/dashboard` → 403，菜单点了也没用 | 登录 → `/system/users`，正常出数据 |
| 只授权「任务」 | 同上 | 登录 → `/tasks` |
| 只勾了「系统管理」目录、没勾子菜单 | `/dashboard` → 403 | 「尚未分配功能权限」提示页（因为 `/system` 不是已注册页面） |
| 一个菜单都没授权 | 403（像链接坏了） | 提示页 + 退出登录按钮 |
| 超管 | `/dashboard` | `/dashboard`（不变） |
| 手动访问无权限页面（如只授权用户管理却点角色管理） | 403 | 403（不变，这才是 403 该出现的地方） |
| 换账号登录 | 恢复上个账号的标签页，点进去 403 | 历史标签按当前权限过滤后恢复 |

## 五、扩展方式

- **新增页面**：只要在 `src/config/page-registry.ts` 注册，就会自动进入首页候选顺序；不需要改 `home-path.ts`
- **想指定某个页面优先做首页**（例如「工作台」）：在 `resolveHomePath` 里把 `/dashboard` 那一行换成目标路径，或调整 `PAGE_REGISTRY` 的键顺序
- **后端加了「仪表盘」菜单**：只要给角色勾上 `url=/dashboard` 的菜单节点，规则 2 会自动生效，无需改前端
- **想给某类页面永久免权限**：加到 `ALWAYS_ALLOWED`（`lib/permissions.ts`）；注意加进去的路径同时也会被排除在「首页候选」之外才有意义

- 用真实库 + 真实 `/v1/auth/permissions` 返回值模拟解析结果：

| 账号/构造 | 可见路径 | 解析出的落地页 |
| --- | --- | --- |
| 只授权用户管理 | `/system`、`/system/users` | `/system/users` |
| 只授权目录 | `/system` | `null`（提示页） |

## 七、注意事项

1. **`computePermittedPaths` 必须保持同步**。路由 `beforeLoad` 与 `TabsProvider` 的 `useState` 初始化都在渲染前后同步执行，改成 async 后这两处会拿到 `null`（= 不过滤），权限过滤会被静默跳过。
2. **`resolveHomePath` 依赖 `PAGE_REGISTRY` 的键顺序**（Object.keys 的顺序 = 声明顺序）。想调优先级就调声明顺序，别在别处再写一份顺序表。
3. **首页解析发生在「登录快照」基础上**。改了角色授权后必须重新登录（前端 `permissions`/`menus` 是登录时写入的），否则还会按旧快照落地。
4. **错误页不再进标签栏**。`TabsProvider` 里用 `pathname.startsWith('/errors')` 过滤；如果以后要保留错误页标签，记得同步调整。
5. 本次顺手把 `PermissionGuard` 里「未登录直接不渲染」的分支补进提交（退出登录瞬间的重定向死循环），此前只存在于工作区。
