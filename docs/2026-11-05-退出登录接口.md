# 2026-11-05 退出登录接口

## 背景

此前登出只是前端清 localStorage，token 本身仍然有效（被人抄走还能继续用到自然过期，refreshToken 还能续命 7 天）。本次新增服务端退出登录：令牌立即失效 + 在线会话删除。

## 改动文件

| 文件 | 类型 | 说明 |
|---|---|---|
| `src/modules/ops/online/online.service.ts` | 增强 | 新增 `logout(token, ttlSeconds, refreshToken?, refreshTtlSeconds?)`：accessToken 拉黑 + 删在线会话 + refreshToken 拉黑；Redis 未启用时静默跳过 |
| `src/modules/auth/services/auth.service.ts` | 新增 | `logout(token, refreshToken?)`：从令牌 payload 解出 exp 计算 TTL（拉黑到自然过期）；`refreshToken()` 增加 `isRevoked` 检查，防止登出后用 refreshToken 续命 |
| `src/modules/auth/controllers/auth.v1.controller.ts` | 新增 | `POST /api/v1/auth/logout`（需登录，无按钮权限要求，所有登录用户可用） |
| concise-admin `src/lib/auth.ts` | 前端 | `logout()` 先尽力调后端接口（失败不阻断），再清本地凭证；`nav-user` / `profile-dropdown` 调用方无需改动 |

## 接口

```
POST /api/v1/auth/logout
Authorization: Bearer <accessToken>
Content-Type: application/json

{"refreshToken": "<可选，带了就一并失效>"}
```

响应：`{ "code": 0, "data": { "loggedOut": true }, "message": "success" }`

## 每个东西是干什么的

- **黑名单复用**：直接复用强制下线的 `online:revoked:<tokenHash>` 黑名单。accessToken 的校验点在 `JwtStrategy`（每次请求都查），refreshToken 的校验点在 `refreshToken()`（刷新前查）。两个令牌哈希不同，共用一个前缀不会冲突；缓存监控里的「强制下线令牌黑名单」分组自动覆盖。
- **TTL 策略**：拉黑时长 = 令牌自身剩余有效期（最少 60 秒）。令牌自然过期后黑名单条目也自动消失，Redis 不留垃圾。
- **前端 fire-and-forget**：`logout()` 发请求但不 await，本地凭证立即清掉并跳登录页；网络失败/后端 401（登出后再点一次）都不影响前端流程。
- **删除会话**：登出即删 `online:session:<hash>`，在线用户列表立即少一条，不需要等 TTL。

## 遇到的坑

1. **shell 命令里的密码字面量会被改写**（老坑再验证）：写 `'admin123'` 到命令里实际到达服务端的是别的字符串，HTTP 登录一直 1007。联调改用读 `.env` 的 JWT_SECRET 自签 token 构造登录态，完整验证了登出链路。
2. **`@Body()` 与 `req.body` 二选一**：一开始两个都声明，类型上互相干扰；body 只从 `@Body()` 拿。
3. **`headers.authorization` 类型是 `string | string[]`**：要按 login 接口的写法先 `Array.isArray` 归一化再 split。
4. **登出后重复调用会 401**（令牌已拉黑，被全局守卫拦截），这是预期行为；前端 fire-and-forget 天然忽略。

## 怎么扩展 / 使用

- **调用**：登录用户 `POST /backend-api/v1/auth/logout`，body 带上登录时返回的 refreshToken（前端 `lib/auth.ts` 的 `logout()` 已封装好，任何页面调它即可）。
- **强制下线 vs 退出登录**：管理员踢人用 `DELETE /api/v1/online/:sessionId`；用户自己登出用本接口。两者底层同一套黑名单。
- **refreshToken 校验**：以后任何签发/校验 refreshToken 的地方（如做多端登录、改 refresh 轮换）都要记得过 `onlineService.isRevoked()`。
