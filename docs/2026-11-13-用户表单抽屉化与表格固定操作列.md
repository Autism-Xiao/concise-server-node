## 背景

用户管理的新增/编辑是居中 Dialog（`sm:max-w-lg`），表单字段 14+ 个，弹窗内部滚动区被标题和按钮挤得很小；另外列多的表格（用户表 12 列）横向滚动时「操作」列会跟着滚出视野，得滚回最右才能点按钮。

## 每个东西是干什么的

**AppDrawer（公共抽屉）**——两种用法：

1. **表单模式**：传 `onSubmit`，组件把内容区和底部按钮包进同一个 `<form>`，主按钮即 `type="submit"`——回车提交、原生 required/minLength 校验都天然生效；
2. **展示模式**：不传 `onSubmit`、自己传 `footer` 节点（传 `null` 则没有底栏）。

其余能力：`size`（sm/md/lg/xl 四档宽度，默认 md）、`submitting`（提交中双按钮禁用）、`submitDisabled`（数据没加载完禁提交）、`bodyClassName`。头部描述行可选，右上角关闭按钮由底层 Sheet 自带。

**固定操作列（`.table-sticky-action`）**——`position: sticky; right: 0` + 自绘背景 + 左侧渐隐投影。三层配套：

- 默认底色 `var(--card)`（表格都在 Card 里）；
- `tr:hover > .table-sticky-action` 手动对齐 hover 色（`muted 50% + card` 的 color-mix），否则操作列不跟着行高亮；
- `tr[data-state='selected']` 对齐选中色；
- 弹窗/抽屉里背景是 `--popover` 不是 `--card`，所以补了 `.table-sticky-action-popover` 变体（回收站用）。

**接入方式两条路**：

- `DataTable`（TanStack 封装，14 个列表页共用）：自动判断可见列的最后一个 `id === 'actions'` 就 sticky，页面零改动；约定操作列 id 必须叫 `actions`（全站已统一）。
- 自绘表格（部门/菜单/区划/文件/供应商/回收站）：表头 `<th>` 和单元格 `<td>` 手工加类。

## 遇到的坑

1. **sticky 单元格必须自绘背景**：不设背景时横向滚动的内容会从操作列下面透出来，这是 sticky 列最常见的翻车点。
2. **hover 色不跟随**：tr 的 `hover:bg-muted/50` 画在 tr 上，被 td 自己的背景盖住，所以 CSS 里要单独写 `tr:hover > .table-sticky-action`，且用 `color-mix(muted 50%, card)` 精确复现半透明叠加色。
3. **覆盖 SheetContent 默认宽度**：底层默认 `data-[side=right]:sm:max-w-sm`，传 `sm:max-w-lg` 这种「少半截变体」的类不一定被合并掉，要用一模一样的变体前缀 `data-[side=right]:sm:max-w-lg` 才能稳定覆盖（cn 是 clsx+twMerge 语义）。
4. **验证环境没有 playwright**：装一套要拉 150MB 浏览器，改用本机 Chrome + 原生 CDP（`--headless=new --remote-debugging-port` + Node 22 全局 WebSocket），手签 admin JWT 注入 localStorage 绕过登录截图，零依赖完成验证。
5. 部门表浅色下恰好没触发横向滚动（列不算宽），固定列只在「表格比容器宽」时才看得出效果——这是 sticky 的正常行为，不是没生效。

## 怎么扩展

1. **新页面想用抽屉表单**：`import { AppDrawer } from '@/components/app-drawer'`，传 `open/onOpenChange/title/onSubmit/submitting`，内容直接写表单字段，不用再管底部按钮。
2. **新列表页想固定操作列**：用 `DataTable` 就什么都不用做（操作列 id 叫 `actions` 即可）；自绘表格就给操作列的 th/td 加 `table-sticky-action`（弹窗内加 `table-sticky-action-popover`）。
3. **想调固定列视觉**（阴影深浅/底色）：只改 `src/index.css` 里「表格固定操作列」一段，全站生效。
