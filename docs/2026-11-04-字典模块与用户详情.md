# 2026-11-04 字典模块与用户详情增强

本轮新增字典管理（dict-type / dict-item）和用户详情带部门，中后台下拉框数据有了统一管理入口。

## 一、字典模块

### 新增文件（`src/modules/system/`）

| 文件 | 说明 |
|---|---|
| `dict-type/entities/dict-type.entity.ts` | 字典类型：name / **code（唯一索引）** / status / remark |
| `dict-type/dto/*.ts` | 编码格式校验（小写字母开头的字母数字下划线） |
| `dict-type/dict-type.service.ts` | CRUD + 编码唯一性校验 + **有字典项时禁止删除** + keyword 分页 |
| `dict-type/dict-type.controller.ts` | `/dict-types` CRUD（@Perms system:dict:*） |
| `dict-item/entities/dict-item.entity.ts` | 字典项：label / value / dictTypeId / sort / status |
| `dict-item/dto/*.ts` | 校验 |
| `dict-item/dict-item.service.ts` | CRUD + **同类型下 value 唯一**校验 + `listByTypeCode()` |
| `dict-item/dict-item.controller.ts` | `/dict-items` CRUD + **`GET /dict-items/code/:code`** |
| 两个 `*.module.ts` | DictItemModule 同时 forFeature 两个实体（需注入 DictType 仓库） |

### 接口设计要点

- **`GET /dict-items/code/:code` 不加 @Roles/@Perms**——所有登录用户可用，就是给前端下拉框用的；管理类 CRUD 才限 admin + 按钮
- 路由顺序：`code/:code` 注册在 `:id` 之前，避免被 `ParseIntPipe` 吞掉
- `listByTypeCode` 只返回启用项，结构 `{ code, name, items: [{label, value, sort, remark}] }`，前端直接渲染

### 数据表（迁移 1793735965438）

`dict_type`（code 唯一索引）、`dict_item`。演示数据：`sys_user_gender`（男/女/未知）、`sys_menu_status`（启用/禁用）。

## 踩坑记录

1. **`@InjectRepository(DictTypeEntity)` 报 UnknownDependenciesException**：跨模块注入仓库必须在**本模块** `forFeature` 注册（导入对方模块只导出 Service 不导出仓库）
2. **`select: ['sort']` 编译报错**：`sort` 与数组原型方法类型冲突，改用对象形式 `{ label: true, ..., sort: true }`
3. **oxlint no-misused-spread**：实体实例展开组树是刻意的 plain-object 快照（响应走 JSON 序列化无副作用），用行内 disable 注释抑制（menu/dept 两处）
4. 3457 端口被外部代理进程占用导致 curl "upstream connect failed"——本地测试换 3459

## 以后加字典的套路

1. `POST /dict-types` 建类型（如 `sys_notice_type`）
2. `POST /dict-items` 挂字典项
3. 前端 `GET /dict-items/code/sys_notice_type` 拉取渲染下拉框
