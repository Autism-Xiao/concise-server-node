# 修复：新增/编辑用户报 depts.map is not a function

日期：2026-11-06　仓库：concise-admin（前端）　类型：bug 修复（上一轮分页统一的遗漏）

## 问题现象

打开「新增用户」对话框整页崩溃：`Something went wrong! depts.map is not a function`（用户管理页 5174/5175 均可复现）。

## 根因

上一轮「列表分页结构统一」把后端 `/v1/depts` 的响应从裸数组改成统一 `Pagination`（`records/total/current/size/pages`）。`src/features/system/dept/api.ts` 的页面读取已同步改为 `page.records`，但 `src/features/users/api.ts` 里用户表单用的 `fetchBackendDepts()` 也请求同一端点，**漏改**——它把 Pagination 对象当数组返回，表单里 `depts.map(...)` 即抛错。

## 改动文件

| 文件 | 类型 | 说明 |
|---|---|---|
| `src/features/users/api.ts` | 修复 | `fetchBackendDepts` 改为读 `page.records` 后返回数组 |

## 排查结论

全站 `getApiResult<Array<...>>` 复查：其余数组型调用均指向 `/tree`、`/options` 等真数组端点（`fetchRoleOptions` 走 `/roles/options`），无其他同类漏网。

## 怎么扩展/避免再踩

后端列表接口已全部统一为 Pagination；**新增调用方时按 `PageResult<T>` 接，取 `.records`**，不要再假设裸数组。下次调整列表响应结构时，用 `grep -rn "getApiResult<Array" src/` 兜底排查所有调用方。

- 刷新用户管理 → 新增用户，部门下拉应正常加载（提交 `74ad29f`，已推送）
