# 2026-11-14 选人面板滚动条误关修复 + 全站用户快捷选人

## 背景

用户反馈两点（滚轮坏了，只能拖滚动条）：
1. 「发送站内信」弹窗里打开选人面板后，**拖弹窗自己的滚动条面板就消失**——滚动条在选人组件外部，触发「点击外部关闭」；
2. 希望加**「全站用户」一键全选**和**「选择个别」**按钮，不用一个个搜着挑。

## 改动清单

| 文件 | 类型 | 说明 |
| --- | --- | --- |
| `concise-admin/src/features/users/components/user-multi-select.tsx` | 修改 | 关闭逻辑改造：`pointerdown` 在组件外才关闭，但**显式豁免滚动条槽**（点击坐标 offsetX/Y 超出目标 clientWidth/Height 且对应方向有溢出 → 视为拖滚动条，不关闭）；面板底部新增「全选候选」按钮；新增 `usersCache` prop（外部批量选中时直接提供 id→账号映射，渲染时合并，避免逐个 lookup——lookup 上限 100）；chips 移除按钮补 `preventDefault` |
| `concise-admin/src/features/users/api.ts` | 修改 | 新增 `fetchAllUserBriefs(max=1000)`：按满页循环拉取全站用户简要列表（后端列表 pageSize 上限 100），返回是否被 max 截断 |
| `concise-admin/src/features/system/message/index.tsx` | 修改 | 接收人标签右侧新增「全站用户」「选择个别」快捷按钮：前者翻页拉全站用户一键全选（toast 提示人数，超 1000 提示已达单次上限），后者把选人面板聚焦弹出；全选时把账号映射通过 `usersCache` 传给选人控件 |

选人组件是共享的，本次关闭逻辑修复同时惠及公告「指定用户」、任务指派等所有用它的场景。

## 行为细节

- 拖滚动条（弹窗的、页面的、面板自己的）面板都保持打开；点别的输入框、按钮、遮罩仍正常关闭；
- 「全选候选」只选当前搜索结果里的用户（≤100 个/页）；「全站用户」翻页拉全量（后端单次发送上限 1000 人）。

## 踩的坑

1. **判断条件写反**：纵向滚动条应为 `offsetX >= clientWidth && scrollHeight > clientHeight`（内容纵向溢出才有纵向滚动条），初版错把 `scrollWidth` 用在纵向——第一版无头测试复现不出来还误以为修复无效；
2. **无头环境滚动条槽为 0**（overlay 模式）：CDP 点击 `right-5` 落在内容区，等于在测「点内容关闭」，必须靠页面内监听记录真实事件的 `target/offsetX/clientWidth` 才定位到判断写反；
3. **usersCache 只进判断不进渲染**：全站全选后 chips 显示红色 `#id`——`usersCache` 参与了「缺谁去查」但没参与 chip 渲染，渲染处要 `briefs[id] ?? usersCache?.[id]`；
4. **连续 click 两个候选项只选中一个**：第一次 click 触发 React 重渲染，第二个 DOM 节点引用失效——脚本要「点一个 → 等 400ms → 重新 query 再点」；
5. vite 只监听 `[::1]`，无头脚本要用 `localhost` 不能用 `127.0.0.1`（复确认）。

## 验证

- 无头浏览器全流程实测：面板打开 → 在弹窗滚动条槽内（gutter=10px，真实命中滚动容器，offsetX 507 ≥ clientW 502）按下拖动 → **面板保持打开**；点标题输入框 → 正常关闭；「全站用户」→ 4 个 chips 显示真实账号（concise/ceshi/zhangsan/admin）+ toast「已选择全站 4 名用户」；「选择个别」→ 面板重新弹出；
- `tsc`、ESLint、`pnpm build` 全部通过。

## 如何扩展

- 其他页面要做「一键全选」，复用 `fetchAllUserBriefs` + `usersCache` 组合即可；注意后端 DTO 数量上限（消息 1000）。
