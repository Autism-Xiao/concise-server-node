# 首页布局平衡与快捷入口权限收口

## 背景

访客模式实测反馈三个问题：

1. **欢迎条右侧大片空白**：左列内容（头像/问候/标签）靠左，右列只有一行「上次登录」+ 两个按钮，中间整段留白，视觉重心偏左。
2. **卡片头部断成两行、箭头样式不对**：「我的待办」「通知公告」「最近操作」「系统状态」四张卡的标题和「任务看板 →」等链接各占一行 —— 根因是新 `CardHeader` 是 **grid** 容器（`grid auto-rows-min gap-1`），写 `flex-row justify-between` 完全不生效；且链接箭头用的是实心 `→`（ArrowRight），用户期望 `›`（ChevronRight）。
3. **快捷入口越权显示**：访客的菜单树里没有「文件管理」，快捷入口却显示了「文件管理」—— 因为过滤只看了按钮权限（`perm: null` 即全放），没看菜单授权。点进去就是 403。

## 每个东西是干什么的

### `CardAction` 插槽

新版 shadcn Card 的 `CardHeader` 是 grid：`has-data-[slot=card-action]:grid-cols-[1fr_auto]`。把「任务看板 ›」这类动作按钮放进 `<CardAction>`，标题列自动占 `1fr`、动作列 `auto` 靠右 —— 不需要在 header 上手写 flex 覆盖。

### 快捷入口双重门槛

```
可见 = (perm 为 null 或 hasPermission(perm))  且  (!permitted 或 isPathAllowed(path, permitted))
```

- `permitted`（`usePermittedPaths`）：当前角色菜单树里的路径集合；`null` = 超管或加载中，不做菜单过滤。
- `isPathAllowed` 与路由守卫同源（含父路径放行逻辑），保证「入口可见 ⇔ 点进去不 403」。
- 访客（viewer，授权了任务/菜单管理/角色权限/仪表盘）现在只看到 3 个入口，与侧边栏完全一致；文件管理、通知公告、用户管理等全部消失。

### 卡片跳转按钮同源收口

不只快捷入口 —— 欢迎条的「通知公告」、待办卡的「任务看板」、公告卡的「全部」、最近操作的「操作日志」按钮都吃同一份 `canGo`：目标页不在菜单范围时**不渲染按钮**（访客的公告列表照样能看，只是没有「去管理页」的入口）。

## 遇到的坑

1. **grid 容器上写 flex 类无效**：`CardHeader className="flex-row items-center justify-between"` 不报错也不生效（display 仍是 grid），布局塌成两行还很难看出原因。判别方法：看 `card.tsx` 里 `CardHeader` 的基础类是不是 grid；是 grid 就用 `CardAction` 插槽。
2. **按钮权限 ≠ 页面权限**：`perm: null` 只说明「这个页面没有按钮门槛」，不说明「菜单里授权了这个页面」。两者必须都查，缺一个就会出现「入口显示但点进去 403」。
3. **welcome-bar 的通知按钮原本只判 `noticeCount > 0`**：访客能看到已发布公告（全员接口），所以按钮会出现，但目标页是公告管理页（需要菜单授权）—— 也要吃 `canOpenNotices`。

## 怎么扩展 / 使用

- **加快捷入口**：往 `ENTRIES` 里加一行 `{ path, label, icon, perm }`；`perm` 填该页数据接口的 `@Perms` 编码（如 `system:dict:list`），纯页面级入口填 `null`。菜单范围自动判定，不用额外配置。
- **新卡片要加「更多 ›」跳转**：用 `<CardAction><Button variant="link">…<ChevronRight /></Button></CardAction>`，并在 `index.tsx` 的 `canGo` 里登记目标路径后以 prop 传入。
- **想调欢迎条密度**：右列现在是「今天 / 上次登录 / 按钮组」三行，纵向间距 `gap-2.5`。

## 验证

- `tsc -b` 零错误、eslint 零告警、`node --test` 7/7 通过。
- 访客视角（viewer）推演：快捷入口 = 任务看板 / 角色权限 / 菜单管理；欢迎条无「通知公告」按钮；四张卡头部为「标题左 + 动作右」单行布局。
