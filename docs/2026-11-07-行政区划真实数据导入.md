# 行政区划全量真实数据导入

## 背景

此前 `sys_region` 仅有迁移预置的 34 个省级区划。本次灌入国家统计局 2024 年行政区划真实数据（前四级），系统具备完整省/市/区县/镇街级联能力。

## 数据概况

| 级别 | level | level_text | 条数 | 来源 |
| --- | --- | --- | --- | --- |
| 省级 | 0 | 省份 | 34 | 迁移预置（31 大陆省 + 港澳台） |
| 城市 | 1 | 城市 | 344 | 本次导入 |
| 区县 | 2 | 区县 | 3255 | 本次导入 |
| 镇街 | 3 | 街道/镇/乡 | 41350 | 本次导入 |
| 合计 | | | **44983** | 村居一级（62 万条）不导入，表设计不支持 level 5 |

- 数据源：[adyliu/china_area](https://github.com/adyliu/china_area)（国家统计局 2023/2024 县以上+县以下区划代码）
- 拼音：pinyin-pro 自动生成（仅用于关键字搜索；山西/陕西拼音同 ShanXi 属正常）
- 东莞/中山等直筒子市：镇街（level 3）直接挂市级，为官方数据形态，级联选择正常

## 港澳台码标准化（已对存量库执行）

```sql
UPDATE sys_region SET area_code='710000000000' WHERE area_code='7112684281636';
UPDATE sys_region SET area_code='810000000000' WHERE area_code='8113135772653';
UPDATE sys_region SET area_code='820000000000' WHERE area_code='8212407077174';
```

旧伪码为第三方源私有码，国标码可保证后续任何标准数据源的市/县级数据能正确挂接。

## 怎么复现导入

```bash
curl -L -o /tmp/area_code_2024.csv.gz https://raw.githubusercontent.com/adyliu/china_area/master/area_code_2024.csv.gz
gunzip /tmp/area_code_2024.csv.gz
npm install pinyin-pro   # 脚本依赖
node scripts/import-region-2024.cjs /tmp/area_code_2024.csv /tmp/region-import.sql
mysql -uroot -p --default-character-set=utf8mb4 concise_server < /tmp/region-import.sql
# 对账：SELECT level,COUNT(*) FROM sys_region GROUP BY level;
```

## 遇到的坑

1. **冒烟残留**：10.8 的导入测试数据靠 `keyword=<码前缀>` 搜索清理，但服务端 keyword 只匹配名称/拼音等文本字段不匹配 areaCode，永远搜不到 → 残留 3 条。改为按名称搜「冒烟」全删。
2. **拼音搜索断言过时**：全量数据后 `guang` 命中 288 条（各种带"广"的县镇），改用 dongguan。
3. **INSERT IGNORE 与存量行**：之前冒烟经 API 导入过的行（如部分东莞镇街）不会被本次数据覆盖，属预期。
4. CSV 城乡分类列（第 5 列）仅村居有值，前四级忽略。

## 使用/扩展

- 前端区划页已支持 level 0-3 筛选与三级级联，无需改动
- 级联接口 `GET /v1/regions/children/:parentCode` 登录即可用，性能已建 parent_code 索引
- 若需要镇街之下的村居（level 5），需先扩表：level 上限、DTO `@Max(3)`、REGION_LEVEL_TEXTS、前端筛选同步放开
