## 跑出来的三个「红」及归因

### 1. smoke-tenant 3 项失败 → 断言过时，不是隔离漏洞

断言还是「租户 A 看不到任何字典」的旧语义，但平台共享字典（`tenant_id=0` 对所有租户可见）是设计行为——库里 8 条字典全是共享的。隔离本身是好的（租户 A 私建的字典在租户 B 的列表里并不存在）。

修法：断言改成「A 只看到共享字典 + 自己的 1 条」「B 只看到共享字典、无 A 的私有码泄漏」，共享数量从库里现查，不写死。

**教训**：改了共享语义（`0 = 平台共享`）时要连冒烟断言一起改，否则每次跑都是狼来了。

### 2. smoke-auth-lock-watermark 2 项失败 → 全局水印被测成了 forced

库里 `sys_watermark_setting` 的平台行 `mode='forced'`（内容「平台水印mwi2horq」是冒烟脚本生成的水印戳，11-10 快照里还是 optional）——测试残留。`resolveWatermarkState` 的优先级里 forced 压过一切，超管自然 `editable=false`、改自己返回 1005。恢复 optional 基线后 22/22。

**教训**：任何依赖全局策略基线的测试，开头要显式把基线摆到预期状态（或跑完恢复），不能赌环境干净。

### 3. smoke-test 1 项失败 → 异步派发的时序抖动 + 顺藤摸出残留账号

「过期提醒创建即触发」在 POST 后立即查未读数撞上异步派发间隙（提醒日志 1 秒内实际落库了）。改成最多轮询 5 秒。**顺带发现**：这个脚本每次运行都留下一个**未软删的活跃账号** `smoke_verify_<stamp>`（库里已积了 2 个）。补上清理断言（`login.result.userInfo.id` → DELETE /v1/users/:id），历史残留用 API 软删归零，重跑 222/222 且无残留。

**教训**：`login.json.result` 里是 `userInfo` 不是 `user`——接口契约要对着代码确认，别猜字段。

## 安全审计发现

### 依赖（后端，生产链 2 个 moderate，均为低实际风险）

| 包 | 版本 | 依赖方 | 实际风险 |
| --- | --- | --- | --- |
| `file-type` | 16.5.4（需 ≥21.3.1） | `jimp@0.22`（水印合成） | 漏洞在 ASF（媒体格式）解析器死循环；上传先过自研位图签名白名单（`detectImageSignature`），ASF 根本到不了 file-type。升级需 jimp 0.22 → 1.x 大版本迁移，暂挂 |
| `uuid` | 8.3.2（需 ≥11.1.1） | `exceljs@4.4.0` | 漏洞在 v3/v5/v6 带 buf 的路径，exceljs 只用 v4，不可达 |

其余 27 个全在 dev 链（jest → deepmerge 等），不进运行时。npmmirror 不支持 audit 端点，要跑 `pnpm audit --registry=https://registry.npmjs.org`。

### 依赖（前端）：shadcn 放错位置，已修

`shadcn` CLI（`@shadcn/registry`、`ts-morph` 两条 moderate/low）被放在 **dependencies** 里，进了生产审计。它只在构建期被 `src/index.css` 的 `@import 'shadcn/tailwind.css'` 引用，应用代码零 import → 移到 devDependencies，生产审计归零。

### 代码扫描（全绿）

- `eval/new Function`：仅 Redis `EVAL` 常量 Lua 解锁脚本，无动态代码执行
- `child_process`：仅 codegen `spawn(process.execPath, [script, ...args], { windowsHide: true })`，无 shell、参数固定、模块名走 spec JSON 且被脚本内正则校验
- 运行时原生 SQL：全部 `?` 参数化（role/dept/log/tenant-provision/job 等 15 处），无字符串拼接
- 路径穿越：`local-storage.provider.resolve()` 与 `file.service.absolutePath()` 双双做了 `startsWith(root + sep)` 包含性校验
- 密钥：`.env` 不入库（只有 example），仓库内无硬编码 secret；冒烟临时账号密码用 `crypto.randomBytes` 生成
- `@Public()` 面：登录/验证码/SSO/健康检查，面收敛
- 防爆破：登录/校验密码共享锁定计数（5 次 → 429/1009）、全局 120/min/IP 限流，冒烟均有覆盖

### 仍挂着的已知风险（非本轮引入）

1. **admin/admin123 弱口令 + 全站 2FA 未开**（含 admin，`totp_secret` 全空）——上线前必须改密 + 开 2FA
2. helmet `contentSecurityPolicy: false`——后端只出 JSON 和文档页，页面在 nginx 那侧，建议部署时在 nginx 配 CSP
3. 生产环境默认禁用 codegen（`NODE_ENV=production` 且无 `CODEGEN_ENABLED` 即关），语义已核对无误

## 踩的坑

- **npmmirror 没有 audit 端点**，`pnpm audit` 直接报 `ERR_PNPM_AUDIT_ENDPOINT_NOT_EXISTS`，必须 `--registry=https://registry.npmjs.org`
- **冒烟脚本的 BASE 约定不统一**：dashboard/file 用 `/api` 结尾，tenant 系用 `/api/v1` 结尾——统一传错一个就会整脚本 404 崩（本次第一批就中招）。要收敛就把默认值统一掉
- **验证码冒烟必须单独实例**：`CAPTCHA_ENABLED=true` 起 3461，其余脚本要 false；关掉再开不是重启进程能省的
- **`pnpm install` 移依赖后要跑 approve**：pnpm 12 对依赖的 postinstall 脚本有白名单，移动包会触发重新审批提示

## 如何扩展

- **定时体检**：这一轮的全部命令可以串成一个 `scripts/check-all.mjs`（单测 → 起实例 → 冒烟 → 停实例 → 汇总），接 CI 或任务计划
- **断言基线自检**：冒烟脚本开头统一加「环境预检」段（全局水印模式、共享字典数量），基线不对就自动摆正，别让环境漂移变成假失败
- **jimp 升级**：1.x API 变化大（`Jimp.read` → `Jimp.fromBuffer` 等），等 file-type 的 ASF 漏洞有实际攻击面再动，现在白名单已挡住
