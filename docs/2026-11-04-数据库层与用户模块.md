### 迁移工作流怎么用

```bash
pnpm run migration:generate   # 依据实体差异自动生成迁移文件到 src/migrations/
pnpm run migration:run        # 执行未跑过的迁移（会先 build）
pnpm run migration:revert     # 回滚最近一次迁移
pnpm run migration:create     # 手写空迁移文件
```

原理：先 `nest build` 编译到 `dist/`，再用 `typeorm -d dist/shared/database/data-source.js` 连库执行。`database.config.ts` 里 `entities` 和 `migrations` 都指向 dist 路径。

### 遇到的坑（已解决）

1. TypeORM 1.1 + TypeScript 6：泛型必须写 `T extends ObjectLiteral` 约束，否则编译报错
2. `connectorPackage: "mysql2"` 在 TypeORM 1.x 已移除，写了会编译失败
3. 迁移回滚前不能删迁移源文件，revert 需要加载迁移类里的 `down()` 方法

### 接口一览（统一响应 `{ code, data, message }`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/users?page=1&pageSize=10&keyword=xx&status=1` | 分页列表（条件过滤） |
| GET | `/api/users/:id` | 详情（不存在返回 404） |
| POST | `/api/users` | 创建（参数不合法返回 400，message 是中文校验提示） |
| PUT | `/api/users/:id` | 更新 |
| DELETE | `/api/users/:id` | 删除 |

### 实测结论

创建/校验/列表/搜索/详情/更新/删除 7 项全部通过；响应不含密码字段；删除后再查正确返回 404。

### 遇到的坑（已解决）

URL query 参数进来是**字符串**，`@IsInt` 校验会失败——在 `PagerDto` 的 page/pageSize 上加 `@Type(() => Number)` 转换后解决。所有继承 `PagerDto` 的列表 DTO 自动获得此能力。

## 三、以后新增业务模块的标准套路

1. 建实体 `modules/<feature>/entities/<feature>.entity.ts`
2. `pnpm run migration:generate && pnpm run migration:run` 建表
3. 写 Create/Update/Query 三个 DTO（列表 DTO 继承 `PagerDto`）
4. Service 继承 `BaseService`，需要条件查询时重写 list 方法
5. Controller 五个路由照抄 user 模块
6. `app.module.ts` 注册模块
