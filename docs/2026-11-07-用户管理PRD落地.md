## 密码策略语义

- `must_change_password=1` 或 `password_expire_at <= now` 时：登录**照常放行**（拿到令牌），但登录响应 `mustChangePassword: true`，前端布局层弹不可关闭的改密框，改完才能用
- 管理员「重置密码」会自动置 mustChangePassword=1（重置口令视为临时口令）
- 自助改密成功：清 mustChangePassword、清 passwordExpireAt（新有效期由管理员再设）
- 扩展点：如需全局默认有效期（如 90 天），在 env 加配置并在 login 计算处补一条判断即可

## 数据范围（data_scope）

- 档位：1 全部 / 2 本部门及以下 / 3 本部门 / 4 仅本人；默认 1 = 与改造前行为一致
- 生效点：用户列表 + 用户导出（`buildListQuery` → `applyDataScope`）；多角色取「可见范围最大」档；超管角色不受限
- 部门树展开在内存完成（部门表量级小）；无部门的用户在 2/3 档看不到任何人（1=0 防误放）
- 坑：`applyDataScope` 需要异步查部门树，`buildListQuery` 已改为 async，调用方 `await`

## 遇到的坑

1. **TypeORM 反射**：`avatar?: string | null`、`Date | null` 这类联合类型会被反射成 Object 拒绝建连，列必须显式写 `type: 'varchar' / 'datetime'`
2. **登录日志缺 operateUserId**：recordLogin 此前根本没落这列，「按用户过滤」查出来恒为空；已在 recordLogin 与 auth.service 两端补齐
3. **冒烟连跑误报**：verify-password 限流 20 次/5 分钟/IP，冒烟三轮连跑会撞 429（code=429），等窗口即可；非代码问题
4. **Base UI Dialog**：DialogContent 不支持 onInteractOutside/onEscapeKeyDown，不可关闭弹窗用 `open` 固定 + 忽略 `onOpenChange` 实现
