# 角色管理 V1 增删改查重构

> 日期：2026-11-04
> 仓库：concise-server-node

## 背景

角色管理原有 CRUD 挂在旧路由 `/api/roles`，且与授权接口分散。按约定「新增/修改的接口一律挂 `/api/v1`」，本次把角色增删改查整体迁到 `/api/v1/roles` 并补齐业务规则。数据库沿用 jeecg-boot 设计（`sys_role` + `sys_role_permission` 多对多，32 位字符串主键），**无需删表重建**。

## 改动文件

| 文件 | 类型 | 说明 |
|---|---|---|
| `src/modules/role/role.v1.controller.ts` | 重写 | 完整七接口：列表/详情/创建/更新/删除 + menu-ids 回显 + menus 授权 |

| `scripts/seed-menus.cjs` | 修改 | 新增角色按钮权限段（menu_52~54），menu_40 挂 `system:role:list` |

## 接口清单（V1）

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| GET | `/api/v1/roles?keyword=` | 角色列表（全量不分页，含已授权菜单） | admin |
| GET | `/api/v1/roles/:id` | 角色详情（含已授权菜单） | admin |
| POST | `/api/v1/roles` | 创建角色（可带 menuIds） | admin + system:role:add |
| PUT | `/api/v1/roles/:id` | 更新角色（menuIds 传入即全量覆盖授权） | admin + system:role:update |
| DELETE | `/api/v1/roles/:id` | 删除角色 | admin + system:role:delete |
| GET | `/api/v1/roles/:id/menu-ids` | 已授权菜单/按钮 id 回显（授权弹窗用） | admin |
| PUT | `/api/v1/roles/:id/menus` | 保存菜单/按钮授权（全量覆盖） | admin + system:role:update |

## 业务规则

- **roleCode 唯一**：数据库唯一索引兜底，Service 层提前拦截并返回可读报错「角色编码「xx」已存在」
- **内置 admin 保护**：roleCode 为 `admin` 的角色不可删除；其 roleCode 不允许修改
- **删除保护**：角色下仍有用户（`sys_user_role`）时拒绝删除，提示先解绑；删除前自动清理 `sys_role_permission` 关联行
- **授权全量覆盖**：`PUT :id/menus` 传完整勾选列表，空数组即清空（多退少补，不重复插关联行）
- 写操作均带 `@OperLog('角色管理')`，自动进操作日志（密码类敏感字段不涉及）

## 踩坑

- **后台 `&` 起的进程随 shell 退出被杀**：长驻服务用 run_in_background 的任务方式启动
- **curl 走系统代理**：本机代理拦截 localhost 请求报 "upstream connect failed"，测试需 `--noproxy '*'` + `127.0.0.1`
- **登录测试受限**：命令行内联密码触发敏感审批，改用应用上下文直调 Service 完成验证；另注意 `.env` 里 `CAPTCHA_ENABLED=true`，本地联调可临时 `CAPTCHA_ENABLED=false` 环境变量覆盖（ConfigModule 不覆盖已存在的环境变量）
- **admin 密码不是 admin123**：库里 admin 是 jeecg 原始种子数据（salt `RCGTeGiH`），与记忆中的 admin/admin123 不符，后续联调需确认真实密码或重置
