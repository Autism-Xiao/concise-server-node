# 部门管理：一屏布局 + 表内滚动 + 吸顶表头

> 日期：2026-11-07 ｜ 仓库：concise-admin ｜ 类型：前端布局调整

## 背景

行政区划页上一轮已改成「一屏装下、数据超出只在表格里滚、表头吸顶」。本轮把部门管理页对齐同一套交互：部门树一展开、或者子部门多起来之后，整页被撑长、表头一滚就看不见，操作时需要反复回顶部确认列含义。

## 改动清单

| 文件 | 类型 | 说明 |
| --- | --- | --- |
| `src/features/system/dept/index.tsx` | 修改 | 根节点改 flex 纵向布局；加载态/错误态/正常态卡片都吃掉剩余高度；表格容器承担竖向滚动；表头 `sticky` 吸顶；顺带修正空态 `colSpan` |

`src/components/ui/table.tsx` 的 `containerClassName` 是区划页那轮加的，本轮直接复用，**没有任何 UI 基础组件的改动**。

## 具体改了什么

### 1. 页面骨架（`DeptPage` 的 return）

```tsx
<div className="flex h-full min-h-0 flex-col gap-6">      {/* 占满一屏 */}
  <div className="flex shrink-0 flex-wrap items-center justify-between gap-2">  {/* 标题栏固定高度 */}
    <h1>部门管理</h1>
    {/* 导出 / 批量删除 / 新增部门 */}
  </div>

  <Card className="flex min-h-0 flex-1 flex-col">          {/* 卡片吃掉剩余高度 */}
    <CardContent className="flex min-h-0 flex-1 flex-col gap-4">
      <div className="flex shrink-0 flex-wrap items-center gap-2">   {/* 搜索栏固定 */}
        <Input placeholder="搜索部门 / 描述" />
      </div>

      <Table containerClassName="min-h-0 flex-1 overflow-y-auto rounded-md border">
        <TableHeader className="bg-card sticky top-0 z-10">
        ...
```

三种状态（loading / error / 正常）都套了 `flex min-h-0 flex-1 flex-col`，所以切换状态时页面高度不跳。

### 2. 空态 colSpan 修正

表格实际有 **10** 列（复选框、部门名称、部门编码、部门类型、排序、状态、备注、创建时间、更新时间、操作），但空态写的是 `colSpan={9}`，导致「没有匹配的部门」提示被挤在左边、右侧留一条空白。已改 10。

## 关键坑（和区划页同一个）

1. **`min-h-0` 不能省。** flex 子项默认 `min-height: auto`，内容多高它就多高，卡片会被内容顶开，`flex-1` 完全不起作用。
2. **竖向滚动必须加在 `Table` 自己那层容器上。** `Table` 外层 div 的 `overflow-x-auto` 会顺带把 `overflow-y` 算成 `auto` —— 它本身就是滚动容器。如果在外面再包一层 `overflow-y-auto`，`sticky` 表头会粘在「高度 = 表格总高」的内层上，等于完全失效（表头会跟着滚走）。
3. **`h-full` 生效的前提**：`main[data-scroll="main"]` 有确定高度（`_authenticated` 布局里），且多标签容器是 `display: contents`，否则页面高度链条断掉。
4. **拖拽排序不受影响。** 行是原生 `draggable`，浏览器对可滚动祖先自带拖动到边缘时的自动滚动，不需要额外处理。

## 实测（headless Chrome，视口 1424×605）

| 场景 | 数据区 scrollHeight / clientHeight | 页面 scrollHeight / clientHeight | 表头 top（容器 top） | 行数 |
| --- | --- | --- | --- | --- |
| 初始（17 个部门，树全展开） | 903 / 228 | 497 / 497 ✅ 无第二滚动条 | 307（306） | 17 |
| 滚到表格底部 | 903 / 228，scrollTop 675 | 497 / 497 | **307（306）吸顶成立** | 17 |
| 搜「研发」 | 297 / 228 | 497 / 497 | 307（306） | 5 |

- 竖向溢出时页面本身不出现滚动条，滚动条只出现在表格边框内
- 滚到底部时表头仍贴在容器顶部（`thead.top` 只比容器 `top` 多 1px 边框）
- 搜索筛选后行数变少，容器高度不变，不会塌陷

## 已知遗留

- **横向宽度**：10 列在 1440 宽度下仍然超出容器，「操作」列需要横向滚动才能完整看到（沿用了 `Table` 自带的 `overflow-x-auto`，与改动前行为一致）。若要优化，可把「备注」降到 `w-32`、更新时间在小屏隐藏，或把创建/更新时间合并成一列。
- 拖拽调层级仅在未搜索状态下可用（`draggable={!filtering}`），这是原有设计，未改动。
