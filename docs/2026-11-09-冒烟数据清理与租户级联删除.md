# 冒烟数据清理与租户级联删除

> 2026-11-09 · 开发库维护

## 背景

冒烟脚本每跑一轮就往库里塞一批临时账号、租户、角色、字典、公告、部门，跑了几十轮之后：

| 表 | 清理前 | 清理后 |
| --- | ---: | ---: |
| `sys_user` | 230 | 4 |
| `sys_tenant` | 14（其中 11 条 `del_flag=1`） | 3 |
| `sys_role` | 10 | 10 |
| `sys_dict` | 42 | 2 |
| `sys_announcement` | 48 | 7 |
| `sys_depart` | 27 | 17 |
| `sys_log` | 8469 | 0（后由正常登录补回） |

账号里 226 个是冒烟产物，其中 2 个还被历史 bug 误标成 `is_platform_admin=1`（能越过所有租户校验）。

## 做了什么

### 1. `scripts/cleanup-smoke-data.mjs`（可复用清理器）

按**命名前缀**识别垃圾，默认 dry-run，`--apply` 才真删，全部在一个事务里。

| 类型 | 识别规则 |
| --- | --- |
| 冒烟账号 | `smk_` `smoke_` `iso_` `iso2_` `pf_` `um_` `um2_` `tmp_probe_` `locktest_` `wm_del_` 前缀；早期无前缀的 `permtest` `crudtest` `kimi_test` `tester` `wangwu` `zs123` 单独列举 |
| 冒烟字典 | `dict_code` 前缀 `smoke_dict_` `bs_dict_`，或等于 `test_dict` |
| 冒烟公告 | `titile` 前缀 `smoke_` `bs_` |
| 软删租户 | `sys_tenant.del_flag = 1` |
| 软删部门 | `sys_depart.del_flag = 1` |
| 孤儿角色 | `tenant_id <> 0` 且 `tenant_id` 不在 `sys_tenant` 里 |
| 日志 | 仅在 `--with-logs` 时全量清 |

保护措施：

- **白名单兜底**：`admin` / `jeecg` / `zhangsan` / `ceshi` 一旦命中删除条件直接报错中止，不执行任何删除。
- 删除顺序严格从子表到主表（`sys_user_post` → `sys_user_depart` → `sys_user_role` → `sys_user_tenant` → `sys_user_setting` → `sys_user_watermark` → `sys_user`）。
- 一个事务，出错全部回滚。

用法：

```bash
node scripts/cleanup-smoke-data.mjs                    # 预览
node scripts/cleanup-smoke-data.mjs --apply            # 执行（保留日志）
node scripts/cleanup-smoke-data.mjs --apply --with-logs # 连日志一起清
```

### 2. 修 `TenantService.remove()`：删租户要级联删角色

清理时发现 `sys_role` 里有 `tenant_id=51/52` 的角色，但 `sys_tenant` 里已经没有这两个租户 —— 原来的 `remove()` 只把租户软删，角色原封不动。

为什么必须删：

- `sys_role` **没有 `del_flag`**，这些行永远不会被任何查询过滤掉；
- 唯一键是 `(tenant_id, role_code)`，孤儿行会一直占着这个位置；
- 角色列表按租户隔离后看不到它们，属于「看不见但一直在长」的垃圾。

改法：`remove()` 改为事务，先软删租户，再按 `tenant_id` 查出角色 id，删 `sys_role_permission` 与 `sys_role`，最后清 `sys_user_tenant`；结束后 `permissionCache.invalidateAll()` + `tenantAccess.invalidate()`。

租户的**业务数据**（部门/字典/公告/任务/文件）仍然保留：租户是软删，业务数据留着才能恢复。角色不同 —— 它是权限配置，租户没了就没有存在意义。

### 3. 冒烟断言补强

`scripts/smoke-tenant.mjs` 从 27 项加到 30 项：

- 删除前租户 A 已有 3 个默认角色（验证建租户自动初始化）
- 删除租户时角色被级联清掉
- 删除租户时角色授权被级联清掉

`scripts/smoke-dashboard.mjs` 修一条过期断言：租户默认角色模板给 `viewer` 授了 `xxx:list`，所以「用户总数」不再是 `null` 而是对象 `{scope,total,active,frozen}`；断言改为判断该对象里 `total` 是数字。

## 遇到的坑

1. **`sys_role` 没有 `del_flag`** —— 一开始想跟着租户软删，查表结构才发现只能物理删。
2. **`sys_user` 没有 `dept_id` 列** —— 部门关联在 `sys_user_depart`，不是用户表字段。
3. **`sys_announcement` 的标题列名是 `titile`**（拼写错误，历史遗留），不是 `title`。
4. **`smoke-dashboard` 的 `userTotal` 是对象不是数字** —— 只看 `=== null` 的旧断言在权限变化后才暴露类型问题。
5. **`smoke-batch-io` 首轮 2 项失败是残留数据导致的偶发** —— 同一脚本连跑两次都 31/31，说明是上一次中断留下的同名部门干扰，不是功能问题。
