## 三、各处逻辑说明

### 1. 中文文件名怎么落地的

HTTP 头里文件名有两个字段：

```
Content-Disposition: attachment; filename="users-1793879023937.xlsx"; filename*=UTF-8''%E7%94%A8%E6%88%B7%E5%88%97%E8%A1%A8-2026-11-05.xlsx
```

- `filename`：纯 ASCII，给不认 RFC 5987 的老浏览器/下载器，同时也是排障时的稳定标识
- `filename*`：`UTF-8''` + `encodeURIComponent` 后的中文名，现代浏览器优先用这个
- 前端 `saveBlobFile` 优先从 `filename*` 解出中文名，取不到才退回 `filename`

六个下载接口的实际响应头（已实测）：

| 接口 | 中文名 |
| --- | --- |
| `GET /api/v1/users/export` | `用户列表-2026-11-05.xlsx` |
| `GET /api/v1/users/import-template` | `用户导入模板.xlsx` |
| `GET /api/v1/roles/export` | `角色列表-2026-11-05.xlsx` |
| `GET /api/v1/roles/import-template` | `角色导入模板.xlsx` |
| `GET /api/v1/logs/login/export` | `登录日志-2026-11-05.xlsx` |
| `GET /api/v1/logs/oper/export` | `操作日志-2026-11-05.xlsx` |

日期取导出当天（`formatDateTime(new Date()).slice(0, 10)`），同一天多次导出会重名，浏览器自动加 `(1)`，这点比时间戳更符合用户习惯。

### 2. 导入唯一键预检

`sys_user` 对 `username / phone / email / work_no` 建了唯一索引，**唯一索引不区分软删除**，所以：

- 手机号被别的账号占用 → 直接 500 级 SQL 错误，用户看不懂
- 手机号被**已软删**的账号占用 → 更费解，「明明删了还说我重复」

`importUsers` 现在会在循环前扫一遍 `existingUsers + deletedUsers` 建成占用表：

```ts
owners: Record<'phone' | 'email' | 'workNo', Map<string, { username, deleted }>>
ownedValues: Record<'phone' | 'email' | 'workNo', Map<string, string>>  // 账号 → 自己占的值
```

- `findConflict(field, label, raw, selfName)`：命中且占用者不是自己 → 整行失败
- `syncOwner(...)`：写入成功后先释放本账号旧值、再登记新值，所以同一份文件里「A 换手机号 → B 用 A 的旧手机号」不会误判
- 归一化用 `trim().toLowerCase()`，邮箱大小写不敏感，手机号容忍首尾空格
- `deleted: true` 时错误文案带「（该账号已删除，但唯一索引仍占用，请先恢复原账号或换一个）」

`describeWriteError` 是并发导入的兜底：两个请求同时过了预检，数据库仍会抛 `Duplicate entry`，这时把索引名翻成「手机号/邮箱/工号/登录账号」，其余异常保留原文便于排查。

实测输出：

```json
{"total":4,"created":0,"updated":1,"skipped":0,"failed":3,
 "errors":[
   {"row":9,"username":"qauser02","message":"手机号「13900001234」已被账号「qaowner01」占用"},
   {"row":10,"username":"qauser03","message":"邮箱「owner01@demo.com」已被账号「qaowner01」占用"},
   {"row":11,"username":"qauser04","message":"工号「QA001」已被账号「qaowner01」占用"}]}
```

第 12 行是 `qaowner01` 自己把手机号/工号填成原值 —— 走 `updated:1`，不算冲突。

### 3. 角色导入模板与行号

角色模板对齐用户模板：

- Sheet1「角色导入」：大标题、填写说明 4 条（表头下方开始填、必填标记、编码规则、不绑菜单权限）、深蓝冻结表头（行 8）
- Sheet2「填写示例」：两行样例。导入只读第一个 sheet，所以示例不会被误导入

导入用 `readXlsxTable(buffer, { headerKeys: ['角色编码', '权限字符', 'roleCode'] })`，返回 `{ rows, headerRow }`；`importRoles(rows, headerRow)` 里 `rowNumber = headerRowNumber + index + 1`，报错行号与 Excel 左侧行号一致（实测第 10 行报错 → `"row": 10`）。

### 4. 拼图验证码形状

```
PIECE_WIDTH = 60   // 透明底图宽度 = 方块边长 50 + 凸起半径 10，与前端 puzzleSize.width 1:1
PIECE_SIZE  = 50   // 方块边长
KNOB_RADIUS = 10   // 凸起/凹槽半径
```

形状判定 `insidePiece(lx, ly)`：方块 ∪ 顶部圆形凸起（圆心在方块上边中点） − 右侧圆形凹槽（圆心在方块右边中点）。`onPieceEdge` 用四邻域判断描边。落点 x∈[40, 230]、y∈[20, 90] 随机，保证凸起不越界。

生成分两步：先在背景上 `carveNotch`（形状内压暗、边缘更深）挖缺口，再从挖之前的原图取色 `buildPiece` 出拼图块并描白边。前端 `rc-slider-captcha` 只做水平平移与 `x` 上报，无需改动。

## 四、踩过的坑

1. **`res.setHeader` 写两个头容易漏**：`Content-Type` 忘了设时浏览器可能当文本打开；抽成 `setDownloadHeaders` 一处设置，避免以后再复制粘贴漏一个。
2. **中文名不能直接塞进 `filename`**：非 ASCII 会触发 `ERR_INVALID_CHAR`，必须走 `filename*=UTF-8''` + `encodeURIComponent`。
3. **唯一索引不释放软删除记录**：这是「删了还提示重复」的根因，预检必须同时扫 `delFlag=0` 与 `delFlag=1`，并在文案里说清楚。
4. **同一份文件内的值会互相占用**：先建占用表再按行 `syncOwner` 释放+登记，否则「A 换号 → B 用 A 旧号」会误报。
5. **表头带 `*` 会定位失败**：模板必填列表头是 richText（`角色编码` + ` *`），`cell.text` 读出来带星号，比较前必须 `replace(/[\s*＊]/g, '')`。
6. **行号要按 Excel 真实行算**：模板有大标题和说明，数据从第 9 行开始，不能再用 `index + 2`。
7. **前端兜底不能替代后端**：`humanizeImportError` 只是显示层保险，真正的修复在后端预检；两边都留，历史数据/并发场景才不会裸奔。

## 六、怎么用 / 怎么扩展

- **新增导出接口**：调 `buildXlsx(名称, 列, 行, { title, subtitle, notes })` 出 buffer，再用 `setDownloadHeaders(res, 'ascii.xlsx', '中文名-日期.xlsx')` 设头，两行搞定。
- **新增导入字段的唯一约束**：在 `UniqueField` 加字段名，在 `importUsers` 的占用表初始化、`pick`、`findConflict`、`syncOwner` 各加一处；同时前端 `import-error.ts` 补索引名映射。
- **改拼图形状**：只动 `insidePiece`/`onPieceEdge`，注意 `PIECE_WIDTH` 必须等于前端 `puzzleSize.width`（默认 60），否则坐标要乘缩放比。
