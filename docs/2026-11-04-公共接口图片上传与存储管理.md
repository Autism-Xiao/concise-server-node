## 与参考项目（E:\demo\nest-admin）的差异

- nest-admin 用 **Fastify multipart**（req.file()），本项目是 **Express**，改用 `@nestjs/platform-express` 自带的 multer（`FileInterceptor` + `@UploadedFile()`）
- 删除接口用项目统一的 `DELETE /api/storage` + body ids，而非参考项目的 `POST /storage/delete`
- 权限装饰器用本项目已有的 `@Perms()`，权限点命名对齐项目风格：`tools:upload`、`tools:storage:list`、`tools:storage:delete`
- 实体列名显式声明 snake_case（TypeORM 1.x 命名策略坑，见下）

## 遇到的坑

1. **tsconfig types 限定**：`"types": ["node","jest"]` 把 @types/multer 的全局 `Express.Multer` 命名空间挡掉了，报 `Namespace 'Express' has no exported member 'Multer'`——把 "multer" 加进 types 数组解决。
2. **useStaticAssets 不在 INestApplication 上**：需要 `NestFactory.create<NestExpressApplication>(...)`。
3. **静态路径含中文目录（如 /图片/）**：HTTP 请求行不允许裸中文，浏览器会自动百分号编码而 curl 不会，手测时返回 400 别误判为服务问题。返回给前端的 path 保持原样即可。
4. **Windows 端口残留**：taskkill 掉 node 子进程后父 wrapper 可能还在，3459 又被占（EADDRINUSE），用 netstat 找所有 LISTENING PID 逐一杀。
