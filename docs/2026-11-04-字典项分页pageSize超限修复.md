# 字典项列表 400：pageSize 超过后端上限

> 2026-11-04 · 前端 `concise-admin` 修复，后端未改动

## 一、现象

打开「系统管理 → 数据字典」，控制台报：

```
GET /backend-api/v1/dict-items?dictId=dict_1&page=1&pageSize=200
{ "code": 1001, "message": "pageSize must not be greater than 100", "success": false }
```

右栏字典项一直是空的，左侧字典类型能正常显示。

## 二、原因

- 后端分页参数基类 `src/common/dto/pager.dto.ts` 对 `pageSize` 有全局约束 `@Max(100)`，超过就由全局 `ValidationPipe` 抛 1001。
- 前端 `src/features/system/dict/api.ts` 的 `fetchDictItems()` 为了「一次取完再做客户端分页」，硬编码了 `pageSize: '200'`。
- 两者对上就 400。**这不是权限或数据问题**，纯粹参数越界。

## 三、改法

没有去放宽后端上限（`@Max(100)` 是防止一次性拉全表的统一护栏，其他列表都按它来），而是让前端按 100 一页翻完：

```ts
const ITEM_PAGE_SIZE = 100 // 后端 PagerDto @Max(100)
const ITEM_MAX_PAGES = 20  // 最多 2000 条，防止脏数据把页面拖死

export async function fetchDictItems(params): Promise<DictItem[]> {
  const items: DictItem[] = []
  for (let page = 1; page <= ITEM_MAX_PAGES; page += 1) {
    const result = await getApiResult<PageResult<DictItem>>(`${ITEM_BASE}?${query}`)
    items.push(...result.items)
    const totalPages = result.totalPages ?? Math.ceil(result.total / ITEM_PAGE_SIZE)
    if (page >= totalPages || result.items.length < ITEM_PAGE_SIZE) break
  }
  return items
}
```

**改动文件**

| 文件 | 类型 | 说明 |
|---|---|---|
| `src/features/system/dict/api.ts` | 修改 | `fetchDictItems` 由「单次 200 条」改为「按 100 条翻页取全量」，返回值由 `PageResult<DictItem>` 改为 `DictItem[]` |
| `src/features/system/dict/index.tsx` | 修改 | 调用处由 `setItems(result.items)` 改为 `setItems(rows)` |

页面仍是客户端分页（右栏表格自己切片），接口行为不变，只是请求次数按需增加：≤100 条时仍然只有 1 次请求。

## 四、为什么要翻页而不是改成 100

直接把 200 改成 100 最省事，但字典项超过 100 条时会被**静默截断**——用户看到的数据少了却没有任何提示。翻页取全量既守住了后端护栏，也不会丢数据。

上限 `ITEM_MAX_PAGES = 20`（2000 条）是保险丝：单个字典 2000 个字典项已属异常配置，触顶后页面只显示前 2000 条，但不会因为数据脏而卡死。

## 五、验证

造 105 条测试字典项（`dict_1` 合计 108 条），用与管理端相同的翻页逻辑请求：

```
pageSize=100 翻页取回： 108 条，去重后： 108 条
包含分页测试项： true / true     // tmp_v1 与 tmp_v105 都在
pageSize=200 旧调用： 1001 pageSize must not be greater than 100   // 复现原报错
```

确认：两页正好取完、无重复、首尾都在。验证后测试数据已删除（`dict_1` 恢复 3 条）。

## 六、同类检查

全仓扫了一遍 `pageSize` 的硬编码，其余都是 `100`（`ops/job`、`ops/online`、`system/log`、`users`），只有字典这一处是 200，已修。以后新增列表若想「一次取全量」，用同一套翻页写法，别再硬传超过 100 的值。
