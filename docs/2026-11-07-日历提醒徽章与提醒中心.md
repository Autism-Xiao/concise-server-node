# 日历提醒徽章与提醒中心（2026-11-07）

> 需求：日历日程标题旁加一个「提醒」红色徽章；顺带把提醒能力延伸成一整套可视的提醒体系。
> 后端改动极小（提醒调度器、消息落库早已具备），主要是把能力露出来 + 前端呈现。

## 功能总览

| 层级 | 功能 | 说明 |
| --- | --- | --- |
| 日程 chip | 标题旁铃铛徽章 | 红底铃铛 = 已设提醒、待触发；灰色 = 已推送过；无提醒不渲染 |
| 日期格 | 数字角标 | 日期右上角红色数字 = 当天待提醒条数（>9 显示 9+），替代原纯红点 |
| 日历页 | 「本月待提醒」面板 | 右侧栏列出本月所有待触发提醒，带倒计时（还剩 x 分钟/小时/天、已到点等待推送），支持**推迟 15 分钟**与**取消提醒**，点标题跳到该日期所在月份 |
| 顶栏 | 提醒铃铛 | 未读数红色角标（每 60s 轮询）+ 最近消息下拉 + 单条/全部已读 + 点击跳日历 |

## 关键实现细节

### 提醒状态判定（前端唯一入口）

```ts
type RemindState = 'none' | 'pending' | 'fired'
// remindAt 为空 → none；isReminded（tinyint 0/1）→ fired / pending
```

后端存 tinyint，判断一律 `!ev.isReminded`（别写 `Boolean()` 包裹再取反，eslint 会报 no-extra-boolean-cast）。

### 推迟/取消提醒的机制

`PUT /v1/schedule/events/:id` 传 `remindAt`（新时间）→ 后端 `needReregister` 分支会**重置 is_reminded=0 并重挂内存定时器**；
传 `remindAt: null` → 取消提醒但日程保留。前端改完只 patch 本地这条，不整月重拉。

### 快照揭示判据没参与本轮——但面板揭幕节奏参考了

「本月待提醒」是纯派生数据（`events.filter(pending).sort(remindAt)`），增删改只动 `events` 一处，面板/角标/徽章三处自动同步。

### 顶栏铃铛的静默降级

未读数是环境信息：拉取失败一律 `catch(() => undefined)`，**不弹 toast**（提醒服务挂了不能影响顶栏其它功能）；
标已读失败也不打断用户跳转，下次轮询自动纠正。

## 遇到的坑

1. **接口重复造轮子**：`ScheduleService` 的 `listReminders/unreadCount/markRead/markAllRead` 早已实现且挂在 `reminder.v1.controller.ts`，第一版差点在 `schedule.v1.controller.ts` 里再暴露一遍（`/reminders/*` 与 `/reminder/*` 路径还不同）。先删重，只把 service 返回值补齐（Pagination + 影响条数）。
2. **TypeScript 交叉类型把 null 挤掉**：`Partial<CreateEventPayload> & { remindAt?: string | null }` 中 `remindAt` 求交成 `string`，传 `null` 取消提醒直接类型报错。必须 `Omit<Partial<CreateEventPayload>, 'remindAt'> & { remindAt?: string | null }`。
3. **演示数据被登录滑块挡住**：`POST /auth/login` 开着滑块验证，脚本造数直接自签 JWT（`.env` 的 `JWT_SECRET`，admin id 是 `e9ca23d68d884d4ebb19d07889727dae`）。
4. **`hasPanel` 探测选择器**：shadcn `CardTitle` 渲染为 `div` 不是 `h3`，自动化断言按文本找节点更稳。
