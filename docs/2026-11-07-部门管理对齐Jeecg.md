## 每个东西是干什么的

### 1. 状态（本轮新增的可见能力）

- 列表「状态」列：StatusBadge 正常/停用；弹窗 radio 启用/停用，后端 `sys_depart.status` 原生支持。
- **用户表单贯通**：停用部门在部门多选里标灰加「（已停用）」，不能新勾选；编辑已挂停用部门的用户时照常回显、也允许摘除。要想新挂或管理，先去部门管理启用。

### 2. 部门编码（orgCode）可手编

- 新建：留空由后端按层级自动生成（A01 / A01A01）；也可手填（如 NANSHAN），重复被 400 拒。
- 编辑：可改码，改码会同步刷新挂靠用户的 `sys_user.org_code`（后端原有逻辑）；撞别人编码 400，提交自身原编码不误判。
- **换父级**：自动按新父级重算编码（手填编码时以手填为准）；**同父级内拖拽排序不再重算**——这是本轮修的存量坑，否则拖一下就把手编的 NANSHAN 冲成 AA01。

### 3. 列表对齐

- 列：部门名称（树+拖拽把手）/ 部门编码 / 部门类型（公司|子公司=主色 tag，部门=amber tag，岗位=灰 tag）/ 排序 / 状态 / 备注（超长截断+title）/ 创建时间 / 更新时间 / 操作。
- 操作：文本按钮 `+添加`（子部门）/ `修改` / `删除`，按 `system:dept:add|update|delete` 权限显隐。
- 拖拽调层级/排序、批量删除、导出等既有功能全保留。

## 遇到的坑

- **同父级拖拽也会重算 orgCode**：后端 update 只要 dto.parentId !== undefined 且没传 orgCode 就重算，而前端拖拽排序永远带 parentId → 每次拖拽都换码。修法：后端比较 `dto.parentId !== before.parentId` 才重算。
- **拖拽 walk 只拷了部分字段**：列表加了部门类型/时间列后，乐观更新 `setList(next)` 会把这些列冲成 '-'；改为展开整个节点。
- **创建时手编编码没查重**：唯一索引撞了会 500，按安全基线前置查重转 400（update 同理，需排除自身）。
- 冒烟断言清理临时部门用 `del_flag='1'`（sys_depart 的 delFlag 是 varchar，别写成数字）。

## 怎么扩展 / 使用

- **冒烟**：起 `PORT=3461 CAPTCHA_ENABLED=false node dist/main.js`，跑 `node scripts/smoke-dept-status.mjs`（9 项，临时数据自清理）。
- 想让「停用」进一步收紧（如数据权限里排除停用部门），后端在 `UserService.countScoped` / applyDataScope 的部门分支按 `status` 过滤即可，字段已就绪。
