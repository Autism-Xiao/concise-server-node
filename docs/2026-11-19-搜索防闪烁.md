# 搜索时页面闪烁修复（全局）+ 消息接口分页参数被白名单吞掉

## 背景

列表全部改成服务端筛选后（见 [列表全面改为服务端筛选](./2026-11-19-列表全面改为服务端筛选.md)），暴露一个全局体验问题：**每次搜索/翻页，整张卡片会闪一下** —— 搜索框失焦、骨架屏一闪、布局跳动。

根因：所有列表页的渲染都是 `{loading ? <骨架屏卡片> : <表格卡片>}`。服务端筛选让 `loading` 在每次搜索时变 true，于是**整张卡片连同搜索框一起被卸载再重挂**。以前客户端模式只在首次加载时 loading，问题不明显；现在每次搜索都触发，就成了高频闪烁。

修复原则：**骨架屏只在「首次加载」出现；之后的搜索/翻页表格保持挂载，只盖一层轻量遮罩**。布局不跳、输入框不失焦、加载状态仍然可见。

## 踩的坑

### 1. ValidationPipe 的 whitelist 会吞掉 DTO 未声明的参数（无报错）

前端消息页传 `pageSize=20`，接口却始终每页 10 条 —— `QueryMessageDto` 只声明了 `keyword/msgType`，全局 `ValidationPipe(transform + whitelist)` 把 `page/pageSize` **静默剔除**，service 里 `query.pageSize` 恒为 undefined，回落默认 10。接口不报错、参数类型上也说得通，极难排查。

**教训**：任何 service 里手写 `query: XxxDto & { page?: number; pageSize?: number }` 的交集签名都是个信号 —— 说明 DTO 没继承 `PagerDto`，参数根本到不了 service。本次已全部消灭（grep `& { page?: number` 为 0）。

### 2. `npm run build` 无输出 ≠ 构建成功

重启实例后验证 `messages?pageSize=20` 仍返回 `size: 10`，一度怀疑修复没生效 —— 实际是 dist 目录时间戳还停在半小时前：那次 `npm run build` 退出码 0、无任何输出，但**没有产出**。改用 `npx tsc -p tsconfig.build.json` 直接编译后正常。**判新代码生效的唯一可靠依据是产物时间戳 / `curl 新路由` 的行为，不是命令退出码。**

### 3. dashboard 冒烟两条断言是旧预期（viewer 权限被模板设计排除）

`smoke-dashboard.mjs` 断言「viewer 用户总数可见（有 system:user:list）」，但租户角色模板早已把 `/system/users`、`/system/role` 列入 `TENANT_RESTRICTED_MODULES`（访客能翻手机号/邮箱是隐私面，**设计上就不给 viewer**），所以仪表盘对应块按设计返回 null。断言已改为期望 null，60/60 通过。

顺带发现两个环境问题（未在本轮修，属既有脚本与策略脱节）：
- `smoke-tenant-isolation.mjs` / `smoke-tenant-demo.mjs` 用弱口令建号被密码策略 400 拦截，脚本中途退出；
- 默认租户 viewer 角色的存量授权比模板缺 45 条（用 `POST /v1/tenants/provision-all` 补齐），且 **provision-all 补权后没有失效角色权限缓存**（Redis `perm:role:*` 仍是旧集合，需手动失效或等 TTL）—— 这个缓存失效缺口值得单独修。

### 4. 遮罩层的 z-index 要压过表格内 sticky 表头

部门树表的表头是 `sticky top-0 z-10`，遮罩层用 `z-20` 才能盖住它；其他表没有 sticky 头，`z-10` 够用。

## 设计细节

- **`booted` 在 finally 里置位**：请求失败也置 true —— 首次失败后显示错误卡片和「重试」，不要永远停在骨架屏。
- **遮罩不拦截交互**（没加 pointer-events 阻断）：搜索/翻页时旧数据仍可读，操作按钮要不要禁用由页面自己决定，hook 不越权。
- **`aria-live="polite"`**：无障碍上让读屏器感知加载状态。
- **竞态防护沿用上一轮的请求序号**：慢请求不落地，遮罩只会闪一次然后直接换新数据。

## 如何扩展

**新列表页的 loading 正确姿势**（三选一，按页面形态）：

1. 用 `useServerTable` 的页面：骨架屏条件写 `!booted`，`<DataTable loading={loading} />` 让遮罩自己出现；
2. `useDataTable` 小表页：自己加 `const [booted, setBooted] = useState(false)`，首次 `load()` 的 finally 里置位，骨架屏条件 `!booted`；
3. 手写分页页：同 2，容器记得 `relative`，遮罩 `absolute inset-0`。

**判据一句话**：骨架屏是「页面还没站起来」，遮罩是「页面站着换数据」。任何时候都不要让 loading 把搜索框卸下去。
