## 背景

## 相比旧生成器修掉的 6 处脱节

1. **唯一键真查重**：Service 生成 `assertUnique`（按租户作用域、含软删占用——软删行仍占数据库唯一键所以查重不过滤 del_flag）+ 捕获 ER_DUP_ENTRY 转 400；迁移生成 `UNIQUE KEY (tenant_id, 字段)`。
2. **列表查询有 DTO**：ListXxxDto，page/pageSize/keyword/q 字段带 `@Type(() => Number)`，不再被 ValidationPipe 白名单丢弃。
3. **create_by/update_by**：实体列 + 迁移列 + Service 里 `TenantContext.userId()` 自动戳记。
4. **菜单 INSERT 现代化**：17 列全量（component/is_route/perms/perms_type/hidden/rule_flag/**scope**），按钮权限 perms_type='0'，菜单挂 `--menu-parent`（默认 menu_collab）。
5. **前端规约对齐**：DataTable（序号列/多选前置/固定操作列自动获得）+ AppDrawer 表单抽屉 + ConfirmDialog，替代旧的自绘 table + 手写弹窗。
6. **自动注册**：app.module、前端路由文件、page-registry、i18n 中英双条全部脚本写入（锚点找不到则明确告警不写坏文件），`--dry-run` 全程预览。

## 生成器用法

```bash
node scripts/gen-module.cjs \
  --module customer --label 客户 --perms customer \
  --fields "name:string:客户名称:rs, contact:string:联系人, phone:string:电话:u, vip:enum:客户等级:e=0:普通|1:VIP"
# 生成后：pnpm migration:run → POST /v1/tenants/provision-all
```

字段格式 `名称:类型:中文备注[:选项]`；选项连写：r 必填 / u 唯一 / q 精确过滤 / s 模糊搜索 / default=N / e=值:标签|值:标签（enum 专用，标签里别用冒号）。

## 踩的坑（都已在生成器里规避）

1. **TypeORM `type: 'enum'` 会触发原生枚举校验**（要求 enum/enumName 属性）→ enum 字段实体落 `tinyint`，值域靠 DTO `@IsIn` 控制；
2. **`@Column({ length })` 可空必须显式 `type: 'varchar'`**，否则推断成 Object 报 DataTypeNotSupportedError（老坑复发，已写进模板）；
3. **DTO 不满足 `Record<string, unknown>` 索引签名** → assertAllUnique 参数收 `object` 再内部断言；
4. **生成代码按字段类型条件化 import**（无 bool 字段不 import Switch 等），否则 tsc 未使用报错；
5. **无头验证注入登录态要带全 5 把钥匙**：concise-auth/token/user 之外还有 `concise-perms`、`concise-menus`（登录响应写入的权限树），缺了会进「尚未分配功能权限」守卫页。

## 如何扩展

- 加字段类型：`TYPE_MAP` 加一行（ts/mysql/dto/fe 四映射）+ `NUMERIC_TYPES` 视情况 + 前端 cell/控件分支；
- 加新控件映射：`customer-form-drawer` 模板的字段分支处加 case；
- 注册锚点变化：app.module（最后一个 `./modules/` import）、page-registry（PAGE_REGISTRY 开行）、i18n（nav.system 中文/英文行）——锚点失效时生成器会告警而非写坏文件；
- 后续规划：P1 加 `--smoke` 自检（生成→build→curl→revert 一条命令回归），交互式 CLI 与可视化壳均以本 DSL 为底座。
