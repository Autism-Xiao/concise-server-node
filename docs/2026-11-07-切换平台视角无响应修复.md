# 切换「平台视角」点了没反应 —— 根因与修复

## 现象

超管在顶栏把租户切到「深圳 / 长沙」后，想再切回**平台视角**，点击下拉里的「平台视角」：

- 没有任何提示（无 toast、无报错）
- 页面不刷新、数据不变
- 顶栏标签仍显示「平台视角」（明明正在某个租户里）

## 根因

问题不在切换接口，而在 `GET /v1/tenants/mine` 返回的 `current` 恒为 `null`。

`TenantService.mine()` 里原来这么写：

```ts
const { tenantId } = await this.tenantAccess.resolveTenant(userId)  // ← 没传 requested
```

`resolveTenant(userId, requested)` 第二个参数才是 `X-Tenant-Id` 请求头的值。不传它：

- 超管分支 `if (requested && requested > 0)` 永远不成立 → 一律返回 `tenantId: null`
- 也就是说，无论当前真的在哪个租户里，`mine.current` 都是 `null`（「平台视角」）

前端 `tenant-switcher.tsx` 用 `current` 做两件事：

```tsx
<DropdownMenuItem disabled={current === null} onSelect={() => handleSwitch(0)}>
{current === null ? <Check /> : null}
```

`current` 恒为 `null` → **「平台视角」这一项永远是 disabled + 打勾状态**，点击事件根本不触发，所以既没有请求也没有提示 —— 表现就是"点了没反应"。

同一个原因还带来两个错位：

- 顶栏标签恒为「平台视角」，即使实际在深圳租户里
- 租户列表里当前租户那一项没有勾，也不会被禁用（可以重复点自己）

## 修法

「当前生效租户」这件事，中间件已经在每个请求进入时按 `X-Tenant-Id` 算好了，并放进 AsyncLocalStorage（`TenantContext`）。`mine()` 不该再自己算一次，直接读上下文：

```ts
const store = TenantContext.get()
const current = store ? store.tenantId : (await this.tenantAccess.resolveTenant(userId)).tenantId
```

`store.tenantId` 的三态和语义完全对得上前端需要的东西：

| 值 | 含义 | 切换器表现 |
| --- | --- | --- |
| `null` | 超管且未指定租户（平台视角） | 顶部显示「平台视角」，该项打勾 + 禁用 |
| `0` | 无任何租户归属（只看共享数据） | 普通用户显示「未分配租户」 |
| `> 0` | 该租户 + 平台共享数据 | 顶部显示租户名，该项打勾 + 禁用 |

保留 `resolveTenant` 兜底只是为了脚本/单测里直接调 service（没有请求上下文）时不至于拿不到值。

## 改了哪些文件

| 文件 | 类型 | 说明 |
| --- | --- | --- |
| `src/modules/system/tenant/tenant.service.ts` | 修改 | `mine()` 改读 `TenantContext.get()?.tenantId`，不再重复 resolve（丢掉请求头） |
| `scripts/smoke-tenant.mjs` | 修改 | 新增回归断言「超管带租户头时 mine.current = 该租户」，共 27 项 |

前端 `tenant-switcher.tsx` / `api.ts` **未改**：它的逻辑本身是对的（后端返回什么就显示什么、`disabled` 判断依赖 `current`），错的只是后端给的值。

## 为什么之前冒烟没抓到

原脚本只测了三种情况：

1. 普通用户 `mine.current === A`（`preferredTenantId` 生效，走的不是请求头分支）
2. 超管 `mine.isSuper === true`、列表含全部租户（没看 `current`）
3. `switch(0)` 返回 `tenantId === null`（接口本身是对的）

缺的正是「超管**带着** `X-Tenant-Id` 请求时 `mine.current` 应该等于该租户」这一条 —— 已补上，断言失败信息会打印两边实际值。

## 怎么验证

```powershell

# 2. 另开一个终端跑冒烟（27 项应全 PASS）
node scripts/smoke-tenant.mjs
```

浏览器侧手工验证：

1. 超管登录 → 顶栏下拉选「深圳演示公司」→ 页面刷新，顶栏应显示「深圳演示公司」，下拉里该项打勾且置灰
2. 再点「平台视角」→ 页面刷新，顶栏回到「平台视角」，用户列表 / 部门等恢复成全量

## 坑与注意

- **不要在 service 里自己解析请求头来算「当前租户」**。只要越过中间件，`X-Tenant-Id` 就没了；正确入口只有 `TenantContext.get()`（读）与 `TenantContext.run()`（建）。任何"顺手再 resolve 一次"的写法都会退化成忽略请求头。
- `moni` 这类接口（`mine` / 首页概览）返回的"当前状态"要和**实际查询用的过滤值**同源，否则前端展示与数据永远差一拍。
- `TenantAccessService` 的结果按 userId 缓存 30s，`switch()` 改的是 `sys_user.login_tenant_id`，**不影响** `membership` 缓存；所以切租户后同一请求内的 `current` 依然由请求头决定，不会因为缓存而误判。

## 扩展

后续如果要加「切换后保持某个页面内的筛选」之类的逻辑，记住切换是**整页重载**（`window.location.reload()`）—— 租户变了几乎每个列表的数据源都变了，局部刷新会留下上一个租户的分页/字典缓存。要保留状态请走 URL query，不要走内存。
