# 菜单快照自动对账：后端新增菜单无需重登即可见

## 背景

用户反馈「没看到代码生成菜单」。排查结论：后端 `/v1/auth/permissions` 已返回该菜单（迁移已落库、admin 可见），但**前端菜单树只在登录那一刻写进 localStorage（`concise-menus`）**，之后不再刷新——登录早于菜单入库的用户刷新页面也看不到，必须退出重登。同类问题还有：切换租户视角后不重拉菜单，平台级菜单（scope=platform）会残留在租户视角的侧边栏。

## 方案

新增「权限快照对账」机制（`src/lib/permissions.ts`）：

- `syncPermissionSummary(options?)`：拉一次 `/v1/auth/permissions`，把 `permissions` / `menus` 与本地快照做 JSON 比对，**有差异才落盘**并 `notifyPermissionsChanged()` 通知侧边栏重算
- 挂载点 1：`_authenticated.tsx` 的 `AuthenticatedLayout` 挂载时对账一次（进入工作区即修正陈旧快照）
- 挂载点 2：`tenant-scope-provider.tsx` 的 `applySwitch` 里 `setTenantId` 之后 `force` 对账（换视角菜单必然不同，且此时请求头已是新租户）

设计取舍：按「租户视角」做 key（同视角只对账一次）；并发去重（`summarySyncing`）；失败静默保留本地快照下次再试；401 由 http 层统一踢登录（此处语义正确，与 `settings.ts` 不能用 `getApiResult` 的场景不同）。

## 文件清单

| 文件 | 类型 | 说明 |
| --- | --- | --- |
| `src/lib/permissions.ts` | 新增能力 | `syncPermissionSummary()`：权限/菜单快照与后端对账，按租户视角 key 去重 |
| `src/routes/_authenticated.tsx` | 接线 | `AuthenticatedLayout` 挂载时触发一次对账 |
| `src/context/tenant-scope-provider.tsx` | 接线 | 切换租户落库新租户头后 `force` 对账 |

## 踩的坑

1. `isAuthenticated()` 只认 `concise-auth === 'true'`，对账前必须先判，否则登录页也会发请求。
2. 对账请求走 `getApiResult`：401 会踢登录页——在这里是**正确语义**（快照对账的前提就是已登录），别照搬到 `settings.ts` 那种 401 不该踢的场景。
3. 切租户的对账要放在 `setTenantId` **之后**：请求头 `X-Tenant-Id` 从 localStorage 读，顺序反了会拿旧视角的菜单。
4. 验证方法：无头浏览器注入「剔除目标菜单」的伪造快照，进工作区后断言 `concise-menus` 恢复完整且侧边栏文本含目标项——比肉眼刷新可靠。

## 如何扩展

- 以后后端新增菜单/按钮权限（迁移、代码生成器自动注册、provision-all），用户**刷新页面即可见**，不再需要重新登录。
- 若后续做「权限变更实时推送」（WebSocket/SSE），把推送回调接到 `syncPermissionSummary({ force: true })` 即可，落盘与通知逻辑已收敛在这一个函数里。
