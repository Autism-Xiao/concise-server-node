## 背景

多租户功能（后端 `88caa2c`）上线后有个体验问题：库里只有「平台默认租户」和一个空的「前端联调租户」，切换租户后列表几乎没变化 —— 功能在跑，但看不出隔离效果，也没法给别人演示。

本次不碰业务代码，只做两件事：**清掉测试残留** + **灌一套能一眼看出隔离的演示数据**。

## 怎么验证

```powershell
# 1. 灌数据（幂等，可重复跑）
npm run build; node scripts/seed-tenant-demo.cjs

# 2. 起一个免验证码的测试实例
$env:PORT="3461"; $env:CAPTCHA_ENABLED="false"; node dist/main.js

# 3. 另开一个终端跑断言
node scripts/smoke-tenant-demo.mjs
```

界面上看：admin 登录 → 顶栏切「深圳示范科技」→ 部门管理只有深圳那套、公告只有深圳两条 + 平台公告；切「长沙示范科技」→ 全换；切回「平台视角」→ 两家都能看到（不过滤）。

冒烟结果 **21/21 通过**：部门互不可见（4 项）、公告互不可见（2 项）、共享公告三租户可见（2 项）、平台视角全可见（1 项）、mine 返回全部租户（2 项）、越权 403（1 项）、无归属账号 mine 为空（2 项）等。

## 遇到的坑

1. **公告 `send_status` 枚举填错**：`'0' 未发布 / '1' 已发布 / '2' 已撤销`。第一次按「2 = 已发布」灌，前端公告栏什么都看不到。已修，并且共享公告改成 upsert（只插不改会让历史错误值永远留在库里）。
2. **`org_code` / `post_code` / `level_name` 是全局唯一索引，不是租户内唯一**。所以深圳用 `B01` 段、长沙用 `C01` 段，岗位/职级名称也带城市前缀。这是当前表结构的限制，见下方「后续建议」。
3. **数组 `includes` 是精确匹配**：断言公告标题时写 `titles.includes('【平台】系统维护公告')`，而库里标题带了「（所有租户可见）」，导致误报功能失败。改用 `some(t => t.includes(...))`。
4. **新账号访问业务接口是 403，别当成租户问题**：没有任何角色的账号调 `/depts` 会被 `PermsGuard` 拦。验证租户层要用登录即可访问的接口（`/tenants/mine`）。
5. **前端任务页仍走 mock**（`/mock/tasks.json`），任务模块只有 legacy 无前缀路由，`LEGACY_ROUTES_ENABLED` 关闭时不可达。所以演示任务数据只在库里，界面上看不到 —— 是既有遗留，不是本次引入。

## 后续建议（未做）

**把三个编码的唯一索引改成租户内唯一**：真 SaaS 里「部门编码 A01」应该是每家公司各有一套，现在全局唯一会逼着运维给每家客户换编码段。改法：

```sql
ALTER TABLE sys_depart DROP INDEX <org_code 唯一索引名>,
  ADD UNIQUE KEY uniq_depart_tenant_org (tenant_id, org_code);
-- sys_position.post_code、sys_level.level_name 同理
```

改之前要先确认业务代码里按 `org_code` 单列查重的地方（`DeptService.create/update` 的前置查重）一并加上 `tenant_id` 条件，否则查重会跨租户误判。
