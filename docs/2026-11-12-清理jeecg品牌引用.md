# 清理 jeecg / JeecgBoot 品牌引用

日期：2026-11-12
范围：后端 `concise-server-node` + 前端 `concise-admin` 源码

## 一、为什么做

项目早期的表结构（`sys_user` / `sys_role` / `sys_permission` / `sys_dict` / `sys_quartz_job` 等）是照着某个 Java 后台脚手架（jeecg-boot）设计的，代码里留下了大量「对齐 JeecgBoot」「jeecg 语义」「jeecg 原生列」这类注释。现在项目已经独立演进，注释里的品牌名既不准确（很多设计早就改过）也会误导后来人，因此统一清掉。

**只清引用，不改行为**：没有一行可执行逻辑被改动（除注释、Swagger 文案、建表 COMMENT 文本）。

## 二、改了什么（按文件类型）

| 文件 | 类型 | 说明 |
| --- | --- | --- |
| `src/migrations/*.ts`（12 个） | 注释 / 建表 COMMENT | 去掉「（对齐 JeecgBoot sys_xxx）」括注，`COMMENT='用户表（对齐 …）'` → `COMMENT='用户表'`；字段映射说明改写为「原表结构」 |
| `src/modules/**/entities/*.entity.ts`（14 个） | 类注释 + `@ApiProperty` 描述 | 表说明改为中性描述；`'租户 ID（对齐 JeecgBoot，默认 0）'` → `'租户 ID（默认 0）'`；`@ApiProperty` 里 `（JeecgBoot 语义）` → `取值`/`结果` |
| `src/modules/**/*.service.ts`、`*.controller.ts`（约 20 个） | 注释 + `@ApiOperation` | 「status 为 jeecg 语义 0 成功 / 1 失败」→「status 取值 0 成功 / 1 失败」；「密码按 JeecgBoot 算法加密入库」→「密码由服务端哈希后入库」（**原文本来就是错的，新用户走 Argon2id**） |
| `src/common/*`、`src/shared/*`、`src/helper/*`、`src/config/*` | 注释 | 「对齐 JeecgBoot Result<T>」等去掉品牌，补上真实字段列表（`code / message / result / success / timestamp`、`records / total / current / size / pages`） |
| `src/utils/password.util.ts` | 注释 | 「JeecgBoot 兼容密码工具」→「历史密码兼容工具」，算法说明保留（PBKDF1 + DES 细节对维护有用） |
| `scripts/seed-level-post.cjs`、`scripts/seed-menus.cjs` | 种子数据备注 / 注释 | 职级 remark 里 `'JeecgBoot position_rank=1…'` → `'职级序号 1…'` |
| 前端 `src/features/**/*.ts(x)`、`src/lib/http.ts`（13 个） | 注释 + 一处 `DialogDescription` | 去掉「（对齐 JeecgBoot）」「jeecg 语义」；定时任务弹窗的可见文案改为「任务类名对应后端已注册的执行器」 |

合计：后端 72 个文件、前端 13 个文件，约 180 处。

## 三、没动的地方（有意保留）

| 位置 | 原因 |
| --- | --- |
| `src/utils/password.util.ts` 的 `encryptPassword` / `deriveKeyIV` / `randomSalt` | **还在用**。库里 `jeecg`、`zhangsan` 两个账号仍是旧格式哈希（16/32 位十六进制），删掉实现这两个账号就无法登录。只改了注释措辞，函数与行为不变 |
| `src/migrations/1793765557497-Migration.ts` 的 INSERT 数据行 | 真实初始数据：`winter@jeecg.org`、`https://static.jeecg.com/...`、账号名 `jeecg`。改文本会篡改历史数据，且该迁移早已执行完 |
| `scripts/cleanup-smoke-data.mjs` 的 `PROTECTED_USERS` | 里面的 `'jeecg'` 是**真实账号名**（防误删白名单），不是品牌引用 |
| `docs/**` 历史变更文档 | 属于当时的记录，改写等于篡改历史；本次结论已记在本文件 |
| `sql/*.sql` 整库快照 | 数据库导出件，不是源码 |

## 四、坑与经验

1. **批量正则替换中文注释会造病句**。第一遍用「去掉括注 + 兜底把品牌名换成『旧系统』」的规则跑，出现 `旧系统 结构带独立 id`（多余空格）、`岗位： sys_position`（吞了前半句）、`用户管理列表要 演示的`（语法崩）等问题。第二遍改成逐条精确字符串替换才修好。**批量改注释务必回读 diff 逐行看**，不能只看「jeecg 没了」。
2. **品牌名出现在三种位置，处理方式不同**：①纯括注（直接删）②句子主语（要换成「原表 / 既有设计 / 历史数据」）③真实数据（必须保留）。用同一个规则一把梭必然出错。
3. **顺手发现并修正了一处事实错误**：`@ApiOperation` 和 `create-user.dto` 原写「密码按 JeecgBoot 算法加密入库」，实际 `UserService.create` 走的是 `hashPassword`（Argon2id）。旧算法只在**校验历史数据**时才用。
4. **后端 jest 有一个套件失败与本次无关**：`src/helper/export/excel-export.spec.ts` 报 `Must use import to load ES Module: @nestjs/common`，是本机 Node 22 跑 ESM 依赖的老问题（需 Node ≥ 24.9），改动前就存在。其余 4 套件 39 个用例全过。
