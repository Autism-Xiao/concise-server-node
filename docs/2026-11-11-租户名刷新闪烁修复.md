# 顶栏租户名刷新闪烁修复（mine 缓存水合）

## 问题

页面刷新（F5 / 首次进入）后，顶栏「当前租户」先短暂显示默认值——超管显示「平台视角」、普通用户显示「未分配租户」——等 `GET /v1/tenants/mine` 返回后才跳成真实租户名。根因：`TenantScopeProvider` 的 `tenants/current/isSuper` 三个 state 初始全空，`currentLabel` 只能先算默认值；而 localStorage 里只有租户 id（`concise-tenant`），**没有名称**，首帧无从渲染。

## 改了哪些文件

| 文件 | 类型 | 说明 |
| --- | --- | --- |
| `concise-admin/src/context/tenant-scope-provider.tsx` | 修改 | 新增 `concise-tenant-info` 本地缓存；Provider 初始化时**同步水合**（`useState(readTenantInfoCache)`），首帧直出真实租户名/当前 id/切换入口；mine 返回后写缓存静默校准 |
| `concise-admin/src/lib/auth.ts` | 修改 | `logout()` 增加清除 `concise-tenant-info`（登出清干净，不留跨会话残留） |

## 每个东西是干什么的

- **`readTenantInfoCache()`**：读缓存并做两道校验——JSON 结构完整 + `user` 字段等于当前登录用户名（`getUsername()`）。换账号（非登出路径，如令牌过期后直接换号登录）时 user 不匹配即作废，回落到旧的「加载后修正」行为，不会串台显示别人的租户。
- **`writeTenantInfoCache()`**：mine 每次成功返回后写回 `{ user, tenants, isSuper, current }`。租户改名/停用/角色变化在下一次刷新即体现（缓存只是展示水合源，不是数据真源）。
- **`tenantInfoLoaded` 初始为 `Boolean(cachedInfo)`**：有缓存时切换入口菜单（头像下拉的「当前租户」行 + 切换菜单项）立即渲染，不再等接口。切换弹窗/顶栏角标/工作台都吃同一个 context，一并受益。

## 遇到的坑

- **vite 只监听 IPv6**：本机 5173 的 vite 监听 `[::1]:5173`，`curl http://127.0.0.1:5173`（IPv4）报 000 像是挂了，实际浏览器访问 localhost 正常——判断服务死活别只测 127.0.0.1，先看 `netstat` 监听地址。
- 缓存写在 try/catch 里静默失败：隐私模式/配额满只是退回旧的闪烁表现，不值得为展示优化报错。
- 切换租户后 `setCurrent(applied)` 与缓存里的 `current` 有短暂不一致，但 epoch 变化立即触发 mine 重拉并写缓存，窗口毫秒级，可忽略。

## 怎么扩展 / 使用

- 无需任何配置，刷新页面即可看到效果；想清掉缓存手动删 localStorage 的 `concise-tenant-info` 即可。
- 以后若有别的组件需要「刷新后立即可用的租户信息」，直接读 `useTenantScope()`（已自动水合），**不要**再自己拉一遍 mine。
