## 脚本为什么密码不上命令行

`mysqldump -p123456` 会把密码暴露在进程列表、shell 历史和错误输出里，也容易触发仓库的敏感信息检查（本轮就因为这个读不了旧 README）。脚本改成：

```js
spawn(MYSQLDUMP, args, { env: { ...process.env, MYSQL_PWD: password } })
```

密码从 `.env` 的 `DB_PASSWORD` 读，只经环境变量传给子进程。

## 坑

1. **日期不能用 `toISOString()`**：那是 UTC，晚上 19:50 导出会被记成 `2026-11-10` 没错，但 0:30 导出就会变成前一天。脚本用 `toLocaleDateString('sv-SE')` 取本地日期（`sv-SE` 格式天然是 `YYYY-MM-DD`）。
2. **`--routines --events` 在 8.4 需要权限**：root 没问题；换成受限账号导出会报错退出，脚本已保留 stderr 输出便于定位。
3. **导出不等于可恢复**：必须实测导入。本轮用 `restore_check_20261110b` 临时库跑了一遍，验完立即 `DROP DATABASE` 清理。
4. **`--no-tablespaces` 不能省**：缺了它，非 root 账号会因 `PROCESS` 权限不足报 `Access denied`。
5. **快照是「数据 + 结构」全量**：含用户密码哈希、日志等真实数据，仓库是私有的才可提交；公开仓库要先脱敏。

## 怎么用 / 怎么扩展

```bash
node scripts/dump-sql.mjs                    # 全量，文件名自动带今天日期
node scripts/dump-sql.mjs --schema-only      # 只要结构（给别人建空库用）
node scripts/dump-sql.mjs --date=2026-12-01  # 指定日期（补历史快照用）
```

- 换机器导出：`MYSQLDUMP_PATH="D:/mysql/bin/mysqldump.exe" node scripts/dump-sql.mjs`
- 想只导某几张表：在脚本 `dumpArgs` 末尾追加表名（mysqldump 支持 `db table1 table2`），文件名建议用 `用途_日期.sql`
- 想把旧快照清掉只留最新：`git rm sql/concise_server_full_2026-11-07.sql`（本轮保留作对比）
