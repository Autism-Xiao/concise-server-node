# 整库恢复到 2026-11-17 快照（含 .env 重建）

> 2026-11-17 · 运维/数据 · 高风险操作，已备份 + 用户确认

## 背景

用户要求「把 sql 下的 `concise_server_full_2026-11-17.sql` 覆盖现在的数据库」。当前库还是 11-15 的形态（33 表 / 55 条迁移），而 11-17 快照是 41 表 / 72 条迁移（多了租户套餐、代维审计、Webhook、应用密钥、参数配置租户级等一批表）。

属于**整库覆盖**：先 `DROP DATABASE` 再建库导入，今天 19:37 之后的所有改动数据都会回退。

## 执行前：先备份当前库

```bash
MYSQL_PWD=*** mysqldump -h127.0.0.1 -P3306 -uroot \
  --default-character-set=utf8mb4 --single-transaction --quick --no-tablespaces \
  --set-gtid-purged=OFF --routines --events --triggers --hex-blob concise_server \
  > sql/concise_server_full_backup-pre-restore-2026-11-17.sql
```

产物 7,387,993 字节（33 表），末尾 `Dump completed on 2026-11-17 22:23:31`。**这个文件是本次唯一的回滚入口**，目前留在工作区未入库（7.4 MB，是否需要入库由仓库策略决定）。

## 执行：停后端 → 重建 → 导入

```bash
# 1) 停 3000 上的后端（避免导入期间连接报错、脏查询）
#    Stop-Process 掉监听 3000 的进程
# 2) 重建库（utf8mb4_unicode_ci 必须显式指定，快照不带 CREATE DATABASE）
mysql -uroot -e "DROP DATABASE IF EXISTS concise_server;
  CREATE DATABASE concise_server COLLATE utf8mb4_unicode_ci;"
# 3) 导入
mysql -uroot --default-character-set=utf8mb4 concise_server \
  < sql/concise_server_full_2026-11-17.sql
```

## 意外：`.env` 不见了，启动直接失败

重启后端报：

```
环境变量校验未通过，请检查 .env：
  - JWT_SECRET 长度至少 16 位；缺少 JWT_SECRET（accessToken 签名密钥）
  - JWT_REFRESH_SECRET 长度至少 16 位；缺少 JWT_REFRESH_SECRET（refreshToken 签名密钥）
```

根因：仓库在 22:19 被更新（拉到 `aaaaee8` 等新提交），`.env` 是 gitignore 的未跟踪文件，被这次清理一起带走了。**代码没坏，是运行环境丢了。**

按 `.env.example` 重建，只填必需项，值取自历史记忆与已验证的连接信息：

- `DB_PASSWORD=123456`（本次 mysql 导入用的同一口令，已实测）
- `JWT_SECRET` / `JWT_REFRESH_SECRET`：`crypto.randomBytes(32).toString('hex')` **新生成**（两个不同）
- `CAPTCHA_ENABLED=false`（本地直连调试）、`REDIS_ENABLED=false`（单实例不需要）、`RATE_LIMIT_ENABLED=true`、`LOGIN_MAX_FAILS=5`
- `SWAGGER_ENABLED=true`

**副作用：JWT 密钥换了，所有旧 token 失效，前端需要重新登录一次。** 这是重建 .env 无法避免的。

第二个坑：`SWAGGER_ENABLED=`（留空）会挂在 `@IsIn(BOOLEAN_STRINGS)` 上——`@IsOptional()` 只放过 `undefined/null`，**不放过空字符串**。要么写 `true`，要么整行删掉。

## 踩的坑

- **`.env` 不在 git 里，任何 `git clean`/换分支都可能带走它**。重建后建议单独备一份到仓库外（或改用 `.env.local` + 密码管理器），否则下次换环境又要重新生成 JWT 密钥、全员重登。
- **快照不含 `CREATE DATABASE`**，所以必须手工建库并显式指定 `utf8mb4_unicode_ci`（默认 `0900_ai_ci` 会和 `sys_user` 的 `unicode_ci` JOIN 报错）。
- **导入前必须停后端**：连接池持有旧库句柄、迁移表在写入，导入中途可能拿到半截状态。
- **`@IsOptional()` 不兜空字符串**：`.env` 里留 `SWAGGER_ENABLED=` 会因为 `IsIn` 校验直接启动失败，这类布尔项要么写值要么删行。
- **覆盖式恢复会让前端会话全废**：JWT 密钥变更 + `sys_user` 数据回退，前端要重新登录，别误判成「登录坏了」。

## 如何扩展

- **只恢复某几张表**：不要跑整库。用 `mysql concise_server < 快照` 会逐表 `DROP + CREATE`（快照里每表自带 `DROP TABLE IF EXISTS`），单表恢复就从快照里截取该表的 DDL + INSERT 单独执行。
- **回滚本次**：`DROP DATABASE` 后导入 `sql/concise_server_full_backup-pre-restore-2026-11-17.sql` 即可回到 22:23 的现场。
- **把 .env 纳入密钥管理**：至少把 `JWT_SECRET` / `JWT_REFRESH_SECRET` / `DB_PASSWORD` 存到密码管理器，重建时直接取回，避免「重建即全员掉线」。
