# 文件管理落地（P0）：sys_file + 个人网盘接口 + 前端接真实数据

**日期**：2026-11-07
**仓库**：backend（concise-server-node）+ frontend（concise-admin）

## 背景

文件管理页（`features/system/file/`）一直是个**纯 mock 原型**：`fetchFiles()` 读 `public/mock/files.json`，
保存是 vite 中间件把 JSON 写回文件；后端只有 `tools/upload`（只收图片）和 `tools/storage`（上传记录），
没有目录层级、没有软删，`size` 还存成 `"23.4 KB"` 字符串，撑不起文件管理。

这轮按 P0 范围落地：**目录树 + 上传下载 + 改名 + 星标 + 软删 + 统计**，页面切换到真实接口。

## 数据模型：sys_file

文件夹与文件同表（`is_folder` 区分），`parent_id` 建树。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `parent_id` | INT | 父目录 ID，0 = 根目录；**移动就是改这一列** |
| `name` | VARCHAR(255) | 显示名称（含扩展名） |
| `is_folder` / `ext` / `mime` | — | 文件夹标记、扩展名、MIME |
| `size` | BIGINT | 字节数；旧的 `tool_storage` 存的是可读字符串，没法统计排序 |
| `storage_key` | VARCHAR(255) | 物理相对路径（`yyyy/MM/{sha256}.{ext}`），**只由服务端生成** |
| `hash` | CHAR(64) | sha256，去重（同一内容只存一份磁盘） |
| `owner_id` / `dept_id` | — | 归属；P0 只做个人空间 |
| `is_starred` / `is_deleted` / `deleted_at` | — | 星标 + 回收站软删 |
| `sort_order` | INT | 预留手动排序 |

索引：`(owner_id, parent_id, is_deleted)`、`(owner_id, is_deleted, update_time)`、`(hash)`、`(storage_key)`。

**刻意不加 `(owner_id, parent_id, name)` 唯一索引**：软删后同名会与回收站里的记录冲突（和用户表软删 + 唯一键踩过的坑同一个道理），
重名检查放服务层（`assertNameFree`），并发重名可接受 —— 真实文件系统也允许同名文件。

迁移：`src/migrations/1794110000000-CreateSysFile.ts`（显式 `COLLATE=utf8mb4_unicode_ci`，与 sys_user / sys_region 一致）。

## 存储策略：逻辑目录与物理文件解耦

```
逻辑目录（sys_file.parent_id）  ──storage_key──►  storage/files/yyyy/MM/{sha256}.{ext}
```

- 改名、移动只改数据库，磁盘上什么都不用动；
- 上传时先算 sha256，落地路径由内容决定：**同一份内容被多处引用也只占一份磁盘**；
- 物理目录**不在 `public/` 下**：`public` 是 `useStaticAssets` 静态托管的，用户传个 `.html` 就能同源执行脚本
  （直接读走 localStorage 里的 token）。文件管理一律走 `/v1/files/:id/download` 下载接口。

## 接口清单（/api/v1/files）

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| GET | `/` | 当前目录列表，文件夹优先；`starred=true` 时是**跨目录**星标视图 | system:file:list |
| GET | `/breadcrumb` | 父链上溯，返回「全部文件 → … → 当前」 | system:file:list |
| GET | `/stats` | 总量/文件数/文件夹数/按分类分布/配额 | system:file:list |
| GET | `/recent` | 最近修改的文件 | system:file:list |
| GET | `/recycled` | 回收站列表 | system:file:list |
| GET | `/:id` | 单条详情 | system:file:list |
| POST | `/folders` | 新建文件夹（同目录查重） | system:file:add |
| POST | `/upload` | multipart，`parentId` + `onConflict=rename\|skip\|overwrite` | system:file:upload |
| GET | `/:id/download` | 流式下载，UTF-8 文件名 + `nosniff` | system:file:download |
| PUT | `/:id` | 改名 / 移动 / 星标（移动防环） | system:file:update |
| DELETE | `/:id` | 软删进回收站（文件夹连子孙一起） | system:file:delete |
| POST | `/batch-delete` | 批量软删 | system:file:delete |
| POST | `/restore` | 回收站恢复（父链一并恢复，不产出孤儿） | system:file:update |
| POST | `/purge` | 彻底删除 + 清理无引用的物理文件 | system:file:delete |

**路由顺序**：`breadcrumb` / `stats` / `recent` / `recycled` 必须声明在 `@Get(':id')` 之前，否则会被当成 id 解析。

## 顺带修掉的既有 bug

`sys_permission` 里有 **37 条按钮权限的 `status` 是 NULL**，而权限查询（`PermissionCacheService.loadRolePerms`）
硬条件 `p.status = '1'`，等于这些按钮对非 admin 角色**从未生效**（admin 有超管 bypass，所以一直没被发现）。

`scripts/seed-menus.cjs` 已修：按钮 INSERT 补 `status='1'`，并在末尾统一补齐历史 NULL →
`已补齐 37 条历史按钮权限的 status`。权限缓存 TTL 300s，重启或等 5 分钟生效（或调 `invalidateAll`）。

## 坑

1. **`multer` 必须显式安装**：`FileInterceptor` 能用是因为 `@nestjs/platform-express` 自带依赖，
   但 `import { diskStorage } from 'multer'` 在 pnpm 严格 node_modules 下解析不到（`Cannot find module 'multer'`）。
   `pnpm add multer` 后解决。
2. **大文件不能进内存**：multer 默认 memoryStorage，200MB 视频会直接把 Node 内存打爆。
   改成 `diskStorage` + 临时目录，边读边算 sha256（`hashFile`），最后 `rename` 到内容地址（同盘毫秒级，跨盘 `EXDEV` 退化成 copy）。
3. **中文文件名**：multer 的 `originalname` 按 latin1 解，中文变乱码，要 `Buffer.from(name,'latin1').toString('utf8')`；
   判断"是否已经是合法 UTF-8"不能写 `/[\u0000-\u00ff]/` 这种正则（eslint `no-control-regex` 会报错），改成逐字符 `charCodeAt > 0xff`。
4. **配置读不到**：模块级 `const X = process.env.XXX` 在 `ConfigModule` 加载 `.env` 之前求值，永远是 undefined。
   存储根目录、配额、上传上限全部改成函数惰性读取。
5. **BIGINT 回来是字符串**：`size` 加了 TypeORM `transformer` 统一转 number，否则前端 `size > 1024` 之类的比较会踩字符串比较。
6. **`hasChildren`/软删同名**：软删的记录不参与重名判断（`is_deleted = 0` 才查重），否则回收站里的同名文件会挡住重新上传。
7. **子树上溯要封顶**：`collectSubtreeIds` / `breadcrumb` / `isDescendant` 都限制 32 层，防脏数据成环导致死循环。

## 如何扩展

- **回收站 UI**：后端 `recycled` / `restore` / `purge` 已就绪，前端左栏加一个「回收站」视图即可。
- **移动到…**：`PUT /:id { parentId }` 已支持（含防环），前端加一个目录选择弹层就行。
- **文件夹打包下载**：目前返回 400 提示；接 `archiver` 后流式 zip 即可（注意别一次性读进内存）。
- **秒传**：前端先算 sha256 调 `POST /files/check-hash`，命中就直接建记录不传字节（`hash` 索引已建好）。
- **部门共享**：`dept_id` 字段已预留；要做共享得在 `list/findOneOrFail` 里把 owner 过滤放宽成"owner 或同部门共享"，同时补共享关系表。
