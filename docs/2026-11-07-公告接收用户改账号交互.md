# 公告「接收用户」改为账号交互（2026-11-07）

> 反馈：编辑公告弹窗里「接收用户 ID」要求手填一串 32 位 UUID，没人记得住 —— 页面应该按**用户账号**交互。
> 存储不动：`sys_announcement.user_ids` 仍存用户 ID（后端下发/权限过滤都靠它），翻译只发生在前端表单层。

## 交互设计

| 环节 | 行为 |
| --- | --- |
| 编辑回显 | 打开弹窗时拉用户表，把存量 ID **翻译成账号**填入输入框 |
| 输入 | 输入框带 `<datalist>` 账号候选（复用 `/v1/users` 列表，前 100 个，含姓名提示） |
| 预览 | 输入框下方实时显示已选账号 chips：蓝色 = `账号（姓名）`；红色 = 账号当前不存在 |
| 提交 | 账号 → ID 换算后下发；**账号不存在直接阻断**并 toast 指出是哪个，避免发出没人收得到的公告 |
| 边界 | 存量 ID 翻不出账号（用户已删）时回显 `#id` 红标，提交时**原样保留**，不弄丢既有配置 |
| 容错 | 用户表拉取失败时退回显示原始 ID，保证已有公告仍可编辑保存 |

token 拆分兼容中英文逗号、空格、换行（`splitUserTokens`）。

## 验证记录（headless Chrome 真实操作）

- 回显：存量 `zhangsan_id,admin_id,deadbeef…` → 输入框显示 `zhangsan,admin,#deadbeef…`，chips 显示 `zhangsan（张三）` `admin（管理员）` + 红色 `deadbeef…（账号未知，按 ID 保留）`
- 保存：PUT 请求体 `userIds` 正确换算回 `3d46…,e9ca…,deadbeef…`（与原值一致，无失真）
- 阻断：输入 `zhangsan,nobody_xxx` 点保存 → **0 个 PUT 请求** + toast「以下账号不存在，请检查：nobody_xxx」
- `tsc -b` / eslint / `npm test` 7/7 全绿

## 遇到的坑

1. **必现时序**：ID→账号翻译依赖用户表先回来，所以翻译放在 `fetchUsers().then` 里做，不能在 useState 初始化器里翻（options 还没加载）。
2. **React 受控 input 设值**：CDP 自动化里 `input.value = x` 不触发 React onChange，必须用 `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, 'value').set.call(input, v)` + dispatch input 事件。
3. **表字段名是 `titile`**（jeecg 历史拼写），直接写 SQL 查 `title` 会报 Unknown column —— 实体层已映射成 `title`，只有裸 SQL 会踩。

## 怎么扩展

- 用户超过 100 个时，datalist 候选不全（可输入任意账号，提交时会校验）；要更好的体验可换成带远程搜索的 combobox（输入时按 keyword 查 `/v1/users?keyword=`）。
- 「按部门/按角色」批量选择接收人：把选中的用户集合换算成 ID 集合即可，后端契约不变。
