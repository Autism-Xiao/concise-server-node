# 2026-11-04 登录验证码与日志联调与公告任务模块

本轮三块：登录验证码（防爆破）、日志模块联调支持、公告/任务模块。接口总数达 40+。

## 一、登录验证码（svg-captcha）

### 新增/改动文件

| 文件 | 说明 |
|---|---|
| `auth/services/captcha.service.ts`（新增） | 生成/校验。**内存 Map 存储**，5 分钟过期、**一次性使用**（验证即销毁防重放）、上限 1 万条自动清理；接 Redis 后可支持多实例 |
| `auth/controllers/auth.controller.ts` | `GET /auth/captcha`（@Public）：返回 `{ captchaId, svg }`；`CAPTCHA_DEBUG=true` 时附带明文 `code`（**仅开发联调用，生产必须关**） |
| `auth/dto/login.dto.ts` | 新增可选 `captchaId` / `captchaCode` |
| `auth/services/auth.service.ts` | login 最前面校验验证码（`CAPTCHA_ENABLED=true` 时强制）；异常记录统一用 `HttpException` 判断 |
| `.env` / `.env.example` | `CAPTCHA_ENABLED=true`、`CAPTCHA_DEBUG`（dev true / example false） |

### 前端对接流程

```
GET /api/auth/captcha → { captchaId, svg(base64可直接 <img :src>) }
POST /api/auth/login  → { username, password, captchaId, captchaCode }
```

| 能力 | 说明 |

## 三、公告模块（`system/notice`）

| 文件 | 说明 |
|---|---|

## 踩坑记录

1. **`@Type(() => Date)` + `@IsISO8601` 冲突**：Type 管道先把字符串转成 Date，IsISO8601 再校验时已不是字符串必挂。改法：DTO 保持 string 只做校验，Service 里 `new Date()` 转换后入库
2. dueDate 签名冲突（DTO string vs 实体 Date）：Service 方法签名用 `Omit<Partial<TaskEntity>, 'dueDate'> & { dueDate?: string }`
3. 联调脚本给多个账号登录时**每个登录都要重新取验证码**（一次性）
