# 字典项语义色：颜色从字典来，不再写死在前端

## 背景

公告优先级、任务优先级的颜色以前写死在页面里的映射：

```tsx
const priorityClass: Record<NoticePriority, string> = {
  H: 'bg-destructive/15 text-destructive',
  M: 'bg-amber-500/15 text-amber-600 dark:text-amber-400',
  L: 'bg-muted text-muted-foreground'
}
```

运营想把「高」从红改成橙，就得改代码发版。字典早就管了文案，却管不了颜色，这个缺口在「审核状态」这类高频变动的业务里尤其难受（通过=绿、驳回=红、待审=橙，每上一套业务就要写一遍映射）。

本次让字典项自带颜色，业务页面统一写 `<DictBadge code="xxx" value={v} />`。

## 设计决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 存什么 | 语义色 `success` / `warning` / `danger` / `info` / `primary` / `neutral` | 存 tailwind class 等于把亮色写死，暗色主题下对比度会崩；也避免任意字符串拼进 `className` 的样式注入面 |
| 颜色给谁用 | 任何字典项都能配，不配就纯文本 | 字典里既有「状态」也有「性别/分类」，分类硬套色块很丑 |
| 未配色怎么渲染 | 纯文本，不是灰章 | 灰章留给显式配了 `neutral` 的项（如「已停用」「草稿」） |
| 存量数据 | 不回填，只给两个优先级字典补默认色 | 迁移里按原 `priorityClass` 补 `H→danger / M→warning / L→neutral`、`2→danger / 1→warning / 0→neutral`，观感不变 |
| 前端接口 | 新增 `useDictMeta`，`useDict` 签名不动 | `useDict` 返回 `Record<string,string>` 被 7 处直接丢给 `<Select items>`，改签名会全线崩 |

## 怎么用

```tsx
// 列表里的状态列：文案 + 颜色都来自字典，改色不用发版
<DictBadge code="biz_audit_status" value={row.status} />

// 需要兜底文案时
<DictBadge code="biz_audit_status" value={row.status} placeholder="未提交" />
```

新建一套审核状态字典：

1. 系统管理 → 数据字典 → 新增，编码 `biz_audit_status`
2. 字典项：`0 草稿`（不套色）/ `1 待审核`（橙）/ `2 已通过`（绿）/ `3 已驳回`（红）
3. 页面里直接用 `DictBadge`，不需要任何前端改动

Excel 批量配颜色时，「颜色」列填 `success` 或 `绿` 都可以；留空表示不动原值，填「无」才是清除。

## 踩的坑

1. **`useDict` 不能改返回值形状**。它是 `Record<string,string>`，7 处直接 `items={priorityItems}` 传给 Select。改成对象会让所有下拉崩掉，所以缓存层存完整数组、两个 hook 各自派生。
2. **导出文件带表尾说明行，导回时被当成数据**（既有缺陷，本次顺手修）。`buildWorkbook` 把 `notes` 写在数据区下方并合并 `A:最后一列`，ExcelJS 会把 master 值复制到整个合并区，所以说明行看起来「每列都有值」。第一次按「只有一个非空单元格」判断失败，最终改为「首列匹配 `说明：/示例：/注：/数字.` 且整行非空单元格内容完全一致」。
   同批修掉自己新加的说明文案：不以「说明：」开头的 notes 会被这条规则漏掉，所以 `dict.v1.controller.ts` 里新写的 notes 也统一加了前缀。
3. **部门批量删除结果依赖 DB 返回顺序**（既有 flaky）。`repository.find` 无 `order by`，父子部门一起删时若子部门先被删，父部门就能删成功，冒烟断言（期望父被保护拒绝）随机红。改为按入参 ids 顺序排序，结果确定：父先到就先被规则挡住。
4. **迁移里的 `CASE` 不要混两种值域**。公告优先级是字母（H/M/L）、任务是数字（0/1/2），一开始写一条 `CASE` 同时匹配两种，读起来要推一遍才确定不误伤，拆成两条更清楚。
5. **可空列必须显式 `type: 'varchar'`**，否则 TypeORM 推断成 Object，迁移生成 `text` 或报错。

## 如何扩展

- **加一档新颜色**：后端 `dict.constants.ts` 的 `DICT_COLORS` + 前端 `dict-color.ts` 的 `DICT_COLOR_OPTIONS` **两处同步**。少改一边不会报错，界面上只是静默退化成纯文本（这是有意的：宁可没颜色，也不要显示错的颜色）。同时给 `COLOR_ALIASES` 补中文写法。
- **想支持图标/字号**：走同样的路子，`sys_dict_item` 加列 + 实体/DTO + `listByCode` + 前端 `DictMeta` 多带一个字段。但**别加自由 class 字段**，白名单是这套设计的安全边界。
- **下拉框里也显示色点**：需要 `Select` 支持 `itemRender`，成本高于收益，暂未做。
- **租户自定义颜色**：平台共享字典（`tenant_id = 0`）的项租户改不了，与文案规则一致；要改就在本租户复制一份同编码字典。
