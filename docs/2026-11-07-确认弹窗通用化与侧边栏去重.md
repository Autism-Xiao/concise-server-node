# 确认弹窗通用化 + 侧边栏仪表盘去重

日期：2026-11-07　仓库：concise-admin（前端为主，后端无代码改动）

## 一、修的两个问题

### 1. 侧边栏出现两个「仪表盘」

**原因**：首页改造时为了让没有「仪表盘」菜单授权的角色也能回首页，在侧边栏加了**固定入口**；但后端菜单树里本来就有 `menu_35`（`name=仪表盘, url=/dashboard, menu_type=0`），于是固定入口 + 菜单树项 = 两个。

**修法**：菜单树渲染时统一剔除指向首页的节点，首页只由固定入口提供（入口不依赖菜单授权，本来就该常驻）。

| 文件 | 改动 |
|---|---|
| `src/components/layout/app-sidebar.tsx` | `visible()` 增加 `menuPath(n) !== HOME_PATH`；静态菜单路径 `visibleGroups` 计算里同步过滤顶层项与二级项 |

> 只过滤**叶子语义**的节点：`menu_35` 无子节点，过滤安全。若将来把「仪表盘」改成真正的目录（下挂子菜单），`toDynItem` 会先处理 children，不会误删子菜单。

### 2. 强退 / 冻结 / 清空弹窗的按钮写着「删除」

**原因**：所有二次确认都复用了 `ConfirmDeleteDialog`，组件里按钮文案**硬编码为「删除」**、配色硬编码 `destructive`。于是「强制下线」「冻结」「清理缓存」「恢复账号」的弹窗底部都写着「删除」。

**修法**：把组件升级为通用 `ConfirmDialog`，标题/按钮文案/按钮配色/加载态全部由调用方决定。

| 文件 | 改动 |
|---|---|
| `src/components/confirm-dialog.tsx` | **新增**。`confirmText`（默认「确定」）、`confirmVariant`（默认 `destructive`）、`loading`（禁用按钮 + 「处理中…」） |
| `src/components/confirm-delete-dialog.tsx` | **删除**（17 个调用点已全部迁移） |
| 17 个调用点文件 | 导入路径 `@/components/confirm-delete-dialog` → `@/components/confirm-dialog`，组件名 `ConfirmDeleteDialog` → `ConfirmDialog` |

## 二、各场景现在的按钮文案

| 场景 | 标题 | 按钮文案 | 配色 |
|---|---|---|---|
| 用户 冻结 | 确认冻结该账号？ | **冻结** | 红 |
| 用户 解冻 | 确认解冻该账号？ | **解冻** | 主色 |
| 用户 强制下线 | 确认强制下线？ | **强制下线** | 红 |
| 用户 批量停用 / 启用 | 确认批量停用 N 个账号？ | **停用** / **启用** | 红 / 主色 |
| 在线用户 强退 / 批量强退 | 强制下线 | **强制下线** | 红 |
| 回收站 恢复账号 | 确认恢复该账号？ | **恢复** | 主色 |
| 缓存清理 | 清理缓存 | **清理** | 红 |
| 操作日志 清空 | 确认清空 | **清空** | 红 |
| 文件 彻底删除 | 彻底删除 | **彻底删除** | 红 |
| 其余所有删除类 | 确认删除 | **删除** | 红 |

**配色规则**：中断/破坏性操作（删除、强退、冻结、清理）用 `destructive`；正向操作（解冻、启用、恢复）用 `default`（主色），避免红色误导。

## 三、坑

1. **不能只改按钮文案**：如果只把「删除」改成「确定」，那所有删除场景也变成「确定」，语义反而更糊。必须让**每一处显式表达意图**——所以纯删除场景也全部补了 `confirmText="删除"`（24 处）。
2. **批量插入文案时有误判**：「清理缓存」的说明文字里含「删除」二字（"即将删除 xxx 下的缓存 key"），被脚本识别成删除类；「彻底删除」也被插成「删除」。两处已人工纠正。**判断依据必须是 `title` 或操作语义，不能只看描述里有没有"删除"**。
3. **JSX 块边界不能用 `/>` 判断**：`</>` 里也含 `/>`，脚本按"缩进相同的独立 `/>` 行"才可靠。
4. **`loading` 与现有「正在处理，请稍候…」并存**：老代码把忙碌提示写进了 `description`，为了不改动调用方行为，`loading` 只作为可选能力保留，两者不冲突。

## 四、以后怎么用

```tsx
// 破坏性操作（删除）
<ConfirmDialog
  open={!!deleting}
  onOpenChange={v => !v && setDeleting(null)}
  confirmText="删除"
  description={<>即将删除「{deleting?.name}」，不可恢复。</>}
  onConfirm={handleDelete}
/>

// 正向操作（启用 / 恢复）：文案 + 主色按钮
<ConfirmDialog
  open={!!target}
  onOpenChange={v => !v && setTarget(null)}
  title="确认恢复该账号？"
  confirmText="恢复"
  confirmVariant="default"
  description={<>恢复后可正常登录。</>}
  onConfirm={handleRestore}
/>

// 动态语义（同一弹窗两种操作）
<ConfirmDialog
  confirmText={frozen ? '解冻' : '冻结'}
  confirmVariant={frozen ? 'default' : 'destructive'}
  title={frozen ? '确认解冻该账号？' : '确认冻结该账号？'}
  ...
/>

// 有耗时请求时
<ConfirmDialog loading={busy} confirmText="清理" ... />
```

**约定：非删除类操作必须传 `confirmText`。** 默认值是「确定」，忘记传不会出现语义错误，但也不够明确。
