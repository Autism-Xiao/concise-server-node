# 接口文档只保留 V1 模块与「系统」分组

日期：2026-11-05

## 需求

Swagger（`/api/docs`）里混着大量旧版**无版本前缀**接口（`/api/auth/**`、`/api/users/**`、`/api/roles/**`、`/api/depts/**`、`/api/tasks/**`、`/api/storage/**`、`/api/upload/**`），与 V1 接口成对出现，分组名字还重名（「认证」vs「认证 V1」），查文档时干扰很大。要求：**文档里只保留 V1 模块 + 「系统」分组**。

## 做法

用 `@ApiExcludeController()` 把旧控制器**从文档中隐藏**，代码与路由原样保留（前端/第三方仍在调用的旧路径不会 404）。

> 为什么不直接删控制器：旧接口是「向后兼容」承诺的一部分，删除属于破坏性变更。要真删，是另一件事（见文末「如何彻底删除」）。

`@ApiExcludeController()` 放在 `@ApiTags` 上方，紧跟一行注释说明「仅为兼容保留」，避免以后有人以为漏写文档。

### 每个装饰器干什么

- `@ApiExcludeController()`：`@nestjs/swagger` 提供的控制器级装饰器，`SwaggerModule.createDocument()` 扫控制器时直接跳过该类 —— 该控制器的**所有路由、DTO、Tag 都不进 OpenAPI**。**不影响**路由注册、守卫、拦截器，接口照常可调用。

## 验证

`tsc --noEmit` 通过；本地起服务拉 `/api/docs-json`：

- 路径数 **53**，其中 `**/v1/**` 53 条里除根路径 `/api`（AppController 健康检查，Tag「系统」）外全部带 `/v1`；
- 旧路径 `/api/auth/**`、`/api/users/**`、`/api/roles/**`、`/api/menus/**`、`/api/depts/**`、`/api/tasks/**`、`/api/storage/**`、`/api/upload/**` 在文档中**全部消失**；
- 剩余分组（15 个）：系统、用户管理 V1、角色管理 V1、认证 V1、菜单管理 V1、日志管理 V1、在线用户 V1、部门管理 V1、数据字典 V1、字典项 V1、通知公告 V1、职级管理 V1、岗位管理 V1、定时任务 V1、运维监控 V1。

## 坑

1. **文档路径带全局前缀**：`docs-json` 里的 path 是 `/api/v1/users` 而不是 `/v1/users`，用脚本筛「非 v1 接口」时要按 `/v1/` 子串判断，别按 `startsWith('/v1')`。
2. **不要用 `SwaggerModule` 的 `tags` 顶层数组判断分组**：本项目 `document.tags` 为空（`ApiTags` 只写在 operation 上，`createDocument` 不会反推顶层 tags），分组要遍历 `paths.*.*.tags[0]` 统计。
3. **`nest start` 会先删 `dist`**（`nest-cli.json` 的 `deleteOutDir: true`），本机安全钩子会拦截批量删除；验证文档时改用 `tsc -p tsconfig.build.json --outDir dist-doc` + `node dist-doc/main.js`，验完删掉临时目录即可。
4. **本机端口要绕代理**：`8080`/`3000`/`3457` 一带有外部代理，`curl` 会拿到 502；探测用 `curl --noproxy '*'` 并换端口（本次 3488）。
5. **排除只影响文档**：前端页面、旧接口调用方完全无感，不需要同步改；如果哪天确认没人用旧接口，再物理删除控制器 + 模块注册。

## 如何扩展 / 彻底删除

- 新增旧版兼容控制器时，同样加 `@ApiExcludeController()`，文档默认保持「V1 + 系统」两态。
- 想彻底删掉旧接口（破坏性）：删对应 `*.controller.ts` → 从所属 `*.module.ts` 的 `controllers` 数组移除 → 删除仅被它的 Swagger 描述引用的 DTO → `npx tsc --noEmit` + 起服务确认 `/api/docs-json` 无残影 → 同步前端 `api.ts` 里的旧路径（本项目前端已全部走 `/backend-api/v1/**`，无需改动）。
