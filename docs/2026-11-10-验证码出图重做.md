# 验证码出图重做：从「两个深色块打架」到「一块玻璃 + 一个凹槽」

> 起因：登录页的滑块验证码观感很差 —— 画面上两个形状叠在一起分不清哪个是块哪个是坑，拼图块带着一圈生硬的白边，图片四周还有一圈白框，整体显得粗糙。

## 一、改前是什么样

三个问题叠在一起，互相放大：

| 现象 | 根因 |
|---|---|
| 拼图块和缺口叠成一个「看不懂的形状」 | 答案 `x` 的最小值是 **40**，而拼图块的初始显示宽度是 **60**。x 取 40~60 时，初始状态的块（画在 0~60）与缺口（画在 40~100）直接重叠，画面上出现两个深色形状黏在一起 |
| 拼图块又暗又脏，和缺口分不出来 | `create()` 里**先挖缺口、再抠拼图块**，块取到的是已经被压暗的像素 —— 块和坑一样暗，拖对了也没有「补上」的视觉反馈 |
| 到处是白边 | ① 拼图块用纯白 `0xffffffff` 硬描边；② 图片外框是 `1px solid var(--border)`，深色主题下就是一圈 10% 白线 |
| 圆弧边缘毛糙 | 逐像素硬判定 `insidePiece`，凸起和凹槽的弧线上全是台阶 |
| 背景杂乱 | 8 个中饱和随机色圆（alpha 0.25~0.45）铺满画面，到处是圆弧边界，缺口反而不好找 |

## 二、改了什么

### 后端 `src/modules/auth/services/captcha.service.ts`

| 改动 | 说明 |
|---|---|
| `X_MIN = PIECE_WIDTH + 50` | 答案左界从 40 提到 110，拼图块初始位置与缺口之间至少留 50px 空隙，画面上永远是「一块 + 一个洞」 |
| `create()` 顺序调整 | **先 `buildPiece`（从干净背景取原色），再 `carveNotch`**。块是亮的、坑是暗的，拖上去才有「补上」的反馈 |
| `pieceCoverage()` 新增 | 4×4 超采样求形状覆盖率（0..1），用作 alpha 与混合系数，圆弧边缘从台阶变成平滑过渡 |
| `generateBackground()` 重写 | 单色系斜向渐变（`hsl()` 基色 + 相邻色相，不再两个独立随机色撞色）+ 平方曲线柔和暗角；**删掉随机圆纹理**，画面里除了缺口没有任何可辨识的几何边界 |
| `carveNotch()` 重写 | 目标亮度按纵向位置微调（顶部 0.42 → 底部 0.5，模拟光从上方来），边缘再压 0.2 形成侧壁；覆盖率参与混合消锯齿 |
| `buildPiece()` 重写 | 块体 = 原色 + 8% 白（半透明玻璃感，任意底色上都看得见）；边缘 88% 白描边（不再是刺眼纯白）；形状外左上侧 1px 深色阴影（`0x0000003a`）给块厚度 |
| 删除 `pastel()` / `drawCircle()` | 随机配色和圆形纹理都不再需要 |

**答案语义完全没变**：仍然是「拼图块左缘的 x 像素」，`verify()` 的容差（±5px）与一次性消费逻辑一行没动。

### 前端

| 文件 | 改动 |
|---|---|
| `src/index.css` | 图片外框从 `1px solid var(--border)`（深色下 10% 白）改成 `color-mix(in oklab, var(--foreground) 6%, transparent)`，投影从 `0 1px 2px / 0.04` 调到 `0 1px 3px / 0.06`；`panel` 下间距 10px → 12px |
| `src/features/auth/login.tsx` | `--rcsc-panel-border-radius` 从 `calc(var(--radius) + 2px)` 改成 `var(--radius)`，图片圆角与滑块条一致（原来图比条更圆，视觉不齐） |

### 新增冒烟 `scripts/smoke-captcha.mjs`（18 项）

覆盖出图结构（PNG/320×160/60×160）、答案范围与随机性、位置校验与容差边界（±5 通过 / ±6 拒绝）、挑战一次性、ticket 一次性消费（持 ticket 登录成功、重放被拒、伪造被拒）。

答案 x 直接从 Redis 的 `captcha:<id>` 读，因此能确定性地验证「图上缺口的位置 = 校验期望的位置」，而不是靠猜。

```powershell
$env:PORT="3461"; $env:CAPTCHA_ENABLED="true"; node dist/main.js      # 另一个窗口
node scripts/smoke-captcha.mjs
```

**本脚本与其它冒烟脚本的开关相反**：其余脚本一律 `CAPTCHA_ENABLED=false`（关掉后登录不校验 ticket，「不带 ticket 被登录」是他们要的正常路径），只有这里必须 `true`。脚本开头会用一次裸登录探针自检，开关没开时直接以退出码 2 中止并提示，`/auth/captcha` 因限流或旧实例拿不到出图时退出码 3，避免刷一屏看不懂的 FAIL 被误判成代码回归。账号可用 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 覆盖。

## 三、验证

- 冒烟 18/18 通过；出图连拉 6 组，色相分布正常（蓝/青/紫/绿/橙/粉），答案全部落在 110~250。
- 无头 Chrome 实测深色与浅色主题：图片外框的「白框」消失，拼图块与缺口一眼可分，1:1 下块也看得见。
- 弹窗几何：左右内边距各 20px，图片下间距 12px，图片与滑块条同宽同圆角。

## 四、坑

1. **拼图块必须先从干净背景取色，再挖缺口**。顺序写反了块会跟着变暗，块和坑同色时用户拖对了也看不出变化。
2. **答案左界必须大于拼图块宽度**。`rc-slider-captcha` 把 puzzle 图放在最左侧且宽 60px，答案 x 小于 60 时初始状态就与缺口重叠。
3. **puzzle 图必须保持 60×160 且 1:1 显示**。它全高 160 是因为纵向位置要和缺口对齐（组件按原图尺寸直接叠放），一旦缩放，拖动距离与实际 x 就对不上。
4. **深色主题下 `var(--border)` 是 10% 白**，用它给图片画 1px 实线，在深色弹窗上就是一圈明显的白框。用 `--foreground` 取 6% 更安全（浅色主题下自动变成淡灰）。
5. `jimp 0.22` 的 `write()` 是回调式，脚本里要 `await writeAsync()`；`node -e` 里 `require('jimp')` 会报 `ERR_AMBIGUOUS_MODULE_SYNTAX`，写成 `.mjs` 用 `import`。
6. **CDP 的 `Input.dispatchMouseEvent` 模拟不了这个组件的拖拽**：组件在 `pointerdown` 里 `preventDefault()` 后，Chrome 不再派发兼容的 `mousemove`，而组件恰好用 `mousemove` 跟手。这是合成输入的限制（真实鼠标不受影响），排查时别误判成产品 bug。

## 五、怎么调整

- 想更鲜艳/更淡：`generateBackground()` 里 `from` 的 `l=0.79`（顶部亮度）、`to` 的 `l=0.62`（底部亮度）、两边 `s`（饱和度）。
- 想加深/减淡凹槽：`carveNotch()` 里 `base = 0.5 - 0.08 * (1 - vertical)` 的 0.5 与 0.08（越大越亮），`target - 0.2` 是侧壁额外压暗量。
- 想让拼图块更「实」：`buildPiece()` 里 `r * 0.92 + 255 * 0.08` 的 0.08 提高，或描边的 0.88 提到 0.95。
- **不要动**：`BG_WIDTH/BG_HEIGHT`（320×160）、`PIECE_WIDTH`（60）、`TOLERANCE`（5）—— 这三个与前端组件、拖动距离、容差策略强绑定。
