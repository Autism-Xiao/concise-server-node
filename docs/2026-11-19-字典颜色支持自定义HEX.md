# 字典颜色支持自定义 HEX（2026-11-19）

## 背景

字典项颜色原本是**语义色白名单**：后端 `DICT_COLORS`（primary/success/warning/danger/info/neutral）+ `@IsIn` 校验，前端 `DICT_COLOR_OPTIONS` 映射到固定 tailwind class。库里存语义名，不存具体色值。

这样设计是为了规避三个坑：存 tailwind class 会把亮色写死（暗色主题对比度崩）、运营得背语法、任意字符串拼进 className 是样式注入面。**代价是运营无法用品牌色 / 精确色值**。

本次改为「预设语义色 + 自定义 #RRGGBB」双轨：预设继续走白名单 class，自定义只认严格 HEX，走 inline style + `color-mix` 跟随主题。

## 关键设计

1. **不存 tailwind class、不接受任意字符串**：自定义只认 `#RRGGBB`（可不带 `#`），后端正则 `^#?([0-9a-fA-F]{6})$`、`@Matches` 整串锚定，3 位简写、`rgb()`、`bg-red-500`、中文颜色名一律 400。
2. **动态 class 走不通**：Tailwind JIT 扫不到运行时拼的 class，所以自定义色必须 inline style。用 `color-mix(in oklab, ${hex} 15%, var(--background))` 做浅底、`50% 色 + var(--foreground)` 做字色——浅色主题浅底深字、暗色主题深底浅字，自动跟随主题且任何色值都有可读对比度。语义色仍走原 class（明暗主题已单独调好）。
3. **import 兼容**：`normalizeDictColor()` 先试 HEX（统一带 `#` 大写），再查别名表（中文/英文→语义名），认不出返回 undefined 保持原值不整行失败；空单元格不改色，「无/none」显式清除。
4. **取色器交互**：原生 `input[type=color]` 用绝对定位 opacity-0 覆盖在「自定义」按钮上（复用 appearance 页已有模式），无需引第三方依赖。`form.color` 存 `#RRGGBB`，`hexDraft` 存输入框草稿态，只在合法时同步到 `form.color`，避免受控输入卡住。

## 踩的坑

- `color-mix` 在这里是**必需的**：直接写 `backgroundColor: hex` 会把亮色写死，暗色主题下字色对比度崩；`bg-current` 圆点会继承 style 里的 color，所以圆点颜色自动跟随。
- inline `style` 优先级高于 className，所以调用方即使传了 `bg-*` class 也不会盖掉自定义色——这是期望行为。
- `isDictColor` 只认 6 个语义名（类型守卫），判断「任意合法色」要用 `isDictColorValue()` 或 `normalizeHexColor()`。
- 冒烟脚本默认 DB 密码 `123456` 与 `.env` 不一致，跑的时候要 `DB_PASSWORD=$(grep '^DB_PASSWORD=' .env | cut -d= -f2-)` 传入。
- `pkill -f serve.mjs` 杀不掉后台 `serve.mjs`（父退子存，历史坑），要 `netstat -ano | grep :3461` 找 PID 再 `taskkill //PID <pid> //F`。

## 如何扩展

- **加新的预设语义色**：后端 `DICT_COLORS` + `COLOR_ALIASES`、前端 `DICT_COLOR_OPTIONS` 三处同步加（前后端白名单必须一致，否则静默退化成纯文本）。
- **改自定义色格式**（如支持 3 位简写 / HSL）：同步改后端 `HEX_PATTERN`、`create-dict-item.dto.ts` 的 `COLOR_PATTERN`、前端 `dict-color.ts` 的 `HEX_PATTERN` 与 `normalizeHexColor()`，并补冒烟断言。
- **业务页新增字典色标签**：直接用 `<DictBadge code="xxx" value={v} />`，无需关心预设还是自定义色。
