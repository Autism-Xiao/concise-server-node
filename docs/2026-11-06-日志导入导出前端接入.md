# 日志导入导出前端接入（对齐用户管理）

> 日期：2026-11-06　｜　范围：`concise-admin/src/features/system/log`、`concise-admin/vite.config.ts`

## 一、这轮到底改了什么

上一轮后端已把日志的导出改成公共写法，并补了四个接口（登录/操作日志各一对「模板下载 + 导入」），但前端日志页还停在旧状态：

- 导出按钮写的是「导出 CSV」，实际后端返回的是 `.xlsx`；下载走的是手写 `fetch`，没取 `filename*`，中文文件名会丢成 `login-logs.xlsx`
- 导出不传任何筛选条件，页面上选了「失败」再点导出，导出的是全量
- 完全没有导入入口

这轮就补这三点，并且**不新增弹窗组件**——直接复用仓库里已有的通用件 `@/components/excel-import-dialog`（字典、职级、岗位、公告在用同一套），下载走 `@/lib/download` 的 `downloadFromApi`（用户、公告导出用的就是它）。所以「和用户管理一致」是调同一套前端公共件，不是复制一份用户页的代码。

## 三、每个东西是干什么的

### 1. `exportLogs(kind, params)` —— 导出带上筛选、拿到中文文件名

```ts
export type LogKind = 'login' | 'oper'

export interface LogExportParams {
  keyword?: string
  status?: LogStatus   // 仅登录日志支持
}

export function exportLogs(kind: LogKind, params: LogExportParams = {}) {
  const qs = new URLSearchParams()
  if (params.keyword) qs.set('username', params.keyword)
  if (params.status && kind === 'login') qs.set('status', params.status === '成功' ? '0' : '1')
  const query = qs.toString()
  return downloadFromApi(`/v1/logs/${kind}/export${query ? `?${query}` : ''}`, `${kind}-logs.xlsx`)
}
```

三个要点：

- **前端字段名是 `keyword`，后端要的是 `username`**，在这里翻译，页面不用关心后端 DTO。
- **操作日志后端没有 `status` 参数**（`QueryOperLogDto` 只有 `username` / `module` / `startTime` / `endTime`），传了会被全局 `whitelist` 静默剥掉，所以直接不传，避免「看起来生效实际没生效」。
- `downloadFromApi` 会先读 `filename*=UTF-8''…` 再退回 `filename="…"`，中文名「登录日志-2026-11-06.xlsx」能正常保存。

### 2. `downloadLogTemplate(kind)` / `importLogs(kind, file)`

```ts
export function downloadLogTemplate(kind: LogKind) {
  return downloadFromApi(`/v1/logs/${kind}/import-template`, `${kind}-logs-import-template.xlsx`)
}

export function importLogs(kind: LogKind, file: File): Promise<ImportResult> {
  const form = new FormData()
  form.append('file', file)
  return getApiResult<ImportResult>(`/backend-api/v1/logs/${kind}/import`, { method: 'POST', body: form })
}
```

返回的 `ImportResult` 直接复用 `@/components/excel-import-dialog` 导出的类型，所以「共 N 行 / 新增 / 更新 / 跳过 / 失败 + 逐行原因」的展示逻辑一行都不用重写。

### 3. `LogTablePage` 的两个新入参

```ts
interface LogTablePageProps<T extends BaseLog> {
  // …原有字段
  /** 导入弹窗的判定规则说明 */
  importDescription: ReactNode
  /** 导入弹窗的表头提示 */
  importHint?: ReactNode
}
```

登录页与操作页的「必填列、时间格式、结果取值」不一样，所以把这些文案做成参数由调用方给，骨架本身保持通用。弹窗挂载方式：

```tsx
{importOpen && (
  <ExcelImportDialog
    open={importOpen}
    onOpenChange={setImportOpen}
    title={`导入${title}`}
    description={importDescription}
    templateHint={importHint ?? '模板含填写说明与示例，必填列带 *'}
    onImported={load}
    downloadTemplate={() => downloadLogTemplate(deleteKind)}
    importFile={file => importLogs(deleteKind, file)}
  />
)}
```

`{importOpen && …}` 这个写法是关键：关闭即卸载，弹窗内的 `file` / `report` 状态自然清空，不会出现「下次打开还留着上次的导入报告」。

## 四、接口对应关系

| 按钮 | 前端函数 | 后端接口 | 权限 |
| --- | --- | --- | --- |
| 导出 | `exportLogs(kind, {keyword, status})` | `GET /api/v1/logs/{login\|oper}/export` | `system:log:export` |
| 导入 | `importLogs(kind, file)` | `POST /api/v1/logs/{login\|oper}/import` | `system:log:import` |
| 下载模板 | `downloadLogTemplate(kind)` | `GET /api/v1/logs/{login\|oper}/import-template` | `system:log:import` |

按钮可见性统一用 `hasPermission('…')`，超管令牌里是 `['*']` 所以全部可见；其他角色要看到「导入」按钮，需要在「角色管理 → 菜单授权」里勾上「日志管理 → 日志导入」（权限点 `system:log:import`，迁移 `1793966203743` 已写入数据库，默认未授权任何角色）。

## 六、踩的坑

1. **模板表头带星号**：模板首行表头是 `用户名 *`（必填标记），后端 `resolveImportLayout` 会剥掉 `*` 再匹配 `用户名`，所以照着模板填能直接导入 —— 自己造 xlsx 时别把星号写进列名。
2. **模板不是从第 1 行就是表头**：说明占 1–6 行、第 7 行空、第 8 行才是表头。手工拼测试文件必须用第一列文本定位表头行（本次脚本里是 `if (String(row.getCell(1).text).includes('操作人')) h = i`），直接写第 2 行会被当成说明文字跳过。
3. **`ExcelImportDialog` 的 `accept` 只有 `.xlsx`**：后端支持 `.csv`（UTF-8），但通用弹窗没放开。日志这轮没改公共组件——如果要放开，需要给 `ExcelImportDialog` 加一个 `accept` 参数，用户管理那个弹窗本来就允许 csv，可以一起收敛。
4. **`exportLogs` 的 `keyword` 必须 `trim()`**：页面搜索框是受控输入，用户敲了空格再点导出，后端 `LIKE '%%'` 虽然不报错但会白跑一次全表。调用处传的是 `keyword.trim()`。
5. **Vite 配置里的 `process.env`**：`vite.config.ts` 在 Node 环境执行，`process.env.BACKEND_URL` 可直接用；换真机调试时 `BACKEND_URL=http://192.168.x.x:3000 pnpm dev` 即可，不用改文件。

## 七、怎么扩展

**给别的模块加导入按钮**：按 `login.tsx` 的写法，把 `importDescription` / `importHint` 传进去即可，不需要再写弹窗。若该模块的导入弹窗已独立存在（用户、公告是这种），则保持原样，不必迁移。

**给日志加时间范围筛选**：后端 `QueryLoginLogDto` / `QueryOperLogDto` 已支持 `startTime` / `endTime`（ISO 8601）。前端只需在 `LogExportParams` 加两个字段、`exportLogs` 里 `qs.set('startTime', …)`，页面加一个日期区间控件即可，导出与列表就能同时对同一段时间生效。

**开放 csv 导入**：给 `ExcelImportDialog` 加可选 `accept`（默认 `.xlsx`），日志页传 `.xlsx,.csv,application/…,text/csv`。
