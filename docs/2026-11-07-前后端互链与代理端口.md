# 前后端互链与 dev 代理端口自适配

## 背景

前端页面全部请求后端，但 `vite.config.ts` 里代理目标端口写死 `3459`，而 `.env` 的 `PORT` 是 `3000` —— 后端改了端口，前端仍指旧端口，页面所有请求 502、终端只报一句"代理转发失败"。另外两个 README 都没有对方的仓库链接，新人拿到任一个仓库都不知道另一半在哪。

## 改动清单

| 文件 | 类型 | 说明 |
| --- | --- | --- |
| `concise-admin/vite.config.ts` | 修改 | 新增 `resolveBackendPort()`：默认读同级后端仓库 `../concise-server-node/.env` 的 `PORT`，读不到退回 3000；`BACKEND_PORT` / `BACKEND_URL` 仍可覆盖 |
| `concise-admin/README.md` | 修改 | 顶部补后端仓库链接；新增「先起后端」小节（启动命令、API 根、Swagger 地址、代理覆盖方式）；修正"内置完整 mock"的过时描述 |
| `concise-server-node/README.md` | 修改 | 补项目简介、前端仓库链接、两端地址表、Quick start（migration:run + restart）与 `sql/` 说明 |

## 关键点

- **端口只维护一处**：后端 `.env` 的 `PORT` 是唯一真源，前端起 dev 时自动读取，两边不会漂移
- **单独 clone 前端也能用**：`fs.readFileSync` 包在 try/catch 里，后端目录不存在时退回 3000，不会因缺文件崩掉 dev server
- 改了 `vite.config.ts` 要**重启 dev server** 才生效（vite 不会每次都热重启配置文件）

## 验证

| 检查 | 结果 |
| --- | --- |
| `http://127.0.0.1:3000/api/v1/auth/captcha` | 200 |
| `http://127.0.0.1:3000/api/docs`（Swagger） | 200 |
| `http://localhost:5173/` | 200 |
| `http://localhost:5173/backend-api/v1/auth/captcha`（代理） | 200 |
| 前端 `eslint vite.config.ts` / `tsc -b` | 通过 |

dev server 启动日志会打印实际代理目标，便于确认：

```
  后端代理 → http://127.0.0.1:3000
  请访问   → http://localhost:5173
```

## 扩展说明

- 真机调试：`BACKEND_URL=http://192.168.1.8:3000 pnpm run dev`
- 只想临时换端口：`BACKEND_PORT=3460 pnpm run dev`
- 若后端 `.env` 的键名不是 `PORT`（改了约定），同步改 `resolveBackendPort()` 里的正则即可
