# 接口错误提示人性化 + 端口防呆

> 2026-11-07 · 前端（concise-admin）

## 起因

页面弹出这样一句话：

```
没有收到后端响应（HTTP 502）：/backend-api/v1/tenants?current=1&size=200。
请确认后端服务已启动，且 vite 代理 BACKEND_URL 指向正确端口
```

这句话对开发者是有用的，对使用者完全是天书：他不知道 `BACKEND_URL` 是什么、也看不到 vite 代理，只知道"用不了了"。

排查时还发现第二个坑：**本机 5173 被另一个项目（`E:\work\huizu-react`，普通话口语测评系统）长期占用**，vite 自动把本项目换到了 5174 —— 但没有任何人注意到这件事，打开 5173 看到的是另一个系统，打开 5174 才不对。用户遇到的 502 很可能就是在错误端口 / 后端未启动两者叠加下产生的。

## 结论：提示分两轨

| 读者 | 看到什么 | 在哪看 |
| --- | --- | --- |
| 使用者 | 「服务暂时连不上，请稍后重试」+ 页面顶部一条常驻横幅 + 「重新连接」按钮 | 页面 |
| 开发者 / 运维 | 完整的接口路径、HTTP 状态、代理目标、响应片段 | 浏览器控制台 `[接口不可用]` |

开发环境（`vite dev`）会把诊断信息附在文案后的括号里，方便本机联调；生产构建只有人话。

## 文案对照

| 场景 | 改前 | 改后（用户可见） |
| --- | --- | --- |
| 代理连不上后端（502/503/504） | 没有收到后端响应（HTTP 502）：/backend-api/... 请确认后端服务已启动，且 vite 代理 BACKEND_URL 指向正确端口 | 服务暂时连不上，请稍后重试 |
| 代理规则没生效，返回了 index.html | 后端返回了非 JSON 响应（HTTP 200）：<!doctype html>... | 服务暂时连不上，请稍后重试 |
| 断网 / 后端进程不在 | `TypeError: Failed to fetch`（浏览器原话） | 网络好像断了，请检查网络后重试 |
| 请求超时（20s 无响应） | 页面一直转圈，没有任何提示 | 请求超时了，请稍后重试 |
| 后端 5xx | 请求失败: 500 | 服务器处理出错了，请稍后重试 |
| 无权限（403） | 禁止访问：当前角色没有该功能的访问权限... | 当前账号没有这个功能的权限，请联系管理员开通 |
| 业务校验失败 | 后端 message | **保持后端 message**（如「部门编码已被占用」—— 比兜底话术有用得多） |

## 端口防呆（这部分才是治本）

`npm run dev` 的终端现在会打印：

```
  后端代理 → http://127.0.0.1:3459
  请访问   → http://localhost:5175
  ⚠ 端口 5173 已被其它程序占用，vite 自动改用了 5175。
    打开 5173 会看到别的项目，请用上面这个地址。
```

后端没起时，终端立刻说清楚：

```
  ✖ 代理转发失败：http://127.0.0.1:3459 连不上（connect ECONNREFUSED）
    请先启动后端：cd ../concise-server-node; npm run restart
    若后端端口不是 3459，用 BACKEND_PORT=<端口> 重新启动前端
```

原来这些信息只出现在浏览器里（且是技术化文案），终端一声不吭。

## 遇到「服务连不上」怎么排查

1. 看 `npm run dev` 那个终端有没有 `✖ 代理转发失败` —— 有就按它说的启动后端。
2. 确认打开的地址是终端打印的「请访问」那一行（不是记忆里的 5173）。
3. 后端在跑但仍 502：端口对不上。看 `concise-server-node/.env` 的 `PORT`，用 `BACKEND_PORT=<端口> npm run dev` 覆盖。
4. 浏览器控制台看 `[接口不可用]` 那条，里面有接口路径和代理目标。

## 怎么扩展

**新增一类错误文案**：只改 `src/lib/api-error.ts` 的 `KIND_MESSAGE`，全站生效（业务代码里不要再自己拼面向用户的技术化文案）。

**页面想自定义错误展示**：

```ts
import { isUnavailableError, userMessageOf } from '@/lib/api-error'

try {
  await doSomething()
} catch (error) {
  if (isUnavailableError(error)) {
    // 服务挂了：显示「重试」而不是把错误当业务失败处理
  } else {
    toast.error(userMessageOf(error, '操作失败'))
  }
}
```

**注意**：`reportRecovered()` 只在「不可用 → 可用」翻转时广播一次，别改成每个成功请求都 dispatch（成功是常态，会白跑一堆渲染）。

## 坑

- `import.meta.env.DEV` 在测试的 CJS 沙箱里是语法错误，测试脚本里做了字符串替换（模拟生产构建）才断言到「无人话后缀」的真实文案。
- 跨 `vm` 上下文的对象原型不同，`assert.deepStrictEqual` 必挂，改成按属性断言。
- 代理错误日志必须节流，否则页面并发几十个请求会把终端刷满。
- `--port 5299` 这类显式指定端口的场景不能说成「端口被占用」，要拿 `server.config.server.port` 和实际监听端口比。
