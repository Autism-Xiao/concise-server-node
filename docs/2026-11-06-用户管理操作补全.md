# 用户管理操作补全：重置密码 / 冻结 / 强制下线 / 解锁 / 自助改密 / 回收站

日期：2026-11-06　仓库：concise-server-node + concise-admin　类型：功能补全

## 背景

用户管理此前只有编辑/删除/水印。补齐中后台标配的管理动作，并打通「会话与登录态」的一致性：改密、冻结必须让旧凭证立即失效，而不是等 JWT 自然过期。

## 后端新增（6 个接口）

| 接口 | 权限 | 说明 |
|---|---|---|
| `PUT /v1/users/:id/password` | system:user:reset-password | 重置密码；留空生成 12 位易读随机口令（`utils/random-token.util`，去掉 0/O/1/l 混淆字符）；明文仅本次响应返回一次，不落库不进日志；成功后该用户全部在线会话立即失效 |
| `PUT /v1/users/:id/status` | system:user:update | 冻结(2)/解冻(1)；冻结自动踢全部会话；内置 admin 不可冻结 |
| `POST /v1/users/:id/force-offline` | system:online:kick | 用户级强制下线，返回踢掉会话数 |
| `DELETE /v1/users/:id/lock` | system:user:update | 解锁登录失败锁定（幂等），清 `auth:login:fail:*` 计数 |
| `GET /v1/users/recycled` | system:user:list | 回收站：软删用户分页列表 |
| `PUT /v1/users/:id/restore` | system:user:restore | 恢复软删用户；可顺带重绑 roleIds/deptIds；用户名被占用时拒绝 |
| `PUT /v1/auth/password` | 登录即可 | 自助改密：验旧密码 → 写新密码 → **其他端全部下线（保留当前会话）**；限流 20 次/5 分钟/IP |

关键实现：

- `OnlineService.kickUser(userId, {keepToken?})`：SCAN 会话逐个拉黑+删除；全量下线时补用户级拉黑标记（覆盖从未登记过会话的令牌）。保留当前 token 模式用于自助改密。
- `loginFailKeyOf` 提取到 `shared/rate-limit/login-fail.util.ts`，AuthService（计数/清零）与 UserService（解锁）共用。
- 冻结后 JWT 每次请求查库即可拒（status≠1），但 **refreshToken 轮换路径不查库**，必须靠用户级黑名单立即掐断——这就是冻结/重置密码要联动 kickUser 的原因。

## 踩坑记录

1. **同秒拉黑误杀**：JWT 的 `iat` 是秒级，用户级黑名单时间戳最初用毫秒 `Date.now()`——「先踢人、后登录」在同一秒内签发的新令牌会被判为"下线前签发"直接 401。修复：黑名单时间戳对齐到整秒（`floor(Date.now()/1000)*1000`）。代价是"与踢人同秒内签发的未使用令牌"可能存活 ≤1 秒，可接受。
2. **限流守卫先于认证**：`@RateLimit({by:'account'})` 在改密接口拿不到 `req.user`（RateLimitGuard 注册在 JwtAuthGuard 之前），退化成按 IP 计数，连跑两轮冒烟就被 5 次/5 分钟限额挡死。守卫已改为优先读 `req.user`（认证后生效的场景预留），该接口本身改用按 IP 20 次/5 分钟。
3. **软删账号的用户名占用**：唯一性预检包含软删行，所以"软删后用同名新建账号"走不通，恢复冲突场景只在直接改库时出现——`restore` 里的占用检查是防御性的，冒烟测纯恢复链路。
4. **冒烟与限流配额**：新增用例引入约 13 次登录，全脚本 ~25 次/轮；登录 IP 限流从 60 调到 **120/分钟**（真正的防爆破是账号级 5 次锁 15 分钟 + 验证码），否则连续重跑冒烟会殃及后续用例。

## 权限点

新增 `system:user:reset-password`、`system:user:restore` 两个按钮权限码（超管 bypass 直接可用；普通角色需在菜单管理录入并勾选）。`system:online:kick`、`system:user:update` 复用已有。

## 验证

- 独立 E2E：23/23 PASS（重置→旧会话失效→新密码登录、冻结→403→解冻、强踢→401→立刻重登可用、5 连错锁定→解锁、旧密码错拒/改密成功/当前会话保留/旧密码失效、回收站可见→恢复→原密码登录）
- 冒烟：**179/179 连跑两轮全 PASS**（新增 19 项用例，含同秒拉黑不误杀）
- 后端 build/lint/lint:ox/test(27) 全绿；前端 tsc/lint/build/test(7) 全绿

## 怎么扩展

- 批量冻结/批量分配角色：照 `batchDelete` + `runBatchDelete` 模式包一层即可。
- 回收站彻底删除（清掉软删行）：注意唯一索引占用，物理删除前应提示。
- 「锁定中」标记：如需在列表展示，可加 `GET lock-state` 批量查 `auth:login:fail:*`（RateLimitService.get），当前先靠"解锁失败再解锁"的操作路径。
