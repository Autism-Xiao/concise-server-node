# 锁屏密码框防快捷录入

## 问题

锁屏输密码时浏览器会：① 自动回填已保存的账号密码（`autoComplete="new-password"` 在部分 Chrome 版本被绕过）；② 解锁后弹「记住密码」气泡；③ 支持粘贴/右键粘贴——旁人可以快捷录入，违背「锁屏挡人」的本意。

## 改了哪些文件

| 文件 | 类型 | 说明 |
| --- | --- | --- |
| `concise-admin/src/components/lock-screen.tsx` | 修改 | 密码输入框四道防线：type 切换 / 管理器忽略标记 / 去 form / 禁粘贴拖放右键 |

## 四道防线（按作用顺序）

1. **Chromium/Safari：全程 `type="text"` + `-webkit-text-security: disc` CSS 打点**——浏览器根本不把它当密码字段，凭据下拉/自动回填/记住气泡统统无从谈起。这是实测后的最终方案：第一版 type 切换只挡了「加载期回填」，Chrome 在**聚焦 password 字段时仍会弹已存凭据下拉**（autoComplete 任何写法都挡不住），只有让它看不见 password 字段才行。Firefox 不支持该 CSS，回落 type 切换（text 起步、聚焦切 password，加载期回填错过且不吞键）。
2. **多层忽略标记**：`autoComplete="new-password"` + 字段名用 `lock-password`（不叫 password）+ `data-1p-ignore`（1Password）+ `data-lpignore="true"`（LastPass）+ `data-form-type="other"`（Dashlane）。
3. **去掉 `<form>`**：Chrome 的「记住密码」气泡由表单提交事件触发，改为 div + 输入框 Enter 提交 + 按钮 onClick，气泡不再弹。
4. **禁快捷录入与明文带出**：`onPaste` / `onDrop` / `onContextMenu` / `onCopy` / `onCut` 全部 preventDefault，只能手动敲键——text-security 打点下选中复制会拿到明文，复制也必须禁。

## 遇到的坑

- **readOnly 方案会吞键**：先实现了「挂载只读、聚焦解锁」，但解锁的那次 keydown 在 readOnly 状态下被吞，用户第一个字符消失，必须敲两遍——换 type 切换方案。
- **autoFocus 与 readOnly 组合自败**：autoFocus 在挂载瞬间就触发 focus 解锁，回填窗口又开了，防线形同虚设——也是弃用 readOnly 的原因之一。
- **type 切换挡不住聚焦下拉**：实测（用户截图）Chrome 在聚焦 password 字段时照样弹已存凭据下拉，加载期躲避没用——升级为 CSS 打点让浏览器全程看不见密码字段。
- **CSS 打点下复制会泄漏明文**：`-webkit-text-security` 只是视觉打点，选中文本 Ctrl+C 拿到的是真实字符——所以 onCopy/onCut 也必须禁。
- `WebkitTextSecurity` 用 `as CSSProperties` 断言（csstype 不含该私有属性）；支持性用 `CSS.supports('-webkit-text-security', 'disc')` 运行时探测，Firefox 自动回落。

## 怎么扩展 / 使用

- 无需配置，锁屏行为自动生效；验证方式：在 Chrome 保存过密码后锁屏 → 输入框不应回填、不弹记住密码、Ctrl+V / 右键粘贴无效。
- 若以后登录页也要防粘贴，参考同一套写法（但登录页**不建议**禁粘贴，密码管理器在登录页是便利性优先）。
