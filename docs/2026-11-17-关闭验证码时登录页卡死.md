# 关闭验证码时登录页进不去（CAPTCHA_ENABLED=false 仍强制滑块）

## 现象

后端 3000、前端 5173 都正常监听，`GET /api/v1/auth/captcha` 也能返回响应，但登录页永远进不去 —— 表现为「项目没起来」。

## 根因（两处叠加，缺一不会出事）

| 层 | 行为 | 后果 |
| --- | --- | --- |
| 后端 `GET /v1/auth/captcha` | 无论 `CAPTCHA_ENABLED` 是什么，都走 `captchaService.create()` → `requireClient()`；滑块挑战存在 Redis 里，本机 `REDIS_ENABLED=false` → 抛 `BizException(SERVICE_UNAVAILABLE, '验证码服务不可用…')`，响应体 `code=503` | 前端拿不到 `captchaId/bgUrl/puzzleUrl` |
| 前端 `handleSubmit` | 无条件 `if (!captchaTicket) return toast.error('请先完成安全验证')` | ticket 永远拿不到 → 提交被拦在本地，请求都没发出 |

关掉验证码的本意是「不验证」，实际却「必须验证但验不了」，登录页成死局。真正让问题变隐蔽的是：页面照常渲染、接口都返回 200（业务码 503 走 HTTP 200），控制台只有一条取图失败的提示。

## 改法

**后端**：`CAPTCHA_ENABLED=false` 时该接口根本不碰 Redis，直接回 `{ enabled: false }`（HTTP 200 / code 0）；开启时才出图并附带 `enabled: true`。

```ts
@Get('captcha')
async captchaChallenge() {
  if (!this.captcha.enabled) return { enabled: false }
  const data = await this.captchaService.create()
  return { enabled: true, ...data }
}
```

登录侧的票据校验本来就有 `if (this.captcha.enabled) await assertTicket(...)`，无需改动。

**前端**：`CaptchaChallenge` 增加 `enabled` 字段（图片字段转可选）；登录页挂载时探测一次，按 `enabled` 决定是否渲染「安全验证」整块，提交时按需带上 `captchaTicket`（关闭时不传空串）。若探测本身失败（开了验证码但 Redis 没起），不再让滑块显示「加载失败」让用户反复点，而是常驻错误条写明原因与两种解法。

## 验证（E2E，不是只看接口）

| 检查 | 结果 |
| --- | --- |
| `GET /api/v1/auth/captcha`（CAPTCHA_ENABLED=false） | `{"code":0,"result":{"enabled":false}}`（改前 `code:503`） |
| `POST /api/v1/auth/login` 不带 captchaTicket | 200 |
| 无头浏览器打开 `/login` | 文案不再含「安全验证 / 点击完成安全验证」，滑块区块消失 |
| 无头浏览器填 `admin/admin123` 点登录 | 跳到 `/dashboard`，侧边栏与订阅列完整，`concise-token` 已写入 |
| 头像 404 | 见下节，已一并清理 |

未覆盖：`CAPTCHA_ENABLED=true` 且 Redis 正常的路径本轮未实机验证（本机未启 Redis），该路径代码未改动，只是多包了一层 `enabled: true`。

## 顺带：清掉指向缺失文件的头像

恢复 11-17 快照后 `admin.avatar` 指向 `/upload/2026-11-11/图片/avater-*.png`，而 `public/upload` 目录在本机不存在（快照只含 `sys_file` 记录、不含物理文件），控制台每次加载都报两条 404。已按「文件不存在即清空引用」逐用户校验后清空（现全站无头像用户），页面不再有 404。

## 怎么扩展

- 新增依赖「后端能力开关」的前端分支时，判断依据要由**后端返回**，不要在前端写死：本次前端原本默认「必须验证码」，只因为没有任何接口告诉它开关状态
- 关闭类的开关要顺手检查「依赖该开关的下游是否还有硬性前置」：本例 `assertTicket` 已经受开关控制，但取图接口没有，于是前置先断了
- 本机没有 Redis 时 `CAPTCHA_ENABLED` 必须为 false；要验证开启路径需先起 Redis（`REDIS_ENABLED=true`）
