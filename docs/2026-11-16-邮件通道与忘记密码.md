# 邮件通道（SMTP）与忘记密码

> 日期：2026-11-16 ｜ 范围：`src/shared/mailer/`、`src/modules/tools/email/`、`src/modules/auth/*`、前端登录页
> 关键词：nodemailer、SMTP、dry-run、验证码、防账号枚举

## 一、为什么做

底座原来只有一种找回密码的方式：**找管理员重置**。这在实际场景里有两个问题：

1. 管理员得人工核对身份，夜里/假期没人处理。
2. 重置完还得想办法把临时密码告诉用户（微信发？电话念？），密码在聊天记录里裸奔。

同时 `src/shared/mailer/` 和 `src/modules/tools/email/` 一直是**空目录**——占着位置没实现，属于"看着有其实没有"的功能。

所以这轮补的是：**能发信** + **用户自助找回**。

## 三、配置为什么分两处

| 配置项 | 位置 | 理由 |
| --- | --- | --- |
| `MAIL_SMTP_HOST/PORT/SECURE/USER/PASS` | **环境变量** | 密码是密钥。`sys_config` 的内容会原样出现在「参数配置」页面，任何有 `system:config:list` 的人都能看到 |
| `mail.enabled` | `sys_config` | 需要在线上随时开关（比如 SMTP 供应商故障时先关掉，别让用户一直等超时） |
| `mail.from` | `sys_config` | 展示信息，改了不该重启 |
| `mail.resetCode.ttlMinutes` | `sys_config` | 安全策略，属于"想调就调"的参数 |

这套划分是刻意的：**密钥走 env，行为走配置中心**。以后加邮件场景（比如周报订阅）也照这个来。

## 四、dry-run 降级：为什么"没配置"不报错

`MailerService.send()` 在「未配置」或「开关关闭」时不抛异常，而是：

1. 把邮件塞进内存 outbox（最多 20 条，`GET /v1/mail/outbox` 可查，**dry-run 时带正文**）
2. 记一条 warn 日志
3. 返回 `{ ok: true, dryRun: true }`

理由：发信失败不该让「忘记密码」直接 500。用户点了没反应比"点完提示已发送、实际没发"更糟——至少后者用户会去查邮箱、然后来找管理员。而本地开发根本没 SMTP，靠 outbox 就能把验证码捞出来走通全流程。

**但测试发信（`POST /v1/mail/test`）不吃 dry-run**：它明确要求 `mail.enabled=true` 且配置齐全，否则直接返回原因。否则会出现"测试通过、线上没配"的假安全感。

## 五、忘记密码的四个安全设计

1. **不做账号枚举**。无论账号不存在、没绑邮箱、还是冷却期内重复申请，接口一律返回 `{ sent: true, ttlMinutes }`。差别只写服务端日志。前端也配合：第一步永远能进第二步，不因"账号不存在"提前报错。
2. **先验码再验密码强度，两者都过才消费码**。顺序反过来会出现：用户填了弱密码 → 码被烧掉 → 得重新申请。现在弱密码会被拒，但码还在，换个密码就能过。
3. **码不存明文**。Redis 里存的是 `sha256(code + userId)`，被读走也没法直接用（6 位数字空间小，加 userId 当盐防彩虹表）。
4. **限流 + 冷却 + 试错上限**：接口 5 次/5 分钟；同账号 60 秒内重复申请不再发信；一个码错 5 次即作废（要重新申请）。

## 六、坑

| 坑 | 现象 | 处理 |
| --- | --- | --- |
| `AuthModule` 没导入 `SystemConfigModule` | 启动即崩：`Nest can't resolve dependencies of PasswordResetService (..., SystemConfigService)` | `MailerModule` 只是自己 import 了它、没导出；用的人得自己 import。已在 `auth.module.ts` 里显式加 |
| pnpm 装包被拦 | `ERR_PNPM_IGNORED_BUILDS` + `vue-demi@0.14.10` | 与本项目无关的传递依赖（pnpm 要求显式表态）。在 `pnpm-workspace.yaml` 的 `allowBuilds` 写 `'vue-demi': false` |
| `whitelist` 会剥掉没装饰器的字段 | `remark` 传了不生效 | 每个字段至少一个 class-validator 装饰器；`@IsOptional()` 之外还要 `@IsString()` 之类的类型校验 |
| `@nestjs/swagger` 重复 import | lint 报 `no-duplicate-imports` | 合并成一行 `{ ApiBearerAuth, ApiOperation, ApiProperty, ApiTags }` |
| 测试时改了真实账号密码 | 冒烟账号 `zhangsan` 被重置 | 改前把 `password/salt/password_expire_at/must_change_password` 四列 dump 到临时文件，验完按原值 UPDATE 回去，再比对一致性确认还原 |
| 权限怎么给 | 不想为一封测试信新增菜单 | 复用配置中心的 `system:config:list`（看状态）/ `system:config:update`（测发信）。能改 `mail.enabled` 的人本来就该能测 |

## 七、怎么扩展

- **加邮件场景**：`mailer.templates.ts` 加一个 `renderXxxMail()`，调用处 `this.mailer.send(to, renderXxxMail(data))`。不要新增"任意收件人 + 任意正文"的通用接口——那等于给系统装一个可被滥用的发信器。
- **换供应商**（SendGrid / 阿里云 DirectMail / 腾讯云 SES）：只改 `MailerService.getTransporter()` 里的 `createTransport(...)`，其余代码不动。走 HTTP API 的供应商需要换成 `createTransport({ host, port, secure, auth })` 之外的适配器，此时把 `send()` 内部替换成 fetch 调用即可，接口签名不变。
- **接队列**：现在发信是同步 await（10 秒超时）。真正量大时应该 `void this.mailer.send(...)`（不阻塞响应）或丢给消息队列重试，注意后者要处理"发失败用户不知道"的问题。
- **加短信通道**：`PasswordResetService` 现在是"发邮件"，抽一个 `NotificationChannel` 接口（sendCode(user, code)），邮件/短信各一个实现，按用户绑定情况选路。
- **配置页分组标题**：`mail.*` 会在参数配置页显示成 `mail` 分组卡片，想要中文标题就在前端加 group 名映射。
