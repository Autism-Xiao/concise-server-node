# 切换租户不再整页刷新（软切换 / 秒切）

## 现象

点顶栏切换租户后，"卡顿一下"：白屏几百毫秒到一两秒，页面整体重来，本地开发下更明显。

## 为什么会卡

原来的实现是最后一步 `window.location.reload()`：

```ts
const applied = await switchTenant(tenantId)
setTenantId(applied)
window.location.reload()   // ← 卡在这
```

整页 reload 的代价远比「重新拉一次数据」大：

| 动作 | 有必要吗 |
| --- | --- |
| 重新下载并执行整个应用 JS | ❌ 代码一个字节都没变 |
| 重建所有 Provider（设置/水印/锁屏/标签页） | ❌ 这些是「跟人不跟租户」的 |
| 重新算菜单树、权限、首屏路由 | ❌ 菜单是按角色的，租户不影响 |
| 重绘水印、重读主题、恢复标签页 | ❌ 白闪的罪魁祸首 |
| 重新发数据请求 | ✅ 这个躲不掉 |

再加上本地 `vite dev`：整页 reload 会触发一次完整的模块图重新加载，1~2 秒很常见（生产构建白屏大约 200~500ms，但仍然有闪烁）。

## 解法：软切换（不刷新整页，只重挂数据区）

项目本来就有两样现成的东西可复用：

1. **多标签页 keep-alive**（`tab-page-renderer.tsx`）：页面用 `key = path:nonce` 控制重挂载，`nonce` 自增就能"刷新当前页"
2. **`http.ts` 每个请求都现读 `localStorage['concise-tenant']`** 生成 `X-Tenant-Id`，不需要重新初始化任何东西

于是切换流程改成：

```
POST /tenants/switch  →  写 localStorage  →  epoch + 1  →  页面 key 变化 → 重挂 → 各自重拉数据
```

`epoch` 是新增的「租户代次」，拼进每个页面的 key：

```tsx
<TabPage key={`${path}:${nonces[path] ?? 0}:${epoch}`} ... />
```

租户一变，所有已挂载页面整体换新实例，`useEffect` 重跑，数据自然重拉——这正是原来靠 reload 保证的"绝不残留上个租户数据"，但省掉了整个应用启动。

### 三个细节（不做就会退化）

1. **先写 localStorage，再推进 epoch**。重挂后页面发出的请求必须已经带上新的 `X-Tenant-Id`，顺序反了就有一批请求打在旧租户上。
2. **重挂后只保留当前页挂载**（`visitedPaths` 重置为当前 path）。否则 keep-alive 里 5 个标签会同时重挂、同时发请求，反而比整页刷新更卡。
3. **切换期间盖遮罩**。388ms 里旧租户的数字还在屏幕上，不遮住容易被当成新租户的数据读。

## 改了哪些文件（concise-admin）

| 文件 | 类型 | 说明 |
| --- | --- | --- |
| `src/context/tenant-scope-provider.tsx` | 新建 | 软切换上下文：`epoch`（重挂信号）、`switching`（遮罩/转圈）、`applySwitch()`（接口 + localStorage + epoch++） |
| `src/routes/_authenticated.tsx` | 修改 | 挂 `TenantScopeProvider`；`SidebarInset` 加 `relative` 并放 `TenantSwitchingOverlay`（半透明遮罩 +「正在切换租户…」） |
| `src/components/layout/tab-page-renderer.tsx` | 修改 | key 拼上 `epoch`；epoch 变化时把 `visitedPaths` 收紧成只留当前页 |
| `src/features/system/tenant/components/tenant-switcher.tsx` | 修改 | 去掉 `window.location.reload()`，改调 `applySwitch()`；切换中按钮转圈、成功 toast 带租户名 |

保留的东西：侧边栏菜单、主题、语言、水印、锁屏、界面设置全部原地不动——它们跟人走，不该因为换租户重来。

## 验证（headless Chrome + CDP 真实点击）

| 检查项 | 结果 |
| --- | --- |
| 页面标记 `window.__marker` 是否存活 | **存活**（整页刷新会丢）|
| 顶栏更新为「长沙示范科技有限公司」 | 388ms |
| 切换后发出的请求 | 只有 `/tenants/switch` + `/dashboard/overview`（没有并发拉其它标签）|
| 提示 | 「已切换到「长沙示范科技有限公司」」 |
| 切回平台视角 | 同样不刷新，顶栏回到「平台视角」 |

## 坑

- **不能只删 reload 就完事**：不重挂页面的话，keep-alive 里的旧组件不会重新 `useEffect`，会把上一个租户的数据一直显示着（这正是最初选择 reload 的原因）。
- `visitedPaths` 如果跟着 epoch 一起"全量重挂"，会一次性并发 N 个页面的请求（`MAX_TABS = 12`），切换瞬间更卡。
- `applySwitch` 里的 `setSwitching(false)` 在 `finally`，遮罩消失时新页面的数据可能还在路上，此时看到的是各页面自己的 loading / 空态——可接受；如果要更极致，可以让遮罩等首屏数据回来再撤（成本高，暂不做）。
- 项目没有全局数据缓存（没有 react-query），所以"重挂 = 重拉"是唯一正确手段。将来若引入查询缓存，可以直接 `queryClient.resetQueries()` 代替重挂，连组件实例都不用重建。

## 怎么回退

把 `tenant-switcher.tsx` 里 `applySwitch(tenantId)` 换回 `switchTenant + setTenantId + window.location.reload()` 即可，`TenantScopeProvider` 不参与其它逻辑（`epoch` 恒为 0 时行为与改动前一致）。
