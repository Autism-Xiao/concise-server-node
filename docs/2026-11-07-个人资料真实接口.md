# 个人资料接真实接口

## 背景

「系统设置 → 个人资料」这一页此前是**纯前端假数据**：姓名写死「张三」、用户名写死「zhangsan」、邮箱写死 `zhangsan@example.com`，点保存只弹一句 toast，刷新就没了。头像和改密码倒是真的（早就接了 `/v1/users/me/avatar` 和 `/v1/auth/password`），唯独资料本身没有任何接口落点 —— 后端连「查自己」的接口都没有（`GET /v1/users/:id` 还要求 `system:user:list`，普通账号点开自己的资料会被 403）。

这次补齐「本人查看/修改自己资料」的整条链路。

## 接口契约

### `GET /api/v1/users/me`

- 鉴权：登录即可（**不挂 `@Perms`**，普通账号也能看自己的资料）
- 返回：`UserEntity`，带 `roles` / `depts` / `posts` / `level` / 水印设置；`password`、`salt` 是 `select: false`，不会漏
- 实现：直接复用 `findOneDetail(req.user.id)`，与详情接口同一套组装逻辑，避免两处字段不一致

### `PUT /api/v1/users/me`

请求体只认白名单字段（全局 `ValidationPipe` 的 `whitelist: true` 会把 `status`、`roleIds`、`username` 之类的多余键**直接丢掉**，不会报错也不会生效）：

| 字段 | 规则 |
| --- | --- |
| `realname` | 字符串，≤100；空串视为清空 |
| `email` | 邮箱格式（空串放行），≤45，**唯一** |
| `phone` | 字符串，≤45，**唯一** |
| `telephone` | 字符串，≤45 |
| `sex` | `0 / 1 / 2`（未知 / 男 / 女），自动转数字 |
| `birthday` | `YYYY-MM-DD`（空串放行，表示清空）；`1990/1/1`、`1990.1.1` 会被归一成标准格式 |
| `bio` | 字符串，≤255 |

返回更新后的完整资料（同 `GET /me`），前端一次请求就能刷新整页状态。

## 实现要点

### 不能自助提权

- 账号、工号、状态、角色、部门、密码**都不在这个接口里**：账号是密码算法的一部分（改了等于登录不了），工号有唯一键，状态/角色/部门属于管理员权限，密码走 `/v1/auth/password`
- 前端就算手动构造 `{"status":2}` 或 `{"username":"hacker"}`，后端也只当没传

### 空串归一成 NULL

`email` / `phone` 上都有唯一索引，而 `''` 也是一个**具体的值**：两个账号都把邮箱清成空串，第二条就会撞 `Duplicate entry ''`。所以 service 里统一把空串转 `null`，语义也更准（没设置 ≠ 设置成空字符串）。

### 唯一键前置查重（含回收站）

`email`、`phone` 的唯一索引对软删账号同样生效（软删不释放唯一键），所以写入前先查一次占用者，冲突直接转成中文 400：

> 邮箱「a@b.com」已被账号「zhangsan」占用（该账号在回收站）

`ER_DUP_ENTRY` 再兜一层（并发场景），由 `describeWriteError` 翻译，用户看不到 SQL 原文。

### 路由顺序的坑

`GET :id` / `PUT :id` 都是单段路由，`me` 也是单段 —— Express 先注册先匹配，所以 `me` 的两个路由必须写在 `:id` **之前**，否则 `GET /v1/users/me` 会被当成「查 id 为 me 的用户」，返回 404 用户不存在。`PUT me/avatar`、`GET me/settings`、`GET me/watermark` 是两段，天然不冲突。

### 前端姓名同步

侧边栏 `NavUser` 渲染时读一次 `getName()`（localStorage）。改完姓名如果只写 localStorage，组件不会重渲染，名字要等整页刷新才变。所以 `setDisplayName` 里顺带 `notifyAuthChanged()`，`NavUser` 监听这个事件重读一次 —— 和登录态同步用的是同一个通道。

页面自测建议路径：改姓名 → 看侧边栏是否立刻跟着变；清空邮箱保存 → 再进来确认是空的（库里是 NULL）；填一个已被占用的邮箱 → 应看到中文 400 提示而不是「保存失败」。

## 扩展说明

- 想加字段（比如「个人主页」）要动三处：迁移加列 → 实体加属性 → `UpdateMyProfileDto` 加校验；漏了 DTO 就会被 whitelist 静默丢掉
- 想开放更多字段给用户自助改，请先确认它不属于「管理员权限」范畴；`status` / `roleIds` / `deptIds` 一旦放开就是提权漏洞
- 用户列表/导出暂未加简介列：`bio` 只服务个人资料页，列表页塞不下也不该塞
