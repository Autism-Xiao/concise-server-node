- 开头一次裸登录探针，能登进去 = 开关没开 → 打印提示 + **退出码 2**；

## 业务错误码分段细化（本轮）

审前后端 code 定义，发现「后端定义得很细、前端消费端完全没接上」：

- `login.tsx` 用 `message.includes('已锁定')` 判账号锁定 → 文案一改就静默失效。根因是 `ApiError` 没透传业务码，调用方想按码分支也拿不到。
- `http.ts` 里 `json.code === 401` 是死分支：后端 401 的 body code 恒为 1003/1007，永远不等于 401（jeecg 时代抄来的双保险）。
- 414/415/416 是短信验证码遗产，全项目零使用，但 Swagger 还在宣传 415。
- 过滤器把未映射的 4xx（如 409）一律映射成 1006「内部错误」，HTTP 与 body 自相矛盾。

改法：
- `biz-error-code.enum.ts` 重写分段：冻结段（0/41x/1001~1009/429/503，**只增不改**）+ 21xx 认证 / 31xx 角色 / 41xx 组织 / 51xx 配置 / 61xx 文件导入 / 71xx 协作 / 81xx 租户 / 91xx 运维。四位数与三位老码天然可辨。
- **加码铁律：一码一消费者**——新增前必须写明谁在用（前端 UI / 监控聚合 / 重试策略），同类细节靠 message 区分（缺哪列都是 6103）。
- 替换 40 余处关键 throw；过滤器未映射 4xx 用 `status` 本身兜底，仅 5xx 回落 1006。
- 前端 `ApiError` 加 `code?: number`（构造参数追加末尾），`http.ts` 透传 `json.code` 并删 401 死分支，登录页改判 `code === 1009`。

坑（都花了时间）：
- `/v1/files/purge` 的 `ids` 必须是**字符串数组**，传 number 返回 `1001 每个 id 必须是字符串`。脚本没检查 code 就打印「删掉 N 项」，看起来成功其实没删，绕了一大圈。
- `smoke-file` 的「移动到根目录」偶发失败：上一轮运行被 `| head` 截断（SIGPIPE 提前退出）导致结尾 purge 没跑，根目录留 `改名后.md`，下次 move 撞同名 400。已在脚本开头加「按冒烟专用命名清根目录残留」，并给该断言补诊断信息。
- 替换 throw 后 `BadRequestException`/`NotFoundException` 的 import 会变成未使用，`eslint --max-warnings=0` 逐个报出来（4 个文件）。
