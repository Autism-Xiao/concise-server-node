## 启动端口占用自动清理（EADDRINUSE）

- 根因：`src/main.ts` 末尾是裸的 `void bootstrap()`，`app.listen` 异步 reject 没人接，日志里只剩 Node 内部堆栈，看不出"上一轮 node dist/main.js 没退"。
- 新增 `scripts/serve.mjs`：`net.createServer().listen(port)` 探测端口 → 占用则 netstat 取 PID → 读命令行判定是否本项目实例（必须 node + `dist/main` / `nest start`，绝对路径还须落在仓库内）→ `taskkill /T /F` → 轮询等释放（最多 8s）→ spawn 子进程并转发退出码。非本项目占用打印 pid / 进程名 / 命令行后 exit 1，不误杀。

## 后台 serve 任务报 exit 1 的真相（易误判）

- 用后台方式跑 `node scripts/serve.mjs` 时，若之后又起一次 serve，新实例会 `taskkill` 掉旧实例的子进程，旧的后台任务因此以 **exit code 1 + failed** 结束 —— 这不是崩溃，是「被替换」。`grep "Nest application successfully started"` 能看到它当时是起成功了的。
- 判断当前跑的是哪份代码：`(Get-Item dist\modules\user\user.service.js).LastWriteTime` 与 `(Get-Process -Id <pid>).StartTime` 对比，进程启动晚于构建 = 加载的是最新构建。
- 3459 是 `.env` 里 `CAPTCHA_ENABLED=true`，所以 curl 直接 `POST /v1/auth/login` 会拿到 `{"code":417,"message":"请先完成滑块验证"}`；要脚本化验证得另起 `PORT=3461 CAPTCHA_ENABLED=false node dist/main.js`，别误以为是密码错。

## 接口错误提示人性化 + 端口防呆（前端本轮）

- 文案两轨：用户只看人话（`src/lib/api-error.ts` 的 `KIND_MESSAGE` 是**唯一出口**），技术细节进 console `[接口不可用]`；只有 `import.meta.env.DEV` 才把 detail 附在括号里，生产只留人话。
- `http.ts` 的 `request()` 统一 20s 超时（AbortController，调用方传了 signal 就不接管）；断网 `TypeError: Failed to fetch` 转 `ApiError('network')`。`parseJsonBody` 把 502/503/504 **以及「返回 index.html（代理没生效被 SPA 兜底）」** 都判成 unavailable —— 后者是用户这次遇到的真实形态。
- 业务错误必须透传后端 message：`new ApiError('business', detail, status, message)` 第 4 参，否则会被兜底话术「操作没成功，请重试」覆盖。
- `ServiceStatusBanner` 挂 `_authenticated`（SiteHeader 下）。`reportUnavailable/reportRecovered` **只在状态翻转时 dispatch**，别改成每个成功请求都广播（成功是常态）。
- vite：启动打印「请访问 → localhost:实到端口」，端口被占自动切换时告警；proxy `configure` 的 error 事件在终端打印「该启动后端」（30s 节流）。判断「被占用」要比 `server.config.server.port` 与实际监听端口，否则 `--port 5299` 手动指定会误报成被占用。
- 实测确认：本机 5173 被 `E:/work/huizu-react`（普通话口语测评系统）长期占用，本项目自动落到 5174 —— 这就是用户「打开 5173 看到别的系统/报 502」的根因。
- 单测 `tests/http-unauthorized.test.cjs` 重写：`import.meta.env.DEV` 在 CJS 沙箱是语法错误（用字符串替换成 false 模拟生产）；跨 `vm` 上下文对象不能 `deepStrictEqual`（原型不同），按属性断言。7/7 过。
