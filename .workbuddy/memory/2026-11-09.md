### 本轮踩的坑

- `CREATE INDEX ... ALGORITHM=INPLACE, LOCK=NONE` 语法报错（COMMENT 位置 + 逗号都不行），干脆不写，MySQL 8 普通二级索引默认就是 Online DDL
- 单事务 `INSERT ... SELECT` 灌 100 万行跑到 679s 未完成，`KILL` 后 InnoDB 回滚 **1180 秒**且一直锁表，后续批次全部 1205；正确做法是分批提交（10 万/批 ≈ 7 秒）
- `typeorm migration:show` 的 `[ ]` 按 name 比较，类名带数字前缀时不可信；以 `migration:run` 的「N new」为准
- 灌数测性能时临时 `SET GLOBAL innodb_flush_log_at_trx_commit=2`，**测完必须改回 1**

## 用户设置改 C 方案：默认值上移后端 + 读时补齐（用户拍板）

- `user-setting.util.ts` 新增三件：`DEFAULT_USER_SETTINGS`（服务端权威默认值，8 项）、`withDefaults(stored)`（读时补齐，内部再 normalize 一次防脏输入漏出）、`stripDefaultSettings(settings)`（写库前剔除等于默认值的键）
- `get()` 现在**永远返回完整 8 项**，`updatedAt: null` 表示「从未修改」；前端 `safeMerge` 退化为离线兜底（只改了注释，逻辑没动）
- **两个必须做的细节，少一个「只存差异」就白做**：
  1. `save()` 的合并基准必须是 `readStored()`（原始差异），**不能用 `get()`** —— 后者已补齐，会把 8 个默认键写回库
  2. 合并后必须 `stripDefaultSettings()` —— 前端 `pushSettings` 推的是完整 `AppSettings`，不剔除等于每次保存都整包固化默认值，将来默认值改版这些人永不跟随
- 语义：某键值等于默认 = 没有自定义；用户把某项改回默认 = 删除该差异
- 迁移 `StripSettingDefaults1794260000000`：清洗历史整包数据（`WHERE settings <> '{}'` 逐行 JS 剔除），**不动 update_time**（运维清洗不是用户行为，改了会给前端「谁更新」的假信号）；迁移里内联默认值快照，不 import 常量（迁移行为不能随代码漂移）。开发库把 admin/ceshi 两行清成了 `{}`
- 单测 15 项：`DEFAULT_USER_SETTINGS` 全部通过白名单（这条能抓住「加了默认键忘加校验」）、`withDefaults` 对脏输入只输出合法结构、`stripDefaultSettings` 四种情形
- 端到端 16 项全过，含「推完整 8 项默认值 → 库里回到 `{}`」「推完整值只一项不同 → 库里只留那一项」
- 加新设置项的顺序：白名单 → `DEFAULT_USER_SETTINGS` → 前端 `AppSettings` → 前端 `DEFAULT_SETTINGS`

- `pageSize` 上限 100（`@Max(100)`），传 200 会 400 且响应没有分页结构，容易误判成「列表 select 漏字段」
- `smoke-user-setting.mjs` 2 条断言是 C 方案前的（期望 `settings=null`、非法值不出现），已改成「下发默认值」「非法 direction 回落 ltr」

### 补充：角色侧也要失效鉴权缓存

- `RoleService.updateRole` 在 `status` / `dataScope` 变化后、`deleteRole` 后调 `authUserCache.invalidateAll()` —— 缓存的 `roles` 里带 status（validate 过滤有效角色用）与 dataScope（数据范围），不清会 30s 内按旧角色放行；名称/描述不动缓存

### 前端设置同步去掉跨时钟比较（concise-admin）

- 旧逻辑 `remote.updatedAt >= local.updatedAt` 比较的是客户端时钟 vs 服务端时钟，**不可比**；`remote.updatedAt || Date.now()` 还会把客户端时间固化成基准 → 机器时钟偏快时云端更新被永久忽略
- 改成 `dirty` 标记：用户改设置 → `persistLocal()`（默认 dirty=true）；推送成功 → `markSynced(settings)`（**带内容比对**，防异步回调把用户新改动标成已同步）；从云端回写必须 `persistLocal(x, t, false)`；`loadSettings` 判定顺序：local.dirty → 云端 → 本地 → 默认值。`updatedAt` 不再参与比较
- 老快照无 dirty 按「已同步」处理（取舍：否则老用户永远压着云端）
- 文档：`docs/2026-11-09-前端设置同步去时钟依赖.md`

## 租户默认角色模板（建租户不再空壳）

- 问题：菜单是平台共享（`sys_permission`），角色是租户级（`sys_role`），只插 `sys_tenant` 的租户**没有任何角色**。而 PermsGuard 只对 `is_platform_admin` 放行，**内置角色不享受绕过** → 空壳租户里连管理员都 403
